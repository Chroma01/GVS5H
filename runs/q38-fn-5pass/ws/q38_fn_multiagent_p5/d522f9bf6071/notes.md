- **Sample tests:** The current solution passes both provided examples. Example 1 returns `[2, 3]`, and example 2 returns `[1, 3, 5, 6]`. No sample-test failure was found, so no tie-breaking or compatibility revision was needed.
- **Approach:** Sort intervals by right endpoint while keeping original indices. Let `dp[i][j]` be the best state using the first `i` sorted intervals and choosing exactly `j` intervals. Each state is `(score, sorted_tuple_of_original_indices)`.
- **Transition:** For interval `i`, either skip it (`dp[i-1][j]`) or take it from `dp[p][j-1]`, where `p = bisect_left(ends, left, 0, i-1)` counts previous intervals ending strictly before the current left endpoint. Insert the current original index into the stored sorted tuple.
- **Tie-breaking:** Compare states by larger score first, then lexicographically smaller tuple. Exact-count states have equal tuple length, so tuple comparison is safe during DP. The final answer compares exact counts `0..4`; Python tuple comparison also correctly makes a shorter prefix lexicographically smaller.
- **Correctness intuition:** For a fixed prefix and exact count, all intervals in that prefix end before any future interval that can use this prefix, so compatibility with future intervals does not depend on which equal-score prefix selection was chosen. Keeping only the lexicographically smallest tuple among equal-score states is therefore safe. Lower-score states cannot catch up because future additions are additive and available possibilities are the same.
- **Complexity:** Sorting is `O(n log n)`. Each interval does one binary search and constant DP work for `j <= 4`, so total time is `O(n log n)`. Memory is `O(5n)` states; tuples have length at most 4.
- **Edge cases:** Strict non-overlap requires `end < left`, so touching endpoints are incompatible. The binary search is limited to previous intervals to avoid self-use. Intervals with the same right endpoint are never compatible with each other, and their relative order does not affect correctness.
- **Pitfalls:** Do not append the current index; it must be inserted into sorted order. Do not use “up to j” states during intermediate DP because lexicographic order across different lengths can be non-monotone before the final comparison. Use `bisect_left`, not `bisect_right`, to enforce strict endpoint separation.
