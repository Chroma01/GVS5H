- **Core reduction:** Let the sorted coordinates be `x_0 < x_1 < ... < x_{n-1}` and define gaps `g_j = x_{j+1} - x_j` for `0 <= j < n-1`. An operation on four consecutive pieces with gaps `(a, b, c)` changes them to `(c, b, a)`. Thus it swaps gaps whose indices differ by 2, preserving the parity of each gap index.
- **Reachability:** For gaps with 1-based odd indices, operations with odd `i` swap adjacent elements in the odd-indexed gap subsequence. For gaps with 1-based even indices, operations with even `i` swap adjacent elements in the even-indexed gap subsequence. The middle gap of the operation is unchanged, so the two parity classes are independent. Adjacent swaps generate all permutations, so every permutation within each parity class is reachable.
- **Objective function:** The sum of coordinates can be written as `n * x_0 + sum_{j=0}^{n-2} (n-1-j) * g_j`. The leftmost coordinate `x_0` is invariant because operations never move the leftmost piece. The weight of gap `j` is `n-1-j`, which strictly decreases as `j` increases.
- **Optimization:** By the rearrangement inequality, within each parity class we should pair larger gaps with smaller weights. Since weights decrease with gap index, this means sorting each parity class in ascending order and assigning them to increasing gap indices.
- **Implementation details:** In 0-based indexing, `gaps[0::2]` corresponds to 1-based odd gap positions and `gaps[1::2]` corresponds to 1-based even gap positions. Sort both lists ascending, then iterate over gap positions from left to right, taking the next gap from the corresponding sorted list and adding `gap * (n-1-j)` to the answer.
- **Complexity:** Computing gaps and sorting takes `O(n log n)` time. Memory usage is `O(n)`. Python integers safely handle the maximum possible answer.
- **Edge cases:** `n = 4` works directly. All gaps are positive initially and remain positive under the operation. The input coordinates are already sorted by the constraints.
