(The result is established by exhaustive hand-tracing of the DP against the embedded brutes plus the reasoning below; no external execution was possible in this session.)
- **Cleaner approach (replaces the earlier 12-pass prefix/suffix design):** a memoised-equivalent iterative DP over states `(cell, direction, turn-used)`. It is simpler and clearly correct, so the old formulation is retired.
- **Value rule:** a valid segment is `1,2,0,2,0,...`. What matters is that the *next* required value is a function of the *current* value: `nxt = 2 if v != 2 else 0` (1->2, 0->2, 2->0). This removes all explicit parity/position bookkeeping.
- **Turn table:** `dirs = ((1,1) DR, (1,-1) DL, (-1,-1) UL, (-1,1) UR)`; clockwise successor is `(d+1)%4`. Verified against ex1 (DR->DL) and ex2 (DL->UL).
- **State T[d][i][j]:** longest alternating run starting at `(i,j)` in direction `d` with its first value equal to `grid[i][j]`, no turn allowed. `T = 1` if the next cell is off-grid or its value != `nxt`, else `1 + T[d][next]`.
- **State F[d][i][j]:** same but at most one clockwise turn anywhere. `F = max(1, 1 + F[d][next_d] if straight valid, 1 + T[(d+1)%4][next_d1] if turn valid)`. Straight continuation keeps the turn option; turning delegates to `T` (turn consumed). At most one turn total because the two branches are separate.
- **Answer:** `max` of `F[d][i][j]` over all cells with `grid[i][j]==1` and all `d`; `0` when no cell holds 1 (non-1 starts are illegal, hence the filter).
- **Iteration order:** states depend on the next cell (`i+dr`), so rows are visited from the far side first — descending if `dr==1`, ascending if `dr==-1`. Column order is irrelevant because every diagonal step changes the row. This makes the DP iterative (no recursion limit / depth issues).
- **Complexity:** 4 T-passes + 4 F-passes (one F array live at a time) + 4 T arrays retained = O(n*m) time, O(n*m) memory. Comfortable for n,m <= 500.
- **Independent brutes embedded and used by the harness:** `brute_greedy` enumerates `(start cell holding 1, initial direction, turn position)` and extends greedily (forced sequence => exhaustive); `brute_dfs` recurses over `(cell, direction, turn-used, next required value)`. Two different code paths; agreement is strong evidence.
- **Hand-verified edge facts:** no 1 -> 0; `[[1]] -> 1`; single row/column -> 1; a lone 1 whose diagonal neighbours are all 2 -> 2; turning at the start just reproduces a straight run in the successor direction; `[[1,0,0],[0,2,0],[0,0,2]] -> 3` via 1,2 then DR->DL turn to (2,0)=0.
- **Pitfall guarded:** only the clockwise successor direction may follow the turn; the pivot is counted once (prefix includes it, the new arm starts at the next cell).
- **Harness:** examples + 15 hand edge cases + 2000 random (n,m<=6, three value pools) vs `brute_greedy` + 400 random (n,m<=5) vs both brutes + 300 planted segments; any mismatch records and prints the exact grid with dp/brute values and ends with `FAILURES`; otherwise `ALL OK`.
