- **Model:** The j-th unit of product i has marginal cost `(2j - 1) * P_i`. Because marginal costs for each product are nondecreasing, the optimal purchase set is a prefix of all marginal costs sorted increasingly.
- **Threshold feasibility:** For a marginal-cost threshold C, product i contributes `x_i = (C // P_i + 1) // 2` units, and the total cost is `sum(P_i * x_i^2)`. This feasibility predicate is monotone in C, so binary search finds the largest feasible C.
- **Upper bound:** Let C* be the maximum feasible threshold. If C* + 1 were not an actual marginal cost, cost(C* + 1) would equal cost(C*) and remain feasible, contradiction. Thus C* + 1 = `(2k + 1) * p` for some product, where k units of that product are bought at threshold C*. Since `p * k^2 <= M`, we have `C* + 1 <= 2 * sqrt(M * p) + p <= 2 * sqrt(M * maxP) + maxP`. The code uses `2 * isqrt(M * maxP) + maxP + 5`, safely above C*.
- **Remainder step:** After buying all units with marginal cost <= C*, the remaining budget can only buy units whose next marginal cost is at least C* + 1. Because C* is maximal, C* + 1 is infeasible as a full threshold, so the remaining budget is strictly less than `count_at_C_plus_1 * (C* + 1)`. Therefore `remaining // (C* + 1)` is exactly the number of additional units affordable at that next marginal cost, and it cannot exceed the available count.
- **Implementation details:** Prices are sorted to allow early stopping when `p > C` and to make infeasible checks often exceed M early. The feasibility function has a separate branch for `C >= max_p` to avoid a per-iteration break check. Integer shifts are used for division by 2.
- **Edge cases:** If no unit can be bought, the maximum feasible threshold may be `min(P) - 1`, and the final division by `C + 1` correctly gives zero extra units. If C = 0, this only happens when marginal cost 1 exists but buying all such units is infeasible; the formula still works. The stock limit `10^100` is never binding under the given M and P constraints.
- **Complexity:** Sorting is `O(N log N)`. Binary search uses about 47-60 iterations depending on bounds, each scanning up to N prices with early exits, so roughly `O(N log(2 * sqrt(M * maxP) + maxP))`. This is intended to fit for N = 2e5.
- **Pitfall:** Using a feasible threshold that is not maximal can overcount, because C + 1 may be below the true next marginal cost. The binary search must find the maximum feasible threshold before applying the remainder formula.
