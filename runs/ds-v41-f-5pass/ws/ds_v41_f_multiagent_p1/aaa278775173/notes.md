- **Problem shape:** Longest valid V-shaped diagonal segment. Sequence is 1,2,0,2,0,... with at most one clockwise 90-degree turn between diagonal directions. Return 0 if no valid segment exists.
- **Direction convention (critical):** clockwise cycle 0=down-right(+1,+1), 1=down-left(+1,-1), 2=up-left(-1,-1), 3=up-right(-1,+1). Clockwise turn is `d -> (d+1)%4`. Verified against examples: Ex1 down-right(0)->down-left(1); Ex2 down-left(1)->up-left(2). Sign/order mistakes here are the top bug source.
- **Next-value table (was the bug):** must be `nxt=(2,2,0)` indexed by current value: 0->2, 1->2, 2->0. The earlier `(2,0,2)` mapped 1->0, breaking runs like 1,2,0,... Fixing it makes Ex3's main diagonal (1,2,0,2,0) validate. With the correct table both 0 and 1 expect 2, and 2 expects 0; value 1 appears only as a segment start.
- **Forward DP `f`:** `f[d][r][c]` = longest alternating run STARTING at (r,c) going direction d. Recurrence `1 + f[d][next]` iff next in-bounds and `grid[next]==nxt[grid[r][c]]`, else 1. Filled by sweeping opposite to direction (descending r/c when component positive).
- **Backward DP `g` (necessary):** `g[d][r][c]` = longest alternating run ENDING at (r,c) arriving via d that STARTS at a value-1 cell; 0 if unreachable. Base `grid==1 -> 1`; else extend predecessor `p=(r-dr,c-dc)` iff `grid[r][c]==nxt[grid[p]]` and `g[d][p]>0`. Sweep ascending when component positive (opposite of forward). This enforces the value-1 start and tracks reachability; both 0 and 1 can precede 2 so reachability must be explicit.
- **Why not reuse `f` at predecessor:** `f[d][predecessor]` keeps going past the apex and does not require a value-1 start; an `f`-only combine is wrong for this reason.
- **Combining at apex:** For each apex and incoming direction d, `total = g[d][apex] + f[(d+1)%4][apex] - 1` (apex counted once). Maximal incoming and outgoing arms are independently optimal.
- **No-turn / single cell / no-1:** Take max `f[d][r][c]` over all d for every value-1 cell -> yields 1 for a lone 1, leaves best=0 when no 1 exists. `g[d]=1` apexes also fall out of the V loop as plain runs, harmless.
- **No self-intersection:** incoming d and outgoing `(d+1)%4` are perpendicular, meeting only at the apex.
- **Complexity:** four directions x two DPs over n*m cells = O(nm) time and memory; flat lists (index `r*m+c`) used for speed/cache. Safe for 500x500.
- **Validated:** Examples 1-4 -> 5, 4, 5, 1 with `nxt=(2,2,0)`. Grids with no value 1 -> 0. `[[1]]` -> 1. Key apexes (Ex1 apex (2,4) incoming down-right len 3 + outgoing down-left len 3 -1 = 5; Ex2 apex (3,2) = 4) confirmed.
