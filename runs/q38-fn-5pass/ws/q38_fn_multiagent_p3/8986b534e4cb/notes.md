- **Current solution:** The validator is replaced by the full solver. It uses the pairwise-conflict characterization and answers range queries by prefix maxima of the latest conflicting previous index.
- **Conflict characterization:** A set of people is feasible iff it contains no conflicting pair among: same interval with opposite signs; same left endpoint with different right endpoint; same right endpoint with different left endpoint; crossing intervals with the same sign. Opposite-sign crossings are compatible.
- **Query reduction:** For each person `j`, compute `bad[j] = max i < j` such that `i` and `j` conflict. Then `pref[j] = max(pref[j-1], bad[j])`. Query `[L, R]` is feasible iff `pref[R] < L`.
- **Endpoint conflicts:** Computed online while reading people. Same interval opposite sign uses a dictionary keyed by encoded `(l, r, sign)`. Same left/right conflicts maintain the latest and second-latest indices with distinct other endpoints for each left/right coordinate.
- **Crossing conflicts:** Process each sign separately in original index order. For one orientation `l_i < l_j < r_i < r_j`, sweep by original index. Insert previous interval `i` into a segment tree over compressed left endpoints, covering all query left endpoints strictly inside `(l_i, r_i)`. Query at `l_j` with threshold `r_j` to get the largest previous index with `r_i < r_j`.
- **Monotone deques in segment tree nodes:** Each node stores encoded values `(r_i << SH) | i` with strictly increasing `r_i`. When appending a new interval, pop from the back while `last_r >= r_new`; an older interval with larger/equal `r` is dominated by the newer one for all future thresholds. Query uses `bisect_left` on encoded values to find the last entry with `r < threshold`.
- **Reversed coordinates:** The other crossing orientation `l_j < l_i < r_j < r_i` becomes the first orientation after mapping town `x` to `N - x + 1`, interval `[l, r]` to `[N-r+1, N-l+1]`. Run the same solver on reversed coordinates for each sign.
- **Coordinate compression:** For each sign and orientation, compress only the relevant left endpoints of that sign. If an update range reaches the last real compressed coordinate, extend it to the power-of-two dummy leaves; this is safe because dummy leaves contain no queries and reduces segment-tree node visits.
- **Encoding details:** `SH = 20`, `MASK = (1 << SH) - 1`. Encoded value is `(r << SH) + idx`; threshold is `r << SH`. Since `idx < 2^SH`, `bisect_left` on encoded values correctly selects entries with `r < threshold`.
- **Complexity:** Endpoint pass is `O(M)` expected. Crossing passes do `O(M log M)` segment-tree node visits per orientation, with binary searches inside visited nodes; memory is dominated by frontier entries in segment-tree nodes, bounded by `O(M log M)` in the worst case but reduced by monotone pops and per-sign processing.
- **Edge cases:** Strict inequalities exclude touching endpoints and equal right endpoints. Single-person queries are always feasible. Empty sign lists are skipped. The prefix maximum is stored in-place in `bad`.
