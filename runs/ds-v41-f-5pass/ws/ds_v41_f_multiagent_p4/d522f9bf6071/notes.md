- **Problem shape:** choose up to 4 non-overlapping intervals (sharing an endpoint counts as overlapping) maximizing total weight; tie-break by lexicographically smallest sorted list of original indices (shorter equal-prefix list wins).
- **Approach 1 works and is implemented:** sort by right endpoint, `p(i) = bisect_left(rights, l_i)` = count of intervals with `r < l_i` (strict). `dp[i][k]` = best `(weight, sorted index tuple)` over the first `i` sorted intervals using exactly `k`. Transition: skip `dp[i-1][k]`; take `dp[p(i)][k-1]` + `(w_i, insert(j))`. Predecessor `p(i) <= i-1` always holds (since `r_i >= l_i`), so no ordering issue.
- **Explicit comparator is required:** compare by higher weight first, then lower tuple. Python native tuple comparison already gives the shorter-is-smaller prefix rule, so it can be used as the secondary key.
- **Local lex-min is safe (monotonicity proved):** adding the same new index `x` to sorted tuples preserves order: if `A < B` then `merge(A,{x}) <= merge(B,{x})`. Proof by the "common prefix up to value c, next element smaller" characterization; covers the prefix (shorter) case too. Hence storing only the lex-min tuple per `(i,k)` is correct.
- **Global answer:** take max `dp[n][k].weight` over `k=0..4`, then the min tuple among those states. All k whose `dp[n][k].weight` equals the global max are exactly the cardinalities achieving it.
- **Verified on both examples:** Ex1 -> `[2,3]` (weight 8), Ex2 -> `[1,3,5,6]` (weight 21). Both match expected. Also checked single-interval, all-overlapping, and tie cases.
- **Complexity:** O(n * 4 * log n) time (bisect) with tiny tuple ops; O(n*5) states. Well within n <= 5e4.
- **Pitfalls confirmed irrelevant/avoided:** strict predecessor via `bisect_left`; equal right endpoints cannot precede each other (they sit at index >= p); using exact-k states avoids the shorter-list ambiguity that at-most states would introduce; weights >= 1 so empty selection never optimal for n >= 1.
