Process the grid by anti-diagonals \(s=h+w\). For every cell maintain the sum of products of paths from \((1,1)\) to that cell excluding the cell itself, and the analogous suffix value to \((H,W)\); also store the corresponding “including the cell” values so that transitions are just additions. Because Takahashi moves to an adjacent cell, each query changes the anti-diagonal by exactly \(\pm1\): when moving to a larger diagonal, recompute prefix data for that whole diagonal from the previous one; when moving to a smaller diagonal, recompute suffix data for that whole diagonal from the next one. The invariant is that prefix data are correct for all diagonals up to the current one, and suffix data are correct for all diagonals from the current one onward, so the coefficient needed for a point update is always available. Updating one cell changes the total answer by \((new-old)\times prefix\_excl\times suffix\_excl\), and the cell’s own prefix/suffix values do not change. This gives \(O(HW + Q\cdot \min(H,W))\) time, with diagonal length at most about \(447\) under \(HW\le 200000\).
