The maximum possible minimum score is monotonic: if a score `x` is achievable, any smaller score is also achievable, so binary search the answer. For a candidate `x`, index `i` needs `ceil(x / points[i])` visits to reach score `x`. Feasibility can be checked greedily from left to right: when at index `i`, any missing visits to `i` should be obtained by bouncing between `i` and `i+1`, because each bounce costs 2 moves and also contributes a useful visit to the right side. Track only how many visits the current index already has, propagate the resulting visits to the next index, and handle the last index specially; if the minimal required moves is at most `m`, the candidate is feasible.
