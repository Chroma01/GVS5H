- **Core reduction:** For two blocks, let B be the highest floor at which they are connected by walkways. If query floors are Y and Z, answer is `abs(Y-Z)` when `min(Y,Z) <= B`, otherwise `Y+Z-2*B`. This is because crossing can be done at the lower floor if it is not above B; otherwise both endpoints must descend to B and ascend.
- **Bottleneck as Kruskal value:** At floor x, only blocks with height at least x exist, and walkways connect adjacent existing blocks. Thus B is the maximum bottleneck path value. Edge weight `min(F_u,F_v)` is enough because the minimum edge weight on a path equals the minimum vertex height on that path.
- **Kruskal reconstruction tree:** Instead of storing an explicit MST, build a union tree. Leaves are blocks. Each successful DSU merge creates a new internal node with weight equal to the current merge height and makes the two component roots its children. For two different leaves, the weight of their LCA is exactly B.
- **Edge generation without sorting edges:** Sort cells by height descending and activate them. When activating cell u, every active neighbour v has height >= F[u], so the edge weight is F[u]. Each undirected grid edge is considered once, when its lower/equal-height endpoint is activated. This processes edges in non-increasing weight order, equivalent to Kruskal.
- **DSU details:** `parent`, `size`, and `comp_root` are maintained over original block representatives. `comp_root[rep]` is the current reconstruction-tree root of that component. Newly activated `u` is initially its own DSU root, so `ru = u` avoids one find call.
- **Tree preprocessing:** Internal nodes are created with increasing indices, so every parent index is larger than its child index. After setting the final root's parent to itself, depths are computed by iterating indices downward. Binary lifting uses `LOG = max(1, (N-1).bit_length())` because leaf depth is at most N-1.
- **Query handling:** Same-block queries must be answered directly as `abs(Y-Z)`; otherwise the reconstruction-tree LCA would be a leaf with weight 0. For different blocks, LCA gives an internal node, and its stored weight is B.
- **Implementation/performance:** Flat grid indexing is used. Neighbor checks are duplicated inline for speed. Large temporary arrays are released before building the binary lifting table. Complexity is roughly `O(N log N + Q log N)` time and `O(N log N)` memory, with N=H*W.
- **Edge cases:** N=1 works because only same-block queries are possible. H=1 or W=1 is handled by boundary checks. Equal heights are processed in arbitrary order but all corresponding merge weights are equal, preserving correctness.
