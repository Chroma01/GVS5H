- **Model reduction:** Only three kinds of positions matter: `X` where `A=1,B=0` (must be flipped odd times), `Y` where `A=0,B=1` (must be flipped odd times), and `Z` where `A=B=1` (may be flipped zero or two times). Positions with `A=B=0` are never useful to flip. Extra pairs of flips on any position can be deleted and only increase cost, so required positions are flipped once and common ones at most twice.
- **Ordering:** In an optimal sequence, all removals (`1 -> 0`) are done before all additions (`0 -> 1`). Swapping an earlier addition with a later removal strictly reduces cost. Among removals, larger `C` should be earlier; among additions, smaller `C` should be earlier.
- **Optional common ones:** For `Z`, choosing a subset to remove and later add back is the only remaining decision. If a smaller-cost common `1` is chosen, replacing it by a larger-cost common `1` is never worse. The marginal cost of adding a common `1` of cost `c` to a fixed existing set is non-increasing in `c`, because increasing `c` moves its removal earlier and its addition later, and the linear slope between crossings is negative. Hence an optimal subset is a prefix of `Z` sorted in non-increasing `C`.
- **Base cost:** With no optional removals, simulate removals from `X` in decreasing `C`, then additions from `Y` in increasing `C`, adding the current weighted sum after each flip.
- **Prefix update:** Let `P` be the sum of already processed larger `Z` costs. When adding next cost `c`, its removal is inserted after existing removals with cost at least `c` (`X >= c` plus previous `Z`), and its addition is inserted before existing additions with cost at least `c` (only `Y < c` are before it). The total cost change is:
  `2*S0 - sumX - sum(X >= c) - 2*prev_sum + sum(Y < c) - c*(count(X < c) + count(Y < c) + 1)`.
- **Implementation:** Sort `X` and `Y` ascending for binary searches and prefix sums. Sort `Z` descending. Maintain `prev_sum` of processed `Z` costs and update `current` cost by the delta formula for each prefix. Python integers avoid overflow.
- **Complexity:** Sorting and binary searches give `O(N log N)` time and `O(N)` memory, suitable for `N <= 2e5`.
- **Edge cases:** Empty `X`, `Y`, or `Z`; already equal arrays; all removals; all additions; equal costs. Tie handling is safe because swapping equal-cost removals or equal-cost additions does not change total cost.
