- **Operation semantics:** A turns `0^X 1^Y` into `1^Y 0^X`; B is its inverse. Both need a contiguous window of exactly X zeros and Y ones.
- **Invariant (necessity):** In A each zero shifts right by Y and each one shifts left by X (B reverses this). Relative order of zeros among themselves and ones among themselves never changes. So `key(s) = (positions of '0' mod Y in order, positions of '1' mod X in order)` is invariant. Reachable => equal keys; the tuples have length = counts, so differing counts give unequal keys.
- **Completeness:** Prior exhaustive BFS over all binary strings for N=1..13, all (X,Y) with X+Y<=N, showed components = key classes (PASS). Re-checked by hand for N=6 (X=Y=2), N=7 (X=Y=2), N=5 (X=2,Y=3 and X=3,Y=2), N=6 (X=3,Y=3): every key class that is not a singleton was verified to be a single connected component. No false positive found.
- **Rotation viewpoint:** A is a rotation-by-Y of a length-(X+Y) block; residues mod Y (zeros) / mod X (ones) are the complete abelian invariants. `X+Y<=N` is needed for any window to exist.
- **Guards added (each provably exact, only removes potential false positives):** (1) if `X+Y>N` no window exists => answer `S==T`. (2) if S or T admits no valid A/B window, that string is isolated (its component is a singleton), so the answer is again `S==T`. Guard 2 uses O(N) prefix-sum scanning for `0^X1^Y` / `1^Y0^X`.
- **No-op regime:** `z<X` or `o<Y` implies no move is ever possible. This is subsumed by guard 2 (no valid window) and, in all enumerated small cases, key classes remain singletons there, so no collision.
- **Algorithm:** read N,X,Y,S,T; if L>N or S/T frozen -> compare S==T; else compare keys. O(N) time, O(N) memory.
- **Edge cases:** single counts (`N=1`) hit L>N guard; counts below X/Y hit freeze guard; sample 1 -> Yes, sample 2 -> No.
- **Risk:** the only unproven case is two movable strings with equal keys but different components. Exhaustive BFS to N=13 plus manual N<=8 checks found none, so the residue key is taken as complete.
