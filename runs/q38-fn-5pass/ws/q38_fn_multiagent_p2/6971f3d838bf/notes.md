- **Sample verdict:** pass. Example 1 returns 7 by deleting -2; Example 2 returns 10 with no deletion. Key edge cases checked include single element, all non-positive, all zeros, all same negative, adjacent duplicates, zeros between positives, multiple occurrences, and non-power-of-two segment-tree padding.
- **Core reduction:** If `max(nums) <= 0`, return `max(nums)`. Otherwise the original maximum subarray is positive. Deleting a non-negative value cannot improve the answer: any subarray after deletion maps to an original interval containing the same kept elements plus non-negative removed values. Only distinct negative values need evaluation.
- **Zero replacement equivalence:** For a negative value `x`, deleting `x` is equivalent for maximum-subarray purposes to replacing every `x` by `0`, because a positive element remains. Any positive zero-replaced subarray can drop leading/trailing zeros; the remaining non-`x` elements are contiguous after deletion. Zero-only subarrays cannot win.
- **Segment tree aggregate:** Each node stores `(sum, best_nonempty_prefix, best_nonempty_suffix, best_nonempty_subarray)`. Combine uses:
  - `sum = sumL + sumR`
  - `pref = max(prefL, sumL + prefR)`
  - `suff = max(suffR, sumR + suffL)`
  - `best = max(bestL, bestR, suffL + prefR)`
  Padding leaves use `sum = 0` and `pref/suff/best = NEG_INF`, which acts as an empty identity without `None` checks.
- **Evaluation:** Build the tree on the original array. For each negative value, temporarily set all occurrence leaves to zero, pull ancestors, read root best, then restore. Total point updates are twice the number of negative occurrences, giving `O(n log n)` time. A safe prune skips `x` if `base_ans + count_x * |x| <= current ans`, since any interval's original sum is at most `base_ans` and contains at most `count_x` occurrences of `x`.
- **Complexity:** Time `O(n log n)`, memory `O(n)`. The array-based tree avoids tuple allocation and is faster than a tuple-based implementation.
- **Edge cases verified:** Single-element arrays return the element. All non-positive arrays, including zeros and all-same-negative arrays, are handled by the early return; without it, zero replacement could incorrectly create a zero subarray. Adjacent occurrences and empty gaps are handled by setting multiple positions to zero. Deletion that would empty the array is irrelevant because negative candidates are evaluated only when a positive element remains.
- **Pitfalls checked:** The zero aggregate is a valid non-empty element, not an empty identity. Padding with `NEG_INF` is safe because valid sums are within about `+/-1e11`. The tree is restored after each value unless an early return ends the method. The positive-sum upper bound is safe because deletion only removes negative values. Kadane is non-empty and handles zeros correctly.
