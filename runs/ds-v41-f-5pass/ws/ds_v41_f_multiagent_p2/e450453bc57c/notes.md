- **Approach:** Two independent stages: (1) cost of a length-x window = sum of |a_i - median|; (2) DP selecting k disjoint windows by start index, total cost is the sum (disjoint => additive).
- **Window costs via Fenwick:** coordinate-compress values to ranks 1..V using a dict (O(n)); maintain two Fenwick trees (count and sum). Slide window by removing nums[p-1] and adding nums[p-1+x], tracking `total`. Target lower-median rank m=(x+1)//2 found by binary lifting over the count tree. Query prefix count/sum at the median rank, then cost = med*cle - sle + (sgt - med*cgt). Even x: any middle value is optimal, so the lower median is safe; elements equal to median contribute exactly 0.
- **DP:** dp_j[idx] = min cost of j windows among starts 0..idx-1. Recurrence dp_j[idx] = min(dp_j[idx-1], dp_{j-1}[max(0, idx-x)] + cost[idx-1]). Base dp_0[idx]=0; dp_j[0]=INF for j>=1. Answer dp_k[W] with W=n-x+1. The shift idx-x enforces previous start <= s-x (non-overlap); adjacent windows (gap exactly x) are allowed.
- **Exactly k vs at least k:** all costs are nonnegative so dropping a window never helps; exactly k is optimal and feasible because k*x <= n (which also implies W >= k).
- **Complexity:** O(n + V + W log V) time for costs, O(k*W) for DP, O(V+W) memory. Fits n=1e5, k<=15, V<=1e5. No balanced BST needed.
- **INF choice:** 1<<60; real total <= k*x*2e6 <= 3e12, so INF-based values (which may accumulate cost but stay ~1.15e18) never beat a feasible finite value.
- **Clamp subtlety:** idx-x<0 is clamped to 0, which correctly maps to dp_0[0]=0 for the first window and to dp_{j>0}[0]=INF (invalid) for later windows.
