- **Problem shape:** Maximum matching K in a threshold bipartite graph on a contiguous sorted subarray. Edge i->j exists iff i<j and A[i]*2 <= A[j]. N,Q up to 2e5, so per-query scans are impossible; need O(log) per query.
- **Key reduction (proved):** For a fixed interval of length M, the optimum uses the K smallest elements as tops and the K largest as bottoms. Proof: with any feasible matching of 2K elements, take the K smallest and K largest of the union (componentwise ordering shows feasibility preserved), then the K smallest of the whole interval are componentwise <= those tops and the K largest are componentwise >= those bottoms. Sorted matching feasibility equals t_j*2 <= b_j for all j.
- **Predicate:** With 1-indexed L,R and d[i] = (first j>=i with A[j] >= 2*A[i]) - i (INF if none), the K smallest tops are L..L+K-1 and the K largest bottoms are R-K+1..R, satisfying b_j - t_j = M-K for every j. So K pairs are possible iff max(d[L .. L+K-1]) <= M-K, plus K <= M//2. Feasibility is monotone in K (max grows, M-K shrinks), enabling binary search for the largest valid K.
- **Precompute d:** Since A is sorted, d[i] = bisect_left(A, 2*A[i]) - i; use INF=n+1 when no partner exists. d[i] >= 1 always because 2*A[i] > A[i].
- **Data structure:** Sparse table for range maximum of d. Build O(N log N), query O(1). Each query binary searches K over [0, M//2] with an O(1) RMQ, giving O(Q log N) total.
- **Off-by-one details that matter:** indices are 0-based internally after subtracting 1 from L,R; the RMQ range for a candidate mid is exactly [L, L+mid-1] (length mid); the second sparse-table block start is L+mid-(1<<kk); condition compares max to M-mid; initial lo=0 is always feasible. Since R-L+1>=2, hi>=1 and K=0 is handled.
- **Verification:** Matches both provided samples exactly (e.g. sample 1: 2,3,1,0,5; sample 2 spot-checked: 0,0,0,0,2,6,0,1,1,0,0,0,3,5,0). Edge: all-equal values give d=INF everywhere so answer 0.
- **Alternatives considered (unneeded):** next-greater chains / binary lifting on prefix maxima of d, offline parallel binary search, Mo's algorithm, divide and conquer on indices. All add complexity; RMQ+binary search is simplest and fast enough.
- **Complexity:** Time O((N+Q) log N), memory O(N log N).
