- **Sign model:** the s-th selected element (1-indexed) contributes +nums if s is odd, -nums if s is even. DP carries the parity of the count of already selected elements, flipping it on every inclusion. Selection order equals original array order.
- **Ranges:** any alternating sum is in [-S, S] with S = sum(nums), so |k| > S gives -1 immediately. Bitsets use bit index (alt + S), width 2S+1.
- **Product semantics:** nums[i] >= 0, so product is 0 iff a zero is selected, and 0 < any positive product. Therefore answer = largest positive product <= limit among valid all-positive subsequences if one exists; else 0 if some valid subsequence contains a zero; else -1.
- **Key trap (validated):** a single DP that caps products at limit and folds zeros in is WRONG. A valid product-0 subsequence may need an intermediate prefix product > limit before a zero is appended, and such prefixes get discarded. Counterexample: nums=[11,12,0], k=-1, limit=10 -> correct answer 0, but the capped single DP returns -1 because prefix 132>10 vanished. Hence zeros must be detected without any product bound.
- **Part 1 (positive products):** dp0[p]/dp1[p] hold bitsets of alt sums for non-empty all-positive subsequences of exact product p in 1..limit. Skip zeros. Per v>0: singleton n1[v] |= bit(v); from dp0[p] -> n1[p*v] |= (bits<<v)&MASK; from dp1[p] -> n0[p*v] |= bits>>v; only when p*v <= limit. Capping is safe here because positive-only products can only grow. Scan p from limit down and return the first hit; all stored products are exact so the first hit is the max <= limit.
- **Part 2 (zero existence):** independent bitset DP dpZ[parity][hasZero] over all elements, no product dimension. Inclusion flips parity, applies +v (parity 0) or -v (parity 1), and forces hasZero when v==0. Singleton per element. Answer can be 0 iff the target bit is set in dpZ[0][1] or dpZ[1][1].
- **Masking:** left shifts must be masked to width; right shifts drop negatives naturally. Unmasked left shifts leak into alt sums above S and later right shifts would create false states.
- **Non-emptiness:** never seed an empty state; only singletons plus transitions from existing states. This correctly excludes the empty subsequence, which matters when k = 0.
- **Complexity:** Part 1 ~ O(n * limit * width/word) big-int ops; loop count <= n*limit = 750k worst case, shifts only on reachable products. Part 2 O(n). Well within limits for n<=150, limit<=5000, S<=1800.
- **Validation:** the three provided examples pass: [1,2,3],k=2,lim=10 -> 6; [0,2,3],k=-5 -> -1; [2,2,3,3],k=0,lim=9 -> 9. Randomized brute-force comparison over n<=6, nums[i]<=4, k in [-8,8], limit<=20 enumerating all non-empty subsequences found no counterexamples. Specific stress cases pass: [11,12,0],k=-1,lim=10 -> 0; [0],k=0 -> 0; [2,2],k=0,lim=3 -> -1; k outside [-S,S] -> -1; empty-subsequence exclusion when k=0 verified.
