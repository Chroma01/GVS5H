- **Core model:** The only global state needed is the parity of the number of reversals performed. Parity 0 means the graph is in its original orientation; parity 1 means every edge has been reversed. Reversing twice restores the original graph, so no other history matters.
- **State encoding:** Use `state = (vertex << 1) | parity`, with vertices converted to 0-indexed. Start state is `0` for vertex 0 and parity 0. Target states are `2*(N-1)` and `2*(N-1)+1`, corresponding to vertex `N-1` with either parity.
- **Transitions:** From `(v, 0)`, a move follows an original outgoing edge `v -> to` with cost 1. From `(v, 1)`, a move follows an original incoming edge `to -> v`, because after reversal it becomes `v -> to`, also with cost 1. From any state, a reversal transition goes to the same vertex with toggled parity and cost `X`.
- **Algorithm:** Run Dijkstra on the implicit product graph of `2N` states. Move edges have weight 1 and reversal edges have weight `X`, all nonnegative. Because Dijkstra settles states in nondecreasing distance order, the first popped target state gives the final answer.
- **Correctness argument:** Every valid sequence of operations corresponds exactly to a path in the product graph, with the same total cost: moves match directed edges in the current parity layer, and reversals match parity toggles. Conversely, every product-graph path corresponds to a valid operation sequence. Therefore the shortest product-graph distance to either target state is the minimum required cost.
- **Complexity:** There are `2N` states. Each state is expanded at most once. Each original edge is considered once from the original layer and once from the reversed layer, so move relaxations are `O(M)`. Reversal relaxations are `O(N)`. Heap operations dominate, giving `O((N + M) log N)` time and `O(N + M)` memory.
- **Implementation details:** Store both original adjacency lists and reversed adjacency lists. Generate transitions on the fly instead of explicitly building the product graph. Use a heap with duplicate-entry skipping via `if d != dist[state]`. Use Python integers, which naturally handle answers beyond 32-bit range. A large sentinel such as `10**30` is sufficient.
- **Performance notes:** Local bindings for `adj`, `radj`, `dist`, `X`, `heappush`, and `heappop` reduce overhead. The target check can be `if s >= target_start` because the two target states are the last two indices in the state array. Input parsing via `map(int, read().split())` is concise and fast enough for `2e5` edges.
- **Pitfalls:** Do not collapse the graph to an undirected graph, because direction matters unless a reversal is paid for. Do not expand a reversal of cost `X` into `X` unit edges, since `X` can be `1e9`. Plain BFS is only sufficient when `X = 1`; otherwise Dijkstra is needed. Self-loops and multiple edges are harmless. The problem guarantees reachability, but the code still has a fallback final minimum if the heap empties.
- **Alternatives considered:** Bucket-based or radix-heap methods could exploit weights `1` and `X`, but are more complex and unnecessary here. Bidirectional Dijkstra is possible but adds subtle termination and parity handling without changing the core complexity.
