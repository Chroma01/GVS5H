- **Transformation:** Define town potentials \(P_i\) as prefix sums of road strengths. A person \(S<T\) requires \(P_S=P_T\) and \(P_k>P_S\) for all interior towns \(k\). A person \(S>T\) requires \(P_S=P_T\) and \(P_k<P_S\). Thus each person becomes a directed interval \([l,r]\) with direction `+` (interiors above endpoints) or `-` (interiors below endpoints).
- **Feasibility as acyclicity:** Equalities contract endpoint towns. Strict inequalities become directed edges of weight 1. Feasibility is equivalent to absence of a directed cycle in the contracted strict graph. Integer potentials exist by topological levels.
- **Pairwise conflict lemma:** A set is feasible iff it has no pairwise conflict. Same direction intervals conflict exactly when they partially overlap or share a left/right endpoint; they are compatible only when disjoint, touching end-to-start, or strictly nested. Opposite direction intervals conflict exactly when they share a left endpoint or share a right endpoint; touching end-to-start is compatible. A small DSU+cycle oracle for tiny instances was used to validate this lemma; no counterexample was found.
- **Monotonicity:** If a contiguous set of people is infeasible, every superset is infeasible. Therefore compute `first_bad[L]`, the smallest right index making `[L, first_bad[L]]` infeasible. Query `[L,R]` is feasible iff `R < first_bad[L]`.
- **Sliding window:** Maintain a feasible window `[L,R)`. Extend `R` while adding interval `R` creates no conflict with the current window. Then `first_bad[L]=R`, remove `L`, and continue. Because the maintained window is feasible, same-direction intervals in it form a laminar/touching family, which allows 1D segment-tree conflict checks.
- **Opposite conflicts:** Maintain counts of left and right endpoints per direction. Adding direction `d` conflicts with active direction `1-d` iff the opposite count at its left or right endpoint is positive.
- **Same-direction conflicts:** For active intervals of the same direction, store at each left endpoint its right endpoint in a max segment tree. For a new interval `[l,r]`:
  - Find the rightmost active left `a <= l` with right `b > l`. If it exists, conflict iff `a == l` or `r >= b`; otherwise the active interval strictly contains the new one.
  - Query max right among active lefts in `[l+1, r)`. If it is at least `r`, an active interval starts inside the new interval and reaches its right endpoint, causing partial overlap or shared right endpoint.
- **Segment tree details:** `find_last_leq` finds the rightmost prefix position with value greater than a threshold by checking the leaf `q`, then left siblings of ancestors where the path goes right, and descending greedily to the right. This avoids recursive range decomposition and is \(O(\log N)\). `range_max_ge` is an early-exit iterative range maximum query.
- **Complexity:** Each interval is added and removed once. Each `can_add` does \(O(\log N)\) work, and each update is \(O(\log N)\). Total \(O((M+Q)\log N)\), with memory \(O(N+M)\).
- **Pitfalls handled:** Strict nesting is strict: same left or same right endpoint is a conflict even if one interval contains the other. Opposite intervals touching as right-to-left are compatible. Direction matters: the same geometric interval with opposite directions is infeasible. Deletions restore the feasible-window invariant required by the laminar same-direction checks.
- **Indexing:** Towns are converted to 0-based indices. `first_bad` stores the first infeasible right endpoint as a 0-based index, or `M` if none exists.
