- **Core model:** Each initial value `x` requires exactly `f(x)` selections, where `f(x)` is the number of divisions by 4 needed to make `x` zero. Equivalently, `f(x)` is the number of powers of 4 that are `<= x`, or `(x.bit_length() + 1) // 2`.
- **Query answer:** For a query `[l, r]`, let `S = sum(f(x) for x in [l, r])`. Each operation can reduce the total remaining required selections by at most 2, so at least `ceil(S / 2)` operations are necessary. This bound is achievable by pairing required selections arbitrarily; if `S` is odd, the final selection is paired with an already-zero element. Since `l < r`, every query has at least two array elements.
- **Distinct-index consideration:** If an operation must select two distinct array positions, the only possible extra lower bound would be `max(f(x))`, because one element cannot be selected twice in the same operation. For any interval of length at least 2, `max(f(x)) <= ceil(S / 2)`: if the maximum is `M` at `r`, then the previous value has `f` either `M` or `M - 1` (the latter only when `r` is a power of 4), so `S >= 2M` or `S >= 2M - 1`. Thus the answer remains `ceil(S / 2)`.
- **Range sum:** To compute `sum_{x=1}^n f(x)` quickly, count threshold contributions. Each power `p = 4^k` contributes 1 to every integer `x >= p`, so `prefix_sum(n) = sum_{p <= n} (n - p + 1)`. The range sum is `prefix_sum(r) - prefix_sum(l - 1)`.
- **Implementation:** Precompute powers of 4 up to the maximum `r` in the input. There are at most 15 such powers for `r <= 10^9`. Each query calls `prefix_sum` twice, each scanning at most those powers. Total time is `O(Q log_4(max_r))`, and memory is `O(log_4(max_r))`.
- **Verification:** The sample tests pass: `[[1,2],[2,4]]` gives `1 + 2 = 3`, and `[[2,6]]` gives total work `8`, hence `4`. An exhaustive small-range check for all `1 <= l < r <= 20` using an independent scheduler over remaining selection counts matches the `ceil(S / 2)` formula.
- **Edge cases:** `l = 1` correctly uses `prefix_sum(0) = 0`. Odd totals are rounded up with `(total_work + 1) // 2`. Boundary values exactly equal to powers of 4 are handled because the threshold condition is `p <= x`. No floating-point logarithms are used.
