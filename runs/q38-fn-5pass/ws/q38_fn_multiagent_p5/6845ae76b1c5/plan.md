Process the queries offline in increasing `X`, maintaining the accumulated contribution of every `B_j` from all `A_i` already added. For a newly added value `a`, partition `B` by value into blocks: blocks completely below `a` receive a lazy linear update `a - B_j`, blocks completely above `a` receive `B_j - a`, and only the one value block containing `a` is updated pointwise. Store the lazy coefficients over value blocks using difference arrays so full-block updates are `O(1)`, and answer a prefix `Y` by scanning value blocks with per-block position lists/prefix sums plus a position-block prefix structure for the pointwise updates. This gives roughly `O(N * V + K * N / V + K * (N / P + P))` time with block sizes around `V ≈ 200` and `P ≈ 320`, suitable for Python.
