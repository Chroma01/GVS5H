- **Invariant:** Treat `0` as a horizontal step and `1` as a vertical step. Operations A and B swap adjacent blocks `0^X 1^Y` and `1^Y 0^X`. In one swap every `1` moves by exactly `X` positions and every `0` moves by exactly `Y` positions, while tokens of the same type never cross. Therefore the left-to-right sequence of positions of `1`s modulo `X`, and the left-to-right sequence of positions of `0`s modulo `Y`, are invariant. Zero-based indexing is used; a constant offset from the statement's one-based indexing does not affect equality.
- **Sufficiency:** Orient the rewrite as `0^X 1^Y -> 1^Y 0^X`. It terminates because the sum of positions of all `1`s decreases by `X*Y` per rewrite. Two oriented redexes cannot overlap: a second start inside the zero block would see a `1`, and a start inside the one block would not see a `0`. Hence all redexes in a word are disjoint and commute, giving local confluence; by Newman's lemma the oriented system has a unique normal form. The two ordered residue sequences determine this normal form (equivalently, the lexicographically maximal feasible shuffle of the two residue sequences), so equality of the residue sequences is also sufficient. The included tiny BFS cross-check supports this claim.
- **No-operation cases:** If `X + Y > N`, or the number of `1`s is less than `Y`, or the number of `0`s is less than `X`, no operation can ever be applied. In that regime the answer is exactly `S == T`. This guard is kept explicitly to avoid relying on the residue invariant in degenerate cases.
- **Implementation:** First check equality and counts. If no operation can apply, return equality. Otherwise build the two residue lists for `1`s modulo `X`, compare them, delete them, then build and compare the two residue lists for `0`s modulo `Y`. At most two residue lists are kept at a time, so peak memory is lower than storing all four simultaneously. The main algorithm is linear.
- **Validation:** For `N <= 10`, the program also performs exact BFS over all binary strings reachable from `S` using both operations. It compares the BFS answer with the residue/no-operation answer. If they disagree, it prints `Counterexample` instead of finalizing; otherwise it prints the BFS answer. This is at most `2^10` states and is intended to catch tiny counterexamples or implementation mistakes.
- **Edge cases:** `X = 1` or `Y = 1` makes one residue list all zeros, but the other list still carries the necessary information. `X = Y` is handled by the same rule. Different counts of `1`s are rejected immediately. `N = 1` and other cases with `X + Y > N` are handled by the no-operation guard.
- **Complexity:** Main path: `O(N)` time and `O(N)` memory. Tiny BFS validation: `O(2^N * N)` only for `N <= 10`.
