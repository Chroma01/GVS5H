- **Core observation:** For any two vertices x and y, f(x, y) is exactly the minimum threshold at which x and y become connected when edges are added in nondecreasing weight order. This is the same as the merge weight in Kruskal's DSU process.
- **Greedy structure:** Process edges by increasing weight. Each DSU component only needs to store the net number of unmatched A occurrences minus unmatched B occurrences. If the value is positive, only A occurrences remain unmatched; if negative, only B occurrences remain unmatched.
- **Merge rule:** When two components merge at weight w, any unmatched A in one and unmatched B in the other become connectable for the first time at cost w. Match as many opposite-signed surpluses as possible, add w times that count to the answer, and keep only the signed sum as the new surplus.
- **Optimality:** Future merges have weights at least w, so matching as many pairs as possible at the earliest possible weight is optimal. Equivalently, after processing all edges up to any threshold t, the greedy algorithm has matched the maximum possible number of pairs whose f-value is at most t, namely the sum over current components of min(A_count, B_count).
- **Equal weights:** Sequential DSU unions among edges of the same weight are safe. All matches made during that weight class have the same cost, and the total number matched depends only on the total signed surplus before the class, not on the union order.
- **Implementation details:** Use zero-based vertices, sort edges as (w, u, v), DSU with path halving and union by size. Python integers handle the maximum answer, up to about 2e14.
- **Edge cases:** Duplicate vertices inside A or inside B are handled naturally by counts. A vertex appearing in both sequences would cancel at zero cost, though the statement guarantees this does not happen. The graph is connected and total A count equals total B count, so the final surplus is zero.
