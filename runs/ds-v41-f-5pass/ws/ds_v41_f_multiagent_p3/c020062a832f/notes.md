- **Problem shape:** answer for shift k is the inversion count of B_i = (A_i + k) mod M. Recomputing per k is O(N^2 log) and impossible; need O((N+M) log M).
- **Key identity (verified against all 3 samples):** Let inv0 be inversions of A. Over transitions k->k+1, the only pairs whose inversion status flips are those with exactly one element wrapping (value M-1 -> 0). Per-element bookkeeping reduces the total change to a pure position sum, independent of the other element's value.
- **Derivation:** at transition k, the wrapping elements are exactly those with A_i = M-1-k. For a wrapping element i, left pairs (i<j) lose an inversion (-1 each) and right pairs (h<i) gain one (+1 each); both-wrapping pairs cancel. Summing the "cross" terms over all wrapping elements telescopes to zero, leaving net change = sum over wrapping i of (2i+1-N) = -(sum of N-2i-1).
- **Final formula:** bucket[A_i+1] += (N-2i-1) for each 0-based i; diff = prefix sums over indices 0..M; answer(k) = inv0 + diff[M-k]. Total of all (N-2i-1) is N^2 - N(N-1) - N = 0, so diff[M]=0 and answer(0)=inv0 automatically.
- **Off-by-one map (confirmed):** element with value A_i wraps at transition k=M-1-A_i; bucket index A_i+1 lines up with diff[M-k] exactly. Values with A_i=0 map to k=M-1 which is outside the transition range, so they correctly contribute nothing to any output delta.
- **inv0 via Fenwick** over values [0,M-1], value v at 1-based v+1; for each new v add (inserted - count(<=v)). inv0 up to ~N^2/2 = 2e10, Python ints handle it; no overflow concerns unlike fixed-width languages.
- **Edge cases:** M=1 (all A_i=0, single line 0); N=1 (no pairs, all 0); duplicates handled since strict comparison means equal values never invert, and equal A_i go into the same bucket summed together.
- **Complexity:** O(N log M + M) time. Arrays sized m+2 to allow bucket index up to m and diff up to m.
- **Sample checks (hand-traced):** sample1 -> 3,1,1; sample2 -> 7,3,3,1,1,5; sample3 -> 0,6,10,12,12,10,6. All match.
