- **Approach:** Trim common prefix/suffix, reject if length difference exceeds K, then run Landau-Vishkin furthest-reaching DP for edit distance at most K with insert/delete/substitute cost 1. State `V_e[d]` is the maximum row `i` such that `S[:i]` can become `T[:i+d]` with at most `e` edits, where `d = j - i`.
- **Transitions:** From previous edit count `e-1` to `e` on diagonal `d`: carry `V[d]`; insert from `d-1` with same `i` if previous column `< m`; delete from `d+1` with `i+1` if previous row `< n`; substitute from `d` with `i+1` if both next characters exist. Take the maximum candidate before LCP extension, then extend along the diagonal by matching characters.
- **Why max-before-extension is safe:** All candidates are on the same diagonal. If a smaller candidate extends past a larger one, the larger one lies inside the same matching run and therefore extends at least as far. Boundary-invalid furthest states are not needed for successful paths; standard furthest-reaching dominance applies.
- **Initialization and target:** `V_0[0] = LCP(0,0)`. After each extension, return Yes if `i == n` and `i + d == m`. Arrays are size `2K+3`, offset `K+1`, sentinel `-1`.
- **Diagonal pruning:** Let `D = m - n`. At edit count `e`, only diagonals satisfying `abs(D - d) <= K - e` can still reach the target, because each remaining edit changes diagonal by at most 1. This prunes states safely.
- **Trimming:** Common prefix and suffix can be preserved in an optimal edit sequence. Trim prefix first, then suffix without crossing the prefix. If one side becomes empty, the answer is Yes iff the remaining length is at most K (already implied by the initial length-difference check).
- **Upper-bound shortcut:** If `K >= max(n, m)` after trimming, answer Yes: substitute up to `min(n,m)` positions and insert/delete the remaining length difference.
- **LCP helper:** Deterministic, no hashing. It first checks up to 64 bytes directly, then compares 8192-byte chunks using `memoryview` slice equality, then finishes the mismatched/final chunk byte-by-byte. This avoids Python-level scanning for long equal runs while remaining exact.
- **Complexity:** DP has at most `(K+1)^2 <= 441` states. LCP work is dominated by chunked C-level comparisons; worst-case repeated long matches are about `O(K^2 * N / CHUNK)` C byte comparisons plus `O(K^2 * CHUNK)` Python byte loops, acceptable for `N=500000, K=20`. Memory is `O(N + K)`.
- **Edge cases covered:** equal strings, one side empty after trimming, K=0, nonzero target diagonal, states at the end of S or T, overlapping prefix/suffix trimming, and length difference greater than K.
