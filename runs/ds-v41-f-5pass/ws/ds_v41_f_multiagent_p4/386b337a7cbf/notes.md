- **Problem:** Find a non-empty subsequence with alternating sum exactly k, maximizing the product of its elements without exceeding limit. Return the product, or -1 if none exists.
- **Alternating sum bound:** Sum of all nums is at most 150*12 = 1800, so any alternating sum lies in [-S, S]. Use an offset `off = S` and represent reachable sums as a bitset; target index is `k + off`.
- **Quick reject:** If `k + off < 0` or `> 2*S`, no subsequence can reach k, return -1.
- **Zero-product handling:** Any subsequence containing at least one zero has product 0, regardless of other elements. Compute reachability of k using a separate DP over states `(hasZero, parity)` mapped to bitsets of alternating sums. `hasZero` becomes true when a zero is included or already true. This covers all zero-containing subsequences without needing product tracking.
- **Positive-product DP:** For product > 0, exclude zeros. Process only `v >= 1` in original order. State: product `p` (1..limit) mapped to two bitsets `even[p]` (even length) and `odd[p]` (odd length). Start a new subsequence with `v` (parity odd, sum +v). Append `v` to existing: from even length add v and switch to odd; from odd length subtract v and switch to even. Skip transitions where `p * v > limit`. Use a snapshot of existing states before appending so each element is used at most once.
- **Answer extraction:** Scan products from `limit` down to 1; return the first p whose combined bitset contains the target bit. If none, and zero-product is reachable, return 0. Otherwise return -1.
- **Complexity:** O(n * limit * (2S)/word) time, O(limit * (2S)/word) memory. With n <= 150, limit <= 5000, 2S <= 3600, this runs well within limits.
- **Edge cases:** Empty subsequence is never counted (positive DP starts with elements; zero DP requires hasZero). Elements > limit cannot participate in positive products (start and append are skipped). Product 1 from ones alone is handled naturally. Order matters, and left-to-right processing preserves it.
