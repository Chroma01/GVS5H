- **Core idea:** Precompute prefix distinct counts `L[i]` and suffix distinct counts `R[i]`. Sweep the second cut `j` from left to right. For each active first cut `i < j`, maintain `L[i] + distinct(A[i+1..j])`. When appending `A[j]`, it increases this value by 1 exactly for first cuts `i >= prev[A[j]]`, or for all active `i` if there is no previous occurrence.
- **Difference-array segment tree:** Rather than using a lazy segment tree for suffix range adds, maintain the difference array `D` of those suffix adds. For an active first cut `i`, the maintained value is `L[i] + prefix_sum_D(i)`. A suffix add `[l, m]` would normally be `D[l] += 1` and `D[m+1] -= 1`.
- **Segment tree invariant:** Each node stores `sumv`, the sum of `D` in its interval, and `best`, the maximum over active positions `p` in that interval of `L[p] + sum of D from the interval start to p`. For a parent with left and right children: `sum = left.sum + right.sum`, and `best = max(left.best, left.sum + right.best)`. The root `best` is the maximum over all active first cuts.
- **Delayed boundary optimization:** The `-1` boundary at `m+1` only matters for future first cuts to its right. Since active first cuts are always a prefix, this boundary can be postponed until position `m+1` itself is activated. Therefore, when activating position `i > 1`, set its leaf `D[i] = -1`; position 1 has `D[1] = 0`. Only the `+1` at `l` is applied immediately. This reduces the sweep to two point updates per `j` and avoids lazy propagation entirely.
- **Activation details:** Leaves start with `best = NEG` and `sumv = 0`. Activating `i` sets the leaf sum to `-1` for `i > 1` (or leaves it `0` for `i = 1`) and sets leaf best to `L[i] + sumv[i]`. Then ancestors are pulled. The subsequent `add_one(l)` updates an already active leaf. Inactive leaves remain `NEG` and cannot affect the root maximum.
- **Sweep order:** For `j = 2..N-1`, compute previous occurrence `p` using a `last` array initialized with `last[A[1]] = 1`. Let `m = j - 1` and `l = p if p else 1`. Activate `m`, add one at `l`, then update answer with `root_best + R[j+1]`. The boundary at `j` is not applied immediately; it is applied when first cut `j` is activated, except for `j = N-1`, which is never needed.
- **Precomputations:** `L` and `R` are computed with `bytearray` seen arrays. Previous occurrences are computed on the fly during the sweep, so no separate `prev` array is needed. The input list is reused as a 1-indexed array to save memory.
- **Complexity:** Time `O(N log N)` with about two point updates per second cut. Memory `O(N)`. This is faster in Python than a lazy range-add segment tree while preserving the same forward-sweep logic.
- **Edge cases:** `N = 3`, previous occurrence zero, previous occurrence immediately before `j`, all elements equal, and all elements distinct. The answer is at most `N`, so `NEG = -10**9` is safely below any active value.
- **Superseded:** The original lazy segment tree plan with range add and point activation is correct but slower. The delayed difference-array point-update tree is equivalent and more efficient.
