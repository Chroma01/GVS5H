- **Problem structure:** Simulating the final position is trivial O(M). The hard part is counting distinct houses lying on the union of up to M axis-aligned segments. Horizontal moves only touch houses with matching y; vertical moves only touch houses with matching x. This decomposes into two independent 1D problems.
- **Chosen approach (offline per-row/per-column interval merging):** While simulating, record horizontal moves as inclusive x-intervals keyed by their y (`h_intervals[y]`), and vertical moves as inclusive y-intervals keyed by their x (`v_intervals[x]`). Group houses as `by_y[y] = [(x, idx)]` and `by_x[x] = [(y, idx)]`.
- **Coverage test:** For each row y with recorded intervals, sort and merge overlapping intervals (merge when `lo <= cur_hi`). Store merged `starts`/`ends`. A house at (x, y) is covered iff `j = bisect_right(starts, x) - 1 >= 0` and `x <= ends[j]`. Symmetric for columns using `by_x`.
- **Dedup:** A single global `covered = bytearray(N)`; a house can be flagged by both the row pass and the column pass but counted once. Final answer is `sum(covered)`.
- **Endpoints:** Intervals are inclusive on both ends; `bisect_right(starts, x) - 1` plus an explicit `x <= ends[j]` check handles inclusivity exactly. Merging adjacent-integer intervals (e.g. [1,2] and [3,4]) is unnecessary but harmless; `lo <= chi` is the safe merge condition.
- **Overflow:** All coordinates can exceed 32-bit; Python ints handle this natively (sample 2 reaches 3e9).
- **Complexity:** O((N + M) log) overall — sorting intervals per key plus one binary search per house per relevant dimension. Well within limits for N, M ≤ 2e5.
