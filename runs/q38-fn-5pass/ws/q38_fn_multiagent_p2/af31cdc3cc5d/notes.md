- **Core reduction:** Repeatedly removing adjacent pairs is equivalent to choosing a non-crossing matching on the original positions. For even N this is a perfect matching; for odd N exactly one element remains unmatched.
- **Unmatched element constraint:** If an element remains unmatched, no matched pair can have endpoints on both sides of it, because that element would always stay between them. Therefore the unmatched 0-based index must be even, splitting the sequence into an even prefix and an even suffix that are solved independently.
- **Even block theorem:** For any even contiguous block of length 2m, the maximum score is the sum of its largest m values minus the sum of its smallest m values. The upper bound follows by orienting each pair from larger to smaller. Attainability follows by coloring the largest half red and the smallest half blue; since counts are equal, there is always an adjacent opposite-color pair, and removing such pairs repeatedly gives a valid non-crossing matching. Every red value is at least every blue value, so each pair contributes exactly red minus blue.
- **Prefix/suffix computation:** The order inside an even block does not affect its optimal value, so each even prefix/suffix value is just the half-sum difference. Maintain two heaps while scanning: low is a max-heap of the smallest ceil(k/2) seen elements, high is a min-heap of the largest floor(k/2) seen elements, with their sums. Invariant: all low values are <= all high values.
- **Heap rebalancing:** Insert into low if the value is at most the current low maximum, otherwise into high. Then rebalance sizes so low has at most one more element than high and never fewer. For even k, low and high have equal size and the block value is high_sum - low_sum.
- **Final combination:** If N is even, the answer is the value of the whole array. If N is odd, compute all even prefix values and all even suffix values, then maximize prefix[i] + suffix[i+1] over even 0-based i.
- **Implementation details:** Use heapq with local bindings for speed. Arrays of length N+1 are initialized to zero; only even lengths are filled. Python integers safely handle sums up to about 1.5e14.
- **Sample checks:** Sample 1 full block sorted as [1,2,3,5], value (5+3)-(1+2)=5, PASS. Sample 2 best split leaves the first element unmatched, suffix [1,4,1,5,9,2] has value (9+5+4)-(1+1+2)=14, PASS. Sample 3 all values equal, every half-sum difference is 0, PASS.
- **Complexity:** Two scans in the odd case, one scan in the even case. Each insertion does O(log N) heap operations, so total time is O(N log N), memory is O(N).
- **Pitfalls checked:** Duplicates at the median are harmless because the partition can assign equal values arbitrarily. The unmatched position parity must be enforced. Prefix and suffix values must be combined only after splitting at the unmatched element; using global largest/smallest halves across the split would be invalid.
