- **Problem model:** an alternating permutation uses all numbers 1..n with parities strictly alternating. Need the k-th in lexicographic order, or [] if fewer than k exist.
- **Core counting fact:** with o unused odds and e unused evens, and a forced next parity P, the parity pattern of the rest is completely determined. Feasible only when counts match the slot counts; then the number of completions is o! * e!. Concretely: odd-start feasible iff o-e in {0,1}; even-start feasible iff e-o in {0,1}; otherwise 0. Empty remainder (o=e=0) gives 1.
- **Block invariance:** every candidate of the same parity at a position yields the SAME completion count, since it depends only on remaining odd/even counts and the required next parity. So the k-th selection is a greedy block-skipping: for each candidate c in ascending order, block = count(o_rem, e_rem, opposite parity of c); if k > block subtract and continue, else pick c.
- **Greedy construction:** at position 0 all unused numbers are candidates; afterwards only unused numbers of parity opposite the previous element. Remove the chosen number, update prev parity and remaining odd/even counts. If position 0 exhausts all candidates -> total < k -> return [] (a None later is only defensive).
- **Totals:** odd count = (n+1)//2, even count = n//2. n odd => O=E+1 => only odd-start feasible; n even => both starts feasible.
- **Complexity:** O(n^2) candidate checks, O(n) factorial precompute. Python big ints handle 50!*50! (~9e128) fine; capping at >1e15 is optional and unnecessary since k <= 1e15.
- **Verified examples:** n=4,k=6 -> [3,4,1,2]; n=3,k=2 -> [3,2,1]; n=2,k=3 -> []; n=1,k=1 -> [1]; n=1,k=2 -> [].
- **Pitfalls handled:** candidates with block 0 are skipped naturally because k>=1 > 0; lexicographic order equals ascending candidate order with contiguous blocks, so subtraction (not division) is correct; the first position's mixed-parity candidate set is the only place both parities compete.
