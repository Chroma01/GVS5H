- **Testing:** The current implementation returns 110 for the first provided example and 985 for the second. A brute-force checker that enumerates all partitions and evaluates the original segment formula agrees on small random arrays, including lengths up to 8 with small values and small k; no failing sample was found.
- **Core reduction:** Let cuts be `0 = r0 < r1 < ... < rm = n`. For segment `t`, using exclusive end `rt`, original cost is `(P[rt] + k*t) * (C[rt] - C[r(t-1)])`, where `P` and `C` are prefix sums of `nums` and `cost`.
- **Telescoping identity:** The ordinal part satisfies `sum_t t * (C[rt] - C[r(t-1)]) = sum_t (C[n] - C[r(t-1)])`. Therefore each edge from `p` to `r` can be assigned weight `P[r] * (C[r] - C[p]) + k * (C[n] - C[p])`, independent of segment index.
- **One-dimensional DP:** Define `dp[0] = 0` and `dp[r] = min_{p < r} dp[p] + P[r] * (C[r] - C[p]) + k * (C[n] - C[p])`. Expanding gives `dp[r] = P[r] * C[r] + k * C[n] + min_{p < r} (dp[p] - (P[r] + k) * C[p])`. The answer is `dp[n]`.
- **Implementation:** Build prefix arrays in O(n), then compute each `dp[r]` by scanning all previous cuts `p`. This is O(n^2) time and O(n) memory, easily within `n <= 1000`.
- **Pitfalls:** `dp[r]` is not the original minimum cost for prefix `r` under the original problem; it includes artificial charges involving the global `C[n]`. It is only meaningful as a shortest-path value toward the full array. Use `C[n]`, not `C[r]`, in the transformed edge weight. Enforce `p < r` to avoid empty subarrays.
- **Complexity:** Time `O(n^2)`, space `O(n)`. Python integers safely handle the maximum possible totals.
