- **Validation:** The provided samples produce 2, 1, and 1. Manual exhaustive checks on the full side=2 boundary set and several small adversarial patterns (same-chain runs, equal-u opposite pairs, delayed activation, sentinel resets) agree with brute force. No failing geometry or DP condition was found.
- **Geometry:** Split the square boundary into chain 0 = bottom + right and chain 1 = left + top, assigning each corner to exactly one chain. For every point use `u = x + y` and `h = min(u, 2*side - u)`. Same-chain Manhattan distance is exactly `|u_i - u_j|`. Opposite-chain distance is `max(|u_i - u_j|, h_i + h_j)`. In all cases distance is at least `|u_i - u_j|`.
- **DP state:** For fixed candidate `d`, after sorting by `(u, chain)`, a valid prefix ending at point `i` only needs the minimum `u` of the last selected point on the opposite chain, or a sentinel if none is relevant. Smaller stored `u` dominates because it only makes future same-chain spacing easier.
- **Transition logic:** If a previous reachable state ends at `u_i <= u_r - d`, it can extend to `r` and all later points, producing a sentinel state. Otherwise, in the near window, same-chain transitions are impossible; only opposite-chain transitions are possible, requiring stored opposite `u + d <= u_r` and `h_i + h_r >= d`.
- **Sweep implementation:** For each DP layer, sweep points by increasing `u`. Maintain `first_u`, the smallest reachable previous ending `u`. Once `u >= first_u + d`, fill the rest of `ndp` with sentinel and stop. Before that, query active opposite-chain states for minimum `u_i` satisfying the height condition.
- **Data structures:** Per chain, a heap keyed by `dp[i] + d` delays states until their stored opposite point is far enough. A Fenwick tree over reversed compressed `h` supports suffix minimum queries for active states. Global minima per chain shortcut full-range queries. Fenwick min-updates use an early break invariant: if a node already has a value <= the new value, all later ancestors on that update path also do.
- **Tie handling:** Points with equal `u` can occur only on opposite chains. Sorting chain 0 before chain 1 is safe: if both equal-`u` points are selected, the state ending at the later chain dominates the earlier-chain ending state for all future extensions.
- **Edge cases:** `d = 0` is immediately feasible and is special-cased. All inequalities use non-strict comparisons because distance at least `d` is allowed. Binary search range is `[0, 2*side]`.
- **Complexity:** Each feasibility check is `O(k n log n)` with small constants; binary search adds `O(log side)`. With `n <= 15000`, `k <= 25`, this fits. Precomputed Fenwick paths reduce constant factors.
