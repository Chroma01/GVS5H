- **Core reformulation:** For any pair, choose one of X/Y/Z attaining the maximum. Then each chosen pair contributes two cakes of the same color, so the problem is equivalent to choosing 2K cakes and assigning each chosen cake one color, with every color used an even number of times, maximizing the sum of assigned attribute values. Conversely, any even-color assignment can be paired within each color, and each pair price is at least the assigned sum.
- **Lagrangian relaxation:** Let f(m) be the optimum for exactly m pairs. For penalty C per pair, maximize f(m) - C*m. Using doubled values, each selected cake assigned color c contributes `2*attr_c - C`. For m pairs (2m selected cakes), the DP value is `2*f(m) - 2*C*m`.
- **DP state:** 8 parity masks for even/odd counts of X, Y, Z. Each cake is either unselected or assigned one color, toggling one bit. Final valid state is mask 0.
- **Tie-breaking:** For each mask, maximize adjusted value first, then selected-cake count. This gives the largest number of pairs among optimal adjusted solutions, which is required for the binary-search predicate.
- **Packed key:** Store `(value, count)` as `value * BASE + count`, with `BASE = 1 << 17` because N <= 1e5. This makes lexicographic comparison a single integer comparison. Precompute each color delta as `(2*attr << SHIFT) + 1`; for penalty C subtract `C << SHIFT`.
- **Unrolled transition:** The 8-state update is fully unrolled and uses old states only, avoiding list allocation and inner loops. This is the main performance optimization.
- **Binary search:** The predicate is `optimal selected count >= 2K`. The predicate is monotone because f(m) is concave (maximum-weight matching cardinality value). Search the largest integer C with predicate true. Upper bound `max2 + 1`, where `max2 = max(2*X_i, 2*Y_i, 2*Z_i)`, is false because every selected cake then has negative adjusted value.
- **Answer recovery:** If `val2` is the doubled adjusted value at the final penalty `lo`, answer is `(val2 + 2*lo*K) // 2`, equivalently `val2/2 + lo*K`. At the largest true penalty, K is among the optimal pair counts, so this gives the exact f(K).
- **Edge cases handled:** zero values, ties, odd N, identical cakes, odd penalties, and K=0 safety. The final DP value is even because the final selected count is even.
- **Performance:** About 31 binary-search iterations over the sum of N, each doing one unrolled 8-state pass. PyPy is recommended. SHIFT=17 keeps packed integers smaller than SHIFT=20 while still safely storing counts.
- **Possible backup optimization:** If the packed DP is too slow, `calc` can be replaced by an unconstrained-best plus parity-correction method: choose each cake's best option, then fix the XOR mask using at most 3 changed cakes (dimension 3 over GF(2)), keeping top-3 losses per delta mask. This was not implemented here.
