- **Core reduction:** For any fixed route, only the minimum building height B on the route matters. If B >= min(Y,Z), cross at floor min(Y,Z) and pay |Y-Z|. Otherwise descend to B, cross, ascend to Z, paying Y+Z-2B. This cost is nonincreasing in B, so each query needs the maximum possible bottleneck B between two cells.
- **Graph model:** Treat adjacent cells as edges with capacity min(F_u, F_v). For paths of positive length, the minimum edge capacity equals the minimum vertex height on the path. Same-cell queries use the cell's own height, handled directly or by leaf weights.
- **Maximum bottleneck:** Build a maximum spanning forest by Kruskal in descending edge weight. A Kruskal reconstruction tree makes the LCA weight of two original cells equal to their maximum bottleneck. Leaves keep original building heights; internal nodes keep the edge weight at which two components merge.
- **Edge packing:** Node ids need at most 18 bits for N <= 250000, but shift is computed dynamically as max(1, (N-1).bit_length()). Pack each edge as (weight << 2*shift) | (u << shift) | v and sort packed integers descending. This avoids tuple overhead.
- **Edge generation:** Generate horizontal and vertical edges into a preallocated list using edge_count = H*(W-1) + (H-1)*W. Use conditional min instead of min() for speed.
- **DSU design:** DSU is kept only over original N cells, not reconstruction-tree nodes. Each DSU representative stores the current reconstruction-tree root in comp_root. Union by size keeps finds fast. When merging, create a new tree node tot with children comp_root[ru], comp_root[rv], set its weight, set up0[child]=tot, then union representatives and update comp_root of the new representative.
- **Early stop:** Once tot == 2*N-1, the grid is connected and the MST is complete; remaining sorted edges can be ignored.
- **Tree properties:** Reconstruction-tree node ids are created increasing, so every parent id is larger than its children. This allows iterative depth computation by scanning internal nodes from tot-1 down to N and propagating depth to children. It also avoids recursion.
- **LCA preprocessing:** up0 is trimmed to tot. Binary lifting levels are built with list comprehensions: next_level = [prev[x] for x in prev]. LOG is based on max_depth.bit_length(), not tot.bit_length(), saving a level when possible.
- **Query answering:** For different cells, compute LCA, take its weight as B, and apply the closed-form answer. Same-cell queries are answered immediately as |Y-Z|.
- **Memory management:** Large temporary structures (edges, DSU arrays, left/right children) are deleted before building the binary lifting table. Aliases are deleted too, including bound-method references, to avoid accidental retention.
- **Edge cases:** N=1 has no edges, root is leaf 0, LOG=1, and all queries are same-cell. H=1 or W=1 works because edge generation skips missing directions. Equal edge weights are fine; arbitrary Kruskal order among equal weights still gives correct LCA weights.
- **I/O:** Grid is read line by line. Queries are read after preprocessing, avoiding storage of all queries. Output is collected in a preallocated list and joined once.
