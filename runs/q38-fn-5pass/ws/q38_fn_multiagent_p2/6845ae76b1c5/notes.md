- **Approach:** Use value-bucket sqrt decomposition. Sort all 2N occurrences by value and split them into contiguous value buckets of size about 300. For pairs in different value buckets, the sign of `A_i - B_j` is fixed, so their contribution is computable from bucket counts and sums. For pairs in the same value bucket, build an exact 2D prefix matrix over original-index prefixes inside that bucket.
- **Bucket construction:** Occurrences are encoded as `(value << CODE_BITS) | code`, where `code` distinguishes A/B and original index. Sorting integers is faster and lighter than sorting tuples. `CODE_BITS` is dynamic from `2N`. Bucket id is `pos // VAL_BS`.
- **Per-bucket data:** For each bucket, A and B occurrences are stored encoded as `(1-based_index << 32) | value`. Only buckets containing both A and B are kept for exact matrices. Sorting these encoded integers sorts by original index.
- **Same-bucket matrices:** For a bucket with `a` A-elements and `b` B-elements, build a flat `(a+1)*(b+1)` prefix matrix where entry `(x,y)` is the sum over first `x` A-elements and first `y` B-elements by index. Stored as `array('q')` to keep memory low. Total entries are at most about `N * VAL_BS / 2`.
- **Cross-bucket formula:** For each value bucket `p`, maintain lower B count/sum. Contribution of A bucket `p` against lower B buckets is `A_sum[p]*B_cnt_lower - A_cnt[p]*B_sum_lower`; against higher B buckets is `A_cnt[p]*B_sum_higher - A_sum[p]*B_cnt_higher`. Same bucket is excluded by subtracting its own B count/sum from the higher side.
- **Query processing:** Sort queries by `X` and incrementally maintain A prefix bucket counts/sums. For B prefixes, precompute bucket count/sum tables at index-block boundaries of size about 300. For each query, copy the boundary row and add the remainder B elements, then compute cross contribution in O(number_of_value_buckets).
- **Same-bucket query addition:** After cross answers are computed, process each bucket separately. Queries are already sorted by `X`, so the number of A-elements in the bucket is advanced by a two-pointer. The number of B-elements is obtained by `bisect_right` on the bucket's sorted B indices, then the matrix is looked up in O(1).
- **Memory management:** Cross structures and boundary tables are deleted before building matrices to reduce peak memory. Encoded integer lists reduce sorting and storage overhead. Matrix arrays are 64-bit; individual bucket entries and final answers fit in signed 64-bit, while Python ints are used for intermediate cross arithmetic.
- **Constants:** `VAL_BS = IDX_BS = 300` was chosen as a practical compromise: fewer value buckets than 250 reduces per-query loops, while matrix memory remains acceptable. If memory is tighter, lowering to 250 is safe; if time is tighter and memory is ample, increasing slightly may help.
- **Pitfalls handled:** Equal values may be split across adjacent value buckets; cross formulas still give zero for equal cross-bucket pairs. A/B indices in matrices are 1-based to match prefix lengths. Cross loop must process A buckets even when their B bucket count is zero. Flat matrix indexing uses `x * (b+1) + y`.
