- **Validation:** The provided samples pass: `"cdcd" -> "cccc"`, `"aca" -> "aaa"`, `"bc" -> ""`. Edge checks also pass: `n < 3` returns empty; `n = 3, 4, 5` effectively force one run because a second run cannot reach length 3; `n = 6` permits a switch only at index 3. Lexicographic tie checks behave correctly: when costs tie, the smaller character at the first differing position is chosen, so a longer first run is kept if its character is smaller, and an earlier switch is chosen if the new character is smaller.
- **Problem model:** A good caption is a concatenation of runs of identical characters, each run length at least 3. Assigning target character `x` to original character `y` costs `abs(x - y)`. For `n >= 3`, a solution always exists by making all characters equal; for `n < 3`, impossible.
- **Suffix DP state:** `F(i, c, l)` is the minimum cost for suffix `i..n-1` given that the run ending at `i-1` has character `c` and capped length `l in {1,2,3}`. `l=3` means length at least 3. At `i=n`, only `l=3` is valid with cost 0; `l=1,2` are invalid.
- **Transitions:** If `l=1`, position `i` must continue `c`: `F(i,c,1)=cost_c+F(i+1,c,2)`. If `l=2`, it must continue: `F(i,c,2)=cost_c+F(i+1,c,3)`. If `l=3`, either continue `c` or switch to `x != c` and start a new run: `min(cost_c+F(i+1,c,3), min_{x!=c}(cost_x+F(i+1,x,1)))`.
- **Switch optimization:** For each row, compute `g[x]=cost_x+F(i+1,x,1)`. Maintain the best and second-best values with their smallest character indices. For state `c`, the best switch excluding `c` is best if best char != `c`, otherwise second best. This gives O(26n) time.
- **Tie-breaking:** The start character is the smallest character attaining the global minimum. For `l=3`, if continue and switch have equal cost, choose the smaller character at the current position. For switch options with equal cost, best/second-best tracking chooses the smallest feasible character. For `l=1,2`, continuation is forced.
- **Correctness of decisions:** By backward induction, each stored decision gives the lexicographically smallest optimal suffix for its state. Since lexicographic order is decided at the first differing position, choosing the smallest feasible optimal character at each state is globally optimal.
- **Memory:** Only two sets of three length-26 arrays are kept for DP values. A `bytearray` of size `n*26` stores decisions for `l=3` states, about 1.3 MB at the maximum constraint.
- **INF handling:** `INF=1e9` is far above the maximum finite cost `25*50000=1.25e6`. Impossible values may exceed INF and are ignored by the best-switch loop. `l=3` values remain finite because an already-complete run can always continue to the end.
- **Reconstruction:** Start with the chosen first character and length 1. At each position, if length is 1 or 2, continue the current run. If length is 3, read the stored decision. Continue keeps capped length 3; switch resets length to 1 and changes current character. A final safety check ensures the last run is complete.
- **Complexity:** Time O(26n), memory O(26n) bytes for decisions plus O(26) working arrays.
- **Status:** No failing sample or edge case was found; the current DP and tie-breaking approach is sufficient.
