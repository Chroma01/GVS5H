- **Model:** The global reversal operation only changes the orientation parity of the graph. After an even number of reversals the graph is original, after an odd number it is fully reversed. Therefore a state `(vertex, parity)` is sufficient.
- **State graph:** For parity 0, moving from `v` to `u` uses original outgoing edges `v -> u` with cost 1. For parity 1, moving from `v` to `u` uses original incoming edges `u -> v`, because those become outgoing in the reversed graph, also with cost 1. From either state, reversing all edges moves to `(v, 1 - parity)` with cost `X`.
- **Answer:** Run Dijkstra from `(1, 0)` and take the minimum finalized distance to `(N, 0)` or `(N, 1)`. Since all edge costs are nonnegative, the first valid popped state whose vertex is `N` is already the global optimum among both target states.
- **Implementation details:** Use two adjacency lists: `g` for original outgoing edges and `rg` for original incoming edges. Encode state as `(vertex << 1) | parity` and store distances in one flat array. Heap entries are `(distance, state)`. Stale heap entries are skipped with `if d != dist[s]`.
- **Complexity:** There are `2N` states, `2M` move relaxations, and `2N` reversal relaxations. Time is `O((N + M) log(N + M))`, memory is `O(N + M)`.
- **Integer range:** The answer can exceed 32-bit integers. Python integers are arbitrary precision; `INF = 10**30` is safely above the maximum possible shortest path cost under the constraints.
- **Pitfalls handled:** Reversed-layer moves must use incoming edges, not outgoing edges. Early stopping must occur only after checking that the heap entry is not stale. The target is either parity of vertex `N`, not only the original orientation.
- **Alternatives considered:** Explicitly building a `2N`-vertex graph is correct but uses more memory and is less cache-friendly in Python. Bidirectional Dijkstra, bucket queues, A*, and DP over reversal counts are unnecessary here and add complexity without improving the worst-case asymptotics.
