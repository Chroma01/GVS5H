- **Core greedy characterization:** For a sorted interval of length m, K pairs are possible iff the K smallest elements can be paired with the K largest elements in order: for every t=0..K-1, 2*A[L+t] <= A[R-K+1+t]. This follows from monotonicity/exchange arguments; using larger small elements or smaller large elements can only make feasibility harder.
- **Reduction to range maximum:** Let nxt[i] be the first global index with A[nxt[i]] >= 2*A[i], and D[i] = nxt[i] - i. For query [L,R], m=R-L+1, K is feasible iff max(D[L..L+K-1]) <= m-K. If nxt[i]=n, D[i]=n-i still correctly fails all feasible K because the required large index is always inside [L,R].
- **Monotonicity:** If K is feasible, K-1 is feasible because the queried prefix shrinks and the bound m-K increases. Therefore the answer can be found by searching the largest feasible K.
- **Binary lifting instead of binary search:** Maintain current feasible prefix length `length` and its maximum D value `curmax`. Try adding blocks of sizes powers of two from high to low. For a block of size 2^b starting at L+length, its maximum is directly `st[b][L+length]`. If max(curmax, block_max) <= m-(length+block_size), the enlarged prefix is feasible. This gives O(log N) per query with one sparse-table access per bit.
- **Useful upper bound:** Besides K <= m//2, the first element gives K <= m-D[L]. Setting hi = min(m//2, m-D[L]) quickly answers impossible queries and reduces binary-lifting steps.
- **Sparse table memory:** The sparse table is built as a list of lists. Higher levels store references to integer objects from lower levels rather than creating many new integers, so memory is roughly O(N log N) pointers plus O(N) integer objects, which is acceptable for N=2e5.
- **Two-pointer nxt computation:** Because A is nondecreasing, targets 2*A[i] are nondecreasing, so the pointer j for nxt[i] only moves forward. Total O(N).
- **Edge cases handled:** K=0, intervals of length 2, duplicate sizes, sentinel nxt=n, and off-by-one between 1-indexed input and 0-indexed arrays.
- **Complexity:** Preprocessing O(N log N), each query O(log N), total O((N+Q) log N).
