- **Model:** Walkways are free but only at a floor no higher than both endpoint buildings; stairs cost vertical distance. For a fixed grid path, the largest common height usable is the path's min building height.
- **Cost formula:** With m = max over grid paths of (min F over all cells on the path, endpoints included), answer = |Y-Z| + 2*max(0, min(Y,Z) - m). Case check: if min(Y,Z) <= m cross at that floor for |Y-Z|; else descend/ascend to m at both ends for |Y-Z| + 2*(min-m).
- **Bottleneck equivalence:** m equals the max w such that start and target are connected in the subgraph induced by cells with F >= w. So activate cells in descending F order and record when each query's endpoints first merge.
- **Same-block queries:** if start and target are the same cell (u==v), m is effectively infinite; answer is just |Y-Z|. Handle these directly and never insert them into the DSU machinery.
- **Offline DSU with per-component query sets:** Attach each query id to both endpoint cells. Activate cells in descending F; each newly active cell is unioned with already-active cardinal neighbours at weight F[cell]. Maintain, per DSU root, a set of query ids having one endpoint in that component. When two components merge, any id present in both sets gets its bottleneck = current cell's F (all active cells have F >= that), then is discarded. This is correct because the merge is the first moment the endpoints connect.
- **Amortization:** Always iterate the smaller query set and insert into the larger; each id's set size at least doubles per move, giving O(Q log Q) total set work. DSU uses union by component size independently; keep the surviving root's set slot consistent.
- **Implementation details:** Use a flat grid, ids i*W+j; neighbours up/down/left/right by index arithmetic. Cache rc = root of the freshly activated cell and update it from merge's return value to avoid a redundant find per edge (roughly halves find calls, ~number of edges = 2N). Path-halving find.
- **Why no LCA needed:** The set-merge offline trick answers all widest-path queries without building a Kruskal reconstruction tree or binary lifting, saving both time and memory.
- **Grid connectivity:** The full pedestrian grid is connected, so every u!=v query is guaranteed to be answered before the activation loop ends.
- **Complexities:** O(N log N) sort + O((N + Q log Q) α) union/set work + O(Q) output; N=H*W<=250000, Q<=2e5.
- **Pitfalls handled:** equal F values (any activation order among equal weights is fine), same-node queries, 0-based vs 1-based indices, reading all input at once for speed.
