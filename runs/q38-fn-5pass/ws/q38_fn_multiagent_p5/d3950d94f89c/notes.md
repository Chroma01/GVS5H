- **Verdict:** The current implementation passes both provided samples and representative edge cases: all equal values, two-node duplicate, unique chain, duplicate outside the current window, and ties where a shorter node count has the same maximum length. No failing case was found under the stated constraints, so no algorithmic fix is required.
- **Core idea:** For each node as the bottom endpoint, the longest valid downward path ending there is the longest suffix of the root-to-node path with unique values. Because all edge lengths are positive, the earliest valid ancestor gives the maximum weighted length for that bottom endpoint.
- **Sliding window invariant:** During DFS, `left` is the minimum depth such that the path from depth `left` to the current node has all unique values. When entering a node with value `x`, only `x` can create a new duplicate. If its previous occurrence on the current path is at depth `p`, any start at or above `p` is invalid, so `left = max(left, p + 1)`. If `p` is above the current window, `left` stays unchanged.
- **Backtracking state:** The DFS is iterative with enter/exit events. On enter, save `old_left` and `prev_last = last[x]`, then update `left` and set `last[x] = depth`. On exit, restore `last[x] = prev_last` and `left = old_left`. This ensures sibling subtrees see the exact parent path state.
- **Distance and node count:** Maintain `dist_by_depth`, where `dist_by_depth[d]` is the root distance of the node at depth `d` on the current DFS path. For a current node at depth `d`, the candidate path length is `dist - dist_by_depth[left]`, and its node count is `d - left + 1`.
- **Tie-breaking:** Track the global maximum length and, among paths with that length, the minimum node count. Single-node paths have length `0` and node count `1`, so initialize the answer to `[0, 1]`.
- **Implementation details:** Build an undirected adjacency list, root the traversal at node `0`, and use a stack of events `(node, parent, depth, dist, state, old_left, prev_last)`. Push the exit event before children so children are processed first. Use an array `last` sized by `max(nums) + 1` because values are bounded by `5 * 10^4`; a dictionary would also work.
- **Correctness intuition:** The invariant ensures `left` is exactly the earliest valid ancestor for the current node. Every special path has a bottom node, and for that bottom the earliest valid ancestor is at least as long as any other valid start. Therefore checking only these candidates finds the global optimum.
- **Complexity:** Time complexity is `O(n + max(nums))`, and memory is `O(n + max(nums))` for adjacency, stack, path distances, and last occurrences.
- **Edge cases:** All values equal gives `[0, 1]`; a single-node tree also gives `[0, 1]`; duplicate values outside the current unique window must not move `left` backward; positive edge weights are essential for earliest-start optimality.
- **Caveat:** If zero-weight edges were allowed, a later start could tie the earliest start's length while using fewer nodes. The current logic relies on the stated constraint `length_i >= 1`, so this is safe.
