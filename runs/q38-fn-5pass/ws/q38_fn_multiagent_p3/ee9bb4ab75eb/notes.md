- **Validation:** Sample 1 and sample 2 pass. Key edge cases checked mentally: `n - 1 < k`, `k = 1`, duplicate words, prefix words, all-zero answers, and robustness for empty strings if they were present. No failing case was found, so the current trie + binary-search solution is retained.
- **Core predicate:** For a trie prefix node at depth `d` with original count `c`, after removing word `i` its count is `c - 1` if word `i` has that prefix, otherwise `c`. It can support `k` remaining strings iff `c > k`, or `c == k` and the removed word does not have that prefix.
- **Depth-level summary:** For each depth `d`, feasibility for removed word `i` is true if any node has count `> k`, or at least two nodes have count `== k`, or there is exactly one count-`== k` node and word `i` does not use it.
- **Why two exact-k nodes are safe:** A word has exactly one prefix of a fixed length, so removing one word can reduce the count of at most one exact-k prefix node. If there are at least two such nodes, at least one remains intact.
- **Monotonicity:** If `k` remaining words share a prefix of length `L`, they also share its prefix of length `L - 1`. The ancestor node has remaining count at least as large, so feasibility is monotone. This justifies binary search per word.
- **Trie construction:** `children` uses `None` for leaves and dictionaries for internal nodes. Each node stores how many words pass through it and its depth. `paths[i]` stores the node ids along word `i`'s path. Total nodes and stored path entries are bounded by total input length, at most `1e5`.
- **Per-depth arrays:** `has_gt[d]` marks existence of a node with count `> k`. `exact_count[d]` counts nodes with count `== k`, capped at 2. `exact_node[d]` stores the unique node id when exactly one such node exists.
- **Query logic:** For each word, binary search `[0, max_len]` using upper mid. If `has_gt[mid]` is true, feasible. Else if `exact_count[mid] >= 2`, feasible. Else if `exact_count[mid] == 1`, feasible when the removed word is shorter than `mid` or its path node at `mid` differs from the unique exact-k node. Otherwise infeasible.
- **Edge handling:** If `n - 1 < k`, return zeros before building the trie. `k = 1` is handled by the same predicate. If the removed word is shorter than `mid`, path indexing is skipped. Depth 0 is not stored; `lo` starts at 0 and is always feasible whenever `n - 1 >= k`.
- **Complexity:** Time is `O(total_length + nodes + n log max_len)`. Memory is `O(total_length + n)`. With total length `1e5`, this is comfortably within limits.
- **Implementation details:** Import `List`. Free trie arrays after building. Node ids are positive, so `-1` is a safe sentinel. Upper mid `(lo + hi + 1) // 2` avoids infinite binary-search loops.
