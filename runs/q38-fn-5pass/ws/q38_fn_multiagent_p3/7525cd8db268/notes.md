- **Core model:** Normalize each conflicting pair to `(lo, hi)` with `lo < hi`. For a fixed right endpoint `r`, only pairs with `hi <= r` are active. A subarray ending at `r` is valid iff its left endpoint is greater than the maximum `lo` among active pairs, so the number of valid subarrays ending at `r` is `r - max_lo`.
- **Sweep state:** Sweep `r` from `1` to `n`, inserting pairs bucketed by `hi`. Maintain only the largest active `lo`, its multiplicity, the unique pair id when multiplicity is one, and the second-largest distinct active `lo`. Since pairs are only inserted as `r` increases, each insertion updates this state in O(1).
- **Gain attribution:** Removing a pair increases the count at right endpoint `r` only if that pair is the unique active pair attaining `max_lo`. In that case the new maximum becomes `second_lo`, so the gain at `r` is `max_lo - second_lo`. Accumulate this gain for the unique pair id at every `r` where it remains the unique maximum.
- **Same right endpoint:** All pairs with the same `hi` must be inserted before computing `base_valid` and gains for that `r`. Otherwise transient states could incorrectly attribute gains to pairs that are immediately tied or superseded by another pair with the same `hi`.
- **Ties and duplicates:** If multiple active pairs share the maximum `lo`, removing one of them does not relax the constraint, so gain is zero. The fallback value is the second-largest distinct `lo`, not the second pair. Duplicate normalized pairs are handled naturally by multiplicity.
- **Complexity:** Time complexity is O(n + m), where `m = len(conflictingPairs)`, because each pair is processed once and each right endpoint is visited once. Memory is O(n + m) for buckets and per-pair gains.
- **Edge cases:** If no pair is active, `max_lo = 0` and all `r` subarrays ending at `r` are valid. If every possible removal gives zero gain, the answer is still `base_valid`, since exactly one pair must be removed but the count need not increase. Python integers safely handle the maximum answer around `n(n+1)/2`.
- **Sample tests:** Example 1 returns 9 and Example 2 returns 12. Targeted checks pass: a single conflicting pair reaches all subarrays after removal; duplicate pairs give zero gain; tied maximum pairs give zero gain while earlier unique dominance still contributes correctly; pairs that never dominate contribute zero; large `n` with many pairs remains linear and within expected performance. No expected-vs-actual failures found.
