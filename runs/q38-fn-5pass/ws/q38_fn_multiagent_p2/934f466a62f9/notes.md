- Reduction: each pair can be charged to one attribute attaining its max. Thus choosing K pairs is equivalent to choosing 2K cakes, coloring each by X/Y/Z, requiring every color count to be even, and maximizing the sum of chosen attribute values. Pairing within each color gives a matching with at least that value, and any matching gives such a coloring with equality.
- Lagrangian scaling: double all attribute values. For a pair penalty mu, subtract mu from every selected cake. A solution with k pairs has doubled adjusted value 2F(k) - 2mu*k. calc(mu) returns the maximum doubled adjusted value and the maximum k among maximizers.
- calc structure: independently choose each cake's best state among unused and three colors, preferring selected states on zero-gain ties. This gives base value, base selected count, and base parity mask. Any feasible solution differs by state changes. A change has a nonzero mask (XOR of toggled color bits), nonnegative loss, and selected-count delta.
- Parity correction: need changes whose masks XOR to base_mask. In GF(2)^3, an optimal min-loss/max-count correction uses at most 3 changed cakes. If more, a dependent subset has XOR 0; removing it preserves parity and does not increase loss. A zero-loss positive-delta subset would contradict the base max-count tie-breaking; a zero-loss negative-delta subset would improve count; positive loss would improve value.
- Candidate pruning: for each mask 1..6 keep top 3 changes by (loss, -delta). Top 3 suffices because when replacing one change, at most two other changed cakes can conflict. Mask 7 is impossible for a single cake state change, so it is excluded from precomputed mask combinations.
- Enumeration: precompute all nondecreasing mask multisets of size 1..3 with XOR target. For each, try candidates from the corresponding top lists, enforcing distinct cake ids. Minimize total loss, then minimize total nd (equivalently maximize selected count). Return pair count as selected_count // 2.
- Binary search: F(k) is concave as the cardinality-constrained matching polytope value. k_max(mu) is nonincreasing. Search the largest integer mu with calc(mu).count >= K. hi is max doubled attribute + 1, since no marginal can exceed the maximum pair price. Recover answer as (calc(mu).value + 2*mu*K) // 2.
- Edge cases: all-zero values and odd N are handled by zero-loss drops; ties among attributes create zero-loss recolors; no-pairs fallback ensures calc never fails; Python integers handle all sums.
- Complexity: each calc is O(N) with small constant plus tiny enumeration. Binary search uses O(log max_value) iterations, so total O(sum N log max_value), easily within limits.
