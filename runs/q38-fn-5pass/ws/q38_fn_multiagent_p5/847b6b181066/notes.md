- **Core reduction:** Let P[t] be the cumulative wind displacement after t steps, with P[0] = (0, 0). Smoke generated at time g is at P[t] - P[g] after the wind at time t.
- **Generation times:** After the wind at time t, the origin is occupied iff some previously generated smoke has returned to the origin, i.e. iff P[t] has appeared among earlier prefix positions. Therefore, new smoke is generated exactly at first occurrences of prefix positions.
- **Query condition:** Smoke is at target (R, C) at time t+0.5 iff there exists a generation time g < t such that P[t] - P[g] = (R, C). This is equivalent to P[g] = P[t] - (R, C). Since every previously seen prefix position has a first occurrence that generated smoke, it is enough to check whether P[t] - (R, C) has appeared before time t.
- **Online algorithm:** Maintain a set of prefix positions seen so far, initially containing (0, 0). For each character, update the current prefix position, test whether the shifted position (current_r - R, current_c - C) is already in the set, append the answer, then insert the current prefix position.
- **Correctness argument:** The set contains exactly P[0], P[1], ..., P[t-1] before processing time t. A hit means some earlier prefix position equals P[t] - (R, C), so the smoke generated at its first occurrence is currently at the target. A miss means no such earlier prefix position exists, so no smoke can be at the target.
- **Complexity:** Each step performs one tuple lookup and one tuple insertion in a hash set, giving expected O(N) time and O(N) memory.
- **Implementation details:** Input is read as bytes. Iterating over the string yields ASCII integer codes: N=78, W=87, S=83, E=69. Coordinate tuples are used directly as hash keys, which is safe and simple for N <= 200000.
- **Edge cases:** The target is guaranteed not to be (0, 0), so checking before inserting the current prefix position is safe. If the target were (0, 0), a separate interpretation-dependent handling would be needed, but constraints exclude this.
- **Superseded alternatives:** Offline first-occurrence dictionaries, coordinate compression, packed integer keys, and sort-and-sweep approaches are unnecessary for this problem; the online tuple-set solution is both simpler and fast enough.
