- **Sample tests:** PASS. Example 1 returns `[3,4,4,3,4]`; example 2 returns `[0,0,0]`.
- **Targeted edge cases:** PASS for `k=1`, `n=k`, `n=k+1`, all identical words, prefix chains, duplicate occurrences, and cases where the best block crosses the removed position.
- **Current approach:** For `k=1`, answer after removing an index is the maximum word length among remaining words, computed from the largest and second-largest lengths and the count of the largest. For `k>=2`, use lexicographic sorted occurrence order.
- **Sorted window property:** The maximum LCP among any `k` strings is attained by `k` consecutive strings in sorted order; its value is the minimum adjacent LCP inside that block.
- **Effect of one removal:** In the sorted order with position `p` removed, every optimal `k`-block is either an original `k`-window avoiding `p`, or an original `(k+1)`-window containing `p` internally. Endpoint cases reduce to an avoiding `k`-window.
- **Global baseline:** The maximum value over all original `(k+1)`-windows is safe for every removal. If the window avoids `p`, one of its `k`-subwindows avoids `p` and has at least that value. If `p` is internal, removing `p` preserves the window's minimum LCP. If `p` is an endpoint, the remaining `k`-window has at least that value.
- **Avoiding windows:** For sorted position `p`, avoiding `k`-window starts are `<= p-k` or `>= p+1`. Prefix and suffix maxima over `k`-window values answer these in O(1).
- **Window computation:** `k`-window values are sliding minima of adjacent LCP with window size `k-1`. The baseline is the maximum sliding minimum of adjacent LCP with window size `k`.
- **Complexity:** Sorting is O(n log n) key comparisons. Adjacent LCP construction is O(total input length) because each adjacent LCP is bounded by the length of the right string. Sliding windows, prefix/suffix arrays, and final mapping are O(n). Memory is O(n).
- **Implementation details:** Sort indices with `key=words.__getitem__`; use deques for sliding minima. Important off-by-one checks: left query index is `pos - k`, right query index is `pos + 1`, and the `k`-window array length is `n - k + 1`. The trie fallback is unnecessary.
