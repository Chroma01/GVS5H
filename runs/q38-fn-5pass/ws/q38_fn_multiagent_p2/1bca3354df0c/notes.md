- **Core reduction:** Legal moves preserve bipartiteness. Inside one connected component, an edge can be added only between opposite color classes. Between two different components, any edge is legal and merges them after choosing a relative flip of one component. Terminal positions are connected complete bipartite graphs `K_{A,B}` with `A+B=N`. The number of moves is `A*B - M`, so the winner is determined by the parity of the final edge count minus the initial `M`.
- **Fixed parity cases:** If `N` is odd, then `A` and `B` have opposite parity in every terminal graph, so `A*B` is always even. Therefore all maximal plays have parity `M mod 2`, and Aoki wins iff `M` is odd. If `N` is even and there are no odd-sized connected components (`k=0`), each component's contribution to the final side parity is fixed. The terminal edge-count parity equals `sum(a_i*b_i) mod 2`, so the move parity equals `sum(a_i*b_i - m_i) mod 2`. Aoki wins iff this value is odd.
- **Odd-component count:** For even `N`, the number `k` of odd-sized components is even. Odd-sized components can be flipped to change the final side parity; even-sized components cannot. If `k=2`, the first player can merge the two odd components and choose the relative flip so that the resulting `k=0` position has even missing-edge parity, which is losing for the next player. Hence Aoki always wins when `k=2`.
- **Case k>=4:** With the above classifications, positions with `k>=4` are losing exactly when `M` is even. An internal move toggles `M` and leaves `k>=4`. A cross-component move toggles `M` and either leaves `k>=4` or, if it merges two odd components, decreases `k` by 2. From `M` even, every move goes to `M` odd, or to `k=2`, which is winning for the next player. From `M` odd, if an internal move exists, taking it leaves `k>=4` and `M` even. If no internal move exists, all components are internally complete bipartite; `M` odd then implies at least one even component exists, and merging it with an odd component keeps `k>=4` and makes `M` even. Thus Aoki wins iff `M` is odd.
- **Component data:** For each connected component, iterative DFS/BFS gives color-class sizes `a,b` and internal edge count `m`. An isolated vertex has `a=1,b=0,m=0`. The component size is `a+b`. `odd_components` counts components with odd size. `missing_parity` accumulates `(a*b - m) & 1` over all components and is used only when `k=0`.
- **Implementation:** Read input. If `N` is odd, answer immediately from `M` parity without building the graph. Otherwise build adjacency lists and run iterative DFS to avoid recursion depth issues. Count directed edge visits and divide by 2 to get `m`. Apply the case distinction: `N` odd -> `M` odd; `k=0` -> `missing_parity` odd; `k=2` -> Aoki; otherwise -> `M` odd. Complexity is `O(N+M)` time and `O(N+M)` memory.
- **Validation:** The samples match. Small exhaustive reasoning for `N<=4` also matches: four isolated vertices (`k=4`, `M=0`) is Takahashi; one edge plus two isolated vertices (`k=2`) is Aoki; two disjoint edges (`k=0`, missing parity 0) is Takahashi; path `P4` (`k=0`, missing parity 1) is Aoki; star `K_{1,3}` (`k=0`, missing parity 0) is Takahashi.
