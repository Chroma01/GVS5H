- **Core model:** The t-th unit of product i has marginal cost `(2t - 1) * P_i`. Since each product's marginal costs are strictly increasing, the optimal purchase is the prefix of all marginal costs sorted globally.
- **Threshold check:** For a threshold x, product i contributes `k = ((x // P_i) + 1) // 2` units, with total cost `k^2 * P_i`. Summing these values gives the cost of all marginal costs <= x.
- **Binary search:** Find the smallest integer y such that the cost of all marginal costs <= y exceeds M. Then all marginal costs < y are affordable, and the remaining budget can be spent only on units whose marginal cost is exactly y.
- **Safe upper bound:** Let `p_min = min(P)`. Choose `a = isqrt(M // p_min) + 1`, so `a^2 * p_min > M`. Then `high = (2a - 1) * p_min` is a marginal cost of the cheapest product and guarantees `f(high) > M`. This keeps the search range around at most about `9e13`.
- **Final computation:** For each product with `P_i <= y`, let `q = y // P_i` and `k_y = (q + 1) // 2`. The count increases by one at y exactly when `q` is odd and `q * P_i == y`. In that case `k_less = k_y - 1` and one boundary unit exists; otherwise `k_less = k_y`. Accumulate `less_count`, `less_cost`, and `equal_count`.
- **Answer:** `less_count + min(equal_count, (M - less_cost) // y)`. The min is safe even though mathematically the quotient should not exceed `equal_count` when y is the first too-expensive threshold.
- **Complexity:** Sorting is `O(N log N)`. Binary search uses at most about 47 threshold checks, each `O(N)` in the worst case, plus one final `O(N)` pass. Memory is `O(N)`.
- **Numerical safety:** The tight upper bound keeps individual `k^2 * P_i` values near or only slightly above `1e18`, so direct multiplication is fast and avoids repeated division-based overflow checks. The final `less_cost` is guaranteed to be at most M by the binary-search invariant.
- **Edge cases:** Handles answer 0 when `M < min(P)`, ties at the boundary marginal cost, products with `P_i > y`, duplicate prices, and the case where y is the first marginal cost of some product.
- **Approaches considered but not used:** Floating-point Lagrangian water-filling, batched priority-queue greedy, and binary search on total units were considered; the exact integer marginal-cost threshold method is simpler and avoids precision or batch-count pitfalls.
