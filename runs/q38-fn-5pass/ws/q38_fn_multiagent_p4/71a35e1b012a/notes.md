- **Core model:** Each chosen operation adds either interval `[L,R]` (type 1) or its complement `[1,L-1] ∪ [R+1,N]` (type 2). Operation order is irrelevant; we need the minimum number of chosen sets whose union is all positions.
- **Cost 1:** Possible exactly when some interval is `[1,N]`, used as type 1. Type 2 can never cover all positions because every interval is nonempty.
- **Cost 2 cases:** With two operations, the only type pairs are `(1,1)`, `(2,2)`, and `(1,2)`. `(1,1)` covers all iff one interval starts at 1, the other ends at N, and they overlap or touch. `(2,2)` covers all iff the two intervals are disjoint. `(1,2)` covers all iff the type-2 interval is contained in the type-1 interval.
- **Containment detection:** Sort intervals by `(L, -R, original_index)`. While scanning, maintain `prefix_max`, the running maximum of `R` over the sorted prefix. For a current interval with right endpoint `R`, if `prefix_max[-1] >= R`, then `bisect_left(prefix_max, R)` gives the earliest sorted position whose `R` is at least the current `R`. That interval has the smallest `L` (and largest `R` among ties) among all previous containers, so it is assigned type 1 and the current interval type 2. This is the requested change; in sample 1 it chooses `[1,4]` rather than `[2,5]`, producing `2 0 1 0`.
- **Disjoint detection:** After no containment is found, sorted `R` values are strictly increasing. Maintain the minimum previous `R`. If it is strictly less than the current `L`, those two intervals are disjoint; output both as type 2.
- **Prefix-suffix detection:** Track the maximum `R` among intervals with `L=1` and the minimum `L` among intervals with `R=N`. If they are distinct and `maxR >= minL - 1`, both as type 1 cover all positions. The `-1` handles integer touching, e.g. `[1,2]` and `[3,N]`.
- **Fallback cost 3:** If no cost 1 or 2 exists, there is no containment and no disjoint pair. After sorting, `L` and `R` are strictly increasing, and the first and last intervals intersect. Choose first and last as type 2 and the second interval as type 1. The only points not covered by the two complements are `first ∩ last = [L_last, R_first]`, and the second interval contains this intersection because `L_second <= L_last` and `R_second >= R_first`.
- **Impossibility:** If neither cost 1 nor cost 2 exists and `M < 3`, no solution exists because at most `M` operations can be used.
- **Sample checks:** Sample 1 containment gives `2 0 1 0`; sample 2 full interval gives `0 1 0 0`; sample 3 prefix-suffix gives `1 1`; sample 4 fails all checks and outputs `-1`.
- **Implementation details:** Store intervals as `(L, -R, original_index)` so normal tuple sorting gives `L` ascending and `R` descending. Keep original indices for output. Use a list of `'0'` strings for the operation array and join it once.
- **Complexity:** Sorting dominates: time `O(M log M)`, memory `O(M)`.
