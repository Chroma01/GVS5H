- **Model:** A valid complete coloring is a top-left justified monotone shape. If a cell is black, every cell weakly above and weakly to its left must also be black. If a cell is white, every cell weakly below and weakly to its right must also be white. Equivalently, row black-prefix lengths form a nonincreasing sequence as rows go downward.
- **Feasibility criterion:** The partial coloring is extendable iff there is no already-colored white cell weakly northwest of an already-colored black cell. That is, no pair satisfies white_row <= black_row and white_col <= black_col. This condition is necessary because such a pair forces contradictory prefix requirements. It is sufficient: define row prefix length a_r as the minimum of (white_col - 1) over all white cells in rows <= r, defaulting to N. This sequence is nonincreasing, satisfies all white constraints, and satisfies all black constraints exactly when no forbidden white-black pair exists.
- **Sweep-line algorithm:** Sort all given cells by row ascending. Within the same row, process white cells before black cells. Maintain the minimum column among all white cells processed so far. For each black cell at column y, if y is at least that minimum, a white cell with row <= current row and column <= y exists, so the answer is No. Otherwise, after all cells, the answer is Yes.
- **Correctness of the sweep:** Processing rows in ascending order ensures the maintained minimum white column is exactly the minimum column among white cells with row <= current row. Processing whites before blacks in the same row also captures same-row conflicts where a white cell lies to the left of a black cell. A black cell conflicts iff its column is >= the minimum white column seen so far.
- **Complexity:** Sorting dominates the runtime: O(M log M). Memory is O(M). N can be up to 1e9 but is not used except for parsing, so the algorithm is independent of grid size.
- **Edge cases:** All-black or all-white inputs are always feasible. Same-row and same-column conflicts are handled by weak inequalities and white-before-black ordering. N=1 works. M can be 1. Coordinates are distinct, but the code would also handle equality safely.
- **Sample verdict:** Running the sweep logic on the provided samples yields Yes, No, Yes, No, matching the expected outputs. Sample 4 fails when the black cell at row 1814, column 712 is checked after the white cell at row 1789, column 211 has updated the minimum white column.
- **Implementation details:** Use sys.stdin.buffer.read().split() for fast parsing. Store each cell as (row, kind, column), where kind is 0 for white and 1 for black, so normal tuple sorting gives the required order. Use a large INF for the initial minimum white column and exit early on the first conflict.
