- **Process closure:** For a fixed starting slime, the remaining slimes absorbed by Takahashi always form a contiguous interval, and his size is the interval sum. Absorbing any adjacent strictly smaller slime only increases the sum and cannot make another previously possible absorption impossible. Therefore the maximum final size is the unique closure obtained by expanding until no adjacent slime is strictly smaller.
- **Stable intervals:** Call an interval stable if its sum is at most each existing outside neighbor; missing outside neighbors are infinite. The closure for a start is the minimal stable interval containing that start. Because all sizes are positive, stable intervals are laminar: two overlapping stable intervals must be nested.
- **Cartesian-tree mapping:** A non-singleton stable interval has sum strictly larger than every slime inside it, so both outside boundaries (if present) are strictly larger than all inside slimes. In a max Cartesian tree with tie broken by later index (build by popping while `A[stack[-1]] <= A[i]`), such an interval is exactly the subtree of its rightmost maximum. Thus all non-singleton stable intervals are represented as Cartesian subtrees.
- **Singleton stable intervals:** A singleton `[i, i]` is stable iff both existing neighbors are at least `A[i]`. These may not be Cartesian subtrees when equal neighbors are involved, so they are answered directly before propagation. A stable singleton inside a larger stable subtree must keep its singleton answer.
- **Algorithm:** Build the Cartesian tree iteratively. Preassign all singleton-stable answers. Compute subtree intervals, sums, and a stable flag bottom-up using actual outside boundaries, not merely the parent value. Traverse top-down carrying the sum of the deepest stable ancestor seen so far. At each node, if its subtree is stable, update the carried sum; if the node's answer is not preassigned, assign the carried sum; pass the carried sum to children. The whole array is always stable, so every index is assigned.
- **Implementation details:** Use iterative stacks everywhere to avoid recursion depth issues. Use a preorder list and reverse it for postorder. Use a `bytearray` for stable flags. Use two parallel stacks for top-down DFS to carry current stable sums without storing a separate current array. Delete large arrays before output to reduce peak memory during string construction.
- **Pitfalls checked:** Equality blocks absorption, so stability uses `>=` for outside boundaries. Missing boundaries are treated as infinite. Tie-breaking must be consistent; later-index tie is used. Stable singleton intervals may be hidden inside larger stable subtrees. A stable subtree root can itself be singleton-stable while its descendants need the subtree sum. Outside boundaries equal to the interval sum block inside starts but may be absorbable by outside starts; this asymmetry is handled by per-index minimal stable intervals.
- **Complexity:** Cartesian construction, bottom-up computation, and top-down propagation are all O(N). Memory is O(N) for the tree, subtree data, answers, and traversal stacks.
