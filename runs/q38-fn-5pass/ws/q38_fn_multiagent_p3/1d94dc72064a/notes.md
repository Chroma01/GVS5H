- **State reduction:** After an index is first chosen, all its remaining tokens become indistinguishable “pass” tokens. A position can be described by the multiset of unclaimed original values and the number `p` of available pass tokens. Claiming an odd `A_i` adds an even number of pass tokens; claiming an even `A_i` adds an odd positive number.
- **Small cases:** For `N=1`, Fennec claims the only index and wins. For `N=2`, Snuke always claims the last remaining index and wins. For `N=3`, Fennec wins iff at least one `A_i` is odd; if all are even, Snuke wins.
- **Core invariant for `N >= 4`:** For any state with at least four unclaimed indices, the next player wins iff `(number of unclaimed odd values + p)` is odd. Initially `p=0`, so Fennec wins exactly when the total number of odd `A_i` is odd.
- **Why the invariant holds:** For `N=4`, direct checking from the `N=3` outcome table establishes the invariant. For larger `N`, assume it holds for all states with one fewer unclaimed index. If `p=0`, a winning position with odd `a+p` has an odd unclaimed value, and claiming it makes the target parity even; a losing position has all claim moves to odd-parity targets. If `p>0`, a winning position can pass to `p-1`, flipping parity to a losing target; a losing position has pass and all claim moves to winning targets.
- **Magnitude independence:** The proof uses only parity of `p` and parity of unclaimed values. An odd value may add zero or positive even tokens, but the invariant depends only on parity, so exact magnitudes do not matter. Even values always add positive odd tokens, also only parity matters.
- **Implementation:** Count odd values `odd`. Branches: `N=1` Fennec; `N=2` Snuke; `N=3` Fennec iff `odd > 0`; `N >= 4` Fennec iff `odd` is odd. Time `O(N)`, memory `O(1)` besides input.
- **Validation:** The program includes an optional exact brute-force DP in `validate()`, runnable with `--validate`. It checks the samples and exhaustive small cases for `N <= 4` with values `1..4`, plus `N=5` with values `1..2`, confirming no dependence on exact magnitudes. It is not run by default to keep judge execution minimal.
- **Edge cases:** All `A_i=1` reduces to exactly `N` forced claim moves, matching the formula. Large values up to `1e9` are handled by parity only. Input may be split across lines; reading all tokens handles this.
