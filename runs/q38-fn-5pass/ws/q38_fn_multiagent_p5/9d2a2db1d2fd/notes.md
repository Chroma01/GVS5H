- **Core reduction:** For two cells, let B be the highest floor at which they are connected using only cells of height at least that floor. If start/target floors are Y,Z, the minimum stair count is `abs(Y-Z)` when `min(Y,Z) <= B`, otherwise `Y+Z-2*B`. The journey can be done by moving to a single floor `t <= B`, crossing horizontally, then moving to the target floor; any path must visit some floor at most B, so this is optimal.
- **Bottleneck as Kruskal tree:** Treat adjacent cells as edges with capacity `min(F_u, F_v)`. The maximum bottleneck between two cells is the LCA value in a maximum-Kruskal reconstruction tree. For the same cell, the leaf value `F_cell` is the bottleneck.
- **Tree construction without storing edges:** Sort cells by height descending and activate them. When a cell of height h activates, every already active neighbor has height at least h, so each edge to it has capacity h. Union active neighbor components and create a new reconstruction node with value h. This is equivalent to processing all grid edges in non-increasing capacity order. Equal heights can be processed sequentially; all merges at that height get the same value.
- **DSU design:** Use DSU over original cell indices with union by size for speed. `root_node[rep]` stores the current reconstruction-tree root for that component. On a successful merge, create node `new`, set `parent[ru]=parent[rv]=new`, `val[new]=h`, and set `root_node[new_rep]=new`. Node ids are assigned increasingly, so every parent id is larger than its child id.
- **Depth and LCA:** Because parent ids are larger than child ids, depths can be computed by scanning nodes from `M-2` down to `0`: `depth[i] = depth[parent[i]] + 1`. Binary lifting is built as lists of lists. `LOG` is based on `max_depth.bit_length()` rather than `M.bit_length()` to save a level when possible. LCA is standard binary lifting.
- **Answering queries:** Convert grid coordinates to leaf indices. If the two leaves are equal, use the leaf value directly; otherwise use the LCA value as B and apply the formula.
- **Input/memory choices:** Input is parsed into a compact `array('i')`. Temporary structures (`order`, DSU, sizes, active, F) are deleted before building the lifting table. The lifting table uses Python lists for speed; higher levels mostly reference existing integer objects, keeping memory reasonable. No recursion is used.
- **Edge cases:** `N=1` works with a single leaf and no merges. `W=1` or `H=1` boundary checks are handled. Same-cell queries with different floors are handled by the leaf bottleneck.
- **Complexity:** Sorting cells is `O(HW log HW)`. Activation/DSU is near linear. LCA preprocessing is `O(HW log HW)` time and memory. Each query is `O(log HW)`.
