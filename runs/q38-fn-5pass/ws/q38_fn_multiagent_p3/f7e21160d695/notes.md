- **Core observation:** The minimax distance f(x, y) is the smallest edge weight at which x and y become connected in Kruskal order. Sorting edges and merging components therefore builds the exact hierarchy needed for the assignment problem.
- **Greedy count:** Each union-find component stores the number of A-points and B-points inside it. When two components merge at weight w, the number of pairs that can first be matched at this weight is min(a1+a2, b1+b2) - min(a1, b1) - min(a2, b2). Add this count multiplied by w.
- **Why greedy works:** Any pair matched inside a child component has cost at most the child's merge weight, which is no larger than the current merge weight. Therefore it is always optimal to match as many opposite-color points as possible inside children before matching across the current boundary.
- **Equal weights:** Processing equal-weight edges one by one is safe. The added match count can also be written using surplus s = a - b as (|s1| + |s2| - |s1+s2|) / 2, which telescopes over all merges at the same weight. Thus explicit grouping by weight is unnecessary.
- **Duplicates and edge cases:** Repeated vertices in A or B are handled by counts. The guarantee that no vertex appears in both A and B is not required by the implementation; if it did, those matches would be treated as cost zero through the min terms.
- **Complexity and implementation:** Time is O(M log M + N alpha(N)) and memory is O(N + M). The implementation uses 0-indexing, edges sorted as (w, u, v), union by size, path-halving find, and bulk input parsing via sys.stdin.buffer.read().split().
