- **Validation:** The current greedy predicate passes the provided samples and targeted edge cases: `m < n`, `n = 2`, `x = 0`, tight move budgets where only one of the final two end positions fits, and large `m`. No counterexample was found after formalizing the end-position and fixed-end greedy arguments.
- **Candidate needs:** For a candidate minimum score `x`, index `i` needs `need[i] = ceil(x / points[i])` visits. Feasibility is monotone in `x`, so binary search is valid. If any `need[i] > m`, feasibility is immediately false because each visit consumes one move.
- **Right-crossing model:** Let `t_i` be the number of moves from `i` to `i + 1`. If the walk ends at `k`, edge `i` has net right crossing `1` when `i < k`, otherwise `0`. Visits can be written in terms of `t`: `v_0 = 1 + t_0` if `k = 0`, else `t_0`; internal `v_i = t_{i-1} + t_i - 1` if `i < k`, else `t_{i-1} + t_i`; last `v_{n-1} = t_{n-2}`. Total moves are `1 + 2 * sum(t_i) - k`. For `x > 0`, all `t_i >= 1`.
- **Optimal end is among the last two:** Moving the end one step right tightens exactly one visit constraint (or the `v_0` lower bound when moving from `0` to `1`) by `1`, so the minimum possible `sum(t_i)` can increase by at most `1`, while the base term `-k` decreases by `1`. Moving two steps right tightens two constraints but can be simulated by increasing one shared `t` variable by at most `1`, giving `M_{k+2} <= M_k`. Therefore any end `k <= n - 3` can be shifted right by two without increasing moves, so an optimum exists at `k = n - 2` or `k = n - 1`.
- **Fixed-end greedy:** For a fixed end among the last two, the constraints form a chain `t_{i-1} + t_i >= b_i` with lower bounds. If some `t_i` is larger than the minimum forced by `t_{i-1}` and its lower bound, lowering it and, only if necessary, raising `t_{i+1}` by one does not increase the total sum. Repeating left to right yields the forward recurrence implemented by the sweep. The final last-index lower bound is handled by taking the maximum at the end.
- **Move counting:** The sweep maintains `cur = t_{i-1}` visits already at index `i` from the left, and `nxt = t_i` visits already at `i + 1` from bounces at `i`. A bounce `i <-> i + 1` costs `2` and increases both relevant visit counts. Moving right costs `1` and finalizes `t_i` when ending to the right. At `n - 2`, if bounces already satisfy the last index, stopping at `n - 2` is optimal; otherwise moving to `n - 1` is never worse than bouncing from `n - 2` to satisfy the last index. The `n = 2` case naturally covers ending at `0` or `1`.
- **Edge cases:** `x = 0` is always feasible. For `x > 0`, `m < n` is impossible because every index needs at least one visit. Early exits when `moves > m` keep the check linear and avoid unnecessary work. The binary-search upper bound `max(points) * m + 1` is safe because no index can be visited more than `m` times.
- **Complexity:** Each feasibility check is `O(n)` time and `O(1)` extra memory. Binary search performs about `log2(max(points) * m) <= 50` iterations, so total time is `O(n log(max(points) * m))`.
