- **Sample tests:** The current implementation returns `20` for `nums = [1, 2, 3], k = 2` and `-6` for `nums = [1, -3, 1], k = 2`, matching both provided examples.
- **Edge tests:** Checked `k = 1`, which correctly returns `2 * sum(nums)` because only singleton subarrays are counted. Checked `k = n`, which reduces to the standard unbounded subarray minimum/maximum contribution formula. Also checked increasing, decreasing, all-equal, duplicate-heavy, and negative arrays against brute-force reasoning.
- **Core idea:** The required answer is the sum of all subarray minimums plus the sum of all subarray maximums, restricted to subarrays of length at most `k`. Compute these two sums independently by contribution.
- **Tie-breaking:** To avoid double-counting equal values, assign each subarray minimum to its leftmost minimum occurrence, and each subarray maximum to its leftmost maximum occurrence. This makes the contribution of each element disjoint for each role.
- **Minimum boundaries:** For element `i` to be the leftmost minimum of a subarray, the subarray cannot extend left past the nearest previous element `<= nums[i]`, and cannot extend right past the nearest next element `< nums[i]`. Equal values on the right are allowed because `i` remains the leftmost minimum.
- **Maximum boundaries:** For element `i` to be the leftmost maximum, the subarray cannot extend left past the nearest previous element `>= nums[i]`, and cannot extend right past the nearest next element `> nums[i]`. Equal values on the right are allowed because `i` remains the leftmost maximum.
- **Monotonic stacks:** Previous boundaries are computed left-to-right. For minima, pop while stack top is `>` current, leaving nearest `<=`. For maxima, pop while stack top is `<` current, leaving nearest `>=`. Next boundaries are computed right-to-left. For minima, pop while stack top is `>=` current, leaving nearest `<`. For maxima, pop while stack top is `<=` current, leaving nearest `>`.
- **Bounded extension count:** For a fixed element, let `a` be the number of valid left extensions and `b` the number of valid right extensions. If `p` is the number of elements taken to the left including the element, and `q` is the number taken to the right including the element, then `1 <= p <= a`, `1 <= q <= b`, and subarray length is `p + q - 1`. We count pairs with `p + q - 1 <= k` in O(1).
- **Counting formula:** Let `m = min(a, k)`. For `p <= k - b + 1`, all `b` right choices are valid. For larger `p`, the right choices are capped by `k - p + 1`. The remaining sum is an arithmetic series. This handles cases where `k` is smaller than, equal to, or larger than the available span.
- **Complexity:** Four monotonic-stack passes plus two contribution passes, so O(n) time and O(n) auxiliary space. This is well within `n <= 80000`.
- **Validation result:** No implementation changes were needed after sample and edge-case review.
