- **Problem model:** Walk starts at index -1 (first move forced to 0), stays in [0,n-1] afterwards, uses at most m moves; each landing on i adds points[i]. For target T, index i needs need[i]=ceil(T/points[i]) landings. T=0 trivially feasible; for T>=1 all need[i]>=1 so the walk must reach n-1.
- **Walk parametrisation:** Fix final index f. Edge j (0..n-2, between j and j+1) crossed t_j = d_j + 2a_j times, d_j=[j<f]; the initial edge (-1,0) is crossed once. Reaching n-1 forces a_j>=1 for j>=f, else a_j>=0. Visit counts: c_0=1+a_0; c_i=a_{i-1}+a_i+[i<=f] (1<=i<=n-2); c_{n-1}=a_{n-2}+[f=n-1]. Total moves = 1+f+2*sum(a_j). Every such integer (a,f) is realisable (Euler trail; exactly -1 and f have odd degree; all edges positive so connected).
- **Feasibility LP:** For fixed f minimise sum(a_j) with c_i>=need[i], a_j>=lb_j=[j>=f]. Substituting a_j=lb_j+x_j (x>=0) yields a path of constraints c_0..c_{n-1}: endpoint constraints are single-variable lower bounds, interior c_i are adjacent-sum bounds on x_{i-1}+x_i. The LP is totally unimodular (consecutive-ones), and its optimum equals the maximum-weight independent set on the constraint path (consecutive constraints conflict). min sum a = (n-1-f) + MWIS, giving Cost(f)=base-f+2*W(f), base=2n-1.
- **MWIS weights (verified by direct derivation):** node i, 0<=i<=n-2: p_i=max(0,need[i]-1) if i<f else q_i=max(0,need[i]-2); node n-1: r=max(0,need[n-1]-1). (For f=0 node 0 uses q_0.) Checked against hand-computed constraints, e.g. [1,1,1],T=2,f=2 correctly gives W=2, cost 7>5.
- **O(n) over all f:** W(f) is a prefix/suffix split. Prefix DP PN/PS (weights p) plus an on-the-fly right-to-left suffix DP SN/SS (weights q,r). Combine W(f)=max(PN[f]+max(SN[f],SS[f]), PS[f]+SN[f]) for f>=1; W(0)=max(SN,SS). Special-case f=n-1 done before the loop (SA=0,SS=r). Cost is NOT unimodal (diff alternates +-1) so ternary search is invalid; scan all f and take the min.
- **Answer:** Binary search largest T in [0, max(points)*m]. maxP*m is a valid inclusive upper bound (a single index is visited <= m times, adding <= maxP each). feasible(0) may return False when n>m (the model forces reaching n-1), which is harmless: binary search returns 0 in that case, the correct answer since index n-1 stays 0.
- **Complexity:** O(n) per feasibility check, O(log(maxP*m)) checks => O(n log(maxP*m)). n=5e4, ~50 iterations => ~7.5e6 loop bodies, comfortably fast in Python.
- **Pitfalls avoided:** first move from -1 matters (c_0=1+...); mandatory a_j>=1 for j>=f (reaching n-1) — earlier naive models without it underestimate cost; final index is free (min over f); T=0 / n>m handled by returning 0.
- **Validation — examples:** [2,4],m=3 -> 4; [1,2,3],m=5 -> 2 (both match expected). Spot checks reasoned by hand: [1,1,1],m=5 -> 1; [3,1,2],m=4 -> 2; [2,2,2],m=7 -> 4; [2,4],m=3 boundary T=5 correctly infeasible.
- **Validation — hardening fuzz:** Re-ran brute-force DFS cross-check with wider ranges (n=2..6, m=1..12, points 1..8) over multiple random seeds plus the original 4000-case run (n=2..5, m=1..10, points 1..5): zero mismatches -> PASS. Brute force enumerates every legal move sequence (branching 2) and tracks the best min gameScore; it is the gold reference.
- **Validation — performance:** Worst-case input n=50000, m=1e9, points all 1e6 (hi=1e15, ~50 binary-search steps) runs in roughly 1-2s, well within typical limits. Values use Python big ints, so need up to ~1e15 and W up to ~5e19 never overflow.
