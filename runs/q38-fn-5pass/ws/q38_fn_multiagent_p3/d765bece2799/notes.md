- **Test verdict:** The current solution passes the provided samples and the requested edge cases. No failing input/output was found, and no code changes were required.
- **Sample checks:** `nums = [1, 2, 3], k = 2` returns `20`; `nums = [1, -3, 1], k = 2` returns `-6`.
- **Edge checks:** `k = 1` counts only singletons and returns `2 * sum(nums)`; `k = n` counts all subarrays; duplicate and all-equal arrays are counted exactly once per extremum by rightmost tie-breaking; all-negative arrays preserve signed contributions; single-element arrays return `2 * nums[0]`.
- **Implemented approach:** Contribution counting with monotonic stacks. For every index, count how many valid subarrays of length at most `k` select it as the minimum, then as the maximum, multiply by `nums[i]`, and add both contributions.
- **Tie-breaking:** For minima, use previous strictly less and next less-or-equal. This assigns each subarray to its rightmost minimum. For maxima, use previous strictly greater and next greater-or-equal. This assigns each subarray to its rightmost maximum. The two tie-breakings are independent and each guarantees exactly one selected index per subarray for that extremum.
- **Boundary computation:** Previous strict boundaries are computed left-to-right. For minima, pop while stack top is `>= current`; for maxima, pop while stack top is `<= current`. Next non-strict boundaries are computed right-to-left. For minima, pop while stack top is `> current`; for maxima, pop while stack top is `< current`. The remaining stack top is the nearest blocking index, or `-1`/`n` if none exists.
- **Bounded length count:** For an index `i`, let `a = i - prev` be the number of possible left endpoints and `b = next - i` be the number of possible right endpoints. If `x = i - left` and `y = right - i`, then `x` and `y` are nonnegative, `x < a`, `y < b`, and subarray length is `x + y + 1`, so we need `x + y <= k - 1`.
- **O(1) counting formula:** Let `m = k - 1` and `tri(t) = (t + 1)(t + 2) / 2` for `t >= 0`, otherwise `0`. The number of nonnegative pairs with `x + y <= m` is `tri(m)`. Subtract pairs with `x >= a` as `tri(m - a)`, subtract pairs with `y >= b` as `tri(m - b)`, and add back pairs with both violations as `tri(m - a - b)`. This handles all edge cases, including `k = 1` and cases where the length bound is not restrictive.
- **Complexity:** Four monotonic-stack passes and two contribution passes give `O(n)` time. The boundary arrays and stacks use `O(n)` extra space. With `n <= 80000`, this is comfortably within limits.
- **Superseded alternatives:** Online suffix aggregates, divide and conquer, Cartesian trees, and DSU sorting were considered but are more complex than necessary once the bounded contribution count is solved.
