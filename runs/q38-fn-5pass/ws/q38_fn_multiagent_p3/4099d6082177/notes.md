- **Interpretation:** The matrix has K vertices per path, so K is the vertex count of each path, not the number of edges. For K=1, every single vertex is already a valid path, so the answer is always Yes.
- **State definition:** Root the tree at vertex 1. For each vertex v, `rem[v] = 0` means the subtree of v can be completely decomposed into valid K-vertex paths. Otherwise `rem[v]` is the number of vertices, between 1 and K-1, in the unique unfinished path segment that contains v and must be extended through the edge to v's parent.
- **Why the state is unique:** A subtree has only one edge to the outside, namely the edge to its parent. In any valid global decomposition, if the subtree is not fully decomposed, exactly one path crosses that edge, and its intersection with the subtree is a path segment containing the subtree root. Counting vertices shows that `subtree_size - rem[v]` must be divisible by K, so a nonzero `rem[v]` is forced by `subtree_size mod K`. Therefore a subtree cannot have both a closed state and an open state, nor two different open lengths.
- **Forced local transitions:** Every child with positive `rem` must attach its unfinished segment to v, because that segment uses the edge to v. Since v belongs to only one path, at most two such child segments can meet at v.
- **Transition cases:** If no child segment is open, v starts a new upward segment of length 1. If one child segment of length L is open, the segment becomes length L+1 at v; it closes if L+1=K, is passed upward if L+1<K, and is impossible if L+1>K. If two child segments of lengths A and B are open, they must be joined through v and cannot use the parent edge, so validity requires A+B+1=K. More than two open child segments is impossible.
- **Root condition:** The root has no parent edge, so the whole tree is valid exactly when `rem[root] == 0`. The same transition gives `rem[root] = 1` when no child segment is open, correctly rejecting K>1.
- **Implementation details:** Read all integers first. Handle K=1 before building adjacency. Build an adjacency list for M=N*K vertices. Use an iterative stack DFS to compute parent and preorder, avoiding recursion depth issues on path-like trees. Process vertices in reversed preorder. For each vertex, scan neighbors excluding the parent, count positive child remainders, and sum their lengths. Stop early if more than two open children or an invalid length sum is found.
- **Complexity:** The algorithm visits each edge a constant number of times, so it runs in O(NK) time and uses O(NK) memory, within the limit NK <= 2e5.
- **Pitfalls handled:** Use vertex counts rather than edge counts; do not try to open a closed child subtree, which is impossible by the subtree-size modulo argument; two open child segments with total length less than K cannot be extended upward because v would already have degree 2 in that path; iterative traversal is required for large trees; K=1 must be special-cased to avoid a false negative at the root.
- **Samples:** Sample 1 produces Yes. Sample 2 produces No because vertex 3 receives two open length-1 child segments for K=2, and 1+1+1 != 2.
