- **Core reduction:** the answer for index i depends only on the value x = A_i; it is the largest divisor d of x such that cnt[d] >= K, where cnt[d] = number of elements of A divisible by d (with multiplicity).
- **Proof:** any K-subset containing A_i with gcd G satisfies G | A_i and every member is a multiple of G, so cnt[G] >= K (upper bound). Conversely if d | A_i and cnt[d] >= K, take A_i plus K-1 other multiples of d; their gcd is a multiple of d, hence >= d (lower bound). So max feasible divisor = max achievable gcd.
- **cnt computation:** for d > M//2 (M = max A) the only multiple of d in [1,M] is d itself, so cnt[d] = freq[d]. For 2 <= d <= M//2 use `sum(freq[d::d])` (C-level slice sum; total ~ M ln M ~ 1.3e7 reads). d = 1 is never needed (always good, cnt = N >= K).
- **Duplicates trap:** cnt is NOT bounded by M//d because freq counts duplicates. A=[8,8], K=2 gives cnt[8]=2 though M//8=1. So do NOT add an M//K cutoff, and keep the freq branch for x > M//2 (duplicates live there).
- **Answer DP (prime pushes):** initialize f = [1]*(M+1) (1 is always good). Iterate x increasing: if good(x) set f[x] = x; then if x <= M//2 and f[x] > 1, push f[x] to p*x for every prime p <= M//x (take max). Completeness: any proper good divisor d of x divides x/p for some prime p | x (p a prime factor of x/d), and f[x/p] >= d by induction, so the push reaches it. Order is safe because x/p < x is already final.
- **Order/boundary safety:** a push always originates at z = x/p <= x/2 <= M//2, so every needed push is performed even though pushes from z > M//2 are skipped (those have no multiple <= M). x = M//2 is included in the slice-sum branch (its multiples are M//2 and possibly M).
- **Cost:** push iterations = sum over primes p of floor(M/p) ~ M ln ln M ~ 2.9e6; slice sums ~ 1.3e7 C-level. Faster than a descending-assignment sieve (~1.4e7 Python iterations). Skipping pushes when f[x] == 1 saves work for large K.
- **Special cases (short-circuited before sieving):** K = 1 -> each answer is A_i; K = N -> answer is gcd of the whole array, identical for every index (printed via string repeat).
- **Edge cases:** M = 1 -> all values 1, main loop empty, output 1. Values x > M//2 never push. M = 1 sieve length 2 handled (`sieve[0]=sieve[1]=0`).
- **Sieve:** `bytearray([1])*(M+1)`, indices 0 and 1 zeroed, `sieve[st::i] = bytes((M-st)//i+1)` for st=i*i, primes via list comprehension.
- **I/O/memory:** `sys.stdin.buffer.read().split()` then an iterator `map(int, it)` into `array('I')` (avoids a big intermediate slice); output in 16384-line chunks. Complexity O(M log M) counting + O(M ln ln M) DP + O(N) I/O; memory O(M+N), M <= 1e6.
- **Verification (manual; no live execution tool in this step):** traced sample 1 (3 4 6 7 12, K=2 -> 3 4 6 1 6), sample 2 (6 10 15, K=3 -> all 1), and hand brute force: A=[4,4,6] K=2 -> [4,4,2]; A=[6,10,15,21] K=2 -> [3,5,5,3] (full DP trace matched); A=[8,8,3] K=2 -> [8,8,1]; A=[2,3,4,6,8] K=3 -> [2,1,2,2,2]. All matched.
- **Performance expectation:** worst case N=1.2e6, values spanning 1..1e6, K=2 ~ 3-4s CPython (counting ~0.6s, DP ~1-2s, output ~0.3s); fits typical large-N limits and improves further under PyPy.
