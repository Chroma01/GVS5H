- **Problem model:** Cardinality-limited weighted interval scheduling. Choose at most 4 non-overlapping intervals maximizing total weight, then return the lexicographically smallest sorted list of original indices achieving that maximum.
- **Compatibility:** Sharing an endpoint counts as overlap. Sort intervals by right endpoint; `p[k] = bisect_left(rights, l_k)` gives the count of intervals with `r < l_k`, which are exactly k's compatible predecessors (the sorted prefix). Strict inequality excludes `r == l_k` even if that interval sorts earlier.
- **DP state:** `dp[j][i]` = (max weight, lex-smallest sorted original-index tuple) using exactly `j` intervals among the first `i` sorted intervals; `j` in 0..4, infeasible uses weight `-1`. `dp[0][i] = (0, ())`.
- **Transition:** with `k=i-1`: `dp[j][i] = max(skip dp[j][i-1], take dp[j-1][p[k]] + w_k)`. On take, insert original index `x` into the sorted tuple; compare tuples only when weights tie.
- **Insertion monotonicity (proved):** For equal-length distinct-element sorted tuples `A < B` and a fresh value `x`, `sorted(A+[x]) < sorted(B+[x])`. Case split on `x` vs `A[d]`,`B[d]` (first differing index `d`: `A[d]<B[d]`): if `x > B[d]`, position `d` already differs; if `x < A[d]`, `x` lands in the common prefix and the difference reappears at `d+1`; if `A[d] < x < B[d]`, then with `A[d-1]=B[d-1]<x`, `B` gets `x` at `d` while `A` keeps `A[d]`. Hence keeping only the lex-smallest max-weight tuple per state is sound.
- **Freshness of x:** `p[k] <= k`, so the prefix `dp[j-1][p[k]]` never contains interval `x`; original indices are distinct. Safe to insert.
- **Final choice:** scan `dp[j][n]` for `j=0..4`; keep max weight then lex-smallest tuple. Python tuple comparison implements the problem's lex rule including the shorter-array-prefix rule, so ties across different cardinalities are handled.
- **Complexity:** `O(n log n)` sort + `O(n)` DP (5 layers, tuple length <= 4), `O(n)` memory. Fits `n <= 5e4`, coordinates up to `1e9` (only comparisons, no coordinate indexing).
- **Fuzzing result:** 20000 random cases (`n<=12`, small coordinate ranges 2..8 to force shared endpoints, weights from `{1,1,1,2,3}` to force ties) plus targeted edge cases (n<4, all-equal weights, duplicates, boundary-sharing, heavy-vs-many-light equal-weight-different-cardinality ties) all matched the brute-force oracle. No mismatch, no counterexample. Oracle enumerates all subsets of size <=4, checks pairwise disjointness by sorting on left and requiring consecutive `prev_r < cur_l` (strict), then picks max weight / lex-min tuple.
- **Edge cases verified:** Sample 1 -> `[2,3]` (w=8); Sample 2 -> `[1,3,5,6]` (w=21); duplicate `[1,2,3]` intervals can never be co-chosen (correctly overlapping); heavy interval can tie the sum of four lighter ones and the shorter list wins lex order.
- **Lex detail:** When one index list is a prefix of another with equal weight, the shorter list is smaller (problem statement + Python tuple semantics agree).
