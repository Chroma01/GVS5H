- **Sample tests:** pass on both provided examples; example 1 returns `[2, 3]`, example 2 returns `[1, 3, 5, 6]`. Additional edge cases checked: single interval, all overlapping, boundary-touching intervals, equal weights/indices, equal max score with different cardinalities, and empty input defensively.
- **Core approach:** exact-cardinality weighted interval scheduling for cardinalities 0 through 4. Sort intervals by end time, then start time, then original index, and run DP over sorted prefixes.
- **Compatibility rule:** intervals are non-overlapping only if one ends strictly before the other starts. For interval i, the compatible previous prefix length is the count of intervals with end < start_i, obtained with `bisect_left` on the sorted end array.
- **DP state:** `scores[c][i]` and `tuples[c][i]` represent the best score and lexicographically smallest sorted tuple of original indices when choosing exactly c intervals from the first i sorted intervals. Unreachable states use a large negative sentinel and `None`.
- **Recurrence:** for each interval, the best state either skips it, inheriting `dp[c][i-1]`, or takes it, combining `dp[c-1][p[i]]` with the current interval. The tuple is updated by inserting the current original index into the previous sorted tuple.
- **Tie-breaking:** compare by score first, then by sorted tuple lexicographically. Python tuple comparison matches the required lexicographic rule, including shorter arrays being smaller when one is a prefix of the other.
- **Why one tuple per state is safe:** for the same cardinality and score, a lexicographically smaller sorted tuple remains lexicographically smaller after inserting any same future index. Compatibility is handled by using prefix `p[i]`: a DP state is only used for future intervals whose start is after every interval in that prefix, so differences in last end inside the prefix do not affect future compatibility.
- **Why lower-score states are not needed:** if two prefix states have the same cardinality and both are compatible with a future interval, the higher-score state remains higher after adding that interval. If the higher-score state is not compatible, it is not present in the relevant prefix `p[i]`. Thus exact-cardinality max-score DP is sufficient.
- **Final selection:** the answer is the best among exact cardinalities 0 through 4 by score, then tuple lexicographic order. This correctly handles “at most 4” and equal-score solutions with different lengths.
- **Complexity:** sorting is O(n log n). DP has O(4n) states and constant-size tuple operations, so overall O(n log n) time. Memory is O(4n) for prefix DP arrays, acceptable for n = 5 * 10^4.
- **Edge cases covered:** single interval, all intervals overlapping, boundary-touching intervals, equal weights with different indices, equal maximum scores with different cardinalities, and empty input defensively.
- **Implementation details:** use 0-based original indices, store intervals as `(end, start, index, weight)`, use local `bisect_left`, descending cardinality loop, and create candidate tuples only when the candidate score is not worse than the current state.
