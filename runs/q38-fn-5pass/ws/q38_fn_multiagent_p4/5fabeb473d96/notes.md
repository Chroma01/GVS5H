- **Core reduction:** For a query `u < v`, edge `x` (`x >= 2`) contributes `A_x` exactly when exactly one of `u, v` lies in the subtree rooted at `x`. If `D_x(y)` is the indicator that `x` is an ancestor of `y` (including `x` itself), the coefficient is `c_x = P(D_x(u) xor D_x(v))`. The required sum over all parent sequences is `(N-1)! * sum_x A_x c_x` modulo `MOD`.
- **Marginal ancestry probability:** In a random recursive tree, for `x < y`, `P(x ancestor y) = 1/x`. This follows by induction on `y`: the parent of `y` is uniform among `1..y-1`, and the average of the ancestor probabilities below `y` remains `1/x`. Also `P(x ancestor x)=1`, and `P(x ancestor y)=0` for `x > y`.
- **Joint ancestry probability:** For `x < u < v`, `P(x ancestor u and x ancestor v) = 2 / (x(x+1))`. One derivation fixes `x,u` and conditions on the parent of the larger endpoint. If `f(y)=P(x ancestor u and x ancestor y)`, then for `y>u`, `f(y) = (1/(y-1)) * sum_{k=x}^{y-1} f(k)`, with `f(x)=f(u)=1/x` and the induction hypothesis for intermediate `k`. The sum telescopes to `2y/(x(x+1))`, giving the constant value `2/(x(x+1))`.
- **Coefficient cases:** For `x < u`, `c_x = 1/x + 1/x - 2 * 2/(x(x+1)) = 2(x-1)/(x(x+1))`. For `x = u`, `c_x = 1 + 1/u - 2/u = (u-1)/u`. For `u < x < v`, `c_x = 1/x`. For `x = v`, `c_x = 1`. For `x > v`, `c_x = 0`. The non-edge `x=1` gives coefficient `0` in the first formula.
- **Brute-force verification:** The code includes a small verifier for `N <= 5`. It enumerates all `(N-1)!` parent sequences, computes exact edge-separation counts for every triple `(u,v,x)`, and cross-multiplies them against the four coefficient cases. It checks boundary cases including `u=1`, `x=u`, `x=v`, and `x<u`.
- **Closed-form query formula:** Let `A_1 = 0`, `S1[t] = sum_{x=2}^t A_x / x`, and `S2[t] = sum_{x=2}^t A_x * 2(x-1)/(x(x+1))`, with empty prefixes equal to `0`. For `u < v`, the expected distance is `S2[u-1] + A_u*(u-1)/u + S1[v-1] - S1[u] + A_v`. The answer is this value multiplied by `(N-1)!` modulo `MOD`.
- **Implementation details:** Precompute modular inverses up to `N+1` linearly, precompute `(N-1)!`, and build `S1` and `S2`. Each query is answered in `O(1)` using the formula above. All denominators are at most `N+1 < MOD`, so modular inverses exist. Complexity is `O(N+Q)` time and `O(N)` memory.
