- **Problem:** two length-N binary strings S, T and positive X, Y. Op A turns a window 0^X 1^Y into 1^Y 0^X; Op B is its inverse 1^Y 0^X -> 0^X 1^Y. Window length X+Y must fit (i from 1 to N-(X+Y)+1). Ask if S can reach T.
- **Key observation:** in Op A every selected 1 shifts left by exactly X and every selected 0 shifts right by exactly Y; Op B does the opposite. Order of the 1s among themselves and of the 0s among themselves is never changed. Hence each individual 1 changes position by a multiple of X and each 0 by a multiple of Y.
- **Invariants:** (count of 1s) plus the ordered list of 1-positions mod X, plus the ordered list of 0-positions mod Y. Order matters: compare the k-th 1 in S with the k-th 1 in T.
- **Sufficiency:** these invariants are also sufficient. Verified by exhaustive brute force: for each N up to 8 (and several larger spot checks), each admissible (X,Y), enumerate all 2^N strings, add edges for every applicable Op A/B, union-find the components, and compare each connected component with its invariant class. No counterexample found; every component equals exactly one invariant class, and distinct classes never merge.
- **Why the mod must be the full X / Y:** weaker checks give false positives. Near-miss: N=6, X=2, Y=4, class of one-positions residues (1,0,1,0). If zeros are keyed mod 2 you would wrongly merge 110011 (zeros at 3,4) with 001111/111100 (zeros at 1,2); keying zeros mod 4 separates them (residues (3,0) vs (1,2)), and 110011 is genuinely isolated. So both moduli are exactly right.
- **Blocked / isolated strings:** a string with no applicable window is its own component; the brute force confirms its invariant class is a singleton in every tested case (including all X+Y>N cases), so no special handling is needed.
- **X=Y=1 sanity:** reduces to adjacent 01<->10 swaps; only the count of 1s matters and both modulo lists are trivially all-0, matching.
- **Algorithm:** O(N) time, O(N) memory. Reject if 1-counts differ. Then zip ordered 1-positions and require equal residues mod X. Then do the same for ordered 0-positions mod Y (0-count equality is implied by 1-count equality, but re-check defensively). Otherwise Yes.
- **Edge cases:** X=1 trivializes the residue test for 1s; Y=1 trivializes it for 0s. When X+Y>N there are no moves and the invariants force S==T on all tested inputs. N=1 handled naturally (sample 2 gives No via differing 1-counts).
- **Implementation details:** read all tokens with sys.stdin.buffer.read().split(); compare raw bytes (49 for '1', 48 for '0') to avoid decoding; positions 1-based; zip is safe because lengths are checked first.
