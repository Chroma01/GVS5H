- **Core reduction:** Let `total` be the XOR of all elements. For chosen set `C` and excluded set `E`, `xor(C) = total ^ xor(E)`. Therefore replace `K` by `M = min(K, N-K)`. If `K <= N-K`, maximize subset XOR directly; otherwise maximize `total ^ subset_xor` over excluded subsets.
- **Bound consequences:** The guarantee `C(N,K) <= 10^6` implies `C(N,M) <= 10^6`. Under this bound, `M` is at most 11. When `M=2`, `N <= 1414`; when `M=3`, `N <= 182`; larger `M` has even smaller `N`. Exhaustive enumeration is therefore feasible.
- **Enumeration design:** Handle `M=0` (choose all), `M=1` (scan), `M=2` (double loop), and `M=3` (triple loop). For `M >= 4`, recursively build a prefix until 4 elements remain, then use four nested loops for the suffix. This shares prefix XORs and avoids tuple allocation overhead from generic combination generation.
- **Transformed objective:** When `direct` is false, the current prefix XOR is combined with `total` before enumerating the suffix, so each leaf evaluates `total ^ subset_xor` for the excluded subset.
- **Performance:** The number of innermost leaves is at most `10^6`. With base size 4, the worst case (`N=22, M=11`) has about 2.2 million total loop iterations and about 280k recursive calls, which is comfortably fast in Python.
- **Edge cases:** `K=N` gives `M=0`. `K=N-1` gives `M=1` with complement transformation. Duplicate values are fine because enumeration is by indices. `K=N/2` uses the direct branch. XOR values are non-negative, so initializing the answer to 0 is safe.
- **Possible pitfalls:** Do not maximize the excluded subset XOR directly when `K > N/2`; always XOR it with `total`. Increasing index loops enforce distinct elements.
