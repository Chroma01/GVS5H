- **Core reduction:** Walkways cost zero. For floor x, free movement is exactly within connected components of cells with height at least x. For two blocks u,v, let M(u,v) be the maximum floor where they are connected. If min(Y,Z) <= M, answer is abs(Y-Z). Otherwise both endpoints must be brought down to M and later up, answer Y+Z-2M.
- **Bottleneck graph:** Make an undirected grid edge between adjacent blocks with weight min(F_u,F_v). Then M(u,v) is the maximum bottleneck path value. Kruskal in descending edge order gives this value as the merge weight when u and v first become connected.
- **Kruskal reconstruction tree:** Process packed edges descending. DSU is over original vertices with union by size. `comp_root[rep]` stores the current reconstruction-tree root for that DSU component. On merging two components with edge weight w, create a new node with value w, make the two old component roots its children via `parent`, and set the new node as the component root. Leaves keep their original building heights in `val`.
- **Same-block queries:** For u==v, M is the building height F_u, stored as the leaf value. The general formula then gives abs(Y-Z).
- **Depth and LCA:** In the reconstruction tree, every parent id is larger than its children. Therefore depths can be computed by scanning node ids from root-1 down to 0. Binary lifting stores only ancestors; the LCA value in `val` is the desired bottleneck M.
- **LOG choice:** Use `max_depth.bit_length()` rather than `total_nodes.bit_length()`. The maximum leaf depth is at most N-1, saving one lifting level for the maximum grid.
- **Memory-conscious tables:** Edge list is packed into Python ints: weight in high bits, endpoints in 20-bit fields. `val`, `parent`, `depth`, and all lifting tables use `array('i')`. Query endpoints and floors are stored in compact arrays. Large temporary objects (`data`, `edges`, DSU arrays, aliases) are deleted before building lifting tables.
- **Input handling:** `sys.stdin.buffer.read().split()` is used for fast parsing, then deleted as soon as all queries are stored. This keeps peak memory acceptable while avoiding a slower custom parser.
- **Edge cases:** H=W=1 has no edges; the tree is a single leaf and all queries are same-block. Equal edge weights are handled naturally; arbitrary tie order still preserves bottleneck values. Kruskal stops after N-1 unions.
- **Complexity:** Sorting O(HW log(HW)), Kruskal O(HW alpha), lifting table O(N log N), queries O(Q log N), where N=H*W. Memory is O(N log N) with compact arrays.
