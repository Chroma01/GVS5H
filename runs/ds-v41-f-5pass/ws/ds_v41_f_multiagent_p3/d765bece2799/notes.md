- **Problem model:** Answer = sum over subarrays of length <= k of (min + max). Min and max contributions are computed independently; with a fixed tie-break each subarray has exactly one designated min and one designated max.
- **Tie-break (leftmost occurrence):** For value at i to be the leftmost min, the subarray must not extend left over any j<i with nums[j] <= nums[i] (`prev_le`) nor right over any j>i with nums[j] < nums[i] (`next_lt`). For leftmost max use `prev_ge` (>= on left) and `next_gt` (> on right). This assigns each subarray's min to its first minimum and max to its first maximum.
- **Monotonic stacks:** All four boundaries in O(n). `prev_le`: pop while nums[top] > x. `next_lt`: scan right-to-left, pop while nums[top] >= x. `prev_ge`: pop while nums[top] < x. `next_gt`: scan right-to-left, pop while nums[top] <= x.
- **Extensions:** With i fixed, Lmin = i - prev_le[i], Rmin = next_lt[i] - i (same shape for max). Left extension a in [1,L], right extension b in [1,R], subarray length a+b-1.
- **Capped count formula:** count(L,R) = #(a,b) with 1<=a<=L, 1<=b<=R, a+b <= S where S=k+1. Let m = min(L, S-1). For a <= S-R the bound is R; let q = clamp(min(m, S-R), 0, m). Result q*R plus, for a = q+1..m, sum of (S-a) via arithmetic series. `count_pairs` was hand-checked against small (L,R,k) tables; no off-by-one.
- **Correctness intuition for tie-break:** Using <= / < on the min side guarantees i is the first occurrence of the minimum in any counted subarray; using >= / > for max does the same for the maximum. The two counts are independent, so every subarray contributes once per side.
- **Complexity:** O(n) time, O(n) memory. n <= 80000 so four stack passes plus 2n constant-time calls is fast in Python. Totals fit Python ints (max magnitude ~ n(n+1)/2 * 2e6).
- **Sample verification (traced end to end):** nums=[1,2,3], k=2 -> min sum 9, max sum 11, total 20 (expected 20, pass). nums=[1,-3,1], k=2 -> 3 + (-12) + 3 = -6 (expected -6, pass).
- **Additional checks (hand-brute-forced):** k=1 reduces both counts to 1 so total = 2*sum(nums); k=n gives L*R because L+R-1 <= n <= k always. All-equal arrays counted correctly via leftmost tie-break ([2,2] k=2 -> 12; [-1,-1] k=2 -> -6). Strictly increasing/decreasing and mixed duplicates with negatives checked: [3,1,2] k=2 -> 19; [-1,2,-1] k=3 -> 3, both matching naive enumeration. No failing case found.
- **Pitfalls avoided:** clamping q to >= 0 when S < R; keeping strict/non-strict comparisons consistent between min and max side; treating a and b as extension lengths including i; using S = k+1 rather than k.
