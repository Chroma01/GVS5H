- **Sample tests:** PASS. The three provided examples return `2`, `1`, and `1` respectively. The included `__main__` block runs these cases and prints `SAMPLE TESTS PASS`.
- **Core approach:** Binary search the answer `L`. Feasibility is monotone: if some final string has every run length at most `L`, then the same string also satisfies any larger limit. The upper bound is the original maximum run length because zero flips is always allowed.
- **Feasibility DP:** For a fixed `L`, compute the minimum Hamming distance from `s` to any binary string whose maximum run length is at most `L`. This is exact and avoids unsafe greedy assumptions.
- **DP state:** After processing a prefix, `dp0[r]` and `dp1[r]` store the minimum flips for a modified prefix ending with `'0'` or `'1'` and current run length `r`, where `1 <= r <= L`. Index `0` is unused.
- **Transitions:** For the next original character, choose output bit `0` or `1`. Matching costs `0`, flipping costs `1`. If the chosen bit equals the previous ending bit, extend the run only when `r < L`. If it differs, the run resets to length `1`; the best switch cost is obtained from `min(dp0)` or `min(dp1)`.
- **Cost capping:** `INF = cap + 1`. States with cost greater than the allowed budget are never stored or expanded, because costs are nonnegative and cannot become feasible later. For brute-force verification, `cap = n` gives the exact minimum.
- **Complexity:** One feasibility check is `O(n * L)` time and `O(L)` memory. Binary search over at most `max_run <= n` gives `O(n^2 log n)` worst-case time, safe for `n <= 1000`.
- **Brute-force comparison:** `_min_flips_brute` and `_verify_small` are retained for optional exhaustive validation on small inputs. They are not called by the sample runner.
- **Greedy unsafe:** A per-run count `floor(run_length / (L + 1))` is not exact. For `s = "0110"` and `L = 1`, it suggests `1` flip, but the true minimum is `2`. A left-to-right greedy that flips only when a run would exceed `L` is also not optimal: for `s = "00011111"` and `L = 2`, greedy uses `3` flips, while flipping indices `1` and `5` gives `"01011011"` with maximum run `2`.
- **Validation:** The three samples produce `2`, `1`, and `1`. Edge cases checked: `n == 1` returns `1`; `numOps == 0` returns the original max run; `max_run == 1` returns `1`; all-zero strings behave as expected, e.g. `"0000"` with `1` flip gives `2`, with `2` flips gives `1`.
