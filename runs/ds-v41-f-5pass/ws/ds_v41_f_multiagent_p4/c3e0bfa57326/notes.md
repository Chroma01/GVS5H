- **Problem core:** Operation on a balanced substring is reverse-complement (reverse then swap parens). It preserves Dyck validity.
- **Forest model:** A valid sequence encodes an ordered rooted forest. A balanced substring corresponds to a contiguous run of siblings under some parent. Applying the operation reverses the order of those siblings AND recursively reverse-complements each of their subtrees.
- **Invariant:** The unordered rooted-forest shape (multiset-of-children structure recursively) is preserved, since reversing order / recursing never changes unordered shape. So all reachable strings are exactly the ordered forests isomorphic to the original as an unordered forest.
- **Reachability argument:** For adjacent siblings A,B, the balanced substring AB maps to rev(B)rev(A); applying rev again to the first component gives B rev(A), then to the second gives BA. Net: swap A,B with descendants fully restored. So adjacent transpositions of siblings are achievable => full symmetric group per node => arbitrary child permutations possible with subtrees intact. Hence reachable set = all ordered forests isomorphic to the given unordered forest.
- **Swap trick detail:** each of the 3 sub-moves targets a valid balanced substring (AB, then the whole rev(B) component, then the rev(A) component), so all legal. Involution rev(rev(X))=X is the key.
- **Counting formula:** Number of distinct strings = product over EVERY node (including a virtual root above the top-level trees) of the multinomial coefficient c! / (m_1! m_2! ...) where c = number of children and m_i are multiplicities of children grouped by canonical shape. This counts distinct orderings of children by shape.
- **Canonical IDs:** Compute bottom-up. Node's signature = sorted tuple of its children's canonical IDs; map tuple->integer via a dict for uniqueness (no hashing collisions, exact tuples). Leaves have empty tuple. IDs form a bijection with unordered shapes.
- **One-pass parsing:** Maintain a stack of child-id lists. On '(' push a new empty list; on ')' pop, compute that node's multinomial (multiply into answer), canonicalize, and append its id to the parent list. Avoids explicit tree/recursion (N up to 5000).
- **Virtual root:** After the loop, stack[0] holds top-level tree ids; multiply its multinomial too. Do not forget this factor.
- **Verification:** S="(())()" -> root children shapes {node-with-leaf, leaf} distinct => 2!/(1!1!)=2; correct. S="()" -> 1. Identical siblings (e.g. "()()", "(())(())") collapse to factor 1, giving the same string, as expected.
- **Complexity:** O(N log N) time (sorting child ids), O(N) space. Factorials precomputed to N.
- **Pitfalls avoided:** deep recursion (iterative), double counting isomorphic strings (multinomial by canonical shape), forgetting virtual root, hash ambiguity (exact tuple keys).
