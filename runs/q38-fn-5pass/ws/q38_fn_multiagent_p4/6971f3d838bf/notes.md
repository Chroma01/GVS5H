- **Core observation:** Deleting a non-negative value cannot improve the answer. Any subarray after deleting such a value corresponds to an original subarray spanning the same remaining elements plus the removed non-negative values, so its sum is no larger than an original subarray sum. Therefore only negative values need explicit consideration, plus the original array.
- **Block model:** For a fixed negative value x, removing all occurrences of x concatenates maximal x-free blocks. The maximum subarray sum after deletion is exactly the maximum subarray sum of this concatenated sequence.
- **Monoid summary:** Each sequence is summarized by `(total_sum, best_nonempty_prefix, best_nonempty_suffix, best_nonempty_subarray)`. `None` is used as the empty identity. The merge operation is associative and preserves left-to-right order.
- **Precomputation:** Prefix and suffix summary arrays provide the first and last x-free blocks in O(1). An iterative segment tree provides summaries for internal blocks between consecutive occurrences of x.
- **Processing values:** Negative indices are grouped by value. For each negative value with count `< n`, combine: prefix before first occurrence, segment-tree summaries of non-empty gaps between consecutive occurrences, and suffix after last occurrence. Update the global answer with the combined best. Values with count `== n` are skipped because deletion would empty the array.
- **Conditional tree build:** The segment tree is built only if some negative value has a non-empty internal gap. If every negative value occurs in one contiguous run or only once, prefix/suffix summaries alone are sufficient, making those cases linear.
- **Complexity:** There are at most `n` internal blocks over all negative values, because the sum of `(count[x] - 1)` over distinct negative values is at most `n`. Each internal block query costs `O(log n)`, so worst-case time is `O(n log n)`. Prefix/suffix construction, grouping, and block combination are `O(n)`. Memory is `O(n)` for prefix/suffix arrays, the optional segment tree, and position lists.

The brute-force maximum subarray routine uses nested loops rather than Kadane to avoid sharing assumptions with the solution. It tests 1000 random arrays of length at most 8 with values in `[-5, 5]`, plus exhaustive arrays of length at most 4 with values in `[-2, 2]`.

- **Edge cases handled:** single element, all elements equal, all non-negative, all negative, adjacent occurrences, zeros, negative maximum, and invalid deletions that would empty the array.
- **Implementation details:** Kadane computes the original maximum while grouping negative positions. `_merge` avoids sentinel values by using `None` for empty. The segment tree query uses separate left and right accumulators to preserve order. The checker is placed under `__main__` so normal LeetCode-style imports do not execute it.
