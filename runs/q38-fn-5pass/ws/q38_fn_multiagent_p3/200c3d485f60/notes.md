- **Core observation:** An array of length `n` has exactly `n - 1` adjacent transitions. Each transition is either equal (`arr[i - 1] == arr[i]`) or different.
- **Counting formula:** Choose which `k` of the `n - 1` transitions are equal: `C(n - 1, k)`. Choose the first array value: `m` choices. Every different transition has `m - 1` choices, while every equal transition has only `1` forced choice. Therefore the answer is `m * C(n - 1, k) * (m - 1)^(n - 1 - k) mod 1e9+7`.
- **Why the formula is valid:** Once the equal/different pattern is fixed, values can be generated left to right. The first value is arbitrary. For a different transition, the next value can be any value except the previous one. For an equal transition, the next value is forced. Choices at different transitions are independent.
- **Modular combination:** Since `n <= 1e5` and `MOD = 1e9+7` is prime and larger than `n`, factorials and inverse factorials modulo `MOD` can be precomputed safely. `C(N, K) = fact[N] * invfact[K] * invfact[N-K] mod MOD`.
- **Edge cases:** If `n = 1`, there are zero transitions, so only `k = 0` is valid and the answer is `m`. If `m = 1`, different transitions are impossible; the answer is `1` only when all transitions are equal, i.e. `k = n - 1`, otherwise `0`. Python's `pow(0, 0, MOD)` correctly returns `1`, which handles the all-equal case.
- **Implementation detail:** The solution uses class-level cached factorial and inverse-factorial arrays so repeated calls in the same process do not recompute from scratch. Extending the arrays preserves correctness because existing inverse factorials for smaller indices remain valid.
- **Complexity:** With caching, the first call up to maximum `n` costs `O(n)` time and `O(n)` memory. Subsequent calls cost `O(1)` plus modular exponentiation `O(log n)`.
