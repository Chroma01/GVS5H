- **Objective shape:** This is a min-max (minimize the largest identical run), not a minimize-total problem. Cannot be solved by a single greedy pass; the right frame is a decision predicate plus a search for the smallest target L.
- **Monotonicity is the key:** If a string has every run <= L, it also satisfies every larger bound. So "can we achieve max-run <= L within numOps flips?" is monotone, enabling binary search on L over [1, n].
- **Search bounds:** L ranges [1, n]. Answer 1 is always eventually reachable when numOps is large enough (alternating costs at most about n/2). Upper bound n is safe because the original string already has runs <= n, requiring 0 flips.
- **Check for L >= 2 (per-run greedy):** Scan maximal equal-character runs; a run of length m is broken with m // (L + 1) flips. Reason: flip every (L+1)-th character inside the run, chopping it into pieces of size at most L; ceiling-free floor works because integer division counts the breakpoints needed. Verified: m=3, L=2 -> 1; m=4, L=2 -> 1 (4//3 = 1); run of length 1 contributes 0.
- **Why runs are independent for L >= 2:** Adjacent maximal runs already differ in character. Flipping an interior element of a run (not its two boundary elements) cannot merge with a neighbor, and since L >= 2 the surviving pieces are nonempty and short. So the per-run costs simply add.
- **L = 1 is the critical special case:** With bound 1 the only legal strings are fully alternating, which is a global constraint the per-run formula underestimates. Counterexample baked into these notes: "00100" has runs 2,1,2, giving per-run sum 1+0+1 = 2, but the true cost is min(dist to "01010", dist to "10101") = min(3, 4) = 3. Therefore L = 1 must be computed as the Hamming distance to the two alternating patterns, never folded into the run formula.
- **Alternating cost detail:** Build both targets 0101... and 1010...; for each index count a mismatch for exactly one of them (they are complementary), so one pass yields both costs. Answer is the min of the two totals.
- **Early termination:** Cap the running flip count at numOps inside the scan and bail out as soon as it exceeds, keeping the check O(n) overall.
- **Binary search mechanics:** Standard lower-bound loop lo=1, hi=n, mid=(lo+hi)//2, shrink hi when feasible else lo=mid+1; return lo.
- **Edge cases covered:** n == 1 returns 1 (single run, L=1 cost 0 <= numOps). numOps == 0 with an already-alternating string returns 1; with a constant string returns n. All-equal string "0000" with numOps 2 yields 1. numOps >= n trivially yields 1. Large numOps makes L=1 feasible via the alternating branch.
- **Validation results:** Example 1 "000001", numOps 1 -> L=1 cost 2 infeasible, L=2 cost 5//3=1 feasible, answer 2. Example 2 "0000", numOps 2 -> L=1 cost 2 feasible, answer 1. Example 3 "0101", numOps 0 -> L=1 cost 0 feasible, answer 1. All match.
- **Complexity:** O(n log n) time, O(1) extra space.
