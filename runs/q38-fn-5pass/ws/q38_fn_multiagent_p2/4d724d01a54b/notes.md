- **Problem model:** Adjacent swap cost is the current 1-indexed position. Every inversion must be swapped exactly once, but the cost depends on where the swap happens, so the main task is choosing an order that makes necessary crossings happen as far left as possible. The answer can be cubic in N, so Python integers are appropriate.
- **Key greedy/exchange argument:** Process values from N down to 1. When value x is the maximum among the remaining active prefix, all larger values have already been moved to their final positions and removed. The larger values originally before x have crossed x, moving x left as much as possible. x cannot be left of that position before it starts moving right, and performing its required right swaps consecutively from that position is optimal. This gives an independent lower bound for each x and is achievable by the descending greedy process.
- **Formula:** Let p_x be the original position of x and L_x be the number of larger elements before x. After removing those larger-before elements, x's current position among values 1..x is cur_x = p_x - L_x. It must move right to final position x, crossing x - cur_x smaller elements. The cost contribution is the arithmetic sum cur_x + (cur_x + 1) + ... + (x - 1), computed as (cur_x + x - 1) * (x - cur_x) // 2.
- **Closed-form computation:** Scan the permutation left to right while maintaining a Fenwick tree over values. For current x at original position pos, let le be the number of already seen values <= x. Then larger_before = (pos - 1) - le, and cur = pos - larger_before = le + 1. Add the arithmetic-sum contribution if cur < x, then add x to the Fenwick tree.
- **Why le + 1 works:** Among values <= x, exactly the seen values <= x remain to the left of x after all larger-before elements are conceptually removed. Therefore x's active position is le + 1. Its final active position is x because there are exactly x values <= x.
- **Implementation details:** Use a 1-indexed Fenwick tree. Prefix sum loop runs while j > 0, update loop runs while j <= n. Read all integers from stdin. The algorithm is O(N log N) time and O(N) memory.
- **Edge cases:** Already sorted permutations give cur = x for every element and answer 0. Reverse permutations give cur = 1 for every x and sum triangular numbers. The guard cur < x handles zero-step cases; cur > x cannot occur for a valid permutation.
- **Validation:** Sample [3, 2, 1] gives contributions 3 and 1, total 4. Sample [2, 4, 1, 3, 5] gives contributions 1 and 5, total 6. Sorted input gives 0.
