- **Core problem:** weighted interval scheduling with at most 4 intervals, strict non-overlap, and lexicographically smallest sorted original indices among maximum-score choices.
- **Sorting and compatibility:** sort original indices by right endpoint. For an interval with left `l`, compatible previous intervals are those with right `< l`, found by `bisect_left(rights, l, 0, i - 1)`. This enforces strict non-overlap and excludes shared boundaries.
- **DP state:** flat DP over sorted prefixes and exact chosen count `k = 0..4`. Each state stores maximum score and an encoded lexicographically smallest sorted index tuple.
- **Transitions:** skip copies the previous prefix state. Take combines the best compatible prefix state for `k - 1` with the current interval. Current interval is never combined with itself because the compatible prefix is always before the current sorted position.
- **Tie-breaking correctness:** for the same prefix, count, and score, keeping only the lexicographically smallest tuple is safe. Inserting the same future original index into two sorted tuples preserves lexicographic order. Lower-score states cannot catch up because future added weights are independent of the tuple within the same prefix and count.
- **Final selection:** compare states for `k = 0..4` by score first, then lexicographic order. Sentinel padding makes shorter arrays smaller when they are a prefix of longer arrays.
- **Packed tuple representation:** up to four sorted original indices are packed into fixed-width integer fields. Values are `index + 1`, and `0` is sentinel. Numeric comparison of packed integers equals lexicographic comparison of the padded arrays. Field width is chosen from `n.bit_length()`, so it is safe for the constraints.
- **Insertion:** insertion into packed tuples of length 0, 1, 2, or 3 is unrolled. It maintains sorted order and pads remaining fields with sentinel zero.
- **Memory and time:** sorting is `O(n log n)`, DP is `O(n)` with constant factor 4. Flat lists avoid per-row list and tuple object overhead, making `n = 5 * 10^4` comfortable.
- **Edge cases:** boundary-sharing intervals are incompatible; equal right endpoints are mutually incompatible; optimal answer may use fewer than 4 intervals; ties across different cardinalities are handled; impossible states use score `-1`; empty input returns empty list.
- **Testing verdict:** manual execution of samples and targeted edge cases passes. Sample 1 returns `[2, 3]`; sample 2 returns `[1, 3, 5, 6]`. Strict boundary cases such as `[1,2]` vs `[2,3]` correctly choose one interval and keep the smaller index on ties, while `[1,2]` vs `[3,4]` correctly combine. Equal-weight all-overlap cases keep the smallest index. Equal-weight all-compatible cases with a late small original index update to the lexicographically smallest 4-index set. Fewer-than-4 compatible intervals return the best 3-index set. Lexicographic ties across cardinalities choose `[0]` over `[1,2]` when scores tie, and `[0,1]` over `[2]` when scores tie. No failing case was found.
- **Potential pitfalls:** use `bisect_left`, not `bisect_right`; use 0-based original indices; do not query a prefix that includes the current interval; sort order among equal right endpoints does not affect the final result.
