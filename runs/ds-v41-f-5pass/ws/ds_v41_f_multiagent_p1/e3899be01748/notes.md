- **Problem restated:** count substrings whose integer value is divisible by their own last digit; substrings ending in 0 are never counted; leading zeros allowed; n up to 1e5 so O(n^2) enumeration is impossible.
- **Key observation:** every substring ending at index i has last digit equal to s[i]. So for a fixed ending index, the divisor is fixed (= s[i]) and only one divisibility test is needed per ending position.
- **Approach (incremental residue DP):** maintain, for each modulus d = 1..9, the residue distribution of all substrings ending at the previous position. For a new digit x, the new distribution is new[(10*r + x) % d] += old[r], plus one fresh substring at residue x % d. Then if x != 0, add cnt[x][0] to the answer.
- **Why all nine moduli:** the answer at index i uses modulus s[i], but future indices may need any modulus 1..9, so all nine distributions must be extended every step. Total work per character is sum_{d=1..9} d = 45, giving O(45n) time and O(45) space.
- **Correctness intuition:** extending a substring with value v by digit x gives 10v + x; residues update as (10*r + x) mod d for whichever modulus d is tracked. Only substrings whose last digit (= current x) is non-zero are queried, and residue 0 is exactly divisibility.
- **Single digits:** handled naturally; the single-character contribution at index i has value x, residue x % x = 0, so it is counted for its own divisor when x != 0.
- **Leading zeros:** no special handling needed; they just change the value and are carried through the same residue updates. Do not trim them.
- **Zeros as last digit:** when x == 0 we still update all distributions (needed for future extensions) but never add to the answer.
- **Implementation detail:** precomputed transition tables `trans[d][x][r]` and `single[d][x]` eliminate modulo operations from the inner loops. Arrays `cnt[d]` are reallocated each step; total allocated elements per character is 45, so memory churn is negligible.
- **Verification:** Executed the solution on the three provided samples and an independent O(n^2) brute-force reference. Results: `"12936"` -> 11 (expected 11) PASS; `"5701283"` -> 18 (expected 18) PASS; `"1010101010"` -> 25 (expected 25) PASS. Random cross-check: 2000 random strings of length up to 12, plus all strings up to length 6, all outputs matched the brute force. Verdict: PASS.
- **Timing:** on a 1e5-length worst case (`"9"*100000` and `"1234567890"*10000`), the DP executes about 4.5e6 inner iterations and runs in under 0.5s in CPython on typical judge hardware. Well within limits.
- **Pitfalls avoided:** divisibility by a variable modulus (must keep per-modulus state, not a single prefix); the fact that a substring's last digit equals the ending position's digit regardless of its start (leading zeros are fine); and accidentally counting substrings ending in 0.
