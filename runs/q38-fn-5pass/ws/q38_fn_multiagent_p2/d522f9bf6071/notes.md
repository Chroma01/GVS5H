- **Selected approach:** Sort intervals by right endpoint. For each interval, compute the compatible prefix count with `bisect_left(ends, start, 0, pos)`, enforcing strict non-overlap by excluding intervals ending exactly at the start. Maintain exact-count DP states for counts 1 through 4.
- **State meaning:** For each prefix of sorted intervals and exact count, store the maximum score and the lexicographically smallest sorted tuple of original indices achieving that score. Count 0 is implicit with score 0 and empty tuple.
- **Transition:** Skip carries the previous prefix state. Take combines the current interval with the best state of count `c-1` from the compatible prefix. The compatible prefix contains exactly intervals ending strictly before the current start.
- **Lexicographic encoding:** Encode sorted original indices as four base-`B` digits, where `B = n + 1`, digit = original_index + 1, and unused positions are sentinel 0. Numeric comparison of these fixed-length codes is equivalent to lexicographic comparison of index arrays, including the rule that a shorter prefix is smaller.
- **Tie safety:** Keeping only the best score and smallest code for each prefix/count is safe. For states in the same prefix, any future interval that uses this prefix is compatible with all of them. If a future interval is not compatible with the whole prefix, its transition uses an earlier compatible prefix where the compatible state is still stored. Adding the same future set preserves lexicographic order for equal-size sorted sets because the smallest symmetric-difference element is unchanged.
- **Implementation details:** Separate arrays are used for counts 1..4 to reduce overhead. Insertion of the current original index into the encoded tuple is specialized for lengths 0..3. Invalid exact-count states use score -1.
- **Final selection:** Compare counts 0 through 4 by maximum score first, then by encoded lexicographic order. Decode the winning code by extracting four base digits and subtracting 1 from nonzero digits.
- **Complexity:** Sorting and compatibility precomputation take O(n log n). DP is O(4n). Memory is O(4n) for score and code arrays, plus O(n) for sorted intervals and compatibility.
- **Edge cases:** Strict boundary overlap is handled by `bisect_left`. Equal-score ties across different counts are handled by sentinel-padded encoding. Invalid states are ignored. Empty input returns an empty list.
