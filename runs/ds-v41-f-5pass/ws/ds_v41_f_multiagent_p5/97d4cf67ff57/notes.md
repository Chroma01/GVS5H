- **Problem model:** choose a connected edge-subset of the host tree whose selected-degree of every used vertex is 1 or 4, with at least one degree-4 vertex, maximizing used vertices. Subgraph need not be induced, so we freely pick incident edges.
- **Topmost-vertex view:** root host at 1; let r be the alkane vertex of minimum depth. r has no selected parent edge, so its selected degree = number of selected children. Non-top vertex attached via parent edge has degree = 1 + (selected children).
- **Degree rules that follow:** non-top internal vertex needs exactly 3 selected children; non-top leaf needs exactly 0 (branch is a single vertex). Topmost vertex is either a leaf with exactly 1 selected child, or degree-4 with exactly 4 selected children.
- **Local DP:** B[v] = best size of a valid branch rooted at v that is attached upward (parent edge selected). If v has <3 children it must be a leaf in the alkane, so B[v]=1 (its subtrees are unusable). If v has >=3 children it is internal, so B[v] = 1 + sum of the 3 largest B[child] (extra children stay unselected; sums are strictly positive so exactly 3).
- **Degree-4 witness:** an internal vertex is itself degree-4, so its branch automatically contains a degree-4 vertex; a leaf branch is just one vertex and contains none. Hence B1[v] = B[v] if v has >=3 children (v internal), else -1 (impossible).
- **Top candidates over all vertices v:** (a) v is degree-4 top: requires >=4 children, value 1 + sum of 4 largest B[child] = B[v] + (4th largest B[child]); (b) v is leaf top: requires some child with B1 != -1, value 1 + max B1[child]. Answer is the max of both over all v, else -1.
- **Why B (not a stronger state) suffices inside:** for an internal vertex the degree-4 requirement is met at that vertex; its descendant branches need only be locally valid, so the plain maximum-size value is enough. Only the single final leaf-top branch must actually carry the degree-4 witness, which is what B1 captures.
- **Verification on samples:** sample1 root 1 leaf-top with child 2 internal (3 children 3,6,7; child 3 internal with 4,8,9) gives 1+B1[2]=1+7=8. sample2 has no vertex with >=3 children anywhere, so all B1=-1 and all tops fail => -1.
- **Implementation notes:** iterative BFS from 1 to get parent and an order; process vertices in reverse BFS order so children precede parents (no recursion). Use -1 as the impossible sentinel (all real sizes >=1). Sort a copy of child B-values only when there are >=3 children; O(N log N) worst case, fine for 2e5. Handle N<2 as -1.
