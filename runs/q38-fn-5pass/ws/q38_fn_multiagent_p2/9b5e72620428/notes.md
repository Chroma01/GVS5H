- Reduction: Only the multisets of fixed non-negative values in A and B matter. Since A can be permuted arbitrarily, fixed A values can be assigned to any B positions, and B wildcards can be filled with arbitrary non-negative values.
- Target sum: If the final common sum is S, every fixed value must be at most S. A fixed A value a can be paired with a fixed B value only when b = S - a.
- Required fixed-fixed pairs: Let FA and FB be fixed counts, and WA = N - FA, WB = N - FB. If k fixed-fixed pairs are made, remaining fixed A values need B wildcards and remaining fixed B values need A wildcards. Thus k >= FA - WB and k >= FB - WA. Both lower bounds equal FA + FB - N, so T = max(0, FA + FB - N).
- Immediate Yes: If T <= 0, choose any S >= max fixed value and cover all fixed values with opposite-side wildcards. If T == 1 and both sides have fixed values, pairing a global maximum with any fixed value on the other side gives a valid S >= max fixed value.
- Feasibility condition: For T > 0, a target S is feasible iff S >= max_fixed and M(S) >= T, where M(S) = sum_a min(cntA[a], cntB[S-a]). This is the maximum number of fixed-fixed pairs possible for S.
- Candidate sums: If T > 0 and M(S) >= T, then M(S) > 0, so S must be a + b for some fixed values a and b. Therefore it is enough to inspect pair sums of fixed values that are at least max_fixed.
- Weighted pair-sum mode: Each unique value pair (a, b) contributes weight min(cntA[a], cntB[b]) to sum a + b. The problem becomes checking whether some sum >= max_fixed has accumulated weight at least T.
- Early heavy-pair check: If some value pair has both counts at least T and its sum is at least max_fixed, answer is Yes immediately. This also covers the case where a single value pair alone supplies all required pairs.
- Enumeration optimization: Use the smaller unique side as the outer loop. Sort the inner unique values and counts. For each outer value x, only inner values y with x + y >= max_fixed matter; find the first such y with bisect_left.
- Encoding: Pack each relevant pair as ((x + y) << shift) | weight, where shift = max(1, n.bit_length()). Since weight <= n < 2^shift, sorting these integers groups equal sums contiguously without carry between weight and sum bits.
- Scan: Sort encoded integers, then scan contiguous blocks with the same sum, adding lower-bit weights. If any block total reaches T, answer Yes.
- One-side uniqueness shortcut: If only one outer value can participate, or only one inner unique value exists, valid sums cannot collide. After the heavy-pair check, this means No.
- Complexity: Unique values are at most N, so generated relevant pairs are at most N^2 = 4,000,000. Sorting dominates: O(P log P) time and O(P) memory, where P is the filtered pair count. This is acceptable for N <= 2000.
- Pitfalls: Feasibility is not monotone in S, so binary search is unsafe. Duplicate values require min-count weights, not just distinct value pairs. Sums below max_fixed are invalid even if they have enough pair weight. The T formula already accounts for both wildcard capacities.
