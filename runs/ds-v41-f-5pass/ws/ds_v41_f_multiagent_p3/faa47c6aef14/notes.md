- **Model:** Each operation moves reds at box i along P (i -> P_i) and blues along Q (i -> Q_i). Reds and blues move as units, always decreasing their respective distance-to-X by exactly 1 when their box is operated.
- **Distances:** For a permutation cycle of length L containing X, traversal list `trav = [X, P(X), P^2(X), ...]`. For node `trav[j]`, distance to X is `(L-j) mod L`. X has distance 0; predecessor has distance 1. Nodes outside X's cycle get -1.
- **Feasibility:** If any red ball sits off X's P-cycle, or any blue ball off X's Q-cycle, answer is -1. Every red-bearing node (dist>=1) lies in the red chain; every blue-bearing node in the blue chain.
- **Required chains:** Farthest red at distance `dred` forces operations on nodes at distances `dred, dred-1, ..., 1` in that order (R). Similarly blue gives B. These are exactly the contiguous segments `travP[LP-dred:]` and `travQ[LQ-dblue:]`. Never operate X (dist 0), so balls reaching X stay.
- **Answer = SCS(R,B):** Any valid sequence must contain R as a subsequence (farthest red's forced journey) and B as a subsequence (farthest blue's), giving a lower bound of the shortest common supersequence. Conversely simulating any common supersequence of R and B achieves the goal — extra/repeated ops only advance balls greedily toward X and cannot push a ball away from X, so the SCS is achievable.
- **SCS formula:** `SCS = |R| + |B| - LCS(R,B)`. Since nodes are distinct within each chain, LCS is found by mapping each B-node to its index in R and computing a strictly-increasing LIS (patience sorting, bisect_left), O(N log N).
- **Verified samples:** (1) R=[2,1,4], B=[5,1], LCS=1 -> 4. (2) empty chains -> 0. (3) red box off cycle -> -1. (4) R=[6,2,8], B=[4,5,2,8,7,1,3], LCS=2 -> 3+7-2=8.
- **Edge cases:** d_red or d_blue = 0 gives empty chain; multiple red/blue balls handled automatically by the max-distance; guard the empty-slice case.
