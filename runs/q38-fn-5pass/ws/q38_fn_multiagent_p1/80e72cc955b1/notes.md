- **Sample verdict:** The current implementation passes the provided examples. `[[1,2],[2,4]]` returns `3`, and `[[2,6]]` returns `4`.
- **Edge cases checked:** Small ranges such as `[1,2]`, `[1,3]`, `[1,4]`, `[4,5]`, `[4,16]`, and `[16,64]` behave correctly. Boundary values at powers of four (`1, 4, 16, 64`) are handled correctly. The implementation also safely handles empty query lists and non-positive prefix-sum arguments.
- **Cost model:** For a positive integer `x`, each selection replaces it by `floor(x / 4)`. The number of selections required is fixed and equals `c(x) = floor(log_4(x)) + 1`. For `x <= 10^9`, the maximum cost is `15`.
- **Query answer:** A query `[l, r]` produces the multiset of costs `c(l), c(l+1), ..., c(r)`. One operation consumes one remaining selection from two distinct array positions. Therefore the answer is at least `ceil(total_cost / 2)` and at least `max_cost`. These bounds are simultaneously achievable by pairing largest remaining costs, using zero-valued positions as dummy partners when needed. Thus the query answer is `max(ceil(total / 2), max_cost)`.
- **Range sums:** `c(x)` is constant on buckets `[4^(k-1), 4^k - 1]`. The code precomputes powers of four and prefix sums at bucket boundaries. `prefix_sum(n)` computes `sum_{x=1}^n c(x)` by binary searching the bucket containing `n`. For each query, `total = prefix_sum(r) - prefix_sum(l - 1)`, and `max_cost = c(r)` because `c` is nondecreasing.
- **Implementation details:** `powers[i] = 4^i`. `prefix[i]` stores `F(powers[i] - 1)`. For `prefix_sum(n)`, `idx = bisect_right(powers, n) - 1` gives the largest power of four not exceeding `n`. Completed buckets contribute `prefix[idx]`, and the partial bucket contributes `(n - powers[idx] + 1) * (idx + 1)`. `cost(n)` is `bisect_right(powers, n)`.
- **Complexities:** Precomputation is `O(log max_r)`. Each query uses two prefix-sum calls and one cost lookup, each effectively `O(log log max_r)` with a tiny constant because there are only about 16 buckets for the constraints. Overall time is effectively `O(q)`, and memory is `O(log max_r)`. Python integers safely handle the accumulated answer.
