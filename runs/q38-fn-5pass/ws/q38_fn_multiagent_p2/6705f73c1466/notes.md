- **Approach:** Collect the 0-based positions `p[j]` of all `1` characters. If there are `k` ones and the final contiguous block starts at `x`, the `j`-th one should move to `x + j`. The cost is `sum |p[j] - (x + j)|`, which equals `sum |(p[j] - j) - x|`. This is minimized by choosing `x` as the median of the transformed values `a[j] = p[j] - j`.
- **Median choice:** Since the positions `p[j]` are strictly increasing by at least 1, the transformed values `a[j]` are nondecreasing. Therefore the median can be taken directly as `a[k // 2]`. For even `k`, either middle value is optimal; using the upper middle value is fine.
- **Validity of median:** Each transformed value satisfies `0 <= p[j] - j <= N - k`. The lower bound holds because at least `j` positions are needed before the `j`-th one, and the upper bound holds because at least `k - 1 - j` positions are needed after it. Hence the median is always a legal starting position for the final block.
- **Why order-preserving matching is optimal:** Adjacent swaps move a `1` by one position across a `0`, so the number of swaps equals the total distance moved by the ones. For sorted original positions and sorted target positions, matching them in order minimizes the sum of absolute distances; crossing matches can be uncrossed without increasing the cost.
- **Complexity:** The solution runs in `O(N)` time and uses `O(k)` memory, where `k` is the number of ones. With `N <= 5 * 10^5`, this is easily fast enough in Python.
- **Implementation details:** Read input as bytes for speed, compare each byte to `49` for `'1'`, store positions, compute the median transformed value, and sum absolute deviations. Python integers safely handle the maximum possible answer.
