- **Problem model:** Starting slime K repeatedly absorbs an adjacent strictly smaller slime. Absorption only increases size and never removes future options, so the process is confluent: the maximal reachable interval is unique. Its sum equals the answer.
- **Key structure:** The final interval is always the subtree interval of some node in the max Cartesian tree (strict pop: pop while `A[stack[-1]] < A[i]`). Ties keep the earlier index higher, giving a valid heap.
- **Subtree sums S:** `S[u] = A[u] + S[left] + S[right]`; computed iteratively via a pre-order list reversed (children before parents). Avoids recursion depth issues at N = 5e5.
- **Crossing condition e:** A start that has fully absorbed u's subtree (sum `S[u]`) can absorb u's parent p iff `S[u] > A[p]` (strict). After absorbing p, all of p's sibling-subtree elements are `< A[p] < S[u]+A[p]`, so the whole p-subtree is absorbed, giving sum `S[p]`. Thus crossing is transitive.
- **top computation:** `top[child] = top[parent] if S[child] > A[parent] else child`, root initialized to itself. Processed in pre-order so parents are done first. Inlined without a separate `e` array.
- **Readiness g:** Start u can move iff an existing child's adjacent position is strictly smaller: `(left child and A[u-1]<A[u]) or (right child and A[u+1]<A[u])`. If u has no child on a side, that outside neighbour is `>= A[u]` (nearest greater-or-equal under this tie-break), so it is never absorbable. Leaves therefore always have `g=false`.
- **Answer:** `ans[u] = S[top[u]]` if `g[u]` else `A[u]`. If `g[u]` is true, absorbing one smaller neighbour raises the sum above `A[u]`; every element of u's subtree is `<= A[u] < sum`, so the whole subtree is absorbed, then the ancestor chain via e follows.
- **Why the other neighbour is safe:** For u's subtree boundaries, the non-parent neighbour q is an ancestor with `A[q] >= A[parent]`. If `e[u]` is false then `S[u] <= A[parent] <= A[q]`, so q is not absorbable; the chain stopping at `top[u]` is correct. If a start can absorb a higher ancestor q directly, all intermediate `S[x] >= S[u] > A[q] >= A[ancestor]`, so the e-chain automatically extends past q.
- **Tie handling verified:** all-equal arrays give all answers `A_i`; e.g. `[7,7,7] -> 7 7 7`, `[5,5,1] -> 5 15 1`, `[1,7,7] -> 1 15 7`, `[4,4,1,4] -> 4 13 1 13`. Equal maxima separated by smaller values still allow crossing after growth.
- **Samples:** Both provided samples reproduced exactly (`4 30 2 13 2 13` and `22 47 235 10 31 235 2 235 5 235 6 235`).
- **Complexity:** O(N) time, O(N) memory, fully iterative with buffer I/O.
