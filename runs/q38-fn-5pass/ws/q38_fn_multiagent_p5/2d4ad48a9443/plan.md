Use the fact that the minimal increments for a subarray equal the sum of its running prefix maxima minus the sum of its elements. For a fixed left endpoint this cost is monotone in the right endpoint, and removing a left endpoint cannot increase the cost, so a two-pointer window can count all valid subarrays if we can query `cost(l, r)` quickly. The running maximum changes only when we jump to the next strictly greater element to the right, so precompute next-greater pointers and binary-lift them, storing the cost contributed by each jump segment. Then `cost(l, r)` can be computed in `O(log n)` by taking large next-greater jumps while their landing index is within `r`, then adding the final truncated segment. Finally, slide the left pointer and extend the right pointer while the queried cost is at most `k`.
