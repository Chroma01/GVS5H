- **Problem:** pick a non-empty subsequence (order preserved) whose alternating sum (even positions +, odd positions -) equals k; among those with product <= limit maximize the product; return -1 if none.
- **Decomposition:** (a) max positive product with sum k and product <= limit, (b) existence of any zero-containing subsequence with sum k (product 0). Positive > 0, so check (a) first; if none, return 0 when (b) holds, else -1.
- **Alternating-sum bitmask:** M = sum(nums) <= 1800; every alt sum s obeys |s| <= M. Store a state's achievable sums as a big-int with bit (s+M) set. Adding +x is mask<<x, subtracting x is mask>>x. No masking needed: valid sums never leave [0,2M], so left shifts stay inside the useful window and right shifts only drop non-physical bits.
- **Parity required:** next sign is + iff an even count was chosen so far; each state carries parity (0 -> next is +, 1 -> next is -), flipped on every pick.
- **Positive DP:** key (used, parity, product) -> sum mask. Skip x==0 (product 0 handled separately) and x>limit (any product containing x exceeds limit). Seed (0,0,1) at bit M. Per x: copy dict, add fresh (1,1,x) at bit M+x, then extend every non-empty state with product*x<=limit via <<x (parity 0) / >>x (parity 1). Copy-then-add guarantees each element is used at most once (crucial for x==1, which keeps product but flips parity).
- **Monotonic pruning safe:** for zero-free subsequences the product never decreases, so discarding product>limit loses nothing. It is NOT safe for zero-products (a >limit intermediate could be zeroed later), hence the separate DP.
- **Positive answer:** max prod over used states with bit M+k set. The `used` flag excludes the empty subsequence (product 1, sum 0) when k==0.
- **Zero DP:** key (parity, seen_zero) -> sum mask, over all elements including zeros; extend the empty state and all states; seen |= (x==0); shifts as above. Any state with seen and bit M+k set means a valid product-0 subsequence exists.
- **Verification (traced against brute force):** Example 1 [1,2,3] k=2 L=10 -> 6; Example 2 [0,2,3] k=-5 L=12 -> -1; Example 3 [2,2,3,3] k=0 L=9 -> 9. Extra hand-traced cases matching full-subset enumeration: [3,1,4] k=6 L=100 -> 12 (state (1,1,12) reaches bit M+6); [2,2] k=0 L=3 -> -1; [1,0,1] k=1 L=5 -> 1; [0] k=0 -> 0; [12] k=12 L=11 -> -1; [2,3] k=-1 -> 6; [0,3] k=0 -> 0. No counterexamples found.
- **Complexity:** reachable products are 11-smooth numbers <= limit (a few hundred), so the positive DP has O(#products) keys; zero DP has 4. Per element O(1) big-int ops on <= ~3600 bits. Comfortable for n<=150.
