- **Core observation:** A 400 number has exactly two distinct prime factors, and every prime exponent in its factorization is even. Therefore it is a perfect square. If N = x^2, then the distinct prime factors of N are exactly the distinct prime factors of x, and their exponents in N are twice those in x. Thus N is a 400 number iff x has exactly two distinct prime factors.
- **Search bound:** Since A <= 10^12, sqrt(A) <= 10^6. It is enough to precompute all integers x <= 10^6 with exactly two distinct prime factors and store x^2.
- **Sieve design:** Use an array omega where omega[n] counts distinct prime factors. For each prime p, increment omega[m] for all multiples m of p. A number is prime during the sieve if omega[p] is still zero before processing it. This counts distinct primes, not multiplicity.
- **Query answering:** The squares x^2 are generated in increasing order of x, so the list is already sorted. For each query A, use bisect_right to find the first square greater than A, then take the previous element.
- **Complexity:** Sieve cost is O(L log log L) with L <= 10^6, and query cost is O(Q log M), where M is the number of valid squares up to 10^12. Memory is O(L + M).
- **Pitfalls:** Do not count prime factors with multiplicity; do not use floating-point sqrt for the bound; ensure the sieve limit is based on the maximum query, not a fixed smaller value; the answer always exists because A >= 36 and 36 = 6^2 is valid.
