- **Graph structure:** Vertices are intervals; an edge exists iff intervals are disjoint, i.e. `R_i < L_j` or `R_j < L_i`. All weights are positive, so an optimal path can be assumed simple and induced: any chord allows shortcutting and strictly reduces the sum.
- **Induced path bound:** In an induced path, for three consecutive intervals, the outer two must overlap. If the two edge orientations were the same (left-left or right-right), transitivity of interval order would make the outer two disjoint, a chord. Thus orientations alternate. A five-vertex induced path would have orientations `left, right, left, right` up to symmetry. Assuming `I1` left `I2`, we get `I3` left `I2`, `I3` left `I4`, `I5` left `I4`. Nonconsecutive overlap `I1` with `I4` gives `L4 <= R1 < L2`; overlap `I2` with `I5` gives `R5 >= L2`; but `I5` left `I4` gives `R5 < L4`, contradiction. Hence every optimal path has at most three edges.
- **Two-edge candidates:** If overlapping endpoints `s,t` are connected by a two-edge path through `u`, then `u` must be completely left of both or completely right of both. Mixed sides are impossible because the endpoints overlap. These are covered by `leftMin[min(L_s,L_t)]` and `rightMin[max(R_s,R_t)]`.
- **Three-edge candidates:** For overlapping endpoints, let `x` be the endpoint with smaller `L` and `y` the other. In an optimal induced three-edge path `x-u-v-y`, `u` cannot be left of `x` because then it would also be left of `y`, creating a chord. Thus `u` is right of `x`: `L_u > R_x`. Similarly, an optimal `v` is left of `y`: `R_v < L_y`. These two conditions automatically imply `u` and `v` are disjoint because `R_v < L_y <= R_x < L_u`. The middle weights can be minimized independently, giving candidate `rightMin[R_x] + leftMin[L_y]`. If the independently chosen vertices create chords, the corresponding two-edge path is cheaper and is already included.
- **Tie handling:** If `L_s == L_t`, choosing either endpoint as `x` is safe. Any three-edge path that would be missed or made non-induced by the tie is dominated by a two-edge path through a vertex left of both or right of both.
- **Precomputation:** Coordinates are at most `2N`. Build arrays of size `2N+3`. Initially store minimum weight at each `R_i` and `L_i`. Convert in-place to strict prefix/suffix minima: for `leftMin[x]`, store the current minimum before adding weights with `R=x`; for `rightMin[x]`, scan downward and store the current minimum before adding weights with `L=x`. This enforces strict inequalities.
- **Query formula:** If disjoint, answer `W_s + W_t`. Otherwise answer `W_s + W_t + min(leftMin[minL], rightMin[maxR], rightMin[R_x] + leftMin[L_y])`, or `-1` if the minimum is infinite.
- **Implementation details:** Use fast integer parsing via `map(int, read().split())`, 1-indexed arrays, `INF = 10**30`, and buffered output. Python integers handle all sums easily. The algorithm is `O(N + Q + maxCoordinate)` time and `O(N + maxCoordinate)` memory.
- **Edge cases checked:** touching intervals (`R_i == L_j`) are not edges; strict inequalities are used everywhere. Endpoints cannot be selected as middle vertices in overlap cases because they fail the strict side conditions. The two middle vertices in the three-edge candidate cannot coincide because one must start after `R_x` and the other must end before `L_y <= R_x`.
