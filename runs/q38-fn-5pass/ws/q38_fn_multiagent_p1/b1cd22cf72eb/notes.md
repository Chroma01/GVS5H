- **Core reduction:** If the final common sum is `H`, the final total tooth length is exactly `N * H`. Therefore the grinding cost is `original_total - N * H`, so minimizing cost is equivalent to maximizing feasible `H`.
- **Fixed-H constraints:** For a chosen `H`, the final upper length `u_i` must satisfy `0 <= u_i <= U_i` and `0 <= H - u_i <= D_i`. Hence `u_i` must lie in `[max(0, H - D_i), min(U_i, H)]`.
- **Feasibility check:** For fixed `H`, propagate the reachable interval of `u_i` from left to right. If the previous reachable interval is `[lo, hi]`, the next value can be any integer in `[lo - X, hi + X]`; intersect this with the current tooth's valid interval. The reachable set remains an interval, and non-emptiness after the last tooth is equivalent to feasibility.
- **Monotonicity:** If `H` is feasible with upper sequence `u_i`, then any smaller `H' >= 0` is feasible by replacing each `u_i` with `min(u_i, H')`. This keeps values within the new valid intervals, and capping by a constant cannot increase adjacent differences. Thus binary search on `H` is valid.
- **Search bounds:** `H` cannot exceed `min_i(U_i + D_i)`, because both final teeth at position `i` are nonnegative and cannot exceed their original lengths. `H = 0` is always feasible by grinding all teeth to zero.
- **Complexity:** Each feasibility check is `O(N)`, and binary search uses `O(log(min_i(U_i + D_i)))` checks, about 31 iterations. Total time is `O(N log 2e9)`, memory is `O(N)`.
- **Implementation details:** Use Python integers to avoid overflow; the answer can be around `4e14`. Keep the feasibility function tight with local/default bindings to reduce overhead. Remember that final tooth lengths may be zero, so the lower bound `max(0, H - D_i)` is necessary.
