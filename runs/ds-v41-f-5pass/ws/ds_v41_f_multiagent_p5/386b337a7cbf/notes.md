- **Problem structure:** choose a non-empty subsequence (order preserved); its alternating sum = (+v0 -v1 +v2 ...). Appending value x contributes +x when the selected count so far is even, -x when odd, then flips parity. So order/parity matters, not just the multiset.
- **Objective:** maximize product subject to product <= limit, and alternating sum == k. Positive product > 0, so it always beats a zero product.
- **Positive DP (zero-free):** dict product -> bitset of sums, split by parity. Sum s lives at bit s+OFF with OFF=sum(nums). Take x = left/right shift by x; also seed a new subsequence with x. If p*x > limit, prune: all values are >=1 so product only grows and can never return under limit.
- **Zero DP:** any subsequence containing a zero has product 0 <= limit, so no product cap is needed and elements larger than limit are still usable. Track four bitsets: E0/E1 (zero-free, even/odd parity) and Z0/Z1 (has >=1 zero). Taking x>0 shifts sums; taking 0 shifts by nothing and moves a zero-free state into the has-zero states. Answer 0 iff bit (k+OFF) is set in Z0|Z1.
- **Combine:** scan reachable positive products, return the largest whose bitset contains k; else return 0 if zero-product reachable; else -1.
- **Bounds:** alternating sum always lies in [-total, total] (magnitude <= sum of chosen values <= total), so bits stay in [0, 2*OFF]; out-of-range bits produced by shifts are physically impossible and safe to drop.
- **Empty subsequence:** never stored as a positive state (positive DP seeds only from single elements), so k=0 is not satisfied by the empty set. A product-1, sum-0, non-empty answer (e.g. [1,1]) is still captured correctly.
- **Why max-per-state is wrong:** keeping only the largest product per (parity,sum) loses smaller products that could later extend to valid larger ones; we keep the whole reachable set per product via bitsets.
- **Verified examples:** [1,2,3],k=2,limit=10 -> 6 ([1,2,3]); [0,2,3],k=-5,limit=12 -> -1; [2,2,3,3],k=0,limit=9 -> 9 ([3,3]); plus [5,0],k=5,limit=3 -> 0 and [0,3],k=-3,limit=2 -> 0.
- **Complexity:** positive DP ~ O(n * limit) big-int shifts on O(total)-bit words; zero DP O(n) shifts. Fine for n<=150, limit<=5000, total<=1800.
