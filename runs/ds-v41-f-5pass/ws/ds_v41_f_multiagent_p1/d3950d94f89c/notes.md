- **Problem:** Tree rooted at 0. Find longest special path (ancestor-to-descendant, all node values unique). Tie-break: minimum number of nodes among all longest special paths.
- **Key reduction:** For a fixed endpoint v, valid starts form a suffix of the root-to-v chain by depth. Only the shallowest valid start m0(v) matters. Because every edge length is at least 1, any deeper start is strictly shorter, so non-maximal paths can never tie the global maximum. Thus only one candidate per endpoint needs evaluation.
- **m0 recurrence:** During DFS maintain `last[value] = deepest depth on the current root-to-node path with that value`. On entering v: `m0 = max(parent_m0, last[nums[v]] + 1)` if the value was seen before. This ensures all values from depth m0 to v are unique.
- **Length computation:** Let `pref[d]` be the sum of edge lengths from root to the node at depth d. Then the path from depth m0 to depth d has length `pref[d] - pref[m0]`, and node count `d - m0 + 1`.
- **Implementation details:** Use an iterative DFS with an explicit stack to avoid recursion depth issues at n = 5*10^4. Stack holds enter markers `(0, node, parent, depth, parent_m0, edge_len)` and exit markers `(1, node, old_last_value)`. On enter, compute m0 and candidate, update global best, set `last[value] = depth`, push exit marker, then push children. On exit, restore `last[value] = old`. The `pref` array is indexed by depth and overwritten naturally; no popping is needed because it is only read at depths currently on the path.
- **Initial best:** `[0, 1]` handles single-node paths and cases where all values are equal (Example 2 gives [0, 1]).
- **Tie-break update:** `if cur_len > best_len or (cur_len == best_len and cur_nodes < best_nodes)`.
- **Complexity:** O(n) time, O(n) memory.
- **Verified cases:** Example 1 -> [6, 2]; Example 2 -> [0, 1]; all equal values -> [0, 1]; distinct chain -> full path length with maximum nodes; duplicate-forced restarts behave correctly.
