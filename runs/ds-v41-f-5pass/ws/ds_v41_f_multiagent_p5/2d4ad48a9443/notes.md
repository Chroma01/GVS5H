- **Problem:** count subarrays of nums (n <= 1e5, values 1e9, k up to 1e9) fixable to non-decreasing with at most k unit increments (each op raises one element by 1). Examples expect 17 and 12.
- **Cost formula:** minimal increments to make a[0..m-1] non-decreasing is sum over i of (prefix_max(a[0..i]) - a[i]). Any valid non-decreasing f must satisfy f[i] >= max(a[0..i]); choosing f = prefix max attains it.
- **Reversal trick:** b = nums[::-1]. Subarray nums[l..r] non-decreasing corresponds to mirrored subarray of b non-increasing, same increment cost. In b, cost of window [i..j] = sum_{p=i..j} (suffix_max(b[p..j]) - b[p]).
- **Two-pointer validity:** cost(i,j) <= cost(i,j+1) (suffix maxes only grow when extending right), and cost increases as window grows leftward. For fixed j valid left endpoints form a suffix; as j grows the minimal valid left is non-decreasing. So slide with one left pointer and add (j - left + 1) per right endpoint.
- **Deque structure:** groups (value, count) left->right with strictly decreasing values, each group = a run of positions sharing the same current suffix max. total_sufmax = sum(value*count). cost = total_sufmax - total_sum where total_sum = sum of b over window.
- **Adding right x:** positions with suffix max <= x form the rightmost run; pop groups while tail value <= x, accumulate counts, subtract their old contributions, push (x, 1+popped). total_sufmax += x*cnt; total_sum += x. Each push/pop O(1) amortized => overall O(n).
- **Shrinking left:** removing the leftmost position does not alter remaining suffix maxima (they never include it). Subtract vals[head] from total_sufmax and b[left] from total_sum; popleft if count==1 else decrement count; left++. Loop while cost > k.
- **No empty-window bug:** a one-element window always has cost 0 <= k (k>=1), so the shrink loop stops with at least one element; total_sufmax/total_sum stay consistent (both 0 only if empty, which is never reached as a stop condition needing checking).
- **Implementation notes:** flat arrays vals/cnts of size n+2 with head/tail avoid collections.deque overhead; tail <= n always because pushes = n and right-pops only reduce it, left-pops only move head. Python big ints handle sums up to ~1e14.
- **Verified cases:** example1 [6,3,1,2,4,4] k=7 -> 17; example2 [6,3,1,3,6] k=4 -> 12; n=1 -> 1; all equal -> n(n+1)/2; strictly increasing -> n(n+1)/2; strictly decreasing [3,2,1] k=1 -> 5; [5,1,4,2] k=3 -> 7; [3,1,2] k=1 -> 4; [1,3,2] k=1 -> 6.
- **Complexity:** O(n) time, O(n) space.
