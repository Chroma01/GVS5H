- **Core reduction:** For a fixed deleted value `x`, the resulting array is the concatenation of all maximal contiguous blocks that do not contain `x`. The answer for deleting `x` is the maximum-subarray monoid of those blocks merged left-to-right.
- **Monoid:** Each segment is represented by `(sum, pref, suff, best)`, where `pref` and `suff` are non-empty best prefix/suffix sums and `best` is non-empty best subarray sum. Identity is `(0, NEG, NEG, NEG)` with `NEG = -10**30`. Merge is associative and handles empty segments safely.
- **Range retrieval:** Prefix and suffix monoid arrays answer gaps touching the array ends in O(1). Gaps of length 1 or 2 are computed directly. Only internal gaps of length at least 3 require the iterative segment tree.
- **Conditional segment tree:** The tree is built only if some value has two consecutive occurrences separated by an internal gap of length at least 3. This avoids tree construction and queries in cases such as all values distinct or only small gaps.
- **Processing values:** One pass builds occurrence lists and the baseline Kadane answer. For each present value with frequency less than `n`, scan its occurrence positions, merge all non-empty gaps, and update the answer. Values not present are covered by the baseline no-deletion case.
- **Edge cases:** `n == 1` returns the only element. If all elements are equal, deletion is invalid and the baseline is returned. Empty gaps between consecutive occurrences are skipped. All-negative arrays still return the maximum single element because the monoid enforces non-empty subarrays.
- **Complexity:** Worst-case time is O(n log n) due to segment-tree queries for internal long gaps; many practical cases are O(n). Memory is O(n) for occurrence lists, prefix/suffix monoids, and optionally the segment tree.
- **Implementation notes:** Segment-tree components are stored in separate arrays to reduce tuple overhead. The iterative query maintains left and right accumulators and merges them at the end. Direct handling of tiny gaps significantly reduces query count.
- **Latent bug fixed:** The segment-tree right accumulator originally computed `nb` but then assigned the old `rb` instead of `nb`, so the right accumulator's `best` was not updated. This did not affect the final answer on the tested cases because the baseline Kadane result already covers subarrays internal to a single gap, but the fix makes the monoid fully correct.
