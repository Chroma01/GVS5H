- **Problem model:** Partition all NK vertices into N vertex-disjoint simple paths of exactly K vertices. Equivalent to orienting/merging so every vertex lies in one path of K vertices.
- **Rooted subtree invariant:** In a subtree of size `s`, everything outside the (at most one) fragment crossing the parent edge is covered by complete K-paths. Hence `s - L ≡ 0 (mod K)` where `L` is the in-subtree fragment length. Since `1 <= L <= K-1`, the length is forced to `L = s mod K`. So the state is uniquely determined by `s mod K`: residue 0 means the subtree must be closed; nonzero residue means it must be open with that exact length. No extra DP dimension is needed.
- **Forced children:** A child with residue 0 (if feasible) is closed and contributes nothing. A child with residue != 0 must be open and its fragment can only be extended through the parent edge, so it always attaches to the parent. "Active child" = child with `size % K != 0` and feasible.
- **Node conditions:** Let `ac` = number of active children. If any child infeasible -> node infeasible. If `s % K == 0` (closed): need `ac <= 2`. If `s % K != 0` (open): need `ac <= 1`. The length-sum condition (`1 + sum >= K` boundary) is automatically implied by the residue arithmetic; e.g. for two active children with closed residue, their residues sum to exactly `K-1`, and an over-long combination flips the residue to nonzero, correctly forcing an impossible `ac=2` open state.
- **Base case:** A leaf has size 1, residue 1, `ac=0`, so it is feasible as an open fragment of length 1. The root always has size NK, residue 0, so the answer is `feasible[root]` requiring a closed root.
- **K=1:** Every residue is 0 and `ac` is always 0, so every node is closed-feasible; answer is always Yes. Handled implicitly (no special branch needed except the trivial V==1 early exit).
- **Complexity:** O(NK) time and memory. Iterative DFS plus reversed pre-order avoids recursion-depth issues at 2e5 vertices.
