- **Reduction:** For query i, the answer is the largest divisor d of A_i such that at least K elements of A are divisible by d. If gcd of chosen K elements is g, then g divides A_i and all chosen elements, so at least K elements are divisible by g. Conversely, if d divides A_i and cnt[d] >= K, choose A_i plus any K-1 other elements divisible by d; their gcd is at least d. Thus the maximum such d is exactly the answer.
- **cnt computation:** Let freq[v] be the frequency of value v. cnt[d] = sum over multiples m of d of freq[m] = number of input elements divisible by d. Compute via prime-based multiple zeta transform: for each prime p, for d = M//p down to 1: cnt[d] += cnt[d*p]. This is O(M log log M), about 2.9e6 iterations for M = 1e6.
- **Answer transform:** Set f[d] = d if cnt[d] >= K else 0. We need for every x, max_{d|x} f[d]. Compute via prime-based divisor max transform: for each prime p, for x = 1 to M//p: f[x*p] = max(f[x*p], f[x]) in ascending x order to allow chaining. This is also O(M log log M).
- **Sieve:** Use a bytearray for primality and slice assignment to mark multiples. Build the list of primes up to M = max(A). M <= 1e6, so the sieve is fast.
- **Edge cases:** K = 1 shortcut: answer is A_i. K = N: valid d must divide all elements, so answer is gcd of all elements (handled naturally). Duplicates are handled because cnt counts multiplicities. d = 1 is always valid since cnt[1] = N >= K.
- **Implementation details:** Use sys.stdin.buffer.read().split() for fast input. Store cnt in a list of ints. Avoid per-query factorization. Tight loops with local variables and pointer arithmetic instead of multiplication. Output via '\n'.join. Memory: A list ~44MB, cnt ~36MB, is_prime ~1MB, input data freed early. Total under 150MB.
- **Complexity:** O(M log log M + N) time, O(M + N) memory. Passes the given constraints (N up to 1.2e6, A_i up to 1e6).
