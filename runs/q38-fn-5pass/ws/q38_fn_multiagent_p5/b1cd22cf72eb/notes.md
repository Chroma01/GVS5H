- **Reduction:** For any final common sum H, each upper-lower pair has final total length H, so the total grinding cost is initial total length minus N*H. Therefore the problem is equivalent to maximizing the feasible H.
- **Fixed H constraints:** If final upper lengths are u_i, then 0 <= u_i <= U_i and 0 <= H - u_i <= D_i. Hence u_i must lie in [max(0, H - D_i), min(U_i, H)], and adjacent u_i values must differ by at most X.
- **Interval Lipschitz feasibility:** For intervals [L_i, R_i], a sequence with adjacent difference at most X exists iff for every pair i, j, L_i <= R_j + X*abs(i-j). Necessity follows from |u_i - u_j| <= X*abs(i-j). Sufficiency can be shown by defining a_i = max_j(L_j - X*abs(i-j)); the pairwise condition ensures a_i <= R_i, while a_i is X-Lipschitz and satisfies a_i >= L_i.
- **Bottleneck formula:** Substituting L_i = max(0, H - D_i) and R_j = min(U_j, H), the pairwise feasibility condition is equivalent to H <= U_j + D_i + X*abs(i-j) for all i, j. If H <= D_i or H <= U_j, the inequality is automatic because initial lengths are positive; otherwise it reduces exactly to the displayed bound. Thus the maximum feasible H is min_{i,j}(U_j + D_i + X*abs(i-j)).
- **Computation:** For each i, compute D_i + min_j(U_j + X*abs(i-j)). Split into j <= i and j >= i. Maintain a prefix minimum of U_j - X*j to handle j <= i, giving cur + X*i. Maintain a suffix minimum of U_j + X*j to handle j >= i, giving cur - X*i. Two linear passes compute the global minimum H.
- **Implementation notes:** Use 0-indexed positions. Values can reach about 2e14, so Python integers are safe. The diagonal pairs i=j are included automatically, ensuring H never exceeds any U_i + D_i. The final answer total - N*H may exceed 32-bit range.
- **Superseded:** Binary search on H with reachable interval propagation is valid but unnecessary; the all-pairs bottleneck formula gives a direct O(N) solution.
