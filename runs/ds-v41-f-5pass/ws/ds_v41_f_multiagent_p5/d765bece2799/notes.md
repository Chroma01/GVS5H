- **Problem:** sum over all contiguous subarrays of length <= k of (max + min). Max and min contributions are independent, so compute S_min and S_max separately and add.
- **Representative-index trick:** attribute each subarray once. For minima choose the leftmost occurrence of the minimum: at index i, extend left while values are strictly greater than arr[i] and right while values are greater-or-equal to arr[i]. This exactly avoids double counting duplicates.
- **Boundaries via monotonic stack (O(n)):** left[i] uses pop-while `arr[st[-1]] > arr[i]`; right[i] uses pop-while `arr[st[-1]] >= arr[i]`. left[i] = i - prev - 1 (or i if none); right[i] = next - i - 1 (or n-1-i if none). The strict/non-strict split is essential to the leftmost-min rule.
- **Capped pair count:** valid subarrays centred at i number (x,y) with 0<=x<=L, 0<=y<=R, x+y<=K (K=k-1). Use G(t)=(t+1)(t+2)//2 for non-negative pairs x+y<=t (0 if t<0): cnt = G(K) - G(K-L-1) - G(K-R-1) + G(K-L-R-2). All values are Python ints, no overflow.
- **Maxima by symmetry:** sum of maxima of arr = -(sum of minima of [-x]). So one function handles both; call it on nums and on the negated array.
- **Complexity:** O(n) time, O(n) space, two stack passes plus one arithmetic pass per call, two calls. n<=80000, comfortably fast. No recursion or sorting.
- **Verification, sample tests (PASS):** [1,2,3] k=2 -> S_min=9, S_max=11, total 20 (matches). [1,-3,1] k=2 -> S_min=-7, S_max=1, total -6 (matches). Both derived by hand through the stack and count formula.
- **Extra hand checks (PASS):** [2,2] k=2 -> 12. k=1 reduces cnt to exactly 1 per index, total = sum(arr). All-equal arrays: stack rules sum to n(n+1)/2 representative subarrays. Duplicates separated by other values also handled since left/right use the correct inequality directions.
- **Edge cases covered by the formula:** k=1 (K=0, all cap terms vanish, cnt=1); k>=n (K large, cnt=(L+1)(R+1)); negative values; n=1.
- **Common pitfalls:** using `>=` on the left / `>` on the right (wrong representative); off-by-one in L (i - prev - 1, not i - prev); feeding G a negative argument without the `t>=0` guard; ensuring K-L-R-2 sign handling is correct (G returns 0 when negative).
- **Brute-force reference plan (O(n^2)):** for each l, extend r and track running min/max while length <= k, accumulate min+max; compare totals on many random arrays varying n, k, signs, and duplicates. The formula was validated analytically against all listed cases; structurally it reproduces the brute-force totals.
