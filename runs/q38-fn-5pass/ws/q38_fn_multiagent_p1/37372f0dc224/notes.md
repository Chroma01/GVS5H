- **Problem reduction:** If B is the longest palindromic suffix of S with length L, the shortest palindrome having S as prefix is S + reverse(S[:n-L]). Any valid palindrome with t appended characters forces the appended part to be reverse(S[:t]) and the remaining middle suffix S[t:] to be a palindrome, so minimal t is n-L.
- **Finding L:** A suffix X of S of length L is a palindrome iff X equals reverse(X). The first L characters of reverse(S) are exactly reverse(S[n-L:]). Therefore the longest palindromic suffix is the longest prefix of reverse(S) that matches a suffix of S.
- **KMP method:** Build the prefix function for pattern P = reverse(S). Scan S as text with KMP. The state q after the scan is the length of the longest prefix of P that is a suffix of S, which is L.
- **Implementation details:** Use bytes for faster indexing and output. The prefix function is computed in O(n). During scanning, if q reaches n before the end, fall back using pi[q-1] before reading the next character; in this problem q can reach n only at the final character, but the guard keeps the loop safe. The answer can be written as s + r[q:] because r[q:] equals reverse(s[:n-q]).
- **Edge cases:** n=1 returns the original string. If S is already a palindrome, q=n and no characters are appended. Every non-empty string has at least a length-1 palindromic suffix, so q is at least 1 for non-empty input. Empty input is ignored defensively.
- **Complexity:** Time O(n), memory O(n) for the pattern, prefix array, and output. n <= 500000 is comfortably within limits.
- **Alternative considered:** Computing prefix function on reverse(S) + separator + S and taking the final value also works, but the scan version avoids concatenating a 2n+1 string and matches the requested approach.
