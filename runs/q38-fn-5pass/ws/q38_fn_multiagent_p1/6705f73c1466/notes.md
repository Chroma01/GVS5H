- **Approach:** Collect the 0-based positions `p_i` of all `1`s in increasing order. If the final contiguous block of `k` ones starts at position `x`, its target positions are `x, x+1, ..., x+k-1`. The minimum adjacent swaps for this fixed block are `sum |p_i - (x+i)|`.
- **Reduction:** Define `q_i = p_i - i`. Then the cost becomes `sum |q_i - x|`, which is minimized by choosing `x` as a median of the sorted array `q`. Since `p_i` is strictly increasing and `i` increases by one, `q_i` is nondecreasing, so `q[k // 2]` is a valid median.
- **Validity of median:** For the `i`-th one, `p_i >= i`, so `q_i >= 0`. Also, because there are `k-1-i` ones after it, `p_i <= N-k+i`, so `q_i <= N-k`. Therefore the chosen median is always a valid starting position for the final block.
- **Even `k`:** Any `x` between the two middle values of `q` is optimal. Choosing the upper median `q[k // 2]` is sufficient and gives the same minimum cost.
- **Complexity:** The algorithm scans the string once and stores one value per `1`, so it runs in `O(N)` time and `O(k)` memory, where `k` is the number of ones. This is easily fast enough for `N <= 500000`.
- **Integer size:** The answer can be quadratic in `N`, but Python integers are arbitrary precision, so no overflow handling is needed.
- **Edge cases:** If there is only one `1`, the shifted array has length one and the answer is `0`. If the ones are already contiguous, all `q_i` are equal and the answer is `0`. Leading and trailing zeros are handled naturally by the shifted positions.
- **Implementation details:** While enumerating the string, `len(shifted)` is the current index `i` of the one being processed, so `i - len(shifted)` directly forms `q_i`. The final answer is computed by summing absolute deviations from the median.
