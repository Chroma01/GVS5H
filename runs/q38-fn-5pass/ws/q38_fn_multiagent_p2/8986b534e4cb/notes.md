- **Direct leaves:** `compute_min_left_arrays` no longer uses lazy heaps. A feasible active window has at most one interval for each normalized left endpoint and each normalized right endpoint, so segment-tree leaves are updated directly to the opposite endpoint, or to `INF`/`0` on removal.
- **Why uniqueness holds:** The bad-pair characterization forbids two active intervals with the same normalized left or right endpoint. Input uniqueness also prevents duplicate normalized same-direction intervals, which would otherwise be feasible but harmless under constraints.
- **Endpoint counts:** `cntL` and `cntR` still detect shared normalized endpoints across both directions. They also guarantee that a leaf is empty before insertion and should be cleared on removal.
- **Precomputed ranges:** For each interval, compressed ranges for right endpoints in `(l, r)` and left endpoints in `(l, r)` are computed once during coordinate compression. This removes repeated `bisect` calls from the sliding-window conflict test.
- **Conflict test:** First checks endpoint counts. Then uses a min segment tree over right endpoints to detect `li < l < ri < r`, and a max segment tree over left endpoints to detect `l < li < r < ri`, both only within the same direction.
- **Sliding window:** Maintains a feasible active window. Since feasibility is hereditary and monotone, removing from the left until the new interval has no conflict yields the minimal feasible left endpoint for each right endpoint.
- **Query answer:** For query `[L, R]`, answer is Yes iff `min_left[R-1] <= L`.
- **Complexity:** Each interval is added once and removed at most once. Each add/remove does two point updates; each conflict test does two range queries. Total time is `O(M log M + Q)`, memory `O(M + N)`.
- **Input handling:** Queries are parsed and stored before running the solver, then the raw token list is deleted to reduce peak memory during the heavy computation.
- **Validation:** The built-in random validator remains. It compares the exact DSU/acyclicity oracle, the pair predicate, the optimized sliding solver, and a small pair-based solver on all subsets and all contiguous query ranges for small random cases.
- **Stress harness:** `run_stress_tests` generates a deterministic 200k-interval, 200k-query case with many crossings and alternating directions, checks monotonicity of `min_left`, and times the solver. It runs only when stdin is empty, after the random validator passes.
- **Superseded:** Lazy heap multisets and packed heap entries are removed; the old dynamic multiset leaf maintenance is no longer needed.
