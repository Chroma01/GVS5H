- **Complement symmetry:** Let `total` be the XOR of all elements. Choosing `K` elements is equivalent to excluding `N-K` elements, because `XOR(chosen) = total XOR XOR(excluded)`. Therefore enumerate `r = min(K, N-K)` indices. If `K <= N-K`, maximize the subset XOR directly (`mask = 0`). Otherwise maximize `total XOR subset_xor` (`mask = total`).
- **Enumeration bound:** The constraint gives `C(N, r) = C(N, K) <= 10^6`. Since `r <= N/2`, `r` is at most 11 because `C(24, 12) > 10^6`. Thus exhaustive enumeration is feasible.
- **Fast special cases:** `r = 0` means all elements are chosen, answer is `total`. `r = 1` is handled directly: if selecting one element, answer is `max(A)`; if excluding one element, answer is `max(total ^ A_i)`.
- **Combination iteration:** For `r >= 2`, maintain the current combination indices and current XOR. Generate the next lexicographic combination by finding the rightmost index not at its maximum, incrementing it, and resetting following indices. Update the XOR incrementally by XORing removed and added array values. This avoids tuple allocation and recomputing the XOR from scratch for every combination.
- **Correctness of incremental update:** Only indices from the pivot position onward change. The current XOR is updated by removing old values and adding new values for exactly those changed positions. Unchanged positions are skipped. Duplicate values are harmless because XOR is applied by index values, and equal values cancel naturally.
- **Complexity:** Input processing is `O(N)`. Enumeration is proportional to the number of combinations times the average number of changed positions, worst-case `O(r * C(N, r))`, with `r <= 11`. Memory is `O(N)` for the input array and small combination state.
- **Edge cases:** `K = N`, `K = 1`, `K = N-1`, all-zero arrays, and duplicate values are covered. Python integers handle values below `2^60` without issue.
