- **Core requirement:** Count substrings whose numeric value is divisible by their last digit, ignoring substrings ending in `0`. Leading zeros are allowed and make substrings distinct even when their numeric values are equal.
- **Chosen method:** Online residue dynamic programming. For each possible divisor `d = 1..9`, maintain counts of residues modulo `d` among all substrings ending at the previous position. When reading digit `x`, every previous substring extends to a new substring with residue `(r * 10 + x) % d`. Also add the one-character substring `x`.
- **Correctness invariant:** After processing position `i`, the table for divisor `d` contains residue counts for exactly all substrings ending at `i`. If the current digit is `x != 0`, every substring ending at `i` has last digit `x`, so the valid ones are exactly those with residue `0` modulo `x`.
- **Implementation detail:** The nine residue tables are stored in one flat list of length `1 + 2 + ... + 9 = 45`. `offset[d]` gives the start index of divisor `d`'s table. Precomputing transitions and single-character indices avoids repeated modulo arithmetic inside the main loop.
- **Complexity:** Each character updates all 45 residue states and adds 9 single-character states, so time is `O(45n) = O(n)` and extra memory is `O(1)`. For `n = 10^5`, this is about 4.5 million residue updates, safe in Python.
- **Edge cases:** A single nonzero digit returns `1`; strings ending in `0` contribute nothing at that position but still update residue states for future extensions; divisor `1` has only residue `0`, so all substrings ending in `1` are counted; the answer can exceed 32-bit range, but Python integers handle it.
- **Test results:** Checked the current implementation against the provided samples and several edge cases. Sample 1 `"12936"` returns `11`, sample 2 `"5701283"` returns `18`, and sample 3 `"1010101010"` returns `25`. Additional checks include `"0" -> 0`, `"1" -> 1`, `"10" -> 1`, `"11" -> 3`, `"12" -> 3`, `"13" -> 2`, `"01" -> 2`, `"012" -> 5`, and all-`'1'` strings where the answer is `n(n+1)//2`. No failures were found.
- **Performance note:** Using a flat list reduces list allocations from nine per character to one per character while preserving the same DP semantics.
- **Alternatives considered:** Prefix-normalized counting for divisors coprime to 10, digit-sum rules for 3 and 9, last-two/three-digit rules for 4 and 8, and specialized handling for 7. These can be faster in constant factor but are more error-prone; the uniform residue DP is robust and sufficient.
