- **Core formula:** For any even-length segment, the maximum score is the sum of the largest half minus the sum of the smallest half. Upper bound: each removed pair contributes larger minus smaller, so the larger endpoints form some half of the multiset, whose sum is at most the sum of the largest half. Construction: mark the largest half as plus and the smallest half as minus. While both signs remain, there is an adjacent opposite-sign pair; remove it. Since every plus value is at least every minus value, each removal scores plus minus, and the total telescopes to the formula.
- **Odd N reduction:** With odd N, exactly one element remains. It is never removed, so it separates the array and no pair can cross it. Therefore the number of elements on both sides must be even, meaning the remaining 0-based index is even (1-based odd). The left and right even segments are independent, so the answer is the maximum over even split indices of best(prefix before split) + best(suffix after split).
- **Even N implementation:** Sort the array and output `total - 2 * sum(smallest N/2)`, which is equivalent to sum(largest half) - sum(smallest half).
- **Order-statistic maintenance:** For odd N, compute all even prefix values by scanning left to right. Maintain two heaps: `lo` is a max-heap stored as negatives for the smallest floor(m/2) elements, and `up` is a min-heap for the largest ceil(m/2) elements. Keep running sums `slo` and `sup`. After each insertion, rebalance so `len(lo) == m // 2`, then swap the maximum of `lo` with the minimum of `up` if the order invariant is violated. When `m` is even, the segment value is `sup - slo`.
- **Suffix combination:** Store prefix values in `pref[k]` for prefix length `2k`. Scan from right to left with the same heap structure. When the current suffix length `n` is even, the unmatched index is `N - n - 1`, so the corresponding prefix length is `N - n - 1 = 2k`; combine `pref[k] + (sup - slo)`. The empty suffix case, where the last element remains, is initialized as `pref[-1]`.
- **Complexity:** Even N sorting is O(N log N). Odd N uses two heap scans with O(N) insertions and O(log N) heap operations each, so O(N log N) time and O(N) memory.
- **Edge cases:** N=2 is handled by sorting. N=3 checks the first and last possible remaining elements. Empty prefix/suffix values are zero. Duplicates are handled naturally by heap comparisons. Python integers avoid overflow.
