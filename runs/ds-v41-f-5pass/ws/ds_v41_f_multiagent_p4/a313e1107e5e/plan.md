Reduce each query to a 2D dominance maximum: precompute `dp[i]` = length of the longest strictly increasing subsequence ending at position `i`, then the answer is the maximum `dp[i]` among positions `i <= R` and values `A_i <= X`. Compute all `dp[i]` in `O(N log N)` using coordinate compression and a Fenwick tree for prefix maximum over values. Answer queries offline by sorting them by `X`, inserting positions into a second Fenwick tree ordered by index as `A_i <= X`, and taking prefix max up to `R`. This yields `O((N+Q) log N)` time and `O(N+Q)` memory.
