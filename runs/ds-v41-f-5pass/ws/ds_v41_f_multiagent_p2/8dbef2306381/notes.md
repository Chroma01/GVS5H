- **Problem model:** dp[p] = 1 iff p is good AND some dp[p-i] = 1 for i in [A,B]. Answer is dp[N]. Squares 1 and N are always good (constraints L_i>1, R_i<N), all bad intervals lie strictly inside.
- **Merge blocks:** Input intervals are sorted and disjoint (R_i<L_{i+1}); merge when L <= prev_R+1 to get maximal contiguous bad blocks. Only merged length matters for the "too long" test.
- **Case A==B:** Reachable set is fixed: 1,1+A,... so require (N-1)%A==0, else No. Then for each merged block, if it contains x ≡ 1 (mod A) (x = L + ((1-L)%A) <= R) the path lands on a bad square -> No. Otherwise Yes. A length>=A block is automatically caught because A consecutive integers cover every residue.
- **Length test for A<B:** If any merged block has length >= B, no single jump (max B) can clear it, and every block is left of N, so the answer is No. This also guarantees afterwards that every bad block has length <= B-1.
- **Sliding-window bitmask:** reach bit j = dp[cur-j], window size B. Step to next square: newbit = 1 iff (reach & maskA) != 0 where maskA has bits A-1..B-1; then reach = ((reach<<1)|newbit) & full, full=(1<<B)-1. For a bad block of length len: reach = (reach<<len) & full (all new bits are 0).
- **Saturation for long good runs:** For A<B, from one reachable position z, using increments A and A+1, every z+s with s >= A^2-A is reachable (Frobenius of {A,A+1}). The first reachable position inside a run lies within B of the run's start (its predecessor must fall before the run). Hence a good run of length >= THRESH = A^2+2B+5 forces the window to become all-ones, and it stays full for the rest of the run. So such runs are handled in O(1): set reach=full. Shorter runs are simulated step by step (< THRESH <= ~406 steps), and simulation breaks early once reach==full.
- **Reach never dies inside a good run:** if reach!=0, a set bit at position j (<B) reaches position A-1..B-1 before shifting out (since A-1<=B-1), producing a new bit0; so starting nonzero, reach stays nonzero and eventually saturates.
- **reach==0:** once the window is all zeros no future square can ever be reachable (predecessors must lie within B), so return No immediately. This can legitimately occur after a short bad block whose shift pushes all reachable bits past the window.
- **Complexity:** O(M * THRESH) worst case for simulations (~8e6 ops), O(M) for merging/checks. Memory O(M).
- **Verified:** Samples 1,2,3 all produce the expected Yes/No; sample 3 traced by hand through all four blocks. Edge cases checked: M=0; N-1 < A; block starting at 2; block length B-1 crossed by a length-B jump; A=1 (maskA=full).
- **Pitfalls avoided:** Don't assume a longer position is always better (no greedy); don't map A==B into the bitmask DP (no saturation, arithmetic progression only); don't forget to merge touching intervals before the length test.
