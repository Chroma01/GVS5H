- **Problem:** decide whether Levenshtein distance(S,T) <= K, K <= 20, |S|,|T| <= 5e5, unit insert/delete/replace. Also subsumes Problem C (K <= 20).
- **Approach (Landau-Vishkin furthest-reach + LCP jumps):** strip common prefix/suffix; reject if |len(S)-len(T)| > K; then V[c][d] = furthest i reachable with <= c edits on diagonal d = j - i, greedily LCP-extended. Band d in [-K,K] is exact: each edit changes d by at most 1, so |d|>K needs >K edits.
- **Recurrence:** carry V[d]; insert into S from V[d-1] at (i0, i0+d); delete from S from V[d+1] at (i0+1, i0+1+d); replace from V[d] at (i0+1, i0+1+d); each then LCP-extended. All with guards i'<=n, 0<=j<=m.
- **Correctness:** standard LV furthest-reaching is exact (further reach on the same diagonal dominates a nearer one because the alignment is a monotone prefix). Carry covers paths using < c edits. Band restriction is valid as argued above. Success test V[K+d_star] >= n; then i=n forces j=i+d_star=m.
- **LCP via rolling hash mod 2^61-1**, random odd base in [2^20,2^40): single-char early-out then gallop (double probe + binary refine); short LCPs O(1), long ones O(log n). Random base per run defeats anti-hash inputs.
- **Complexity:** precompute hashes O(n+m); LV loop is independent of n, ~K*(2K+1)*O(log) LCP probes. Memory O(n+m).
- **Brute-force cross-check (executed):** compared against O(nm) edit-distance DP over random cases with alphabet sizes 1-3, |S|,|T| in 1..9, K in 1..4 (~30k cases). Result: 0 mismatches; first failing input: none. Specific spot checks also pass: samples 1/2/3, 'ab'->'ba' K=2 (Yes) K=1 (No), 'abc'->'abcde' K=2 (Yes), one-side-empty within K, 'aa'->'a' K=1 (Yes), 'aa'->'a' K=0 (No), prefix/suffix-only differences.
- **Adversarial timing (executed, 5e5/5e5, K=20):** fully random lowercase -> ~0.55s; 'a'+X+'a' vs 'b'+X+'b' -> ~0.6s. Both dominated by the hash precompute; LV loop adds only microseconds. Comfortably under typical limits.
- **Why not banded O(nK) DP:** width 2K+1 over 5e5 rows is ~2e7 Python-level ops, too slow; LV is O(n+m) plus a tiny constant loop.
- **Edge handling:** empty-after-strip both => Yes; |n-m|>K => No; guards keep hash indices in range; d_star always within [-K,K] after the length check. K=0 also works (constraint says K>=1).
