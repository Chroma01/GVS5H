- **Core characterization:** For any edge, removing it splits the tree into two parts. In a valid decomposition into paths of K vertices, the edge is used iff neither side has size divisible by K. If the edge is unused, each side is a union of whole K-vertex paths, so both sizes are divisible by K. If the edge is used, exactly one path crosses it, contributing between 1 and K-1 vertices to either side, so that side's size is nonzero modulo K. Since the total size NK is divisible by K, this condition is independent of the rooting.
- **Forced graph:** Root the tree arbitrarily. For each parent-child edge, mark it as forced-used iff the child's subtree size modulo K is nonzero. In any valid decomposition, these forced edges are exactly the edges used by the paths. Therefore they must form N disjoint simple paths, each containing exactly K vertices. Conversely, if the forced edges form such paths, they directly give a valid decomposition.
- **Verification:** Compute subtree residues iteratively. Count forced degrees. If any vertex has forced degree greater than 2, reject. Then traverse connected components using only forced edges and require every component to have exactly K vertices. Because the forced graph is a subgraph of a tree, maximum forced degree at most 2 implies each connected component is a path. The explicit size check ensures each path has the required number of vertices.
- **Implementation details:** Use iterative DFS to avoid recursion depth issues. Store parent and discovery order. Subtree residues can be accumulated bottom-up without a second adjacency pass: initialize all residues to 1, process vertices in reverse DFS order, add each residue to its parent, and reduce modulo K. Forced degrees are then counted from nonzero child residues. Component traversal uses the original adjacency and tests whether an edge is forced by checking the parent-child relation and the child residue. Use a bytearray for visited vertices.
- **Complexity:** The algorithm runs in O(NK) time and uses O(NK) memory, which is within the limit of 2e5 vertices.
- **Pitfalls:** Do not rely only on degree bounds unless the component-size lemma is fully trusted; explicit component-size verification is safer. Root choice does not matter because the total vertex count is divisible by K. Isolated vertices are valid only when K=1; for K>1 they fail the component-size check. Forced degree must count only forced edges, not the original tree degree. K=1 is trivially Yes and is handled separately.
