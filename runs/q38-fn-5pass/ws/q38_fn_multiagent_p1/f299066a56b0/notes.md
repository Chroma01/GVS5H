- **Problem structure:** The mochi sizes are already sorted. A valid pair uses two distinct mochi, with the smaller one on top, requiring `2 * top <= bottom`. Since each pair consumes two mochi, the answer is at most `N // 2`.
- **Chosen approach:** Binary search the answer `K`. For a candidate `K`, test whether `K` pairs are possible by pairing the `K` smallest mochi with the `K` largest mochi in sorted order. The check is: for every `i` from `0` to `K-1`, verify `2 * A[i] <= A[N-K+i]`.
- **Correctness idea:** If some `K` pairs exist, let their tops and bottoms be sorted. In a threshold matching problem like this, if any matching exists, then matching sorted tops to sorted bottoms also works; otherwise some prefix of bottoms would be too small for the corresponding suffix of tops. Replacing the chosen tops by the `K` smallest mochi only makes the top side smaller, and replacing the chosen bottoms by the `K` largest mochi only makes the bottom side larger. Because `K <= N // 2`, these two sets are disjoint, so this canonical pairing is valid whenever any pairing of size `K` is valid.
- **Monotonicity:** If `K` pairs can be made, then `K-1` pairs can also be made by discarding one pair. Therefore feasibility is monotone and binary search is valid.
- **Implementation details:** Read all integers from standard input. Keep `lo` as the largest known feasible value and `hi` as the smallest known infeasible value, initialized to `0` and `N // 2 + 1`. Use integer multiplication for the half-size condition to avoid floating-point issues. The feasibility function returns early on the first failure.
- **Complexity:** Each feasibility check is `O(K)`, and binary search performs `O(log N)` checks. With `N <= 5 * 10^5`, this is comfortably fast. Extra memory is `O(1)` beyond the input array.
- **Edge cases:** `K = 0` is always feasible. For `N = 2`, the answer is either `0` or `1`. Equal sizes may make no pairs possible. Large values are safe because Python integers are arbitrary precision. Odd `N` simply leaves the middle element unused when necessary.
- **Pitfalls avoided:** Do not allow the same element to be used as both top and bottom; the split into first `K` and last `K` elements prevents this. Do not use floating-point division for `a <= b / 2`. Ensure the suffix starts at `N - K`, not `N - K - 1`.
