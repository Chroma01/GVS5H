- **Reduction:** Sort every pair so a < b. Subarray [l, r] contains both iff l <= a and r >= b. For fixed r, invalid left endpoints satisfy l <= M(r), where M(r) = max a over pairs with b <= r. Valid subarrays ending at r = r - M(r); base valid count = n(n+1)/2 - sum(M(r)).
- **Deletion gain:** Removing a pair raises the count at r only when that pair is the unique active pair attaining M. Let S(r) be the second-largest distinct active a value (0 if none); the gain at r is M(r) - S(r), else 0. Each pair's total gain sums over rows where it is the unique max owner.
- **Sweep invariants:** Bucket pairs by larger endpoint b, then sweep r = 1..n, activating pairs with b == r via cnt[a] += 1. The active set only grows, so only newly active distinct a's can change the top two: if a > M then S = M, M = a; elif a > S then S = a. Record owner[a] = pair id on the 0 -> 1 transition of cnt[a].
- **Row update:** After the whole batch for row r, add r - M to base. If M > 0 and cnt[M] == 1, add M - S to gain[owner[M]]. Ties (cnt[M] > 1) grant no gain because another copy keeps M active after removal.
- **Why S is the second distinct value:** On removing the unique max-owner, the new maximum equals the next distinct active a, which is exactly S. S rises correctly when intermediate values (between the old S and M) activate, so a simple "previous M" would be wrong.
- **Answer:** base + max(gain). Gains are nonnegative because S <= M, so deleting the best pair never hurts; exactly one pair is removed (m >= 1 guaranteed). The m == 0 branch is a robustness guard only.
- **Complexity:** O(n + m) time and O(n + m) memory. Fits n <= 1e5, m <= 2e5 easily; endpoint values bounded by n so plain arrays beat dicts.
- **Execution / verification:** Example 1 (n=4, [[2,3],[1,4]]): base = 6, gain = [3,0] -> 6 + 3 = 9 (expected 9). Example 2 (n=5, [[1,2],[2,5],[3,5]]): base = 9, gain = [3,0,1] -> 9 + 3 = 12 (expected 12). Both match exactly.
- **Stress tests:** Brute-force enumerator (all subarrays, all single-pair removals) run against the solution on many random cases with n up to 8, covering: m = 1; duplicate pairs; pairs sharing the larger endpoint; pairs sharing the smaller endpoint; nested pairs like [1,4],[1,3] (answer 9) and [1,4],[2,4] (answer 9); disjoint pairs [1,2],[3,4] (answer 7); and pairs whose unique max-owner changes mid-sweep. Zero mismatches observed.
- **Edge cases confirmed:** early rows with no active pairs (M = 0), rows where M is set then shared, and multi-copy max endpoints all behave correctly.
