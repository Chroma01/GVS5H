- **Approach:** Binary search the answer `L`. For each candidate `L`, use an exact automaton-style DP to compute the minimum number of flips needed so that the final string has no identical-character run longer than `L`. The answer is the smallest feasible `L`.
- **Why DP is required:** The tempting per-run count `m // (L + 1)` is not exact because flips at run boundaries can merge with neighboring opposite runs. Counterexample: `s = "1001"`, `L = 1`, `numOps = 1`; per-run says one flip in the `00` run, but either flip creates `11`, so two flips are needed. DP avoids this by constructing the final string directly.
- **DP state:** After processing a prefix, `dp0[r]` stores the minimum flips for a valid prefix ending in `0` with current run length `r`; `dp1[r]` is analogous for ending in `1`. Valid run lengths are `1..L`; index `0` is unused.
- **Initialization:** For the first character, choose final `0` or final `1`. The cost is `0` if it matches the original bit, otherwise `1`. The initial run length is `1`.
- **Transitions:** For each next original bit `x`, writing final `0` costs `x`, and writing final `1` costs `1 - x`. To switch to the opposite character, take the minimum over all run lengths of the previous opposite state and reset the run length to `1`. To extend the same character, shift states with run length `1..L-1` to `2..L`; states at length `L` cannot be extended.
- **Feasibility check:** After processing all characters, if the minimum DP value is at most `numOps`, then maximum run length `L` is achievable.
- **Pruning:** During DP, if both `min(dp0)` and `min(dp1)` already exceed `numOps`, no future transition can reduce the cost, so the check returns `False` early.
- **Monotonicity:** If a maximum run length `L` is feasible, then any larger `L` is also feasible because the constraint is relaxed. This justifies binary search.
- **Complexity:** Each feasibility check runs in `O(n * L)` time and `O(L)` memory. Binary search over `1..n` is easily fast enough for `n <= 1000`.
- **Validation:** Samples pass: `("000001", 1) -> 2`, `("0000", 2) -> 1`, `("0101", 0) -> 1`. Edge cases checked: `n = 1`, `numOps = 0`, all identical strings, already alternating strings, large `numOps`, and boundary-sensitive cases such as `1001` and `0110`. No failing case was found in the current implementation.
- **Superseded:** The PLAN's per-run greedy feasibility is not used; it can undercount operations due to boundary interactions.
