- **Model:** Normalize each conflicting pair to `(a, b)` with `a < b`. For a fixed left endpoint `l`, only pairs with `a >= l` are active. The first right endpoint that makes a subarray invalid is the minimum active `b`; valid subarrays starting at `l` are `min_b - l`, or `n + 1 - l` if no active pair exists.
- **Baseline:** Sweep `l` from `n` down to `1`, inserting pairs whose smaller endpoint equals `l`. Summing the valid counts gives the baseline with all pairs present.
- **Removal gain:** Removing pair `p` increases the count at left endpoint `l` only if `p` is active and is the unique active pair attaining `min_b`. The new first invalid endpoint becomes `second_b`, or `n + 1` if none exists, so the gain is `second_b - min_b`. Add this to `p`'s total gain for every such `l`.
- **State maintenance:** Maintain `min_b`, `min_count`, `min_id` when the minimum is unique, and `second_b` as the smallest distinct active `b` greater than `min_b`. Insert cases: smaller `b` shifts the old minimum to `second_b`; equal `b` destroys uniqueness; a `b` between `min_b` and `second_b` updates `second_b`. Process the entire bucket for a left endpoint before applying gains so duplicates with the same left endpoint are handled correctly.
- **Complexity and edges:** O(n + m) time and O(n + m) memory. Handles unsorted input, duplicate pairs, a single pair, multiple pairs sharing the same binding `b`, and zero-gain cases. Python integers safely cover totals up to `n(n + 1) / 2`.
- **Sample tests:** Example 1 returns 9 and Example 2 returns 12. A single pair returns all `n(n + 1) / 2` subarrays after removal. Duplicate pairs return the baseline because one duplicate remains. Pairs sharing the same binding `b` produce gain only while one of them is the unique active minimum before the other becomes active. Zero-gain cases return the baseline unchanged. Verdict: sample and edge tests pass; no code changes required.
