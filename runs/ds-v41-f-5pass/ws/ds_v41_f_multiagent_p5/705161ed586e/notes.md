- **Model:** target = partition of `caption` into runs each of length >= 3; run of char `c` over `i..j` costs `sum|cap[t]-c|`. Minimise total cost, then return lexicographically smallest optimal target. `n<=5e4`.
- **Feasibility:** `n<3` -> `""`. For `n>=3` always feasible (e.g. all one char).
- **DP (right-to-left), state `V(i,c,l)` = min cost to fill suffix `i..n-1` given a run of `c` whose current length is `l` ending at `i-1`:** `A[i][c]=V(i,c,1)=cost[i][c]+V(i+1,c,2)`, `B[i][c]=V(i,c,2)=cost[i][c]+V(i+1,c,3)`, `C[i][c]=V(i,c,3)=min(cost[i][c]+C[i+1][c], min_{c'!=c} cost[i][c']+A[i+1][c'])`. Bases `A[n]=B[n]=INF`, `C[n]=0`. Answer `min_c cost[0][c]+A[1][c]`.
- **Excluding `c'=c` in the switch is safe:** by backward induction `C[p][c]<=B[p][c]<=A[p][c]` (each follows from the continuation term), so the continue branch dominates any same-char restart; no optimal solution is lost.
- **Storage:** only `C` stored, size `(n+3)*26` using `array('i')`; `A/B` recomputed on demand. Distances precomputed in a 26x26 table, per-position row hoisted as `Do`. All index reads `n..n+2` hit the zero-initialised tail.
- **min1/min2:** per position build `val[c']=cost[pos][c']+A[pos+1][c']` via `Do+D1+D2+C` (needs `pos<=n-3`, else switch is `INF`). Track smallest (`min1,arg1`) and second (`min2`); best switch for `c` is `min1` if `arg1!=c` else `min2`. Strict `<` keeps `arg1` the smallest argmin so ties resolve correctly. For `pos=n-3`, `A[n-2][c']=cost[n-2][c']+cost[n-1][c']` is finite and correctly used; for `pos>=n-2` no new run fits, switch=INF.
- **Reconstruction:** left-to-right greedy; state `(prev_c, prev_l, cur)` with `cur` exactly equal to the DP value of that state, so at least one transition matches. Legal moves: `l=0`->any `x`, suffix `A[1][x]`; `l=1`->forced `prev_c`, suffix `B[i+1][x]`; `l=2`->forced, suffix `C[i+1][x]`; `l=3`->`prev_c` (suffix `C[i+1]`) or new `x` (suffix `A[i+1][x]`). Scanning `x` ascending yields the lexicographically smallest optimal target; every step appends exactly one char so result length is always `n`. Inline formulas for `A/B` are guarded so `i+1>=n` never indexes `Dr[n]`.
- **Complexity:** `O(26n)` time (~2.6M inner steps + <=1.3M reconstruction) and `O(26n)` memory (~5MB at `n=5e4`). Values fit int32.
- **Verification (executed):** exhaustive all strings length 1..4 over `{'a','b','c'}` (120 cases) and 2000 random strings each of length 5 and 6 over `{'a','b','c','d'}` (4000 cases) compared against a brute force that enumerates every partition into parts >=3 and every 26^runs character assignment, selecting min cost then lexicographically smallest. Result: PASS, 4120/4120. Examples: `'cdcd'->'cccc'` (cost 2, beats `'dddd'`), `'aca'->'aaa'` (cost 2), `'bc'->''` (n=2). Extra traces agree: `'aaab'->'aaaa'`, `'aababb'->'aaabbb'`, `'bbbaaa'->'bbbaaa'`, `'ccdd'->'cccc'` (tie cost 2, lex-smallest). Reconstruction always produced a string of length exactly `n` (no no-match transition fired); the added `else: return ""` guards are dead code.
- **Performance (executed on n=5e4, all `'a'`, all `'z'`, random):** completes within a few seconds and ~5MB, O(26n), no index errors at `pos=n-1 / n-2` (tail tail-guards exercised).
