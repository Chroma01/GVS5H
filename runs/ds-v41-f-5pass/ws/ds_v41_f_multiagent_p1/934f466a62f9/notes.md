- **Reduction:** Pairing price = max of three coordinate sums. Colouring both cakes of a pair with the winning coordinate makes every colour count even and preserves total. Conversely, 2K items with even colour counts can be paired inside colour classes with price ≥ assigned sum. Hence `answer = max over (choose 2K items, assign X/Y/Z, all counts even) of assigned-coordinate sum`.
- **Upper bound:** `W_i = max(X_i,Y_i,Z_i)`, base colour = argmax (tie X>Y>Z). Any solution uses 2K items and scores ≤ sum of their W ≤ `G` = sum of the M=2K largest W. So take those items as the *base* configuration, value G.
- **Parity:** M even, 3 colours ⇒ odd-count colours number 0 or 2. If 0, answer is G. Otherwise odd colours A,B, buffer C.
- **Op model:** An op changes parity of exactly two colours (its flip set): recolor base-s item to t ⇒ {s,t}; swap (drop base-s item, add non-base item coloured t) ⇒ {s,t}. Cost = `W_i - coord_t(i)` (recolor) or `W_i - coord_t(j)` (swap), both ≥0 since base items are top-M by W and coord ≤ W.
- **At most two ops suffice:** Any valid config decomposes (relative to base) into **pairwise disjoint** ops with nonnegative costs summing to its loss and XOR of flip sets equal to {A,B}. Given counts x({A,B}), y({A,C}), z({B,C}) with the XOR condition, either x is odd (take one {A,B} op) or y,z are both odd (take one {A,C} and one {B,C}). That sub-multiset is disjoint, keeps parity correct, and its loss ≤ original. So `answer = G - min loss over ≤2 disjoint ops from this base` (valid for any tie-break).
- **Enumeration:** Singles (A→B, B→A); pairs are the four direction combinations of {A,C} and {B,C} (so both odd-colour items painted to C, or buffer used as source, are covered). Each op is a recolor or a swap.
- **Candidate pruning is safe:** In an optimal pair each op is min-cost *given the other*, which uses at most one base and one non-base item of the other op. Removal choice = smallest W base-s avoiding one item (top-2); addition = largest coord_t non-base avoiding one item (top-2); recolor = smallest `W-coord_t` avoiding one base item (top-2). Top-2 per sub-role suffices; code keeps top-5. Any candidate pair examined is a genuine achievable config, so the reported value never exceeds the true optimum.
- **Ties:** Boundary W-ties and argmax-ties correspond to zero-cost swaps/recolors that the same enumeration already considers, so a fixed tie-break cannot lose optimality.
- **Verification:** Samples 1 & 2 reproduce (12; 209, 333). An independent brute-force reference (enumerate all C(N,2K) subsets and all perfect matchings of each, take max total price) was run against the solution on over 8000 random small cases (N ≤ 8, K ≤ floor(N/2), values in 0..6 to force ties, plus edge cases M=N, all-identical items, and tie-heavy coordinate collisions). No mismatch was found. Hand-enumerated small cases also agree.
- **Complexity:** O(N log N) per test for the sort, plus a constant (~a few hundred) candidate/combination checks; total over tests fine for ΣN ≤ 1e5.
