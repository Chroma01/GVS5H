- **Mathematical reduction:** A 400 number has exactly two distinct prime factors, and every exponent in its prime factorization is even. Therefore it can be written as `p^(2a) * q^(2b) = (p^a * q^b)^2`, where `p` and `q` are distinct primes and `a, b >= 1`. Conversely, squaring any integer with exactly two distinct prime factors gives a valid 400 number. Thus the problem reduces to finding the largest square `r^2 <= A` where `r` has exactly two distinct prime factors.
- **Search bound:** Since `A <= 10^12`, the square root `r` is at most `10^6`. It is enough to precompute all valid roots up to `isqrt(max(A))`, not up to `10^12`.
- **Precomputation strategy:** Read all queries first, compute `max_a`, set `limit = isqrt(max_a)`, then sieve all integers up to `limit` to count distinct prime factors. Collect squares of integers with exactly two distinct prime factors into a sorted list.
- **Sieve details:** Use a `bytearray` named `omega` where `omega[n]` stores the number of distinct prime factors of `n`. For each `p` from `2` to `limit`, if `omega[p] == 0`, then `p` is prime, so increment `omega[m]` for every multiple `m` of `p`. This counts distinct prime factors, not multiplicity. The maximum number of distinct prime factors for numbers up to `10^6` is small (at most 7), so `bytearray` is safe.
- **Query answering:** The list of squares is naturally sorted because roots are iterated increasingly. For each query `A`, use `bisect_right(forty_numbers, A) - 1` to get the largest 400 number not exceeding `A`. The problem guarantees an answer exists; the smallest valid number is `36 = 6^2`.
- **Correctness argument:** The sieve correctly computes the number of distinct prime factors for every root up to `limit`. The collected list contains exactly all 400 numbers up to `max_a`, because each valid root produces its square and no invalid root is included. Binary search returns the predecessor in this sorted list, which is exactly the largest valid number not exceeding the query.
- **Complexity:** Let `L = isqrt(max_a) <= 10^6`. The sieve costs `O(L log log L)` increments and `O(L)` outer checks. Building the list costs `O(L)`. Each query costs `O(log K)`, where `K` is the number of valid roots, roughly a few hundred thousand. Total is easily fast enough for `Q <= 2 * 10^5`.
- **Memory:** `omega` uses about 1 MB. The query list and answer list are proportional to `Q`, and the list of 400 numbers is well within limits.
- **Pitfalls handled:** Use integer `isqrt`, not floating-point square root. Count distinct prime factors, not total prime factors with multiplicity. Sieve up to the square-root bound, not the original `10^12` bound. Include root `6` so `36` is always available. Avoid duplicate generation by using the sieve over roots directly.
