- **Model:** constraints i→A_i form a functional graph. Each weakly connected component has exactly one directed cycle; the inequalities force all cycle nodes to share one common value c. Non-cycle nodes form in-trees rooted at cycle nodes (parent of u is A_u), and along these trees values are non-increasing toward leaves.
- **Tree DP:** let g_v(c) = number of valid assignments in v's subtree given x_v=c. Since x_child ≤ x_v, g_v(c)=∏_{tree children u} P_u(c) where P_u(c)=Σ_{t≤c} g_u(t). Leaves give g=1, P(c)=c. Compute via prefix sums, O(M) per node.
- **Cycle combine:** for cycle node v with attached trees, h_v(c)=∏_{tree children u} P_u(c). For common cycle value c the component count is ∏_{v in cycle} h_v(c); summing c=1..M yields the component contribution.
- **Answer:** product over all components of their contributions, mod 998244353. Sample 2: single self-loop root with 3 leaves ⇒ Σ c³ = 2025.
- **Complexity:** O(N·M) time; each tree edge costs O(M) (multiplication) plus O(M) prefix per node, and cycle-node cross-multiplication totals ≤ N·M. N,M ≤ 2025 ⇒ ~4–8M simple ops, fine.
- **Implementation details:** indegree pruning identifies cycle nodes; BFS from cycle nodes gives parent-before-child order, reversed gives leaves-first. Leaves share one immutable `ident` list (c-values) to save memory. Child arrays are freed (`P[u]=None`) after their single consumer reads them (each non-cycle node has exactly one parent). Prefix step uses a single conditional subtract, valid because both operands are < MOD.
- **Edge cases:** self-loops handled as length-1 cycles; M=1 yields answer 1; a cycle with no attached trees contributes exactly M; DAG-free input impossible in a functional graph (always ≥1 cycle).
- **Verification:** hand-traced sample 1 → 6, sample 2 → 2025, sample 3 → 10010 (component {4,5} gives Σ c²·c(c+1)(2c+1)/6 = 2002, component {1,7,9} gives 5, product 10010). All match; no failing case found.
- **Caution:** never mutate a stored P array in place (aliasing to shared `ident` or to a cycle `comp`); every multiply/prefix builds a fresh list. `comp = pu` aliasing on the first child is safe because subsequent operations rebind `comp` to new lists.
