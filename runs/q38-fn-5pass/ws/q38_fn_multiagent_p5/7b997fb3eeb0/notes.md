- **Core reduction:** For any sorted interval of length m, if K pairs are possible, then the K smallest elements can be used as tops and the K largest as bottoms. If some K tops and K bottoms can be matched, sorting them gives 2*t_i <= b_i; replacing tops by smaller elements and bottoms by larger elements preserves feasibility. Thus for query [L, R], K is feasible iff for every t=0..K-1, 2*A[L+t] <= A[R-K+1+t].
- **Auxiliary array:** Let f[i] be the first global index with A[f] >= 2*A[i]. Compute all f[i] in O(N) with a moving pointer because A is sorted. Define h[i] = f[i] - i if f exists, otherwise a sentinel N+1. For query length m, the condition becomes max(h[L..L+K-1]) <= m-K.
- **Monotonicity:** The predicate P(K) = max(h[L..L+K-1]) <= m-K is monotone decreasing in K: if it holds for K, it holds for K-1. This allows binary search or binary lifting.
- **Query method:** Instead of binary searching K, binary lift K using powers of two. Maintain K, cur_max = max h over the already chosen prefix, rem = floor(m/2)-K, and limit = m-K. For each power p descending, candidate K+p is feasible iff max(cur_max, max h[L+K .. L+K+p-1]) <= limit-p. The block maximum is one sparse-table lookup because p is a power of two.
- **Sparse table:** Build st[b][i] = max h[i .. i+2^b-1]. Only levels up to floor(log2(N/2)) are needed. Build each level from the previous one. Rows store existing integer references in CPython and are memory-efficient enough for N=2e5.
- **Implementation details:** Use 0-indexing internally. The sentinel N+1 is larger than any possible m-K for K>=1, so tops with no valid bottom always fail. cur_max starts at 0, safe because all real h values are positive. Checking cur_max <= new_limit before reading the sparse-table row skips impossible candidates early.
- **Input/output handling:** Read all integers at once, slice A and queries, then delete the full data list to reduce retained memory. Output answers as a joined list of strings.
- **Pitfalls:** The pairing condition is inclusive: 2*a <= b, so lower_bound uses A[j] < 2*A[i]. Off-by-one risk in rearranging f[i] <= R-K+1+i to h[i] <= m-K. The top and bottom blocks must be disjoint; this is guaranteed by K <= floor(m/2). Sparse-table row length is N-2^b+1, and binary lifting only accesses valid starts because L+K+p-1 <= R.
- **Complexity:** Precomputation O(N log N), each query O(log N), total O((N+Q) log N). Memory O(N log N), about 3.2 million table entries for N=2e5.
- **Verification:** Hand-checked sample 1: queries produce 2, 3, 1, 0, 5. Edge cases checked: N=2 with valid/invalid pair, all duplicates, no valid bottom, full interval, and cases where a high power is feasible but the next lower bit is not.
