- **Core idea:** Root the tree at node 0. For each node considered as the descendant endpoint of a special path, maintain the shallowest ancestor depth `left` such that all values on the current root-to-node path from `left` to the current depth are unique. Because all edge lengths are positive, the longest special path ending at that node is obtained by choosing this shallowest valid ancestor.
- **Sliding window on a tree path:** During DFS, the current path is the stack of ancestors. When entering a node with value `x`, if `x` was last seen at depth `d` on the current path, any valid window ending at the new node must start after `d`, so `left = max(left, d + 1)`. The previous window was already unique, and only the new value can introduce a duplicate, so this update is sufficient and gives the minimal valid start depth.
- **State restoration:** The traversal is iterative using enter/exit events. On entering a node, store the previous `left` and the previous last-seen depth for the node's value, then update them and append the current root distance to `path_dist`. On exiting, pop the distance, restore the last-seen depth or remove the value if it was absent before, and restore `left`. This ensures sibling subtrees see exactly the parent path state.
- **Distance and node count:** `path_dist[depth]` stores the root distance of the ancestor at that depth on the current path. For current node at depth `depth` and root distance `dist`, the best path ending here has weighted length `dist - path_dist[left]` and node count `depth - left + 1`. The global answer keeps the maximum length, and among ties the minimum node count.
- **Why only the highest valid ancestor is needed:** For a fixed endpoint, moving the start upward while preserving uniqueness adds positive edge lengths, strictly increasing the weighted length. Therefore a lower start ending at the same node cannot tie the maximum length for that endpoint. Since every special path has some endpoint, checking the highest valid start for every endpoint finds all globally longest paths and the minimum node count among them.
- **Implementation details:** Build an adjacency list with edge weights. Use a stack of tuples `(state, node, parent, depth, dist, prev_last, prev_left)`, where state 0 means enter and state 1 means exit. Use a dictionary for last-seen depths to support arbitrary value ranges. Initialize the answer to `[0, 1]` because a single-node path is always valid. Handle empty input defensively.
- **Complexity:** Each node is entered and exited once, and each undirected edge is inspected twice. Expected time complexity is O(n), and memory usage is O(n) for adjacency, stack, path distances, and last-seen state.
