- **Task:** LeetCode 3464. Pick k boundary points of a square to maximize the minimum pairwise Manhattan distance. n <= 15000, k <= 25, side <= 1e9.
- **Cycle mapping:** bottom (x,0) -> x; right (side,y) -> side+y; top (x,side) -> 2*side+(side-x); left (0,y) -> 3*side+(side-y). Corners resolved by branch order y==0 then y==side then x==0 else right; any consistent assignment is fine.
- **Geometry lemma:** for D <= side, two boundary points have Manhattan distance < D iff their cycle positions (on length 4*side) are at cyclic distance < D. Same-side and adjacent-side pairs have Manhattan exactly equal to the through-corner arc, which is also the smaller cyclic arc (it is <= 2*side while the other arc is >= 2*side). Opposite-side pairs have Manhattan >= side and cyclic distance >= side. So below D = side the two notions agree.
- **Answer bound:** the answer never exceeds side, so binary search on [0, side] is complete for k >= 4.
- **Feasibility(D):** does there exist a set of k cycle positions with all pairwise cyclic distances >= D? Fix the chosen point with smallest position i; all others lie in (pos_i, pos_i + L - D], and taking the earliest feasible next point each time is optimal (standard exchange argument). Max over all starts i; feasible iff some greedy run reaches k points.
- **Check implementation:** doubled array pos2 (length 2n, strictly increasing, sentinel index m). nxt[i] = first j with pos2[j] >= pos2[i] + D via a single monotone two-pointer pass (O(2n)). Binary lifting over nxt with levels = (k-1).bit_length() gives the (k-1)-th greedy successor of every start in O(log k) per start. Start i works iff that successor exists and pos2[succ] <= pos2[i] + L - D.
- **Deadline is essential:** the wrap-around gap (last chosen back to first) must also be >= D, exactly the pos2[succ] <= pos2[i] + L - D bound.
- **Index safety:** for D >= 1, pos2[i] + L - D < pos2[i] + n... all selected doubled indices stay in [i, i+n), i.e. distinct physical points, never re-selecting the start.
- **Complexity:** ~30 binary-search steps, each O(n log k). n = 15000 -> each call well under a second in CPython; memory O(n log k) ints.
- **Validator run in this environment with python3 (see NOTES update):** sample block, stress block, and timing block all executed successfully.
- **Brute force:** exhaustive over all k-subsets, taking min pairwise Manhattan then max; used for stress on side <= 4 (<= 16 boundary lattice points), skipping trials with comb(n,k)*C(k,2) > 200000.
