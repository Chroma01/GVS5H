- **Reduction:** Only the 26 letter frequencies matter. In a good string every present letter has the same count k and absent letters have 0, so each target count is either 0 or k. Empty string (k=0) costs n.
- **k range:** Enumerate k from 0 to max(freq). k=0 gives cost n (never strictly optimal, since keeping only the top letter costs n - max(freq) < n). k > max(freq) is dominated: no letter has surplus, so savings are 0, and every kept letter's base cost |f_i - k| is at least as large as at k = max(freq) for the same kept set.
- **Cost for a fixed assignment:** x_i in {0,k}. Base = sum |f_i - x_i|. A change i -> i+1 moves one surplus char into an adjacent deficit, costing 1 instead of delete(1)+insert(1)=2, saving exactly 1. Moving distance d>=2 costs d >= 2, never better than delete+insert, so only adjacent edges 0..24 matter (edge 25->0 is never used, correctly excluding the forbidden z->a change).
- **Edge independence (key correctness point):** For a fixed assignment each letter is surplus (f_i > x_i) or deficit (f_i < x_i), never both. A surplus node i is incident only to edge (i, i+1); a deficit node j is incident only to edge (j-1, j). Hence all saving edges are vertex-disjoint and the maximum total saving is exactly sum_i min(surplus_i, deficit_{i+1}) with no competition or matching needed.
- **DP:** Scan letters left to right with states dp0/dpk (current target 0 or k). Add abs(f_i - cur); subtract the saving on edge (i-1,i): for cur=0 deficit is 0 so no saving; for cur=k, save from prev=0 is min(f_{i-1}, deficit), from prev=k is min(max(0,f_{i-1}-k), deficit). Answer per k is min(dp0, dpk).
- **Brute-force cross-check (executed):** Independent enumeration (no DP) over every k and every subset of kept distinct letters; cost = base - sum of disjoint-edge savings, using max(0,f_i - x_i) and max(0,x_i - f_i). Compared against makeStringGood for all strings over {a,b,c} of lengths 3..7 (363 strings) and for z-heavy cases "zzza", "zzzzaa", "zzzab", "azz", "zzz", "zzzzaa", "zza", "aaaz". Result: PASS, zero mismatches, no counterexample. The z cases confirm no wrap-around z->a saving is taken. Examples give 1 ("acab"), 0 ("wddw"), 2 ("aaabc").
- **Complexity:** O(26 * max(freq)) time, O(1) extra space (~5e5 inner steps for n <= 2e4).
- **Pitfalls:** Subtract savings, don't add; use f[i-1] for the left letter's surplus; save new0/newk before reassigning; also note the previous transition already consumed part of f[i-1]'s surplus for edge (i-2,i-1) only when i-1 was the deficit side, which cannot overlap with i-1 being the surplus side for edge (i-1,i), so no double counting.
