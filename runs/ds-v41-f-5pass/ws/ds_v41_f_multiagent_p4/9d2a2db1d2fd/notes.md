- **Problem reduction:** Stairs cost only for vertical moves; walkways are free if the adjacent building has enough floors. For cells u,v with maximin bottleneck m (max over paths of the minimum building height along the path), the optimal cost is `(hi-lo) + 2*max(0, lo-m)` where `lo=min(Y,Z)`, `hi=max(Y,Z)`. Reason: pick a single level x and go down/up there; cost = `|Y-x|+|Z-x|`, minimised at x=lo if lo<=m, else at x=m. Special case u==v: m=F[u].
- **Bottleneck via cell-sorted DSU:** Instead of building/sorting explicit edges, sort all cells by F descending. When cell u is processed (marked added), for each already-added neighbour the edge capacity is `min(F_u,F_nb)=F_u` (neighbour added earlier => F_nb>=F_u). Union the roots at capacity `cap=F_u`. This visits each adjacency exactly once and processes merges in non-increasing weight order, so Kruskal correctness holds (ties fine).
- **Query resolution with plain sets:** Each unresolved query id is stored in BOTH endpoint cells' sets: `qs[u].add(qid)` and `qs[v].add(qid)` (lazy create `{qid}` from None). On merging roots ru,rv, resolve any id present in both sets (`m[qid]=cap`, remove from A), otherwise move ids from the smaller set into the larger (small-to-large). Then `qs[rv]=None`, `parent[rv]=ru`. An id appears in a component's set iff one endpoint is inside it; it is resolved exactly when the two endpoint components merge.
- **Union by size:** merge_roots swaps ru,rv by DSU `size` (returning the new root) so the caller can keep `ru` current; set small-to-large is an INDEPENDENT swap of A,B by `len`. Use iterative `find` with path halving (parent pointer default-arg for speed).
- **Representing empty:** store sets only when non-empty; empty becomes None. merge_roots handles `B is None` (nothing), `A is None` (adopt B), else iterate B into A.
- **Answer loop:** recompute from `lo_arr/hi_arr/m`; no need to sort queries.
- **Complexity:** O(N log N) for the cell sort + O((N+Q) α) union/find + O(Q log Q) total small-to-large element moves; memory O(N+Q). N=H*W<=250000, Q<=2e5 — comfortable.
- **Verified sample 1:** order of processing yields m[q1]=10, m[q0]=3, giving answers 10 and 2 exactly.
- **Superseded approaches:** the previous int/set hybrid (None/int/set) and the explicit packed-edge Kruskal were fragile and error-prone; the plain-set + cell-sorted-DSU version is simpler, correct, and avoids packed-bit arithmetic.
