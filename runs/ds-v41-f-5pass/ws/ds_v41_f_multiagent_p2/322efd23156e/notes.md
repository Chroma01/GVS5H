- **Problem shape:** Each food has exactly one vitamin, so choices for vitamins 1/2/3 are independent except they share the single calorie budget X. Objective is the bottleneck (minimum) across the three vitamin totals.
- **Core DP:** For each vitamin v define f_v(c) = max amount of v obtainable using at most c calories from v's foods. This is a 0/1 knapsack over calories. Zero-initialized descending loop gives at-most semantics directly (f_v nondecreasing automatically; prefix-max pass is a cheap safety net and makes bisect valid).
- **Feasibility test:** For target M, cost_v(M) = smallest c with f_v(c) >= M (found via bisect_left on the monotone f_v; result X+1 means unreachable). M is feasible iff sum of the three costs <= X. Feasibility is monotone in M, so binary search over [0, UB].
- **Upper bound UB:** min over v of max_v f_v(X) (equivalently min of group totals). Using f_v(X) is tighter than raw group total sums.
- **Edge cases:** Empty vitamin group -> f all zeros -> UB becomes 0 -> answer 0 (sample 2). M=0 always feasible (cost 0 each). C_i <= X is guaranteed, so loops are safe; guard with idx > X for unreachable.
- **Item-reduction trick:** For a fixed calorie cost c, at most floor(X/c) copies can ever be in a feasible subset. Keeping only that many largest amounts per cost is safe (swap any used item for a larger unused one of same cost). Cheap O(N log N) preprocessing; worst case unchanged but helps on clustered costs.
- **Complexity:** O(N*X) for all DPs (~25M worst case) + O(log(UB) * 3 * log X) for the search. Chosen loop form (local, simple `if`) is the practical fast path in CPython; list-comprehension/slice variants trade allocation for per-element speed.
- **Verified:** Sample 1 -> 3 (test M=3 gives costs 5+5+10=20<=25; M=4 needs 5+10+15=30>25). Sample 2 -> 0.
- **Pitfalls avoided:** Do NOT use exact-capacity DP without prefix maxima (breaks monotone bisect). Do NOT drop "dominated" items by amount/cost within a group — multiple items with the same cost can all be taken, so such removal is invalid.
- **Handling of large A_i:** A_i up to 2e5 but X only 5000, so state must be calories, never vitamin amount. Vitamin totals can be up to ~1e9, so the search range is large but logarithmic.
