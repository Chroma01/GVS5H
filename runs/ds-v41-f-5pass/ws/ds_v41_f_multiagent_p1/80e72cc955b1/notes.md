- **Problem model:** For x >= 1, c(x) = number of /4 steps to reach 0 = floor(log_4 x) + 1. c = k exactly on [4^(k-1), 4^k - 1]: k=1 on [1,3], k=2 on [4,15], k=3 on [16,63], ... For r <= 1e9 only k <= 15 (4^14 = 268435456 <= 1e9 < 4^15).
- **Per-query formula:** With D = sum of c(x) over [l,r] and M = max c(x) = c(r) (c is nondecreasing), the answer is max(M, ceil(D/2)) = max(c(r), (D+1)//2). Two lower bounds: each op consumes exactly 2 divisions so >= ceil(D/2); the element with c=M must be selected M times so >= M. Both are achievable: a single element with residual 1 can be paired with any other nonzero element (it zeroes in that same op), so pairings never waste and the bound is tight.
- **Worked samples:** [1,2]: c(1)+c(2)=2, c(2)=1 -> max(1,1)=1. [2,4]: c=1+1+2=4, c(4)=2 -> max(2,2)=2. Sum=3. [2,6]: c=1+1+2+2+2=8, c(6)=2 -> max(2,4)=4. Both match expected outputs (3 and 4).
- **Prefix computation:** lows/highs/ks built for the 15 intervals; pre[i] = cumulative c over all intervals before i. F(n) = pre[i] + ks[i]*(n - lows[i] + 1) via binary search for the interval containing n; D = F(r) - F(l-1). O(log 15) per call.
