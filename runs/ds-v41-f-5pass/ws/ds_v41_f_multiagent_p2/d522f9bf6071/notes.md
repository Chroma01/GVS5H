- **Problem:** pick up to 4 pairwise non-overlapping intervals (strict: `r_prev < l_next`; shared boundary overlaps), maximize weight sum, return lexicographically smallest sorted 0-based index array among max-weight choices.
- **Algorithm:** sort intervals by right endpoint. `p[i] = bisect_left(rs, l_i)` = count of intervals with `r < l_i`. DP over first `i` sorted intervals and exact count `c=0..4`: `dp[i][0]=(0,())`; for `c>=1`, `dp[i][c] = better(dp[i-1][c], dp[p[i]][c-1] + interval_i)`. "better" = higher weight, tie broken by lexicographically smaller sorted index tuple.
- **Correctness (DP):** in any non-overlapping set, the interval with the largest right endpoint has all others strictly left, so the recurrence `dp[p[i]][c-1]+i` (interval `i` used as the last one) together with `dp[i-1][c]` covers all sets. `p[i]` excludes equal right endpoints (they overlap), which is correct.
- **Tie-break correctness (verified by proof):** all tuples in a single state have equal length `c` (distinct indices), so no tuple is a prefix of another there. For same-length `A < B` and a fresh index `i`, `sorted(A∪{i}) < sorted(B∪{i})`: at the first differing position `k` (`A[k]<B[k]`, common prefix `C`), the elements `< A[k]` are `C` plus `{i}` iff `i<A[k]` in BOTH unions; the next element is `A[k]` for A vs `B[k]`/`i` (both `>A[k]`) for B. Hence keeping only the single best predecessor per state is sufficient.
- **Prefix caveat:** the general "adding i preserves order" claim FAILS for different-length tuples (e.g. `(1,)<(1,2)` but `(1,5)>(1,2,5)`). It is safe here only because state tuples have equal length; the final cross-`c` comparison uses Python tuple comparison directly, which correctly implements the shorter-array rule (e.g. `(2,)` vs `(0,1)` -> `(0,1)` wins).
- **Complexity:** `O(n log n)` time (sort + bisect + `O(4)` per state with `O(4)` tuple insert), `O(n*5)` space. `n<=5e4` fits easily.
- **Edge cases:** boundary-sharing overlaps handled by strict `bisect_left`; equal right endpoints cannot combine; duplicate weights / identical intervals; positive weights (`1..1e9`) mean the empty choice never wins for `n>=1`; large coordinates fine.
- **Verification (SAMPLE TESTS verdict):** Example 1 -> `[2,3]` (weight 8) PASS; Example 2 -> `[1,3,5,6]` (weight 21) PASS.
- **Stress test verdict:** compared against a brute force enumerating all subsets of size `<=4` on ~20k random cases (`n<=8`, coords in `[1,6]`, weights in `[1,4]` to force many ties), including equal endpoints and duplicate intervals. Zero mismatches: the single-tuple-per-state DP always returned the lex-smallest max-weight answer. No minimal counterexample found.
- **Implementation notes:** 1-indexed `dp`; `dp[p][c-1]` possible `None` guarded; manual sorted insert of the new index (length `<=4`); final scan over `c=0..4`.
