- **Feasibility:** A red move flips the parity of `r+c`, while a blue diagonal move preserves it, so `R` must be even. If `R=0`, every move is blue and flips the row parity, so `B` must be even. These conditions are sufficient: all cases with `R` even and (`B` even or `R>0`) are constructed.
- **Coordinates:** Internally use `x` as column and `y` as row. General output uses `r = y + OFF`, `c = x + OFF` with `OFF = 1_000_000`. All generated general coordinates are within `O(R+B)` of the origin, so they safely lie in `[1, 10^9]`.
- **Red-only (`R` even):** For `R=2`, use two horizontally adjacent squares. For `R>=4`, use a `2 x (R/2)` rectangle perimeter: top row left-to-right, bottom row right-to-left.
- **Blue-only (`B` even):** For `B=2`, use two diagonal-adjacent squares. For `B>=4`, let `m=B/2`; output `(0,0)`, then `(i,2-i)` for `i=1..m`, then `(i,-i)` for `i=m-1..1`. Consecutive differences are diagonal, and the last vertex returns to `(0,0)` diagonally.
- **Mixed even (`R,B` positive even):** Let `a=R/2`, `k=B/2`. Starting from `(0,0)`, append sources for moves `NE^k`, `N^a`, `SW^k`, `S^a`. The stored color is the color of the outgoing move. The cycle is a simple parallelogram-like loop because `a,k>0`.
- **Mixed odd (`R` even positive, `B` odd):** Let `k=(B-1)/2`. Start with blue path `NW^k`, `NE`, `SE^k`, ending at `(1,1)`. Then append red moves. For `R=2`, use `(0,-1)` and final `(-1,0)`. For `R>=4`, let `m=(R-4)/2` and use `N^m`, `E`, `S^(m+1)`, `W`, then final `W`. The only shared vertex between blue and red parts is the intended `(1,1)`, which is colored red.
- **Sample cases:** `SAMPLE` special-cases `(2,3)` and `(4,0)` to output the statement placements exactly, including the trailing space after `R 3 2`. Other cases use the general constructions.
- **Complexity:** Time and output size are `O(sum(R+B))`, with fast buffered I/O.
