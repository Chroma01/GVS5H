- **State model:** The whole graph orientation is always either original or reversed, so a complete state is `(vertex, parity)`, where parity `0` means original edges and parity `1` means all edges are reversed. This gives `2N` states.
- **Transitions:** From `(v, 0)`, moving along an original outgoing edge `v -> to` costs `1`. From `(v, 1)`, moving along a currently outgoing edge means traversing an original incoming edge `to -> v`, also costing `1`. Reversing all edges moves `(v, p)` to `(v, 1-p)` at cost `X`.
- **Implementation encoding:** Use state id `2*v + parity`. State `0` is `(0, 0)`. The two target states are `2*(N-1)` and `2*(N-1)+1`. For parity `0`, iterate `adj[v]`; for parity `1`, iterate `rev[v]`, where `rev[v]` stores original predecessors of `v`.
- **Dijkstra:** Edge weights are positive (`1` and `X >= 1`), so Dijkstra over the expanded graph is correct. Distances are stored in one flat list of length `2N`. Heap entries are `(distance, state)`.
- **Early exit:** The first finalized state whose vertex is `N` is the answer, because Dijkstra pops states in nondecreasing distance and the target set consists of the last two state ids. The stale-distance check must be done before the target check.
- **Complexity:** Building adjacency lists is `O(N + M)`. Dijkstra processes at most `2N` states and `2M + 2N` expanded edges, so time is `O((N + M) log N)` and memory is `O(N + M)`.
- **Integer range:** The answer can exceed 32-bit range. Python integers are unbounded; `INF = 10**18` is safely above the maximum possible simple-path cost under the constraints.
- **Pitfalls handled:** Need both outgoing and incoming adjacency lists. Multiple edges and self-loops are harmless. Do not mutate the graph when reversing; parity toggling is sufficient. Consecutive reversals are never useful because `X > 0`, but Dijkstra naturally ignores such positive cycles.
