- **Problem model:** A subarray is bad iff it contains both endpoints of some remaining conflict. Fixing a right endpoint r, conflict (a,b) with a<b and b<=r is active, and [l,r] avoids all active conflicts iff l > max active a. So valid count at r is r - M.
- **Base count:** Sweep r=1..n, activating conflicts when r reaches their larger endpoint (bucket by b so all same-b pairs activate before counting r). Sum (r - M), M = largest active lower endpoint (0 if none). This is the count under the full conflict set.
- **Deletion gain:** Base + gain[idx] equals the valid count when pair idx is removed, because removing a pair can only raise the per-r limit. Removing p helps at r only if p uniquely supplies M; then the new limit is S (second-largest distinct active a) and the extra at r is M - S. If cnt[M] > 1 no single deletion changes M, so gain is 0.
- **Accumulation:** gain[p] = sum over r where p uniquely owns M of (M - S). Answer = base + max(gain); gains are non-negative so the best deletion never loses ground.
- **Maintaining M and S:** Values are only inserted, M is non-decreasing. On inserting a: if a > M then S = M, M = a; else if a < M and a > S then S = a. The a < M guard keeps re-inserting a == M (frequency bump) from corrupting S, and a == S correctly leaves S unchanged.
- **Ownership:** cnt maps a-value to active frequency; owner_of_a set on the first insert of a value and only consulted when cnt[M] == 1, so it is unambiguous there. Group by value, not by pair, for frequency correctness.
- **Edge cases handled:** M and S default to 0 so r-M and M-S stay valid; all pairs with the same larger endpoint activate before that r; duplicate identical conflicts give zero gain; a pair tying for the max value gives zero gain at that r; single-pair input yields base+gain = n(n+1)/2.
- **Complexity:** O(n + m) time, O(n + m) space with dicts; well within n <= 1e5, m <= 2e5.
- **Example verification (executed):** n=4, [[2,3],[1,4]] -> base 6, gain=[3,0], answer 9 (matches 9). n=5, [[1,2],[2,5],[3,5]] -> base 9, gain=[3,0,1], answer 12 (matches 12). Both printed by the harness as ground truth; PASS.
- **Brute-force cross-check:** Harness computes the answer by trying every removed index and recomputing valid subarrays with an O(n^2 * m) containment test, then compares to the sweep. Run over random n in 2..8 with random pair counts, random a<b, some reversed-order and duplicate pairs, plus targeted cases. Examples observed: n=3, [[1,2],[2,3]] -> 4; n=3, [[1,2],[1,3]] -> 5 (only the shared-a pair helps); n=3, [[1,3],[2,3]] -> 5; n=4, [[3,4],[1,2],[2,4]] -> 7 base 5; duplicates n=3, [[1,2],[1,2]] -> 4. All matched the brute force; ties and non-influential pairs behave correctly.
- **Correctness takeaway:** base is the full-set count and gain[idx] is exactly the count of subarrays that become valid only when idx is deleted, so base + max(gain) is optimal.
