- **Validation:** Samples 1-3 pass. Checked side=1 all corners, k=n, all points on one side, wrap-around selections, d=0, d=side, and the C//k bound. No failures found.
- **Perimeter mapping:** Each boundary point is converted to a coordinate on the square perimeter, circumference `C = 4 * side`. A consistent corner assignment is used: bottom `x`, right `side + y`, top `3 * side - x`, left `4 * side - y`. Corners get one coordinate only; circular distances are invariant to the chosen corner representation.
- **Metric equivalence for d <= side:** For points on the same or adjacent sides, Manhattan distance equals the shorter perimeter distance. For opposite sides, Manhattan distance is always at least `side`, and the shorter perimeter distance is also at least `side`. Therefore, for any threshold `d <= side`, Manhattan distance `< d` is equivalent to circular perimeter distance `< d`. This is the key reduction.
- **Upper bound:** Because `k >= 4`, the optimal answer is at most `side`. If four selected points had all pairwise Manhattan distances `> side`, no two could lie on the same side, so there would be one point on each side. Writing their side coordinates as bottom `b`, right `r`, top `t`, left `l`, the four adjacent-side inequalities `r > b`, `t + r < side`, `t > l`, and `l + b > side` contradict each other. A second necessary bound is `d <= C // k` from the sum of `k` circular gaps.
- **Feasibility as circular packing:** For a fixed `d`, the problem becomes selecting `k` points on a circle such that every circular gap between consecutive selected points is at least `d`. Sort perimeter coordinates and duplicate them with `+ C` to handle wrap-around.
- **Greedy check:** For each possible starting point, greedily choose the earliest next point at least `d` ahead. This is optimal for a fixed start: if any feasible selection starts there, the greedy selection's `r`-th point is no farther than the feasible selection's `r`-th point. After choosing `k` points, the wrap-around gap is valid exactly when the last coordinate is at most `start + C - d`.
- **Next-pointer construction:** For each `d`, compute `nxt[i]`, the first index after `i` with coordinate at least `p2[i] + d`, using a monotone two-pointer scan over the duplicated array. This avoids repeated binary searches.
- **Implementation details:** `d = 0` is trivially feasible. The check also returns false early if `d * k > C`. The sentinel index `2n` marks unreachable jumps. The extra guard `idx >= start + n` prevents using a duplicate copy of an already available point; for `d > 0`, the final wrap condition would reject it anyway. The condition `last <= start + C - d` also prevents selecting the duplicate copy of the starting point.
- **Complexity:** Sorting is `O(n log n)`. Each feasibility check is `O(n + n * k)` with `n <= 15000` and `k <= 25`. Binary search over at most `side` adds `O(log side)`, giving roughly `O(n * k * log side)` time and `O(n)` memory.
- **Edge cases covered:** corner points, selections wrapping around coordinate `0`, `k = n`, small side lengths, threshold exactly `side`, and opposite-side pairs that are automatically safe for all thresholds up to `side`.
