- **Core model:** Work on the run-length encoded sequence. Deleting only part of the first run is never useful: it leaves the same first value, does not help any useful swap, and can be merged into the eventual full deletion of that run. Swaps not involving the current first run can be postponed until earlier runs are deleted, so an optimal process can be considered left-to-right.
- **Useful front swap:** For the current first run `i`, a swap that can improve the answer must swap the second and third current runs. It is useful only when both have length 1 and the third value equals the first value. If the fourth current run has the second value, the swap merges first+third and second+fourth, reducing the run count by 2 (effective). Otherwise it only merges first+third, reducing the run count by 1 (neutral). Moving a same-valued run across a longer run costs at least as much as the deletion it saves, so only adjacent length-1 runs need to be considered.
- **DP state:** `dp[i][g]`, `g = 1, 2, 3`, means the current sequence is run `i`, then run `i+g`, then contiguous runs `i+g+1, ...`. The first run may already be a merged run, but the second and third runs are unmerged original runs, so their original lengths are the relevant lengths. If `i+g >= R`, only one run remains and the cost is 1.
- **Transitions:** Let `j = i+g`. Deleting the first run costs `1 + dp[j][1]`. If `k = j+1 < R`, `len[j] = len[k] = 1`, and `val[k] = val[i]`, we may perform the front swap and then delete the merged first run, costing 2. If `l = k+1 < R` and `val[l] = val[j]`, the remaining state is `dp[j][3]`; otherwise it is `dp[j][2]`. Take the minimum. The answer is `dp[0][1]`.
- **Why neutral swaps matter:** A neutral swap has zero immediate net saving, but it can remove a blocking run and enable later effective swaps. Example `1 2 1 3 2 3`: there is no initial effective four-run pattern, but swapping the first `2` and `1`, deleting the merged `1`s, leaves `2 3 2 3`, which is cleared in three more operations. Total is 5, while the run baseline is 6. Thus the earlier greedy idea of counting only initial effective swaps is incorrect.
- **Validation:** The DP matches all samples. Small brute-force BFS checks over short sequences and small alphabets agree with the DP; the neutral-swap example above is the key type of case that distinguishes the DP from a greedy effective-swap count.
- **Implementation:** Fast input, run-length encoding on the fly, and three arrays for `g = 1, 2, 3`. The DP is computed right-to-left in O(R) time per test case, hence O(sum N) overall. A shortcut for `R <= 3` avoids unnecessary work on many tiny tests.
