- **Monotonicity:** After sorting A, B, C in non-increasing order, the expression `A_i B_j + B_j C_k + C_k A_i` is non-increasing when any index is increased. This holds because all values are positive, so increasing one variable value strictly increases the expression.
- **Best-first traversal:** The solution uses a max-heap simulated by negative packed keys. It starts from `(0,0,0)` and repeatedly pops the largest currently available triple.
- **Spanning-tree frontier instead of visited set:** Rather than pushing all three neighbors and storing visited triples, the code uses a fixed rooted spanning tree of the 3D grid. Each triple has a unique parent: decrease `k` if possible, otherwise decrease `j` and reset `k=0`, otherwise decrease `i` and reset `j=k=0`. The children are the inverse moves. Every tree edge increases exactly one index, so parent value is at least child value.
- **Correctness of tree frontier:** For any unvisited triple, follow its tree path from the root. The first unvisited node on that path has a visited parent, so it is already in the heap and has value at least the target triple. Therefore the heap maximum is always at least the maximum unvisited value, and popping K times gives the K-th largest value with multiplicity.
- **Value updates:** Precompute adjacent differences `dA`, `dB`, `dC`, which are non-positive after sorting. For child `(i,j,k+1)`, new value is `val + dC[k] * (A[i] + B[j])`. For child `(i,j+1,0)` from the `k=0` plane, new value is `val + dB[j] * (A[i] + C[0])`. For child `(i+1,0,0)` from `(i,0,0)`, new value is `val + dA[i] * (B[0] + C[0])`. This avoids recomputing three products per child.
- **Compact heap keys:** A triple code packs `i`, `j`, `k` into `3 * shift` bits, where `shift = (N-1).bit_length()`. The heap stores a single integer `(-value << code_bits) + code`. On pop, `code = key & code_mask` and `value = -(key >> code_bits)`. This reduces memory compared with heap tuples.
- **Complexity:** Sorting is `O(N log N)`. The heap performs K pops and at most 3 pushes per pop, so worst-case `O(K log K)`; the tree usually pushes about one child per pop on average. Memory is `O(N + heap_size)`, with heap size at most `2K+1`.
- **Edge cases:** `K=1` and `N=1` are answered directly using maxima without sorting. Dynamic bit packing is safe because all indices are less than `2^shift`. Python integers handle values up to about `3e18` and packed keys safely.
