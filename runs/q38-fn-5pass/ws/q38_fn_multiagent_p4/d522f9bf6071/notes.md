- **Approach:** Sort intervals by right endpoint while preserving original indices. For each sorted interval, compute `p[i] = bisect_left(ends, l_i)`, the number of intervals ending strictly before its start. Run exact-count DP for counts 1 through 4. For each prefix, store the maximum weight and the lexicographically smallest sorted tuple of original indices. Transition: skip the current interval, or take it from the best state at prefix `p[i]` and insert its original index into the tuple.
- **Correctness:** This is weighted interval scheduling with strict compatibility. For a fixed exact count and prefix, keeping only the lexicographically smallest tuple among maximum-weight solutions is safe because inserting any fixed original index into sorted tuples of equal length preserves lexicographic order; repeated insertions preserve it. A lower-weight compatible partial solution is dominated because any future chain compatible with it is also compatible with the higher-weight prefix state used by the transition.
- **Lexicographic details:** The returned indices are sorted ascending because sorting any chosen set gives the lexicographically smallest permutation. Exact-count DP states have equal tuple lengths, so tuple tie-breaking is monotone. Final comparison across counts uses Python tuple comparison, which implements the shorter-is-smaller prefix rule.
- **Strict non-overlap:** Use `bisect_left(ends, l)`, not `bisect_right`, so intervals ending exactly at `l` are excluded. This matches the rule that sharing a left or right boundary is overlapping.
- **Implementation details:** Use rolling rows to keep memory O(n). Invalid states have weight -1 and tuple `None`. `add_idx` manually inserts into tuples of length at most 3. Equal right endpoints are handled naturally: they are mutually incompatible, and every interval's take candidate is considered while skip carries previous candidates, so tie order does not affect the final best.
- **Complexity:** Sorting and predecessor computation take O(n log n). DP takes O(4n) time and O(n) memory. Tuple length is at most 4, so constant factors are small for n <= 5 * 10^4.
- **Tests run:** Guarded asserts verify Example 1 and Example 2. Touching boundaries are checked: `[1,2]` and `[2,3]` cannot both be chosen, while `[1,1]` and `[2,2]` can. All-overlapping equal weights returns the smallest index. Equal-weight ties across counts are checked, including `[0]` beating `[1,2]` and `[0,1]` beating `[2]`. Large coordinates up to `1e9` are checked, including a shared boundary at `1e9`. More than four compatible point intervals choose the first four indices. Duplicate overlapping intervals choose the smallest index. Empty input returns an empty list.
- **Status:** The endpoint-sorted exact-count DP solution passes the sample and edge-case checks; no algorithmic change is required.
