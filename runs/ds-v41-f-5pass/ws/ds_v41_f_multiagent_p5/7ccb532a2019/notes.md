- **Problem model:** For fixed target frequency k, each letter ends with 0 copies (absent) or exactly k (present). Final string good iff all present letters share one count. k=0 (empty string) is vacuously good but never optimal for n>=3.
- **Operations/costs:** delete=1, insert any char=1, change to next letter=1 with no wrap. Moving a char from letter i to j>i costs j-i; backward moves are at best delete+insert=2.
- **Adjacent-only transfers:** i->i+1 costs 1, strictly beating delete+insert=2. Moves of distance>=2 cost>=2, only tying delete+insert, so they never strictly help. Pass-through via an intermediate is net-zero and also ties. Hence restricting to ord-adjacent forward transfers loses nothing; a gapped input alphabet (e.g. {a,b,d}) is handled because the DP iterates real ord-indices 0..25, and the absent middle letter is processed with freq 0.
- **Unary cost:** letter i with freq f costs f if target 0, |f-k| if target k.
- **Transfer saving:** on edge i-1->i, saving = min(surplus_prev, deficit_cur); surplus_prev = f_{i-1} if prev target 0 else max(0,f_{i-1}-k); deficit_cur = max(0,k-f_i). A moved unit saves exactly 1 (one delete plus one insert).
- **DP per k:** states dp0,dpk over letters a..z. dp0 = f_i + min(prev dp0, prev dpk). dpk = |k-f_i| + min(c1,c2), c1 = prev dp0 - min(sp0,dk), c2 = prev dpk - min(spk,dk). O(26) per k.
- **k range:** 1..n suffices; for k>max freq cost only grows. best initialized to n; keeping the most frequent letter costs n-maxfreq < n, so k=0 never wins.
- **Validated examples:** "acab"->1, "wddw"->0, "aaabc"->2 (asserted in script).
- **Brute force design:** Operations and goodness depend only on counts, so run reverse multi-source BFS over count VECTORS (equivalent to BFS over strings). Sources = all good vectors; predecessors of u are u+e_j (rev delete), u-e_j for u_j>0 (rev insert), and u+e_j-e_{j+1} for u_{j+1}>0 (rev change). Optimal cost <= n so optimal paths keep length <= n+#inserts <= 2n; maxlen=14 covers len 3..7.
- **Brute alphabet sufficiency:** include base letters plus successors up to +2. Any target letter >=3 away from every source is never worth using (shift cost>2 vs delete+insert=2); stepping letters lie within +1. Every base alphabet contains 'a', so no below-min target exists. Adding letters cannot make the brute value lower than the true optimum (all edges are real ops), so equality confirms correctness.
- **Validation results:** all four alphabets {a,b,c}, {a,b,c,d}, {a,b,c,z}, {a,b,d} over lengths 3..7 (~50k strings total) matched the DP (0 mismatches). An extra=2 vs extra=3 sanity check on {a,b,c} showed no value changes, supporting alphabet sufficiency.
- **Hand checks:** "aaabc"->2, "aaabcc"->1, "aaaaaabbbb"->1, "aaaab"->1, "aaaaaz"->1, "aab"->1, "aaa"->0, "abc"->0, "aabd"->1, "bbd"->1.
- **Boundary z:** z has no successor, so its surplus can only be deleted; it can still receive from y (not usefully reachable here). Verified on "aaaaaz","wddw".
- **No double counting:** each edge's saving uses only that edge's local surplus/deficit; a letter is surplus XOR deficit, so one target state per letter is enough.
- **Complexity:** O(26*n) time, O(1) extra space. Timing on n=20000 (all-'a' and full-alphabet mixed) completes in well under a second.
