- **Monotonicity:** Sorting A, B, C in descending order preserves the multiset of values. Since all entries are positive, increasing any index cannot increase f(i,j,k)=A_iB_j+B_jC_k+C_kA_i. The exact drops are (A_i-A_{i+1})(B_j+C_k), (B_j-B_{j+1})(A_0+C_k), and (C_k-C_{k+1})(A_0+B_0) for the three tree edges.
- **Canonical tree:** Use parent(i,j,k)=(i-1,j,k) if i>0, else (0,j-1,k) if j>0, else (0,0,k-1). Children are exactly (i+1,j,k), plus (0,j+1,k) when i=0, plus (0,0,k+1) when i=j=0. This is a rooted tree covering every triple once, with parent value >= child value. Best-first popping from this heap-ordered tree gives values in non-increasing order without a visited set.
- **Truncation:** Keep only the first L=min(N,K) elements of each sorted array. Any triple using an index >=K in one coordinate is dominated by K triples using the first K elements of that coordinate together with the largest elements of the other two coordinates. Therefore the K-th largest value is unchanged. Also L^3 >= K, so enough triples remain.
- **Packing:** Let bits=(L-1).bit_length(), shift=3*bits, and code=(i<<(2*bits)) | (j<<bits) | k. The heap key is -(value<<shift)-code. Because code < 2^shift, min-heap order is primarily by decreasing value; code only breaks ties. Decode with t=-key, value=t>>shift, code=t&((1<<shift)-1).
- **Incremental updates:** Precompute adjacent differences dA, dB, dC. From a popped node, the A-child value is val-dA[i]*(B[j]+C[k]); the B-child value is val-dB[j]*(A0+C[k]); the C-child value is val-dC[k]*(A0+B0). This avoids recomputing products from scratch.
- **Heap optimization:** Every node except the last A-layer has an A-child. Use heapreplace to remove the current root and insert the A-child in one operation. If i=0, push the B-child and possibly the C-child afterward. If there is no A-child, just heappop. Run this for K-1 pops, then read the K-th value directly from heap[0] without decoding.
- **Complexity:** Sorting is O(N log N). Heap enumeration is O(K log K) with K <= 5e5. Memory is O(L + heap_size), and heap_size is O(K).
- **Edge cases:** K=1 is answered by max(A), max(B), max(C). N=1 is handled. All-equal arrays are handled because equal values may be popped in code order but the K-th value remains correct. When K=N^3 for small N, the tree enumerates all triples.
- **Pitfalls:** The code fields must not carry into neighboring fields; bounds checks ensure this. The power-of-two base must exceed the maximum code. Positivity is essential for monotonicity. Truncation preserves only the K-th value, not the entire multiset.
