- **Core idea:** Sort A, B, C in descending order. Since all values are positive, the expression is non-increasing when any index increases. Enumerate index triples in descending value by best-first search on the 3D monotone grid.
- **Truncation:** Let M = min(N, K). Any triple with an index >= K is dominated by K distinct triples inside [0, M)^3: cap all indices at K-1 and vary one out-of-range index over 0..K-1. Therefore the K-th largest value is unchanged by truncating each sorted array to M.
- **Enumeration invariant:** `visited` means generated, not necessarily popped. The heap contains generated but unpopped triples. For any ungenerated triple, take the first ungenerated cell on a path from (0,0,0); its predecessor was popped and generated it, so a cell with value at least as large is in the heap. Thus popping the heap maximum gives the next largest triple. Pop K-1 times, then the heap top is the answer.
- **State key:** Use `key = (i * M + j) * M + k`. Successor keys are `key + M*M`, `key + M`, and `key + 1`. Decode with `divmod(key, M*M)` and then `divmod(rem, M)`.
- **Encoded heap:** To reduce memory, store each heap entry as one integer `item = (neg_value << shift) + key`, where `neg_value = -value`, `shift = (M^3 - 1).bit_length()`, and `mask = (1 << shift) - 1`. Because `key < 2^shift`, integer ordering matches ordering by `(-value, key)`. Decode with `key = item & mask` and `neg = item >> shift`. This works with negative integers because right shift is arithmetic and bitwise AND with a power-of-two mask gives the low bits.
- **Delta updates:** Avoid recomputing the full value. For i+1: `new_neg = neg - (A[i+1]-A[i])*(B[j]+C[k])`. For j+1: `new_neg = neg - (B[j+1]-B[j])*(A[i]+C[k])`. For k+1: `new_neg = neg - (C[k+1]-C[k])*(A[i]+B[j])`. Differences are non-positive, so `neg` increases as value decreases.
- **Multiplicity:** Visited states are index triples, not values, so equal values from different triples are counted separately. Tie-breaking by key is harmless.
- **Complexity:** Sorting is O(N log N). Heap enumeration does O(K) pushes/pops, each O(log K), so O(N log N + K log K). Memory is O(K) for heap and visited set.
- **Edge cases and optimizations:** K=1 is answered directly by maxima. If the truncated arrays are all constant, the answer is that constant. Under constraints, M=1 only occurs for K=1. Read all tokens, convert arrays, then delete the token list before heap work.
- **Pitfalls:** Ensure `shift` covers `M^3 - 1`, not just `M`. Do not use value-based visited states. The domination argument is required for truncation; simply keeping K elements per dimension is safe only because of that argument.
