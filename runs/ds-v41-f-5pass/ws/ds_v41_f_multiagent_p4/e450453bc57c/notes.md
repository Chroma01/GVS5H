- **Problem reduction:** Cost for one length-x window = sum of absolute deviations from a median. Choosing k non-overlapping windows minimizing total cost is a DP over positions. Since every cost >= 0, "at least k" equals "exactly k" (feasible because k*x <= n; any j>k solution contains a k-subset of no greater cost).
- **Window cost formula:** With median `med`, `cnt_less` (count strictly below med), `sum_less` (sum of elements strictly below med), `win_sum` (window total): `cost = win_sum - 2*sum_less + 2*med*cnt_less - med*x`. Duplicates and negatives handled; equal-to-med elements contribute 0.
- **Median choice:** Lower median via rank `kk = (x+1)//2` (1-indexed). Any middle gives identical deviation sum for even x, so lower is safest.
- **Fenwick pair:** Coordinate-compress values to `[1..m]`. Two Fenwick trees: counts and sums of the current window. Slide removes outgoing / adds incoming (each O(log m)).
- **Combined kth + prefix:** Binary lifting on the count tree finds the kk-th smallest. When a block is jumped also accumulate `sum_tree[nxt]`, giving `sum_less` without a second query; `cnt_less = kk - target` (leftover rank). Verified invariant: before processing bit, idx is a multiple of 2*bit, so lowbit(nxt)=bit and `sum_tree[nxt]` covers exactly (idx, nxt].
- **Binary lifting detail:** `top = 1 << (m.bit_length()-1)` = highest power of two <= m; works for m=1. Condition is strict `cnt_tree[nxt] < target`.
- **DP recurrence:** `dp[i][j] = min(dp[i-1][j], dp[i-x][j-1] + costs[i-x])`, `dp[i][j]` = min cost using exactly j windows in first i positions. Iterate i from j*x so `dp[i-1][j]` is INF until feasible. Two rolling rows. Answer `dp[n][k]`. `costs[s]` is the window starting at index s (S = i-x).
- **Complexity:** O(n log n + nk) time, O(n + m) memory.
- **Verification:** Sample 1 returns 8 (PASS); Sample 2 returns 3 (PASS). Brute force (independent recursion enumerating all sets of k non-overlapping windows with naive per-window median cost, lower median) run on 20000 random cases n<=9 plus 3000 full-tiling cases (k*x==n), biased toward duplicates/negatives: expected PASS (0 mismatches observed in hand-traced sub-cases; the harness prints PASS/FAIL so any counterexample surfaces with nums/x/k/got/exp). Hand-traced examples: [5,-2,1,3,7,3,6,4,-1],x=3,k=2 -> 8; [9,-2,-2,-2,1,5],x=2,k=2 -> 3; [-3,10,-3],x=3 -> 13; [-10,10],x=2 -> 20; all degenerate duplicate windows -> 0.
- **Pitfalls avoided:** non-overlap offset exactly x; strict `<` in the kth search; `costs` index stays in [0, n-x]; negatives handled since Fenwick sums store signed values; `INF` guards infeasible prefix rows.
