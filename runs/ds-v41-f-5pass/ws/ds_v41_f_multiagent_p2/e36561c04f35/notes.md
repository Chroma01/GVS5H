- **Problem model:** total cost = (# adjacent swaps) + (# deletions). Deleting a maximal equal prefix is always optimal, so cost = inversions + number of deletion groups. Equivalent to partitioning the runs of A into monochromatic groups and ordering them, minimising #groups + inversions.
- **Weighted run-length caching greedy:** compress A into maximal runs (v, L). Maintain ordered levels (deletion groups). For each run (v, L): if v unseen, create a new top level. Else let lvl = highest level of v, w = total length of levels > lvl. If w*L <= 1, reuse lvl (add w*L inversions); else create a new top level for v. Answer = (#levels created) + (accumulated inversions).
- **Validity:** scanning left to right, w*L counts exactly the pairs (element of this run, previously seen element now at a higher level) that become inverted in the final arrangement. Each inversion is charged once. The greedy builds an achievable arrangement, so it gives an upper bound.
- **Tie-break:** at w*L == 1 use `<=` (reuse). Creating would add a level above other values, increasing their future costs, and never strictly improves the total; exhaustive small-case checks confirm reuse is safe.
- **Exhaustive validation:** brute-force BFS/Dijkstra over tuple states with moves: swap any adjacent pair, delete maximal uniform prefix. Compared for ALL arrays N=2..8 over {1,2,3} and N=2..7 over {1,2,3,4}. Zero mismatches. The alternate `R - max good pairs` formula also matched, but the greedy is constructive and safer.
- **Complexity:** O(#runs log #runs) per case via Fenwick over levels; total O(sum N log N) <= ~2e5. Answer is always <= N.
- **Edge cases:** all equal -> 1; all distinct -> N; R<=3 -> R. Long runs make merges expensive (w*L grows), correctly forcing creates.
- **Implementation:** Fenwick over level indices stores lengths; `last[v]` = highest level of v; prefix sum up to lvl gives w = total - prefix(lvl). Read tokens as bytes, convert per run.
