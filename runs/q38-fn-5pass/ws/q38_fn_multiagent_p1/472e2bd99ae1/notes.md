- **Core idea:** Sort each sequence in descending order and compress equal values. Since all entries are positive, `f(x,y,z)=xy+yz+zx` is non-increasing when any coordinate index increases. The K-th largest value can be found by best-first traversal of the monotone unique-value grid while accumulating multiplicities.
- **Canonical tree:** Use a rooted tree over unique indices. Parent of `(i,j,k)` is `(i-1,j,k)` if `i>0`, else `(0,j-1,k)` if `j>0`, else `(0,0,k-1)`. Children are exactly `(i+1,j,k)` always, `(i,j+1,k)` if `i==0`, and `(i,j,k+1)` if `i==0 and j==0`. This visits every unique triple exactly once, and parent value is at least child value, so a max-heap pops unique triples in non-increasing value order without a visited set.
- **Weights and capping:** Each unique triple represents `mx[i]*my[j]*mz[k]` original triples. Multiplicities are capped at `K`. For any remaining need `R<=K`, if the true product is at least `R`, the capped product is also at least `R`: if any factor was capped, it is `K`; otherwise no factor was capped. During counting, multiply factors only until the partial product reaches `remaining`, keeping integers small and preserving the comparison.
- **Dimension order:** The expression is symmetric, so reorder compressed dimensions by decreasing unique length. The longest dimension becomes `i`, the shortest becomes `k`. This matches the asymmetric tree and tends to reduce heap growth because branching is largest on the shortest axis.
- **Heap encoding:** Coordinates are packed into one integer `code` using a dynamic bit width based on the maximum compressed length. The heap key is `(-value << CODE_BITS) + code`, so smaller key means larger value, with `code` as tie-breaker. Decode with arithmetic shift and mask. Child values are updated by delta formulas, e.g. changing `x` to `x2` adds `(x2-x)*(y+z)`.
- **Correctness:** Monotonicity ensures every parent bounds its children. The tree covers all unique triples once. For any unpopped triple, the first unpopped ancestor on its path is in the heap and has value at least as large, so the heap maximum is the next largest unique value. Accumulating capped multiplicities in this order reaches `K` exactly at the K-th largest original value.
- **Complexity:** Sorting is `O(N log N)`. At most `K` unique triples are popped because each has weight at least one. Heap size is `O(K)` (bounded by about `2K`). Each heap operation is `O(log K)`, giving `O(K log K)` after sorting. Memory is `O(N + K)`.
- **Edge cases:** `K=1` is answered directly from maxima. All-equal arrays compress to one triple whose root weight reaches `K`. Small `N` with `K=N^3` still works because capped total weight remains at least `K`. Positive values are essential for monotonicity.
