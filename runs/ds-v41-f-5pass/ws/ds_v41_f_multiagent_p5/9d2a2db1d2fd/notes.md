- **Problem reduction:** Walkways are free and preserve the current floor, so the only cost is vertical movement. An optimal route can be viewed as choosing a floor level f and moving through cells whose buildings have height >= f. For two cells, let M be the maximum bottleneck: the largest f such that the start and target are connected via cells with F >= f. Then the answer is |Y-Z| if M >= min(Y,Z), otherwise Y+Z-2M.
- **Bottleneck computation:** M is the maximum-bottleneck path value in the grid graph where adjacent cells have edge weight min(F[u],F[v]). Equivalently, it is the height at which the two cells become connected when activating cells in decreasing order of F.
- **Offline DSU with small-to-large:** Sort cells by F descending. Activate cells one by one, union with already-active cardinal neighbors. Each DSU root maintains a set of query ids whose endpoints lie in that component but are not yet resolved. When merging two components, iterate over the smaller set; if a query id is present in both sets, record the current height as M for that query and remove it from the merged set. Total work is O((N+Q) log N).
- **Same-cell queries:** If start and target are the same cell, M = F[cell]. Set ans[q] = F[cell] directly; the formula then yields |Y-Z| because min(Y,Z) <= F[cell].
- **Implementation details:** Use 1D indexing idx = i*W + j. Compute neighbors on the fly with i = idx // W, j = idx - i*W. The find function uses path halving. Empty sets are converted to None after merges to save memory and avoid unnecessary work.
- **Edge cases:** Equal building heights are handled correctly because processing order within the same height does not affect the recorded M. Queries with u == v are handled directly. All cells are eventually activated, so every u != v query will be resolved.
