- **Validation:** Checked the provided examples analytically: `"acab"` gives 1, `"wddw"` gives 0, `"aaabc"` gives 2. Also checked already-good strings, single dominant letter, z-boundary cases, all distinct letters, and large imbalance cases. Sample-tests verdict: pass.
- **Problem model:** For a fixed final frequency `f`, every letter is either absent with final count `0` or present with final count `f`. Let `cnt[i]` be the initial count of letter `i`, and choose `y[i] in {0,1}`.
- **Baseline cost:** If only deletions and insertions are used, the cost for fixed `f` and choices `y` is `sum(abs(cnt[i] - f * y[i]))`.
- **Effect of changes:** A change `i -> i+1` costs 1 and can replace one deletion from `i` plus one insertion into `i+1`, saving exactly 1 when `i` has surplus and `i+1` has deficit. Multi-step changes cost at least 2 and are never strictly better than delete plus insert; distance-2 changes only tie, so they do not lower the minimum.
- **Fixed-frequency cost formula:** For each letter, surplus is `max(cnt[i] - f*y[i], 0)` and deficit is `max(f*y[i] - cnt[i], 0)`. The minimum cost for fixed choices is baseline minus `sum(min(surplus[i], deficit[i+1]))` for `i = 0..24`. There is no wrap-around edge from `z` to `a`.
- **Independence of savings:** For fixed `f` and a fixed absent/present choice, a letter cannot be both surplus and deficit. Therefore adjacent savings do not conflict in a way that requires tracking flow amounts; the binary choice per letter is sufficient.
- **Dynamic programming state:** Process letters in alphabet order. `dp0` and `dp1` store the minimum cost up to the previous letter when that previous letter is absent or present. The current letter's surplus/deficit is fully determined by its binary choice.
- **Transitions:** If current letter is absent, add `cnt[i]` and no incoming saving. If current letter is present, add `abs(cnt[i] - f)`. If it has a deficit, subtract the best possible saving from the previous state: previous absent gives surplus `cnt[i-1]`; previous present gives surplus `max(cnt[i-1] - f, 0)`. Cap each saving by the current deficit.
- **Frequency enumeration:** The current implementation enumerates `f` from `1` to `max(cnt)`. This is safe because for `f > max(cnt)`, all present letters are in deficit; increasing `f` by one adds one insert per present letter and can create at most one additional adjacent saving per present letter, so the cost cannot decrease. Enumerating to `n` is also safe but slightly slower.
- **Edge cases:** The final string may omit letters. Empty final string is not needed because keeping one character is always no worse. The `z -> a` change is disallowed, so the DP intentionally has no edge from index 25 to 0. Letters with zero initial count can be present via inserts or absent; absent zero-count letters cannot supply surplus.
- **Complexity:** Time `O(26 * max(cnt))`, which is at most `O(26 * n)`, and extra space `O(1)` besides the 26 counts.
