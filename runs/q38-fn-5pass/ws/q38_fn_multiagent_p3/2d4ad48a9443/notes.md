- **Cost model:** For a subarray, the minimum increments needed to make it non-decreasing equals the sum of its running prefix maxima minus the sum of its original elements. The optimal final value at each position is the maximum original value seen so far in that subarray.
- **Record decomposition:** For a fixed left endpoint, prefix maxima change only at indices obtained by repeatedly jumping to the first strictly greater element to the right. Equal values are not new records. Compute these next-greater pointers with a monotonic stack, popping while `nums[top] <= nums[i]`.
- **Block costs:** If record `i` has next greater record `q` inside the subarray, the full block `[i, q)` contributes `nums[i] * (q - i) - sum(nums[i:q])`. This is nonnegative because no element in the block exceeds `nums[i]`. The final record contributes a partial block `[cur, r]`.
- **Binary lifting:** Build `up[t][i]` as the `2^t`-th next greater record and `sum_cost[t][i]` as the sum of full-block costs for those jumps. Query `[l, r]` by jumping from high to low while `up[t][cur] <= r`, adding the corresponding full-block sum. Afterward, `cur` is the last record and its partial block is added.
- **Capping:** All block contributions are nonnegative. If any stored full-block sum exceeds `k`, any subarray containing that whole jump is infeasible. Capping sums at `k + 1` keeps values small and never turns a feasible subarray into an infeasible one.
- **Two-pointer sweep:** For fixed `r`, cost is nonincreasing as `left` moves right, and for fixed `left`, cost is nondecreasing as `r` moves right. Maintain the smallest feasible `left`; while `cost(left, r) > k`, increment `left`. Add `r - left + 1` feasible starts for each `r`.
- **Implementation details:** Use sentinel index `n`. `LOG = (n + 1).bit_length()` is enough to represent any chain of next-greater jumps. To balance memory and speed, next-greater level 0 is stored as an array, higher `up` levels as lists, and sum tables as `array('q')`. Single-element subarrays are skipped in the query loop because they always cost zero.
- **Complexity:** Time `O(n log n)`, memory `O(n log n)` with compact arrays. Answer can be about `n(n+1)/2`, so Python integer arithmetic is required.
- **Edge cases covered:** equal values, strictly increasing/decreasing arrays, small/large `k`, `n = 1`, and large total counts. Sample outputs 17 and 12 match the algorithm.
