- **Goal:** maximize `pref[i] + mid(i+1,j) + suf[j+1]` over `1 <= i < j <= N-1` (1-indexed), N up to 3e5.
- **Suffix array:** `suf[k]` = # distinct in A[k..N] for k=1..N, `suf[N+1]=0`; built right-to-left with a bytearray seen-flag, O(N). `suf[j+1]` is the third piece.
- **Identity:** `pref[i] + mid(i+1,j) = D_j + overlap(i,j)` where `D_j` = distinct in A[1..j] and `overlap(i,j)` = # values present on BOTH sides of split i inside [1..j]. Rule used: `dist(X)+dist(Y) = dist(X∪Y) + |common|`.
- **Overlap as intervals:** value v is on both sides of i iff `first(v) <= i < last_j(v)`. So v covers the i-interval `[first(v), last_j(v)-1]`; `overlap(i,j)` = coverage depth at i, we need max coverage.
- **Sweep (the whole algorithm):** iterate j = 1..N-1 maintaining coverage over i in one lazy segment tree. When A[j] last occurred at p (p<j), its interval right end moves p-1 -> j-1, so range add +1 on i in [p, j-1], i.e. 0-based half-open `[p-1, j-1)` => tree `[l0, r0) = [p-1, j-1)`. If no previous occurrence, no update. Then for j>=2 candidate = `D_j + suf[j+1] + tree_max`.
- **Why global max is a valid restricted max:** updates at steps j' <= j use `r0 = j'-1 <= j-1`, so 0-based positions `>= j-1` (1-indexed i >= j, all invalid) stay 0. Valid positions are >= 0 in coverage, so global max = max over valid i (invalids only add a 0 that can never dominate). No need to cap the query.
- **Answer per j:** `D_j + suf[j+1] + d[1]`, take global max over j in [2, N-1]. j starts at 1 but only j>=2 has a valid i.
- **Segment tree design (no pushes):** invariant `d[k] = max(d[2k], d[2k+1]) + lz[k]` for internal k, `d[k] = value` for leaves. Because d[k] already includes lz[k], a full-cover range add on node k is just `d[k]+=1, lz[k]+=1` and can never require pushing. Root `d[1]` is always the true global max. This makes the code far simpler and faster than an ACL tree that pushes.
- **Range add mechanics:** ACL-style fringe loop (`l&1`, `r&1`) applies +1 to the O(log) covering nodes; then recompute ONLY the ancestor paths of `lo = l0+size` and `ro-1 = r0-1+size` bottom-up. Covering nodes hang off these two paths, so those paths are sufficient; if a path node was itself directly applied, recomputing it with its incremented `lz` reproduces the correct value, so no double counting.
- **Micro-opt:** single-element ranges (r0-l0==1, the all-equal worst case) skip the fringe loop entirely: bump the leaf and walk parents once. This halves work for the most repetitive input.
- **Complexity:** O(N log N) time, O(N) space. Worst mixed input is ~N lazy range adds of ~log size; expect a few seconds in CPython, fast under PyPy.
- **Verified cases:** sample1 -> 5, sample2 -> 9; also [1,1,1]->3, [1,2,3]->3, [1,2,1,1]->4, [1,2,1,2,1]->5, [1,1,2,2,1,1]->5, [1,2,3,1,2,3]->6; plus [1,1,2]->3, [1,2,1]->3. Hand-traced segment-tree state through mixed point/range updates confirms root correctness.
- **Discarded fallback:** the monotonic-stack + Fenwick "nondominated candidates" idea is unnecessary; the lazy tree above is correct and simple, so it was dropped.
