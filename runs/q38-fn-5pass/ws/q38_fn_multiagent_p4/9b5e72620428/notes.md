- Core reduction: After filling wildcards and permuting A, only the multisets of known A and known B values matter. For a final common sum S, every known value must be at most S, so S >= maxKnown.
- Let uA, uB be wildcard counts, nA = N-uA, nB = N-uB. For fixed S, the maximum number of disjoint known-known pairs is P(S) = sum_x min(cntA[x], cntB[S-x]). Feasibility for S is exactly S >= maxKnown and P(S) >= T, where T = N-uA-uB.
- If T <= 0, enough wildcard slots exist. If T == 1, one known-known pair is always possible: take a known value equal to maxKnown and any known value from the opposite sequence; their sum is at least maxKnown, and the remaining known values exactly fit the wildcard slots.
- For T > 1, any feasible S must be a sum of some known A value and known B value. Enumerate distinct known-value pairs with a+b >= maxKnown and aggregate min(cntA[a], cntB[b]) by sum.
- Implementation uses frequency dictionaries. If one side has all known counts equal to 1, every contribution is 1, so it is enough to count equal pair sums among distinct values.
- Otherwise, contributions are packed as ((a+b) << 12) | weight. Since N <= 2000, weight fits in 12 bits. Sorting packed integers groups equal sums in the high bits, then weights are summed in the low bits.
- Optimizations included: choose the smaller distinct-value side as the outer loop; use bisect to skip pairs with sum < maxKnown; detect when all distinct pairs are valid; precheck whether a single value pair already contributes at least T; in the simple path, skip sorting if the total number of distinct pair sums is less than T.
- Important pitfalls: do not count all element-pair occurrences, because multiplicities must be capped by min(cntA, cntB); sums below maxKnown are invalid even if they have many pairs; T == 1 is a special always-Yes case; B order is irrelevant because A can be rearranged arbitrarily.
- Complexity: with DA and DB distinct known values, worst-case O(DA*DB) generated contributions and O(DA*DB log(DA*DB)) sorting, with DA, DB <= 2000. Memory is O(DA*DB) in the worst case, which is acceptable for N <= 2000 with packed integer lists.
