Compute the inversion count for k=0 using a Fenwick tree over values 0..M-1. Then exploit that increasing k by 1 only changes relative comparisons for elements whose original value is M-1-k, since those wrap from M-1 to 0. Pre-group indices by their A_i value so each wrap group can be processed in O(group size), updating the running inversion count by counting how many earlier/later non-wrapping elements each wrapped element crosses. Iterate k from 0 to M-1, outputting the current count after each update. Use 64-bit integers for counts and O(N log M + M + N) total time.
