- **Problem reduction:** The value for indices i,j,k is A_iB_j + B_jC_k + C_kA_i. Since all A,B,C are positive, the function is strictly increasing in each of the three chosen values. Sorting each sequence in descending order makes the value non-increasing as any index increases.
- **Algorithm:** Use a best-first search (max-heap) over the 3D grid of indices. Start from (0,0,0). Pop the largest value, then push valid successors. To avoid a visited set and duplicate work, enforce a unique path constraint: push (i+1,j,k) only if j==0 and k==0; push (i,j+1,k) only if k==0; push (i,j,k+1) always. This guarantees each triple is generated exactly once and in descending order.
- **Packing indices:** Encode (i,j,k) into a single integer: packed = (i << 40) | (j << 20) | k. Since N <= 2e5 < 2^18, 20 bits per index is safe. Incrementing k is packed+1, incrementing j is packed + (1<<20), incrementing i is packed + (1<<40). This avoids tuple comparison overhead beyond the value.
- **Complexity:** O(K log K) time, O(K) memory. K <= 5e5, so at most ~1.5M pushes and 500k pops. Python's heapq handles this within typical time limits. Packed indices reduce memory and speed up comparisons.
- **Edge cases:** N=1 handled separately. K=1 works with an empty loop and a single pop. Bounds checks prevent out-of-range pushes. All arithmetic uses arbitrary-precision Python ints, so no overflow.
