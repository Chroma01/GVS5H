- **Validation:** The implementation gives 1 for `"acab"`, 0 for `"wddw"`, and 2 for `"aaabc"`. It returns 0 immediately for already-good strings, including all-same-letter strings. Drop states cover solutions where only one or a few letters remain, e.g. counts `[4,1,1]` can keep the first letter at frequency 4 and delete the other two letters for cost 2. Zero-count letters can be kept or dropped without breaking the DP, and there is no edge from `z` to `a`.
- **Model:** Only counts matter. A good final string is defined by a positive target frequency `f` and a subset of letters kept; kept letters end with count `f`, removed letters with count `0`. Deleting all characters gives an upper bound `n`, and keeping one existing character gives at most `n - 1`, so the all-delete initialization is safe.
- **Cost for fixed final counts:** Let `c_i` be initial counts and `x_i` final counts. Baseline delete/insert cost is `sum |c_i - x_i|`. A change `i -> i+1` costs 1 and replaces one delete at `i` plus one insert at `i+1`, saving exactly 1 only when `i` has surplus and `i+1` has deficit. Moves of distance 2 cost the same as delete plus insert, and longer moves are worse, so only adjacent surplus-to-deficit changes can reduce cost.
- **Exact fixed-count cost:** For fixed `x`, the minimum cost is baseline minus `sum_i min(surplus_i, deficit_{i+1})`, where `surplus_i = max(c_i - x_i, 0)` and `deficit_i = max(x_i - c_i, 0)`. A node cannot be both net surplus and net deficit in an optimal solution, so adjacent savings do not compete except through the capacities already captured by these minima.
- **Fixed `f` DP:** For each `f`, each letter has two states: removed (`x_i = 0`) or kept (`x_i = f`). Unary costs are `c_i` for removed and `|c_i - f|` for kept. The only interaction is the saving on edge `i-1 -> i`.
- **Edge saving:** If current is kept and `c_i < f`, its deficit is `f - c_i`; otherwise zero. If previous is removed, previous surplus is `c_{i-1}`; if previous is kept, previous surplus is `max(c_{i-1} - f, 0)`. The edge saving is `min(previous_surplus, current_deficit)`. If current is removed, the saving is zero.
- **DP recurrence:** For letter 0, `drop = c_0` and `keep = |c_0 - f|`. For each next letter `c` with previous count `pc`: `new_drop = min(drop, keep) + c`. If `c >= f`, `new_keep = min(drop, keep) + (c - f)`. If `c < f`, `deficit = f - c`, and `new_keep = min(drop - min(pc, deficit), keep - min(max(pc - f, 0), deficit)) + deficit`. The best cost for this `f` is `min(drop, keep)`.
- **Frequency bound:** Testing `f` only up to `max(cnt)` is sufficient. If `f > max(cnt)`, every kept letter is in deficit. Decreasing `f` by 1 lowers unary deficit cost by one per kept letter, while each kept letter has at most one incoming saving edge, so total savings can fall by at most the same amount. Therefore some optimal `f` is at most `max(cnt)`.
- **Complexity:** At most `2 * 10^4` frequencies and 26 letters with constant transitions, so time is `O(26 * n)` and extra space is `O(1)`.
- **Edge cases:** The early good-string check uses only present letters, so zeros are ignored. The DP has no wrap-around edge from `z` to `a`. Letters with zero initial count can be kept if tied or useful, but they never create outgoing surplus unless their count exceeds `f`, which is impossible when `c = 0` and `f > 0`.
