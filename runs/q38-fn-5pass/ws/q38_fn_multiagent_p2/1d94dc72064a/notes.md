- **State reduction:** The exact game state can be compressed to `(U, P)`, where `U` is the set of unchosen indices and `P` is the total number of remaining optional moves on already chosen indices. The distribution of those optional moves among chosen indices does not matter, because every optional move simply decreases `P` by 1. Choosing an unchosen index `i` removes it from `U` and adds `A_i - 1` optional moves, except when it is the last unchosen index, in which case the mover wins immediately.
- **Small base outcomes:** For `|U| = 1`, the current player always wins. For `|U| = 2`, the current player loses exactly when `P` is even, because claims hand the opponent an immediate win and only pass moves can change the turn. For `|U| = 3`, the losing states are exactly: all three remaining `A_i` odd and `P` odd, or all three remaining `A_i` even and `P` even. If the three parities are mixed, the current player always has a claim to a losing size-2 state.
- **Key invariant for larger states:** For every state with `|U| >= 4`, the current player loses exactly when `P mod 2` equals the number of odd `A_i` among the unchosen indices modulo 2. This was first checked directly for `|U| = 4`, then proved by induction.
- **Induction sketch:** Assume the invariant holds for some `m >= 4`. Consider a state with `m + 1` unchosen indices, odd count `o`, and pass count `P`. If the current player chooses an unchosen index with parity indicator `odd_i`, the target has odd count `o - odd_i` and pass count `P + (1 - odd_i)`. By the induction hypothesis, that target is losing exactly when `P + 1 - odd_i == o - odd_i (mod 2)`, which simplifies to `P == o - 1 (mod 2)`. Thus if `P` has the opposite parity from `o`, every claim wins. If `P` has the same parity as `o`, no claim wins; a pass, if available, moves to `P - 1`, which has opposite parity and is winning for the opponent, so the state is losing. This proves the invariant for all `m >= 4`.
- **Initial-state rule:** Initially `P = 0` and `U` is all indices. Therefore: `N = 1` is always Fennec; `N = 2` is always Snuke; `N = 3` is Fennec iff at least one `A_i` is odd; for `N >= 4`, Fennec wins iff the number of odd `A_i` is odd.
- **Brute-force solver:** The program includes an exact recursive minimax solver over `(mask, P)`. It is acyclic because pass moves decrease `P` and claim moves decrease the number of unchosen indices. This solver is used only in verification mode, not in normal judged input mode.
- **Verification scope:** The brute-force report checks all sequences for `N <= 6` with small values (`A_i <= 4` for `N <= 5`, `A_i <= 3` for `N = 6`), and also `N = 7, 8` with `A_i <= 2`. No counterexamples to the proposed rule were found in these ranges.
- **Observed patterns:** The brute-force table confirms the small exceptions: `N = 1` all win, `N = 2` all lose, `N = 3` loses only when all values are even. For `N >= 4`, the winner depends only on the parity of the odd count, with odd odd-count winning for the first player.
- **Program behavior:** If standard input is empty, or if the first token is `brute`, the program runs the brute-force verification report. Otherwise it reads `N` and `A`, applies the proven rule, and prints `Fennec` or `Snuke`.
- **Complexity:** The judged solution is `O(N)` time and `O(1)` extra memory beyond input storage. The brute-force verification is exponential in the small test dimensions but intentionally limited to small `N` and `A_i`.
