- **Core invariant:** Let P_t be the cumulative wind displacement after t steps. A particle generated at time k is at P_t - P_k at time t+0.5. Therefore the target cell (R,C) is occupied at time t iff P_t - (R,C) appeared among P_0, P_1, ..., P_t.
- **Virtual generation:** New smoke is generated only when the origin is empty, but for occupancy purposes we may imagine a particle generated at every time step. If the origin is already occupied, then some previous prefix equals P_t, so the virtual particle at the origin duplicates the future trajectory of an existing particle.
- **Online algorithm:** Maintain a set of encoded prefix positions seen so far, initially containing P_0. For each wind character, update the current prefix P_t, test whether P_t - (R,C) is in the set, append the answer, then add P_t to the set.
- **Query order:** Querying before adding the current prefix is conceptually clean. Since the problem guarantees (R,C) != (0,0), the current prefix cannot itself satisfy the query, so adding before or after would not change the answer.
- **Integer encoding:** Coordinates can be negative. Prefix coordinates lie in [-N,N], and query coordinates lie in [-2N,2N]. Using shift = 2N+5 and base = 4N+11, encode (x,y) as (x+shift)*base + (y+shift). Both encoded coordinates are nonnegative and strictly less than base, so there are no collisions.
- **Complexity:** O(N) time and O(N) memory. Integer keys and bytearray output keep constant factors small.
- **Pitfalls:** Include the initial prefix P_0. Use the sign P_t - (R,C), not P_t + (R,C). Map N/S to row changes and W/E to column changes exactly as specified. Direct simulation of all smoke cells is infeasible because the occupied region can grow quadratically.
- **Origin target:** If (R,C) were (0,0), the generation timing would need special handling, but the constraints exclude this case.
