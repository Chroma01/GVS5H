- **Block model:** Assign each original position a deletion-batch label. Equal labels are allowed only for equal values. If labels are compressed to deletion order, the number of deletion operations is the number of labels, and the minimum adjacent swaps is the inversion count of the label sequence. Scanning left to right, assigning to an existing label costs the number of already seen elements in later labels; starting a new maximum label costs 1 and adds no immediate inversion.
- **Dominance rule:** If a current element is assigned to a non-last label and there are at least two seen elements in later labels, the immediate cost is at least 2. Replacing that by starting a new maximum label costs 1 and yields a state that can simulate any continuation with no larger cost. Therefore only the last block, and the second-last block when the last block has size 1, can be extended in an optimal solution. Older blocks are dead and force a new block.
- **Run compression:** Process maximal equal-value runs. After a run boundary, only the current run value and the previous run value can be active as last-block values. A state whose last value is the previous run value must have size 1 and second-last value equal to the current run value.
- **State before a run:** For current run value `x`, length `L`, previous run value `p`, second-previous run value `q`: `a` is best cost with last value `p`, `b` is best cost with last value `q`, and `pend` is the cost of the special state with last value `p`, size 1, second-last value `x`.
- **Transition table:**  
  `start = min(a, b, 0 if first run else INF) + 1`.  
  `extend = b if q == x else INF`.  
  `cur = min(start, extend)` is best cost after the run with last value `x`.  
  `prev = pend + L` if `pend` is finite, else INF, is best cost after the run with last value `p`.  
  For the next run value `y`, the next special state exists only if `L == 1`; its cost is `best_y + 1`, where `best_y = a` if `y == p`, `best_y = b` if `y == q`, otherwise INF. If `L > 1`, a size-1 last block of value `x` obtained by delaying the start inside the run is dominated by starting at the first element (or by the `prev` state), so it is not needed.
- **Initialization and dummy owner:** Before the first run, use dummy previous values and empty cost 0. This makes the first run start with cost 1 and prevents any fake second-last extension.
- **Long runs:** Extending a second-last block through a long run is kept as `prev = pend + L` because it is a valid strategy. It is often dominated by starting a new block at the run beginning, but keeping it does not hurt. Splitting a run to create a size-1 last block at its last element is dominated by the same exchange argument.
- **Brute-force validation:** The transition table was checked against exhaustive enumeration of all label assignments for short sequences over small alphabets, computing `#labels + inversions` directly. It matched on all tested cases, including alternating sequences, repeated runs, and non-adjacent repeats.
- **Complexity:** Run-length encoding and DP are O(N) per test case and O(1) extra state besides the input, with total O(sum N).
