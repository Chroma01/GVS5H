- **Problem reduction:** Adjacent swaps preserve relative order of the 1s. The final state is a contiguous block of exactly K ones (K = count of 1s). Sorting original 1-indexed positions p[1..K], the j-th 1 must land at position l + j - 1 for a block starting at l. Cost = sum_j |p[j] - (l+j-1)| = sum_j |(p[j]-j) - (l-1)|.
- **Median trick:** With t[j] = p[j] - j, the cost is sum of absolute deviations of t from the single value (l-1). The minimizing (l-1) is any median of t; the value need not correspond to an actual feasible l because any integer median position is valid for the block and the cost formula is exact. Answer = sum_j |t[j] - median|.
- **Median choice:** Any middle element works. Using t[K//2] (0-indexed) is valid for both odd and even K; for even K any value between the two middles gives the same minimal sum (all "between" values equal a middle element here since we need integer median and sum depends only on the multiset, so picking an actual element is fine).
- **Complexity:** O(N) to collect positions, O(K log K) to sort (K <= N = 5e5, fine). Sum uses Python big ints, so no overflow (answer up to ~O(N^2)).
- **Edge cases:** Single 1 -> answer 0. t values may be negative or zero (e.g. leading 1s give t=0), median logic handles negatives naturally.
- **Verification:** "0101001" -> p=[2,4,7], t=[1,2,4], median 2, sum=1+0+2=3. "100" -> t=[0], sum=0. "0101001001" -> p=[2,4,7,10], t=[1,2,4,6], median index 2 -> 4, sum=3+2+0+2=7. All match.
