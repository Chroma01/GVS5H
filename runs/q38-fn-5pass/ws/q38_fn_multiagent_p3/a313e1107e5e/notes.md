- **Chosen approach:** Process prefixes from left to right while maintaining the standard LIS `tails` array. For the current prefix, `tails[k]` is the minimum possible ending value of a strictly increasing subsequence of length `k + 1`.
- **Query reduction:** For a fixed prefix and bound `X`, the answer is the number of `tails` values that are at most `X`. If `tails[k] <= X`, there exists an increasing subsequence of length `k + 1` ending at `tails[k]`, and all previous elements are smaller, hence also at most `X`. Conversely, any valid subsequence of length `L` ending at a value at most `X` implies the minimum possible tail for length `L` is at most `X`.
- **Strict increase detail:** The update must use `bisect_left(tails, a)`, replacing the first value greater than or equal to `a`. Using `bisect_right` would incorrectly allow equal values to extend each other.
- **Implementation details:** Read all integers at once. Slice `A`. Store queries grouped by `R` in flat lists `[X, idx, X, idx, ...]` to avoid tuple overhead. While scanning `A`, after updating `tails` for position `i`, answer all queries with `R = i` using `bisect_right(tails, X)`.
- **Complexity:** Each array element causes one binary search and each query causes one binary search on `tails`, so time is `O((N + Q) log N)`. Memory is `O(N + Q)`.
- **Edge cases:** If `X` is larger than all tails, the answer is `len(tails)`. If `X` were smaller than the minimum prefix value, the code would return `0`, though the constraints guarantee this does not happen. Queries with the same `R` are all answered after processing `A_R`.
- **Alternative approaches:** Offline by value with Fenwick trees or 2D dominance queries are possible, but the prefix tails method is simpler and efficient in Python.
