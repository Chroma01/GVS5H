- **Sample tests:** Manually exercised the provided examples and requested edge cases: `cdcd -> cccc`, `aca -> aaa`, `bc -> ""`; `n < 3` returns `""`; `n = 3` cases such as `abc -> bbb`, `aaa -> aaa`, `aza -> aaa`; all-same strings like `aaaaaa` and `zzzzzz` remain unchanged; lexicographic tie `abcd -> bbbb` rather than `cccc`; boundary cases `zzzz`, `aaaa`, `azzz -> zzzz`, `aaaz -> aaaa`; and a multi-run tie-ish case `abcdef -> bbbeee`. No failing case was found, so the DP and reconstruction were left unchanged.
- **State definition:** The DP is computed backwards over suffixes. For each position `i` and character `c`, `dp1[i][c]` is the minimum cost to complete positions `i..n-1` when there is already an open run of `c` of length exactly 1 before `i`. `dp2` is the same for length exactly 2, and `dp3` is the same for length at least 3.
- **Base cases:** At position `n`, only a run of length at least 3 is valid, so `dp3[n][c] = 0` for all characters, while `dp1[n][c]` and `dp2[n][c]` are infinite.
- **Transitions:** If the current run length is 1 or 2, the next character is forced to be the same character. If the current run length is at least 3, the next character may either continue the same run or switch to a different character. Switching is invalid if the previous run length is less than 3.
- **Switch optimization:** For `dp3[i][c]`, switching to some `x != c` costs `cost_i[x] + dp1[i+1][x]`. For each position, compute the best and second-best values over all `x`. If the best character is not `c`, use the best; otherwise use the second-best. This avoids an O(26^2) transition and keeps the total time O(26n).
- **Tie handling in best/second:** When multiple characters have the same best value, the second-best must also equal the best so that excluding the best character still allows switching to another tied character. The update logic preserves this.
- **Memory layout:** All three DP layers are stored as flat `array('i')` objects of length `(n + 1) * 26`, indexed by `position * 26 + character`. This is much more memory-efficient than nested Python lists. `INF = 10**9` is safely above the maximum possible real cost, which is at most `25 * 50000`.
- **Finite-state capping:** DP values are only updated from finite next states. Impossible states remain `INF`, preventing overflow and keeping array values within the signed 32-bit range.
- **Initial state:** There is no previous run before position 0. The first character is chosen explicitly, adding its cost and then using `dp1[1][first]` as the remaining suffix cost.
- **Lexicographic reconstruction:** After the minimum cost is known, build the answer left to right. At each step, try characters from `'a'` to `'z'` and choose the smallest one whose transition cost plus the stored DP value equals the current DP value. This greedy choice is correct because DP values are exact suffix minima.
- **Reconstruction state:** Track the current run character and its capped length (1, 2, or 3). Continue updates the capped length; switching resets it to 1 and is allowed only from length 3.
- **Edge cases:** If `n < 3`, no good caption exists. For `n >= 3`, a good caption is always possible, for example all `'a'`, but the code still keeps INF checks for safety. At the last position, switching is impossible because it would create a new run of length 1, and `dp1[n][x]` is INF.
- **Pitfalls:** Do not use `dp3[0]` as the initial state because it would pretend a valid run already exists before the string starts. Do not allow switching to the same character; consecutive equal characters are one run, not a new run. Ensure best/second tie handling is correct, otherwise excluding the current character may incorrectly forbid an optimal switch.
- **Complexity:** Time is O(26n), memory is O(26n) with compact arrays.
