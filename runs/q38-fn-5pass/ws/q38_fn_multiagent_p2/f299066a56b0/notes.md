- **Problem:** Given a sorted array of mochi sizes, find the maximum number of disjoint pairs `(a, b)` such that `a` can be placed on `b`, i.e. `2 * a <= b`.
- **Key structural fact:** If `K` pairs are possible, then the `K` smallest mochi can be paired with the `K` largest mochi. For sorted top indices `t_i` and bottom indices `b_i`, we have `t_i >= i` and `b_i <= N - K + i`, so `2 * A[i] <= 2 * A[t_i] <= A[b_i] <= A[N - K + i]`.
- **Restricted halves:** Since `K <= N // 2`, an optimal solution can be found by considering only the first `N // 2` elements as possible tops and the remaining elements as possible bottoms. This restriction is safe and does not reduce the answer.
- **Chosen algorithm:** Use a greedy two-pointer match between the first half and the second half. Pointer `i` scans possible tops in `A[:N//2]`, pointer `j` scans possible bottoms in `A[N//2:]`.
- **Greedy rule:** If `2 * A[i] <= A[j]`, pair them and advance both pointers. Otherwise, `A[j]` is too small even for the smallest remaining top, so it cannot match any later top; advance only `j`.
- **Why greedy is optimal:** Pairing the smallest available top with the smallest feasible bottom preserves larger bottoms for larger tops. If a bottom cannot match the current smallest top, it cannot match any larger top either.
- **Correctness against global optimum:** The restricted matching only creates valid disjoint pairs, so it cannot exceed the true maximum. Conversely, any feasible global solution with `K` pairs implies a feasible solution using the first `K` elements as tops and the last `K` elements as bottoms, all of which lie in the chosen halves. Thus the restricted greedy count equals the global maximum.
- **Complexity:** The algorithm runs in `O(N)` time and uses `O(N)` storage for the input array, with `O(1)` extra working memory.
- **Implementation details:** Use integer comparison `2 * a <= b` to avoid floating-point issues. Read all input from standard input, compute `m = n // 2`, and loop while `i < m` and `j < n`.
- **Edge cases:** Works for `N = 2`, all equal sizes, odd `N`, and large values up to `10^9`. For odd `N`, the second half has one extra element, which is harmless because it only provides additional possible bottoms.
- **Superseded approaches:** Binary search on `K` with the check `2 * A[i] <= A[N - K + i]` is also valid, but the direct two-pointer half-split solution is simpler and linear.
