- **Final approach:** Split into `A == B` and `A < B`. For `A < B`, process maximal good/bad runs with a `B`-bit reachability mask. Bit 0 represents the previous square; a good square is reachable iff any bit at offsets `A..B` is set. A bad square forces a zero and shifts the mask left.
- **A == B case:** Only squares `1 + k*A` can be visited. Check `N == 1 mod A`, then check whether any bad interval intersects this arithmetic progression using `ceil((L-1)/A)` and `floor((R-1)/A)`.
- **Saturation for A < B:** Since jumps include consecutive integers, gcd is 1. Compute a small threshold `T` such that every distance `>= T` is a sum of jumps in `[A, B]`. This is done by DP until `A` consecutive representable distances are found; then adding `A` proves all larger distances are representable.
- **Long good run skip:** If a good run starts at `s` and the mask is nonzero, some reachable square in the previous `B` positions can jump into the run within its first `B` squares. From that entry point, all squares at distance at least `T` are reachable. If run length is at least `T + 2B + 1`, the last `B` squares are all reachable, so the mask can be set to all ones and the rest of the run skipped.
- **Threshold size:** With `B <= 20`, the exact threshold is small (worst around 342 for `19,20`). The code also has a safe fallback `T = 500`, so `K` stays below about 550.
- **Bad run handling:** A bad run of length at least `B` clears the mask because no jump can cross it. A shorter bad run is handled exactly by shifting zeros into the mask.
- **Interval processing:** Start with `cur = 2` and mask bit for square 1. For each bad interval `[L, R]`, process good run `[cur, L-1]`, then bad run `[L, R]`, then set `cur = R+1`. Finally process `[cur, N]`. Answer is bit 0 after all processing.
- **Correctness details:** The mask always stores exact reachability of the last `B` squares for short simulated runs. Long good-run skipping is sound because any nonzero mask guarantees an entry point inside the first `B` squares, and the length condition guarantees the saturated region covers the final `B` squares. All-ones and zero are fixed points for good runs, so early breaks during simulation are safe.
- **Edge cases:** First good run starts at square 2 with square 1 already reachable; positions `<= 0` are implicitly false. Adjacent bad intervals are processed sequentially and combine correctly. Empty good runs are skipped. Constraints exclude bad squares 1 and N, but the logic is robust for normal interval boundaries.
- **Complexity:** There are `O(M)` runs. Short good runs are simulated up to `K < 550`, so worst-case time is about `O(M*K)` with `M <= 2e4`, easily acceptable. Memory is `O(M)` for intervals plus tiny DP state.
- **Sample behavior:** Sample 1 crosses short bad intervals and reaches N. Sample 2 is blocked by a long bad interval that clears the mask. Sample 3 has enough good-run saturation and crossings to reach N.
