- **Core reduction:** For a sorted interval of length `len`, `K` pairs are possible iff the `K` smallest elements can be paired with the `K` largest elements. This is sufficient by explicit pairing, and necessary because replacing chosen tops by smaller elements and chosen bottoms by larger elements cannot hurt feasibility.
- **Feasibility predicate:** Let `p[i]` be the first index with `A[p[i]] >= 2*A[i]`, or `n` if none exists. Define `D[i] = p[i] - i`. For query `[l, r]` (0-indexed) and candidate `K`, feasibility is equivalent to `max(D[l .. l+K-1]) <= (r-l+1) - K`, with `K <= len//2`.
- **Monotonicity:** As `K` increases, the range maximum is nondecreasing and `len-K` is nonincreasing, so feasibility is monotone. Therefore binary search finds the maximum `K`.
- **Computing `p` / `D`:** Since `A` is sorted, use a two-pointer scan. For each `i`, keep `j` nondecreasing, ensure `j > i`, and advance while `A[j] < 2*A[i]`. Store `D[i] = j - i` directly, avoiding a separate `p` array.
- **Range maximum structure:** Build a sparse table over `D`. Level `k` stores maxima over intervals of length `2^k`, with valid starts `0 .. n-2^k`. Query `[l, l+mid-1]` in O(1) using two overlapping intervals: `st[k][l]` and `st[k][l+mid-2^k]`.
- **Query processing:** For each query, binary search `K` in `[0, len//2]`. Each predicate check does one O(1) sparse-table range maximum query. Total query time is `O(Q log N)`.
- **Input/output handling:** Read all integers at once, slice `A` and `queries`, then delete the raw data list to reduce memory. Build answers as strings and write them with one buffered `join`.
- **Complexities:** Time `O(N log N + Q log N)`. Memory `O(N log N)` for the sparse table, with about `3.4M` references for `N=2e5`, plus input/output overhead.
- **Edge cases:** If no valid larger mochi exists, `D[i] = n-i`, which correctly makes the predicate fail for intervals where that element would need to be a top. Duplicates are handled because `2*A[i] > A[i]` for positive sizes. The last element of an interval is never included in the top range when `K <= len//2`. One-indexed input queries are converted to zero-indexed before processing.
