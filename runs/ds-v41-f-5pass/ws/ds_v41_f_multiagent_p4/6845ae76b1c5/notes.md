- **Problem:** For each of K queries (X_k, Y_k), output S(X,Y) = sum_{i<X, j<Y} |A_i − B_j| (0-indexed prefixes). N up to 1e5, K up to 1e4, values up to 2e8.
- **Core decomposition used:** Pick block size S. x = X//S full A-blocks, y = Y//S full B-blocks. PA = A[x*S:X], PB = B[y*S:Y]. Then S(X,Y) = [i<x*S, j<y*S] + [i in PA, j<y*S] + [i<x*S, j in PB] + [i in PA, j in PB]. The first term collapses into the others giving the clean identity: S(X,Y) = cumE[y][X] + cumD[x][Y] − cumD[x][y*S] + cross(PA,PB), where cumE[y][i] = sum over i'<i, j<y*S of |A_i' − B_j| and cumD[x][j] = sum over j'<j, i<x*S of |A_i − B_j'|.
- **Precompute:** E and D are built block-by-block via a sorted block plus prefix sums formula: sum_b |a − b| = a*cnt(b<a) − sum(b<a) + (total − sum(b<a)) − a*cnt(b≥a). Each block is applied over the whole array (vectorized with numpy, else bisect). cumE/cumD are prefix-summed rows. Memory is O((N/S+1)*N) int64.
- **Per query:** base part is O(1) (two array gathers + one). Only the partial×partial cross term is per-query, computed with sort + searchsorted + prefix sums: O(S log S). With S=1000 this is cheap.
- **Block size:** S=1000 chosen so the (M+1)×(N+1) tables stay ≈80MB each (162MB total), block build is fast, and cross arrays are ≤1000 elements.
- **Pitfalls handled:** indices are 0-based with X,Y as counts; x*S may equal N (empty partial) and row M is still valid; equal values contribute 0 so side='left' vs 'right' is irrelevant; results fit in int64 (max ≈ N²·2e8 ≈ 2e18).
- **Numpy:** primary path requires numpy (present on AtCoder-style judges); a pure-Python bisect fallback is included for environments without numpy (correct but slower). Superseded earlier plans (persistent segment tree, wavelet matrix, CDQ/3D dominance, Mo's) are not needed by this decomposition.
