- **Core sweep:** Sweep the second cut `j` from `2` to `N-1`. For each first cut `i`, the segment tree stores `prefix_distinct[i] + distinct(A[i+1..j])`. For fixed `j`, `suffix_distinct[j+1]` is constant, so the answer candidate is the maximum tree value over valid `i` plus `suffix_distinct[j+1]`.
- **Update rule:** When `j` increases, `A[j]` increases the middle distinct count exactly for first cuts `i` such that the previous occurrence `prev[j]` is not inside the middle, i.e. `i >= prev[j]`. With `prev[j]=0`, all valid `i` are affected. The range add is therefore `[max(1, prev[j]), min(j-1, N-2)]`.
- **Indexing:** Cuts are conceptually 1-indexed. Leaves correspond to `i=1..N-2` as 0-indexed positions `0..N-3`. Query range is `[0, min(j-1, N-2)-1]`. Non-empty subarrays are enforced by `i>=1`, `i<j`, and `j<=N-1`.
- **Lazy tree invariant:** `mx[k]` is the maximum in node `k` including its own lazy tag `lz[k]`, but excluding lazy tags of ancestors. For internal nodes, `mx[k] = lz[k] + max(mx[2k], mx[2k+1])`. Applying `+1` to a node increments `mx[k]`, and increments `lz[k]` if internal.
- **Iterative range add:** The iterative update applies directly to canonical cover nodes. Ancestors are rebuilt bottom-up only when the original left or right boundary is not aligned to that level. This avoids overwriting a node that was directly applied. The rebuild formula preserves the invariant without pushing lazy tags.
- **Prefix maximum query:** Queries are always prefixes. The query descends from the root while carrying accumulated ancestor lazy values. If the current segment is fully inside the prefix, return `mx[k] + carry`. If moving to the right child, the left child is fully included and is considered with the current carry. No pushing is required.
- **Initialization:** Prefix distinct counts and previous occurrence positions are computed in one left-to-right pass. Leaves for valid first cuts are initialized with prefix distinct counts. Unused leaves are set to a very negative sentinel so they never affect maxima. Suffix distinct counts are computed in a right-to-left pass.
- **Edge cases:** `N=3` gives `M=1` and segment tree size `S=1`; the code handles this without special casing. If `prev[j]` is larger than the current valid right end, the add range is empty. The query range is always non-empty for `j=2..N-1`.
- **Complexity:** Time is `O(N log N)` with a small constant from the iterative lazy segment tree. Memory is `O(N)` for arrays and the segment tree.
