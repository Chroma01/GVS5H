- **Problem:** N contests; contest i increments rating by 1 iff current rating in [L_i,R_i]. Answer Q queries of initial rating X. N<=2e5, Q<=3e5, values<=5e5.
- **Key reduction:** Track only the distinct query values, sorted ascending. For any fixed prefix of contests, current ratings are non-decreasing in initial X (induction). Hence at each contest the qualifying queries form a contiguous range [p,q] with p=first current rating >= L_i, qq=first current rating > R_i, q=qq-1. Apply +1 on [p,q]. Each query evolves independently, so discarding non-query positions is valid.
- **Data structure:** Iterative lazy segment tree (ACL style) storing subtree maximum, over m<=3e5 sorted distinct queries, padded to a power of two with -inf (-(1<<60)).
- **Lazy representation (no push-down):** store mx[k] = max of subtree k INCLUDING lz[k] but EXCLUDING ancestors' lazies. Update rule: mx[k] = max(mx[2k],mx[2k+1]) + lz[k]. Range add: add 1 (mx and lz) to canonical covering nodes, then recompute ancestors along the two boundary paths (i=1..log on l0>>i and (r0-1)>>i). This avoids any push-down; the decomposition's canonical nodes are disjoint and cover exactly the range, so each in-range leaf's path sum rises by exactly 1 and out-of-range leaves are untouched.
- **find_first(v):** descend from root carrying acc = sum of ancestors' lz. At node k do acc += lz[k], go left if mx[2k]+acc >= v else right. Leaf value = mx[leaf]+acc. Uses only reads (no mutation). Returns -1 if mx[1]<v.
- **Per contest:** p=find_first(L); skip contest if -1. qq = find_first(R+1) if mx[1]>=R+1 else m. If p<=qq-1 range-add [p,qq-1].
- **Final answers:** push all lazies top-down (k=1..size-1) then read leaves; map value->rating and output in original query order.
- **Correctness checks:** Verified sample 1 by hand (gives 6,6,8) plus tiny cases ([2,2] on X=1,2,3 -> 1,3,3; [1,3] on X=1..4 -> 2,3,4,4).
- **Complexity:** O((N+Q) log m) time, O(m) memory. Each contest does two O(log) searches and one O(log) range add.
- **Pitfalls handled:** padding uses -inf so find_first never returns a padding index (targets are >=1); R+1 can exceed all values -> qq=m; empty qualifying range -> skip; m=1 / size=1 edge case; values grow beyond 5e5 (up to 5e5+N), ints unbounded so fine.
- **Micro-opts:** no push-down makes find_first read-only; local list aliases; inline loops instead of function calls.
