- **Cost formula:** minimal increments to make `nums[l..r]` non-decreasing is `sum_{i=l..r}(max(nums[l..i]) - nums[i])`. Answer = count of subarrays with this cost `<= k`. Cost is nondecreasing in `r` and nonincreasing in `l`.
- **Approach:** divide and conquer over indices. `solve(lo,hi)` returns `solve(left)+solve(right)+crossing`. Each subarray belongs to exactly one node (the one whose split separates its endpoints). Complexity `O(n log n)`, memory `O(n)`.
- **Left cost A(l):** iterate `l` from `mid` down to `lo`, maintaining blocks of equal running maxima for `[l..mid]` in a stack stored right-to-left (`sv[0]` = overall max, values nonincreasing toward the end). Prepend `v=nums[l]`: pop blocks from the end with `value < v`, merge them plus the fresh position into one block of value `v`. `T` = sum of running maxima = `sum sv[i]*sc[i]`. Then `A(l) = T - (pref[mid+1]-pref[l])`.
- **Right part:** `R[t]=max(nums[mid+1..mid+1+t])` nondecreasing. With `H=maxL[l]` and `c=r-mid`, right cost = `sumMax - (pref[r+1]-pref[mid+1])` where `sumMax = H*min(t0,c) + (PM[c]-PM[min(t0,c)])`, `t0`= #`R[t]<H`. Formula reduces to `H*c` when `t0>=c`.
- **Crossing two-pointer:** `H` (hence `t0=ptr0`) is nondecreasing as `l` decreases, so `ptr0` only advances. Valid `r` set shrinks as `l` decreases, so `rstar` only decreases and is reset to `hi` once per node; the inner loop is amortized `O(size)`. If `rstar` drops to `mid`, even `c=1` is infeasible and all smaller `l` are too -> break.
- **Small segments:** `TH=20`; inner brute force over the segment with early break (cost monotone) is faster than continued recursion.
- **Verified:** Example 1 -> 17 (PASS); Example 2 -> 12 (PASS); `n=1` -> 1 (PASS). Cross-checked the crossing logic by hand on `[5,1,3,2],k=3` (crossing valid count 2, total 7) and on `[2,5,1,4,3],k=5` -> 13 (matches brute). Random small arrays vs. brute force matched.
- **Timing:** random `n=1e5` (values up to 1e9, `k=1e9`) runs in ~1.1 s; `k=1` similar. Within limits.
- **Pitfalls:** the stack must be right-to-left so `sv[0]` is the max and pops come from the smallest (end); `T` must be the sum of running maxima per position (a naive `curmax`-only running total undercounts, e.g. gives 2 for `[1,3]`); `t0`/`ptr0` must not reset per `rstar` change; `pref` is global.
- **Python ints** handle costs up to ~`1e14` (no overflow).
