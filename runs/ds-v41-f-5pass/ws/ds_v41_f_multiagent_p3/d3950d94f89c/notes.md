- **Problem shape:** find a downward path (ancestor -> descendant, possibly length 0) whose node values are all distinct. Maximize total edge length; tie-break by minimum node count. Return [maxLen, minNodes].
- **Key reduction:** for a fixed end node u, the best (longest) valid path ends at u and starts as early as possible, since all edge lengths are positive. So we only need one candidate per node.
- **Validity condition:** let prev[v] be the depth of the nearest ancestor of v (on the current root path) sharing v's value, or -1. A path from depth a to depth d is value-unique iff a > max(prev[v]) over all v in [a, d]. Hence the earliest valid start depth is m+1 where m is the running maximum of prev over the root->u path.
- **Why earliest start is globally sufficient:** length strictly increases as start moves earlier (positive weights), so for a fixed u the earliest start is the unique maximizer of length. Any globally-longest path must therefore be the earliest-start candidate of its end node, so scanning one candidate per node suffices for both objectives.
- **Running max recurrence:** m[u] = max(m[parent], last[nums[u]]), where last maps value -> depth of most recent occurrence on the current path. Pass m down through the DFS frame; no need to recompute.
- **Prefix sums:** maintain pref[d] = root-to-node length at depth d, set at node entry. Length of path [start..u] = pref[depth] - pref[start]. Index start <= depth is always safe because prev < depth so m+1 <= depth.
- **Node count:** depth - start + 1. A single node gives length 0, count 1 — initialize best = (0, 1) so this baseline is covered; also handles the all-zero-length case.
- **Backtracking:** last[nums[node]] must be restored on exit. Implemented with an explicit "exit" frame pushed before children (LIFO ensures children finish first). Store the previous last value (prev, possibly -1) in the exit frame.
- **Iterative DFS:** avoid recursion-limit issues for n up to 5e4. Each node contributes one enter + one exit frame and one child push per incident non-parent edge, so O(n) frames and O(n) total work.
- **Edge cases handled:** n=2 with equal values -> [0,1]; repeated values deep in a path -> earliest start collapses to just after the offending duplicate; tie-break strictly prefers fewer nodes (only update count, never length, on equal length).
- **Complexity:** time O(n), space O(n). Verified by hand on both provided examples (example 1 yields [6,2], example 2 yields [0,1]).
