- **Problem:** Choose k boundary points of a square of side S maximizing the minimum Manhattan distance. Feasibility of a threshold D is monotone, so binary search D.
- **Core reduction (valid only for D <= S):** L1(p,q) < D iff shorter circular perimeter distance < D. Same edge: L1 = shorter arc. Adjacent edges: L1 = arc through shared corner (the other arc is >= 2S, never shorter). Opposite edges: both L1 and perimeter distance are >= S >= D, so both "less than D" tests are false (equivalent). Since k >= 4 the answer is <= S, so the reduction always applies.
- **Upper bound:** Perimeter is 4S; any 4 points have 4 gaps summing to 4S so one gap (a pairwise circular distance) <= S. Thus for k >= 4 the answer <= S; binary search range [0, S].
- **Perimeter mapping:** `y==0 -> x`; `x==S -> S+y`; `y==S -> 2S+(S-x)`; else `3S+(S-y)`. Corners land on 0, S, 2S, 3S, so the map boundary -> [0,4S) is a bijection and distinct points stay distinct.
- **Feasibility reformulation:** select k points on a circle of circumference 4S with every cyclically-consecutive gap >= D. Given D <= S <= L/2 this is equivalent to pairwise circular distance >= D, so requiring consecutive gaps (including the wrap gap) >= D is both necessary and sufficient.
- **Feasibility algorithm:** build doubled array A = coords + coords+L. Two-pointer computes nxt[i] = first j > i with A[j]-A[i] >= D. For every start s in [0,n) greedily jump via nxt exactly k-1 times inside window [s, s+n); then require nxt[cur] <= s+n so the last-to-first wrap gap is >= D. Return True if any start succeeds. Greedy is safe because earliest-next minimizes every chosen index; if a solution starting at s exists, greedy's points dominate it index-wise and still pass the wrap test, and any optimal set has a smallest-index member usable as start s.
- **Complexity:** nxt is O(n); the start scan is O(n*k). With n <= 15000, k <= 25, ~30 binary-search steps => ~11M ops, fine in Python.
- **Edge cases:** D=0 always feasible. k <= n guaranteed. Exact distance D allowed (use >= D). Points unique => perimeter coords unique. hi=S handled even if S itself is infeasible.
- **Sample tests (verdict: PASS):** side=2, [[0,2],[2,0],[2,2],[0,0]], k=4 -> 2 (coords {0,2,4,6}, D=2 works, D=3 impossible since 4*3>8). side=2, [[0,0],[1,2],[2,0],[2,2],[2,1]], k=4 -> 1 (D=2 needs gaps exactly 2: 0,2,4,6 but 6 absent). side=2, [[0,0],[0,1],[0,2],[1,2],[2,0],[2,2],[2,1]], k=5 -> 1 (D=2 needs 5 gaps >= 2 summing > 8). Independent cross-checks (side=3 corners+edge points k=4 -> 3; side=4 with opposite-edge midpoints k=4 -> 4) match the reduction and the invariant that opposite-edge pairs never create false positives.
- **Randomized brute force:** enumerate all k-subsets on small side (S <= 4) with random boundary points (corners, edge midpoints, exact-tie configs) and compute the true maximin directly; the solution agrees on every trial, including cases where the answer equals S and where many ties occur.
