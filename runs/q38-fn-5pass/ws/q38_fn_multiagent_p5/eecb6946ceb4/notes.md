- **Core reduction:** A fine triplet is a 3-term AP. For each middle value B, valid endpoints A,C satisfy A+C=2B. If P is the 0/1 indicator polynomial of S, then coefficient of x^(2B) in P(x)^2 counts ordered endpoint pairs (A,C). Since (B,B) is always present when B in S, subtract 1 and divide by 2.
- **NumPy path:** Build float64 indicator up to max(S), use `np.fft.rfft`, square spectrum, `np.fft.irfft`, then read coefficients at indices `2*B`. Round with `floor(x + 0.5 + eps)`. Coefficients are <= N <= 1e6, so double precision is normally safe for length around 2^21.
- **Normalization:** Translation by min(S) and division by gcd of all shifted values preserve AP counts and can greatly reduce the FFT/big-int universe. This is done in both NumPy and fallback paths. Transformed values may include 0; all routines handle 0 correctly.
- **Fallback exact convolution:** Use base 2^24 digits. Create a bytearray with 3 bytes per value, set the low byte of digit s to 1, convert to int, square, convert back to bytes, and extract 3-byte little-endian digits at offsets `6*B`. No carries occur because every convolution coefficient is at most N <= 1e6 < 2^24.
- **Sparse fallback:** For small N and large normalized max_s, enumerate endpoint pairs of the same parity and test midpoint membership with a bytearray. This avoids a large big-integer square when N is moderate. Threshold is roughly 30 million same-parity endpoint pairs and max_s > 200000.
- **Parsing:** Try NumPy first. If available, parse with `np.fromstring` on decoded input. If unavailable or NumPy path fails, use a manual byte parser that builds Python ints directly, reducing peak memory compared with `split()`.
- **Edge cases:** N < 3 outputs 0. Normalization can create value 0. FFT length is next power of two at least `2*max_s+1`. Big-int `to_bytes` length is padded to cover digit `2*max_s`.
- **Performance considerations:** Pure Python NTT/FFT is too slow for 2^21. Big-int multiplication is C-level and exact, but worst-case 3MB integer squares can still be heavy; normalization and sparse path mitigate many cases. NumPy FFT is the intended fast path when available.
