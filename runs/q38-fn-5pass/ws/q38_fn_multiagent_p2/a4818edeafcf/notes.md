- **Chosen approach:** Sweep the right split `j` from left to right. For each `j`, maintain for every possible left split `i` the value `V_i = distinct(A[1..i]) + distinct(A[i+1..j])`. The answer for this `j` is `max_{1 <= i < j} V_i + distinct(A[j+1..N])`.
- **Difference-array segment tree:** Instead of a lazy range-add/range-max tree on `V`, maintain the difference array `D` where `V_i = D_1 + ... + D_i`. A range add `+1` on `V[l..r]` becomes two point updates: `D[l] += 1` and `D[r+1] -= 1`. The segment tree stores for each node the segment sum and the maximum non-empty prefix sum. A prefix query over `D[1..j-1]` returns `max V_i` for active left splits.
- **Why this is equivalent:** The original plan uses range increments over candidate left splits. The difference-array tree supports exactly those range increments with point updates and answers prefix maximums, avoiding lazy propagation while preserving the same sweep logic.
- **Update rule:** Let `p` be the previous occurrence of `A[j]` before position `j`, or `0` if none. When `A[j]` is appended to the middle segment, it increases the middle distinct count exactly for left splits `i` such that the previous occurrence is not inside `A[i+1..j-1]`. This is `i >= p` if `p > 0`, otherwise all active `i`. In 0-based difference positions, apply `+1` at `max(p-1, 0)` and `-1` at `j-1`.
- **Initialization:** Initial `V_i` is the prefix distinct count `L[i]`, so initial `D_i = L[i] - L[i-1]`. Inactive candidate values remain correct because every range update subtracts at its right boundary plus one, leaving prefix sums beyond the active end unchanged. Therefore explicit activation is unnecessary; querying only the first `j-1` positions is enough.
- **Indexing details:** The code uses 1-based `A` and suffix array `R`. The loop runs `j = 2..N-1`. Active left splits are `1..j-1`, so the prefix query count is `j-1`. The suffix contribution is `R[j+1]`. `last[A[1]]` is initialized before the loop, and `last[x]` is updated after processing position `j`.
- **Segment tree combine:** For a node with left child `L` and right child `R`, `sum = L.sum + R.sum` and `pref = max(L.pref, L.sum + R.pref)`. Leaves beyond `N` have `sum = 0` and `pref = -INF`, so they do not affect valid prefix maxima.
- **Prefix query implementation:** The query walks toward the boundary `count`, taking whole left children whenever it goes right, and returns early when the current node is fully covered. This is faster than a generic range query because the query is always a prefix.
- **Pair update implementation:** Each sweep step performs two point updates. The code updates both leaves first and recomputes only the unique ancestors of the two leaves, reducing redundant work compared with two independent point updates.
- **Complexity:** Precomputation is `O(N)`. Each of the `O(N)` sweep steps does one pair update and one prefix query, each `O(log N)`, so total time is `O(N log N)` and memory is `O(N)`.
- **Edge cases:** `N = 3` has only one valid split pair. All-equal and all-distinct sequences are handled naturally. If the previous occurrence is `j-1`, the update affects only the newly active left split `i = j-1`. Negative entries in `D` are fine because the tree stores non-empty prefix maxima, not empty-prefix maxima.
