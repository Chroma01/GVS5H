- **Problem reduction:** For a single value x, let c(x) = number of times it must be selected to reach 0 = floor(log_4 x) + 1 (smallest d with floor(x/4^d)=0); c(0)=0. c is nondecreasing, piecewise constant with c(x)=k exactly on the base-4 block [4^(k-1), 4^k - 1].
- **Per-query answer:** With S = sum of c(x) over [l, r] and mc = c(r) (max over the range, since c is nondecreasing), the minimum operations = max(ceil(S/2), mc). Each operation selects exactly two positions and reduces total "work" by at most 2 (bound S/2); the heaviest element is selected at most once per op so it needs at least mc ops (bound mc).
- **Achievability:** The pairwise-decrement invariant holds: minimum ops to zero all counters = max(max_counter, ceil(sum/2)). If one counter dominates (mc > S/2), pair it with others then finish it by pairing with zero-valued elements; otherwise pair greedily and only a single leftover unit (sum odd) ever remains, which is paired with an existing zero. Array has >= 2 elements because l < r, so a zero partner always exists. Zeros are selectable and stay zero.
- **Computing S:** Only ~15 base-4 blocks cover up to 1e9 (4^14 = 268435456, 4^15 > 1e9). For each query add k * |[l,r] ∩ [4^(k-1), 4^k - 1]|. Complexity O(queries * 15) ≈ 1.5e6, well within limits. mc obtained via bisect_right on block starts.
- **Overflow:** Python ints unlimited; S up to ~15e9, sums safe. Use 64-bit in other languages.
- **Pitfalls handled:** base 4 not base 2; inclusive block ends; c(1)=1 and c(powers of 4) correct (4 -> 2 reductions); bisect count equals c(r); mc term needed when one value dominates.
- **Examples verified:** [[1,2],[2,4]] -> [1,2] S=2 mc=1 => 1; [2,4] S=4 mc=2 => 2; total 3. [[2,6]] c=(1,1,2,2,2) S=8 mc=2 => max(4,2)=4.
- **Brute-force check:** For all 1<=l<r<=200, compared formula to an independent greedy simulation: max-heap of counters c(x); repeatedly pop two largest positive counters, decrement both, drop zeros; if one positive remains, add its value (pairs with a zero). Result: ALL ranges matched, zero mismatches; both provided examples match (3 and 4). Greedy optimality additionally cross-checked against exhaustive min-ops search on small multisets.
- **Block list:** k=1:[1,3], k=2:[4,15], k=3:[16,63], k=4:[64,255], k=5:[256,1023], ... k=15 covers up to 1e9.
