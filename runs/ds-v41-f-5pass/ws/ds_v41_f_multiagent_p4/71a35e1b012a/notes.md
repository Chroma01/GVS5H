- **Problem model:** Operations only turn 0→1, so order is irrelevant. Goal reached iff every position is covered by at least one chosen operation. Type 1 covers `[L,R]`; type 2 covers its complement; cost = number of chosen operations.
- **Min cost bound:** Answer is always 1, 2, 3, or -1. For M≥3 the goal is always achievable (cost ≤3); M=2 may be 2 or -1; M=1 is 1 or -1.
- **Cost 1:** Some interval equals `[1,N]`; use type 1 on it.
- **Cost 2, mixed (FIXED):** Type1 on outer A, type2 on inner B covers all iff `B ⊆ A`. Sort indices by `(L asc, R asc)` and scan once keeping prefix-max R (`curIdx`). Flag when `R[k] <= curMax` (outer=curIdx has strictly smaller L since same-L is handled first by the `prev` rule). Additionally, whenever two consecutive sorted intervals share the same L, the later (larger/equal R) contains the earlier — flag it directly. This combined pass catches all containments: same-L nesting/duplicates via the prev rule, distinct-L containment via prefix max.
- **Why sorted `(L asc, R asc)` now:** earlier `(L,-R)` matched a valid cost-2 but produced a different (equally optimal) op vector. Ascending R makes Sample 1 pick outer=(1,4) idx3, inner=(2,4) idx1 → `2 / 2 0 1 0` exactly.
- **Cost 2, two type-1:** Need an interval with L=1 and one with R=N whose union connects. Take iS = max R among L=1, iT = min L among R=N. Valid iff `iS != iT` and `R[iS]+1 >= L[iT]`.
- **Cost 2, two type-2:** Complements cover all iff the intervals are disjoint. Exists iff `min R < max L`; use the argmin-R and argmax-L indices (always distinct because `L_i ≤ R_i`).
- **Cost 3 construction:** Reachable only when no cost-2 exists and M≥3. Then no disjoint pair (else cost-2 type-2), so intervals pairwise intersect, hence share a point by Helly; also no containment, so it is an antichain. Pick `a` = min L, `c` = max R (distinct, else one interval contains all → cost 2), and any other `b`; then `A_b ⊆ [L_a, R_c] = A_a ∪ A_c`, so type1(a)+type1(c)+type2(b) covers `[1,N]`.
- **Impossible:** M=1 not `[1,N]`; M=2 with none of the cost-1/cost-2 cases. Print `-1`.
- **Check order:** cost1 → mixed cost2 → two-type-1 cost2 → two-type-2 cost2 → cost3 → -1. The order among cost-2 checks does not affect optimality, only which minimal solution is emitted; putting mixed first reproduces the samples exactly.
- **Complexity:** O(M log M) for the sort, O(M) otherwise; memory O(M). Fits N=1e6, M=2e5.
- **Sample verification (traced, exact strings):** S1 `2 / 2 0 1 0`; S2 `1 / 0 1 0 0` (cost-1 `[1,5]`); S3 `2 / 1 1`; S4 `-1` (M=2, no containment, `R=5` interval absent, disjoint test fails).
- **Brute-force differential testing:** Enumerated all 3^M op assignments for small random `(N≤7, M≤6)`; compared only (i) minimum cost K and (ii) semantic validity (each emitted op vector must make every position 1). No mismatches. The semantic comparator (not string equality) is required since any minimum solution is accepted.
- **Completeness argument for mixed detection:** any containment `B ⊆ A` has `L_A ≤ L_B`. If `L_A = L_B`, both are in the same equal-L run; ascending R puts A (larger R) after B, caught by the adjacent same-L rule. If `L_A < L_B`, A is processed earlier, so `R_B ≤ R_A ≤ curMax` at B, caught by the prefix-max rule. Conversely each flagged pair is a genuine containment.
- **Edge cases handled:** integer adjacency `R+1 ≥ L`; N=1 (always cost 1); duplicate intervals (same-L ⇒ cost 2); single-element intervals; output rows of all-zero ops (unused operations).
