- **Reformulation:** Removing every occurrence of `x` is the same as zeroing those positions in a fixed-length copy. Zeroed slots contribute nothing and let surviving neighbours become adjacent, so the max subarray after deleting `x` equals the max subarray of the zero-mutated array. Answer = best over the no-op and over every allowed `x`.
- **All-negative fix:** If `max(nums) < 0`, return `max(nums)`. All sums are ≤ the largest element; the no-op achieves it and no deletion can beat it.
- **Empty-allowed trick and proof:** In the zero-mutated array a range consisting only of deleted slots sums to `0`, whereas the real subarray would be empty (illegal). So the structure reports `max(0, true_best_x)`. Since `mx ≥ 0` implies the no-op best is `≥ 0`, the reported value is the true optimum: `max(noop, max_x max(0, tb_x)) = max(noop, max_x tb_x)`.
- **Two equivalent algorithms:** (a) segment tree over the max-subarray monoid with point updates, `~2n` leaf updates, `O(n log n)`, verified correct; (b) gaps DP + sparse tables, `O(n log n)` with much lighter constants — the shipped version. Both compute the same quantity.
- **Gaps DP (shipped):** For value `x`, split the array at its occurrences into maximal runs (gaps) not containing `x`. Concatenating the gaps equals `B_x` (zero-mutated array). Run a Kadane-style merge over gaps using each gap's `(total t, best prefix p, best suffix s)`: `best = max(best, suf + p)`, `suf = max(0, suf + t, s)`. Within-gap best subarrays are omitted — safe because any such range is also a subarray of the original array, so it is `≤` the no-op answer.
- **Gap quantities via prefix sums:** With `P[i]` = sum of first `i` elements, `t = P[r+1]-P[l]`, `p = max(P[l+1..r+1]) - P[l]`, `s = P[r+1] - min(P[l..r])`. Range max/min use idempotent sparse tables (O(1) queries). `max/min` return existing int objects, so tables store only references — memory is just pointers (~2·m·log m), not new ints.
- **Values with frequency == n** are skipped (deleting them empties the array). Values absent from `nums` coincide with the no-op. Total number of gaps over all values is `n + distinct`, so the DP is `O(n)`.
- **Complexity:** `O(n log n)` time (sparse-table build), `O(n log n)` memory, well within limits for `n ≤ 1e5`.
- **Test results — PASS.**
  - Provided examples: `[-3,2,-2,-1,3,-2,3]` → 7 ✓ ; `[1,2,3,4]` → 10 ✓.
  - Hand-checked against brute force (enumerate every allowed `x`, Kadane each). Cases: `[-5,10,-5]`→10, `[5,-10,5,5]`→15, `[2,-1,2]`→4, `[1,-1,1]`→2, `[7,-9,7]`→14, `[0,-1]`→0, `[3,-1,3,-1,3]`→9, all-negative `[-1,-2]`→-1, single `[7]`→7 / `[-7]`→-7 / `[0]`→0, all-equal `[5,5]`→10, all-equal negative `[-5,-5]`→-5. All match.
  - No minimal counterexample found. The monotone argument above shows none can exist: the only overestimate source (empty subarray) is always dominated by the non-negative no-op candidate when `mx ≥ 0`, and is excluded by the early return when `mx < 0`.
- **Edge cases covered:** `n == 1`; all elements equal (freq == n, only no-op); zeros acting as identity; strictly negative arrays; values appearing once at array boundaries.
