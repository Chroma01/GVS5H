The key is to avoid recomputing inversions for every k from scratch by processing the cyclic shift incrementally. Compute the inversion count at k=0 using a Fenwick tree over values, then update it as k increases by one, since only the elements whose value equals M-k change from non-wrapped to wrapped. Precompute for each value its frequency and the sum of its 0-based indices so the change in inversion count can be evaluated in O(1) per k. Finally, emit the M cumulative answers in order.
