- **Problem:** choose exactly K edges to weight 1 (rest 0), maximize shortest 1->N distance. Adding marks never decreases the shortest distance, so "exactly K" equals "at most K"; and any valid set can be padded with arbitrary extra marks. Answer is in 0..N-1 (a shortest path is simple).
- **Reformulation:** target d is feasible iff there is an edge set S, |S| <= K, hitting every 1->N path in >= d edges. This minimum |S| equals min over integer potentials L (L(1)=0, L(N)>=d, L(v)<=L(u)+1 for every edge u->v) of #{edges with L(v)=L(u)+1}. Forward: L=min marked-edge count satisfies constraints and counted edges are a subset of S. Backward: any path's L-increase telescopes to >= d, and each +1 step is a counted edge, so every path has >= d counted edges.
- **Clamp to [0,d]:** min(max(L,0),d) is monotone 1-Lipschitz, keeps the constraints and L(N)=d, and only removes (never adds) counted edges. So exact labeling in [0,d] suffices; forcing L(N)=d is equivalent to L(N)>=d.
- **Min-cut model (source side = y=1):** y_{v,k}=[L(v)>=k], k=1..d; node(v,k)=v*d+(k-1). S->(N-1,k) and (0,k)->T with INF force L(N)=d and L(1)=0. (v,k+1)->(v,k) INF = monotonicity. Edge u->v: (v,k)->(u,k) cap 1 for k=1..d pays 1 per unit of L(v)-L(u)>0 (so exactly 1 when L(v)=L(u)+1); (v,k)->(u,k-1) INF forbids L(v)>=L(u)+2. Min cut = min |S|.
- **INF choice / feasibility:** INF = M+1 > K and > any finite cut (min |S| <= M). maxflow <= K means a finite (INF-free) cut exists, i.e. d feasible; otherwise some INF edge is cut and flow > K, reported infeasible.
- **Monotonicity:** if a set works for d it works for d-1, so feasibility is downward-closed; scan d=1..N-1, stop at the first failure. Answer defaults to 0.
- **Multi-edges:** each edge contributes its own cost/constraint edges independently; model stays exact (sample 3: two parallel 1->2 need both marked for d=1, so 2 > K=1 -> answer 0).
- **Complexity:** at most ~N*d <= 870 nodes and ~M*(2d-1) edges per d, run for d up to N-1; Dinic with early cap (stop once flow > K) is fast for N<=30, M<=100.
- **Verified samples:** outputs 1, 2, 0.
- **Pitfall avoided:** this min is NOT the ordinary "delete edges to lengthen paths" min d-cut; it counts marking edges, e.g. two disjoint length-2 paths need all 4 edges marked for d=2 but only 2 for d=1.
