- **Reduction:** Split `p` around the two `*` characters into three literal blocks. Empty literal blocks can be removed because their surrounding stars can match zero characters. The remaining non-empty blocks must appear in order as non-overlapping intervals in `s`. The shortest substring starts at the first chosen non-empty block and ends at the last chosen non-empty block.
- **Empty-block cases:** If all blocks are empty, the answer is `0`. If exactly one non-empty block remains, the answer is its length if it occurs, otherwise `-1`. If two non-empty blocks remain, they must satisfy `end(first) <= start(second)`. If three remain, both adjacent pairs must satisfy the same non-overlap condition.
- **Occurrence finding:** Use KMP to find all start positions of each distinct non-empty block in `s`. KMP returns occurrences in increasing order and correctly includes overlapping occurrences. Duplicate blocks are cached to avoid repeated scans. If any required block has no occurrence, return `-1`.
- **Two-block minimization:** Scan occurrences of the second block in increasing start order. Maintain a pointer over first-block occurrences and the latest first-block start whose end is `<=` current second-block start. For each valid second occurrence, candidate length is `second_end - best_first_start`.
- **Three-block minimization:** Scan middle-block occurrences in increasing start order. Maintain the latest valid first-block start ending before the middle start. Also maintain a monotonic pointer to the earliest third-block start that is `>=` the middle end. For each middle occurrence with both sides valid, candidate length is `third_end - best_first_start`.
- **Monotonicity:** Middle occurrences have fixed length, so their ends are nondecreasing. Therefore the earliest valid third-block pointer only moves forward. The latest valid first-block pointer also only moves forward because middle starts are nondecreasing.
- **Complexity:** KMP costs `O(len(s) + len(block))` per distinct block. With at most three blocks, total time is linear in `len(s) + len(p)`. The two- and three-block scans are linear in the number of occurrences, also `O(len(s))` per block. Memory is linear for occurrence lists and KMP prefix arrays.
- **Edge cases covered:** adjacent stars, leading/trailing stars, all-empty pattern, missing blocks, overlapping literal occurrences, zero-length gaps, non-overlap constraints between literal blocks, repeated blocks, and one-block patterns.
- **Test harness:** Added a main-only harness that runs the four examples plus edge cases. It prints `PASS` for each case and `FAIL` with the input if any case fails. The current implementation passes the selected cases.
