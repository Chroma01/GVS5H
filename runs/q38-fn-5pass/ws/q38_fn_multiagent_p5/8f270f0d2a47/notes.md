- **Approach:** Count beautiful numbers up to a bound `n`, then answer `[l, r]` as `count_up_to(r) - count_up_to(l - 1)`. The counting routine is a digit DP over the decimal representation of `n`.
- **DP state:** The tight traversal uses position, whether the number has started, current digit sum, and current digit product. Unrestricted suffixes are memoized by `(remaining_positions, started, digit_sum, digit_product)`, which shares non-tight states across different bounds.
- **Leading zeros:** `started=False` means no non-zero digit has been placed yet. Choosing `0` while not started keeps the state unchanged and does not affect sum or product. Choosing a non-zero digit starts the number with `digit_sum = digit_product = d`. At the end, `started=False` represents the number `0` and is excluded.
- **Zero product handling:** Once a real zero digit is appended after the number has started, the digit product becomes `0` and remains `0` for all further digits. Since every positive integer has a positive digit sum, `0 % digit_sum == 0`, so every number containing at least one non-leading zero digit is beautiful. The free DP now short-circuits these states by returning `10 ** rem`.
- **Tight handling:** While following the bound, digits smaller than the current bound digit create an unrestricted suffix, so their contribution is taken from the memoized free DP. The digit equal to the bound digit continues the tight recursion. This avoids recomputing large non-tight state spaces for both `r` and `l - 1`.
- **State-space and performance:** Because `r < 10^9`, there are at most 9 digits. Non-zero products correspond to products of at most 9 digits from `1` to `9`, and digit sums are at most `81`. The zero-product shortcut removes a large recursive subtree. The cached state count remains small enough for Python `lru_cache` to run comfortably.
- **Edge cases:** `_count_up_to(n)` returns `0` for `n <= 0`, so `l = 1` is handled correctly. Single-digit numbers are all beautiful because product equals sum. Bounds near `10^9` are handled by the same DP. The placeholder product `1` for the not-started state prevents modulo-by-zero issues.
