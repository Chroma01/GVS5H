- **Transition table:** Let `a_i = 1` mean the cycle edge is oriented `i -> i+1 mod N`, otherwise `0`. The cycle indegree contribution at vertex `i` is `c_i = a_{i-1} + (1 - a_i) = 1 + a_{i-1} - a_i`. If `s_i = 0`, `d_i = c_i`, giving transitions: `d=0`: `0->1`; `d=1`: `0->0, 1->1`; `d=2`: `1->0`. If `s_i = 1`, the star edge may add `b_i in {0,1}` to `d_i`, giving: `d=0`: `0->1`; `d=1`: `0->0, 0->1, 1->1`; `d=2`: `0->0, 1->0, 1->1`; `d=3`: `1->0`.
- **Star edge and d_N:** If the star edge at `i` is oriented `N -> i`, it adds `1` to `d_i` and `0` to `d_N`; if oriented `i -> N`, it adds `0` to `d_i` and `1` to `d_N`. The total indegree sum is fixed to `N + K`, where `K` is the number of ones in `s`. Therefore `d_N = N + K - sum_{i=0}^{N-1} d_i`, so it is forced by the prefix and does not create extra choices.
- **Automaton:** Process vertices `0..N-1`. A relation `R subset {0,1}^2` maps the initial cycle state `a_{-1}=a_{N-1}` to the current state after a prefix. Initially `R` is identity. For each chosen `d_i`, compose `R` with the local transition relation. After all `N` vertices, the prefix is feasible iff `R` contains a diagonal pair `(0,0)` or `(1,1)`. This counts distinct degree prefixes, not orientations, because the relation is the deterministic subset-construction state of the nondeterministic automaton.
- **Symmetry reduction:** Swapping cycle states `0 <-> 1` is a symmetry of the whole label set: for `s_i=0`, `0<->2` swaps the `0->1` and `1->0` transitions; for `s_i=1`, `d -> 3-d` swaps them and also swaps the two nondeterministic middle labels. Thus counts of swapped relations are always equal. The program aggregates relations into swap orbits.
- **Orbit transition averaging:** For an orbit of size 2, a label from one member may go to a different orbit than the corresponding swapped label from the other member. Therefore the aggregated transition coefficient is the average over the two members: `sum_member count_to_target / orbit_size`. This can be fractional; modulo arithmetic uses `INV2`. This is essential: using only one representative would be wrong.
- **Final weights:** A relation has a diagonal iff its swapped relation also has one, so final acceptance is orbit-invariant. The code still computes weights generally as `accepted_members / orbit_size`.
- **Block optimization:** The live orbit count is very small (at most 8). To reduce Python loop overhead, all transitions for every 10-bit pattern of `s` are precomputed as sparse matrices over the orbit DP. The input is processed in 10-bit chunks; a short remainder is processed one character at a time.
- **Complexity:** Precomputation is constant time for `B=10` and tiny state count. Processing is `O(N/B * E + N)` where `E` is at most `S^2` per block, plus `O(N)` to build block indices. Memory is `O(2^B * S^2)`, small.
- **Checks:** For sample `N=3, s=010`, the DP gives 14. For cycle-only `N=3, s=000`, it gives 7, matching the distinct cycle orientation indegree sequences.
