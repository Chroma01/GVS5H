- **Problem model:** cost of turning a length-x window constant = sum of absolute deviations from its median. Windows chosen are independent, so each uses its own median (lower median for even x, fixed by rank `(x+1)//2`). Picking k non-overlapping windows. "At least k" reduces to "exactly k" since all costs are nonnegative.
- **Window cost via Fenwick:** sliding window over nums with two compressed Fenwick trees (counts and sums) plus a running `total`. The median is the `target`-th smallest, found by Fenwick binary lifting using `cnt[nxt]` node values with the `nxt<=m` guard; `LOG = 1 << m.bit_length()` works even when `LOG > m` because overshoot is skipped.
- **Key simplification (verified):** during the kth-smallest lifting, accumulate `cl, sl` = count/sum of elements strictly below the median directly from the skipped-in nodes. Then `cost = 2*(median*cl - sl) + total - median*x`. Derivation: cost = (median*cl - sl) + (sg - median*cg) with sg = total - sl - median*ce, cg = x - cl - ce; the `ce` (equals count) cancels, so no `<=` prefix query is needed. This removes two Fenwick prefix queries per window.
- **Median index:** after lifting, `idx` is the largest compressed position with prefix count < target; median = `vals[idx]` (0-based). Elements below median are exactly positions <= idx.
- **DP recurrence:** `dp[j][i] = min(dp[j][i-1], dp[j-1][i-x] + cost[i-x])` over first i positions with j windows. `cost[i-x]` is the window ending at index i-1 (start i-x); `prev[i-x]` guarantees non-overlap but allows adjacency. One rolling row is enough. Initialize j=0 row to zeros; iterate i from x to n (positions < x stay INF). Answer is `prev[n]`.
- **Indexing checks:** cost has length n-x+1; window ending at i has start i-x+1 in 0-based, matching `cost[i-x+1]` at fill time and `cost[i-x]` in DP (i is 1-based count of positions). Verified on both examples by hand.
- **Complexity:** O(n log n) for window costs, O(nk) for DP (<= 1.5e6 steps). Python ints handle sums (~1e11) safely.
- **Sample verdicts (traced):** Example 1 -> cost=[10,5,6,4,4,3,7], best pair start1+start5 = 5+3 = 8 (expected 8) PASS. Example 2 -> cost=[11,0,0,3,4], best pair start1+start3 = 0+3 = 3 (expected 3) PASS.
- **Edge cases checked:** k=1 (single min-cost window), x=n (cost[0] alone, DP i=n uses prev[n-x]=prev[0]), adjacent windows (start s and s+x allowed, e.g. Example 2), duplicates (m=1 gives cost 0), negatives (signed sums fine), even x (lower median throughout).
- **Pitfall watch:** not accumulating `sl` alongside `cl` would force extra prefix queries; the cancellation means equals contribute 0 and need no special handling.
