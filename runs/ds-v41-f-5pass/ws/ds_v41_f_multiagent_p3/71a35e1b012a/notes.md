- **Reformulation:** final x all 1 iff the chosen ops' coverage union is `[1,N]`; op1 covers its interval, op2 covers its complement. Minimize number of chosen ops.
- **Optimal cost ∈ {1,2,3}.** cost-1 iff some interval == `[1,N]` (a lone op2 can never cover its own interval).
- **cost-2 patterns (exhaustive):** (b) containment `I_i ⊆ I_j` -> op2 on i, op1 on j; (a) disjoint pair `R_i < L_j` -> op2 on both; (c) two op1 whose union is `[1,N]`.
- **Detections:** disjoint iff `minR < maxL` (argmin-R and argmax-L are necessarily distinct, else `R<L`). Union: `a = argmax R over L=1`, `b = argmin L over R=N`, works iff `a_best >= b_best-1`; `a_idx != b_idx` (an interval with `L=1,R=N` is caught as cost-1 first).
- **Min-index container (the fix):** for each i the smallest `j != i` with `L_j<=L_i` and `R_j>=R_i`. Sort indices by `(L asc, R asc)`; sweep equal-L groups; inside a group process R-batches from largest R to smallest; query a Fenwick tree that is prefix-min over reversed R ranks (rank 1 = largest R), so a prefix query = suffix-min over `R' >= R`; insert a batch only after querying it. A same-`(L,R)` batch of size >=2 is mutually containing: use smallest `s1` and second-smallest `s2` batch indices (`mb = s2 if t==s1 else s1`). This yields the exact minimum-index container, so the branch emits the lexicographically-smallest contained index.
- **Branch order matters for output:** cost1 -> containment -> disjoint -> union -> cost3. Sample 1 needs containment before union; with the min-index container, i=0 (container 2, NOT 3) gives exactly `2 0 1 0`.
- **cost 3:** reached iff no cost-1/2. No disjoint pair => 1-D Helly gives a common point c in all intervals. Pick i that is not the unique min-L and not the unique max-R (exists for M>=3). Let j be a min-L interval `!= i` (else argmin-L) and k a max-R interval `!= i` (else argmax-R); then `I_j ⊇ [L_i,c]`, `I_k ⊇ [c,R_i]`, so op2 on i plus op1 on j,k covers `[1,N]`. `j != k`, otherwise one interval contains i and containment (b) would have triggered.
- **M<=2 with no cost<=2 => `-1`.**
- **Complexity:** O(M log M) time, O(M) memory; N (up to 1e6) is unused.
- **Pitfalls:** the plain `maxR`-before test misses the first element of an equal-key run and does not give the *minimum* container; use the Fenwick sweep + batch handling. Fenwick query/insert must exclude self (insert after query) to guarantee `j != i`.
- **Testing:** samples 1-4 match exactly (`2 0 1 0`, `1 0 1 0 0`, `1 1`, `-1`); further small cases (e.g. `[1,2]⊂[1,3]`, duplicates, disjoint `[1,2],[3,4]`, cost-3 `[2,5],[3,6],[4,7]` with N=7) verified by hand as valid and minimal.
