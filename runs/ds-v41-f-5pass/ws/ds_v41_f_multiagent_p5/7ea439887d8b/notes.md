- **State model:** The only relevant global state is the current vertex and whether the graph is currently original or reversed. Define state `(v, 0)` for original directions and `(v, 1)` for reversed directions.
- **Transitions:** In parity 0, move along an original edge `v -> u` for cost 1, staying in parity 0. In parity 1, move along an original edge `u -> v`, which is `v -> u` in the reversed graph, for cost 1, staying in parity 1. Reversing all edges costs X and toggles parity at the same vertex.
- **Dijkstra:** All transition costs are nonnegative. Use a heap over `(cost, vertex, parity)`. Keep two distance arrays, `dist0` and `dist1`, each of size `N + 1`. The source is `(1, 0)` with cost 0.
- **Answer:** Reaching vertex N ends the process, so the answer is the minimum over both parities at N. With Dijkstra, the first popped state whose vertex is N is already minimal, so we can return immediately.
- **Complexity:** Each edge is relaxed in the appropriate parity once per successful distance update. The expanded graph has about `2N` states and `2M + 2N` transitions, giving `O((N + M) log N)` time and `O(N + M)` memory, which fits `N, M <= 2 * 10^5`.
- **Overflow:** Answers can exceed 32-bit range, especially with large X and multiple reversals. Python integers are arbitrary precision, but use a sufficiently large `INF`, e.g. `10**30`.
- **Implementation details:** Build both the original adjacency list `adj` and the reverse adjacency list `radj` while reading input. Ignore stale heap entries when the popped distance does not match the stored distance. Self-loops and multiple edges are handled naturally.
- **Key correctness point:** Multiple reversals may be useful, and considering only one reversal or only one orientation is not correct. The parity state fully captures any number of reversals.
