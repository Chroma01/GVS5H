- **Testing:** Sample 1 returns 8 and sample 2 returns 3. Edge cases checked: `x = n, k = 1`; `k * x = n` exact tiling; adjacent windows; negative values; duplicates; even `x`; all equal; large values. No failures found, so the current implementation is kept unchanged.
- **Decomposition:** The final array must contain k disjoint length-x constant blocks. For any valid final array, the total operation cost is at least the sum of the independent optimal costs of those k blocks. Conversely, modifying each chosen block independently to its own median achieves exactly that sum. Therefore the problem separates into computing every length-x window cost and then selecting k non-overlapping windows with minimum total cost.
- **Window cost:** For a fixed window, minimizing the sum of absolute deviations is solved by any median. The implementation uses the lower median with rank `(x + 1) // 2`. For even x, the lower median is still optimal.
- **Fenwick trees:** All values are coordinate-compressed. Two Fenwick trees are maintained over compressed indices: one for counts and one for sums of the current window. This supports adding/removing a value in O(log n), querying prefix count and prefix sum in O(log n), and finding the kth smallest value by binary lifting on the count tree.
- **Cost formula:** Let `med` be the selected median, `c_le` and `s_le` be the count and sum of values <= `med`, and `total` be the current window sum. The cost is:
  `med * c_le - s_le + (total - s_le) - med * (x - c_le)`.
  Elements equal to `med` are included in the left part and contribute zero.
- **Sliding window:** The first x elements are inserted into both Fenwick trees. For each subsequent window, the outgoing element is removed, the incoming element is added, the running total is updated, and the median cost is recomputed. Costs are stored by window start index.
- **Selection dynamic programming:** Let `dp_prev[i]` be the minimum cost to choose `t-1` windows within the first `i` array elements. For `t` windows:
  `dp_cur[i] = min(dp_cur[i-1], dp_prev[i-x] + cost[i-x])` when `i >= x`.
  The loop starts at `i = t*x` because fewer than `t*x` elements cannot contain `t` disjoint length-x windows. The answer is `dp_prev[n]` after k iterations.
- **At least versus exactly:** All window costs are nonnegative. If a solution creates more than k valid windows, selecting any k of them gives a cost no larger than the total. Thus minimizing over exactly k windows is equivalent to minimizing over at least k windows.
- **Complexity:** Coordinate compression is O(n log n). Sliding-window cost computation is O(n log n). The selection DP is O(k n), with k <= 15. Memory usage is O(n).
- **Edge cases handled:** Negative values, duplicate values, even window sizes, adjacent non-overlapping windows, `x = n`, and `k * x = n`. The Fenwick order-statistic search assumes the current window always contains exactly x elements.
- **Implementation details:** A single `add` function updates both Fenwick trees together, and a single `prefix_both` function returns both prefix count and prefix sum, reducing constant factors. Compressed indices are precomputed to avoid dictionary lookups during sliding.
