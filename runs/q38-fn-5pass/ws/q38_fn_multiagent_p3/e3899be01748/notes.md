- **Chosen approach:** Left-to-right residue DP. For each possible non-zero last digit `d = 1..9`, `cnt[d][r]` stores the number of substrings ending at the previous character whose numeric value is congruent to `r` modulo `d`. When reading digit `x`, every old substring is extended by `x`, changing residue `r` to `(10*r + x) % d`, and the one-character substring `x` is added with residue `x % d`. If `x` is non-zero, substrings ending here have last digit `x`, so add `cnt[x][0]`.
- **Implementation details:** Use `cnt = [[0] * d for d in range(10)]`, with `cnt[0]` unused. For each character, build a fresh `new` list for every `d` from `1` to `9`, fill it from the old list, add the new single-digit substring, then replace `cnt[d]`. The answer is accumulated after all residue tables for the current character have been updated.
- **Correctness:** The recurrence exactly matches appending a digit to a decimal string, including substrings with leading zeros. After processing a prefix, the invariant holds for all `d`. At position `i`, a substring is valid iff its last digit `x` is non-zero and its value modulo `x` is zero; `cnt[x][0]` counts exactly those substrings ending at `i`. Summing over positions counts each valid substring once.
- **Complexity:** Each character updates `1 + 2 + ... + 9 = 45` residues, so time is `O(45n) = O(n)` and memory is `O(45) = O(1)`. For `n = 1e5`, this is about 4.5 million inner residue steps plus small list allocations, safe in Python.
- **Sample verification:** For `"12936"`, the DP counts valid endings as `1 + 2 + 1 + 3 + 4 = 11`, matching the sample. For `"5701283"`, the DP counts `18`, matching the sample. For `"1010101010"`, only endings at the five `'1'` positions contribute, with counts `1, 3, 5, 7, 9`, summing to `25`.
- **Edge-case verification:** All zeros returns `0` because zero-ending substrings are never added to the answer. A single non-zero digit returns `1`, while `"0"` returns `0`. Many leading zeros before a non-zero digit are handled correctly; for example `"0001"` counts `"1"`, `"01"`, and `"0001"`, giving `3`. All ones of length `n` counts every substring, giving `n*(n+1)//2`. Alternating `"10"*m` counts only substrings ending at `'1'`, giving `m*m`. Long strings are handled linearly by the same DP.
- **Pitfalls:** Do not update `cnt[d]` in place, because multiple old residues can map to the same new residue and the new single-digit substring must be added after extensions. Do not skip zero digits in the DP state. Do not add to the answer for `x = 0`. The answer lookup `cnt[x][0]` is safe for `x = 1..9` because all moduli are maintained.
