The problem requires answering many prefix-pair sum-of-absolute-differences queries efficiently. Since N is up to 1e5 and K up to 1e4, a direct O(XY) per query is infeasible. We can use a block decomposition on the X-prefix: split the first index into blocks of size ~500. For each block, precompute the contribution of all complete earlier blocks to every possible Y-prefix using a two-pointer sweep over sorted B. For the partial rows inside the current block, we iterate over at most B rows and answer each row's distance to the B-prefix Y using a persistent segment tree built over B, giving O(log N) per row. This yields O(N^2/B + K*B*log N) which is fast enough.
