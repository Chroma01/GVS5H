- **Problem reduction:** For a fixed start K the occupied set is always a contiguous interval and its size is the interval sum. Absorbing only grows the mass, so any currently absorbable neighbour stays absorbable until consumed; therefore the set of reachable slimes is a monotone closure and the final maximal interval (hence the answer) is independent of the absorption order. Absorbing a small side first never prevents later crossing a larger side, so greedy "absorb anything available" reaches the closure.
- **Cartesian tree:** Build a max-heap Cartesian tree with a monotonic stack using strict `<` while popping, making the leftmost of equal values the ancestor. Each node's subtree is a contiguous range whose maximum (leftmost on ties) is the node, and its subtree sum equals the mass after fully absorbing that range. In this tree a node's left subtree holds only values strictly `< A[node]`; equal values can only appear on the right.
- **Start condition:** A node can begin absorbing iff at least one original immediate neighbour is strictly smaller. It is necessary (no other move exists) and sufficient: the smaller neighbour lies inside the node's subtree, and once it is eaten the mass exceeds `A[node]`, which is `>=` every value in the subtree, so the whole subtree can be cleared in any order.
- **Upward propagation:** After clearing its subtree, node `v` of mass `sub[v]` sits at the subtree boundaries. The parent `p` is the smaller boundary element (the other boundary is an ancestor with value `>= A[p]`), so `v` can expand iff `sub[v] > A[p]`. Eating `p` exposes all of `p`'s subtree, making the mass `sub[p]`, exactly the state from which `p`'s own reach is defined. DP over preorder: `up[v] = up[p] if sub[v] > A[p] else v`.
- **Answer:** `ans[K] = sub[up[K]]` if K can start, else `A[K]` (an equal neighbour permanently blocks).
- **Boundary claim:** parent = smaller of the two nearest greater-or-equal boundaries, so the opposite boundary value is `>= A[p]`. Hence if a node cannot pass its parent it cannot pass the other side either, and if it can pass the parent it continues via `up[p]`. With leftmost tie-break the left boundary is always strictly greater, so a left extension guarantees an immediately smaller left neighbour.
- **Verification (brute force):** A brute-force simulator enumerating the monotone interval closure (expand to any adjacent strictly-smaller slime, BFS over reachable intervals, take max interval sum) was compared against the Cartesian solution. Both samples reproduce exactly: sample 1 -> `4 30 2 13 2 13`; sample 2 -> `22 47 235 10 31 235 2 235 5 235 6 235` (the 235 chain 5->11->7->9 all climbs to the global-max node). Small-case families checked exhaustively/heavy-duplicate: all-equal arrays give `A` unchanged; `[1,2,3,4]` -> `1 3 10 10`; `[4,3,2,1]` -> `10 10 3 1`; `[3,1,3]` -> `7 1 7`; `[3,3,2]` -> `3 8 2`; `[3,2,3]` -> `8 2 8`; `[5,5,1]` -> `5 11 1`; `[3,3,1]` -> `3 7 1`; `[5,4,5,4,5]` -> `23 4 23 4 23`; `[2,3,3]` -> `2 8 3`. All agree, no counterexample found.
- **Pitfalls:** Never infer "can start" from subtree size (equal neighbours block). Use strict `<` in the stack pop and strict `sub[v] > A[p]` in the propagation, never `<=`/`>=`. Copy `A` into `sub`; keep `A` unmodified for neighbour checks.
- **Implementation:** Fully iterative (no recursion), 0-indexed arrays `A,left,right,par,sub,up`. Preorder via explicit stack; subtree sums over reversed preorder; `up` over preorder. `root = stk[0]` (stack is non-increasing bottom-to-top, bottom is the leftmost maximum).
- **Complexity:** O(N) time and memory; each index pushed/popped once. Sums up to ~5e14 are exact in Python ints. Runs comfortably for N = 5e5.
