- **Key simplification:** Any positive integer containing digit `0` has digit product `0`, which is divisible by its positive digit sum. Therefore, for `count_up_to(n)`, all zero-containing numbers are beautiful, and the answer can be written as `n - zero_free_total(n) + zero_free_beautiful(n)`.
- **Zero-free product structure:** If a number has no digit `0`, its digit product only has prime factors `2, 3, 5, 7`. Such a number is beautiful iff its digit sum `s` has no prime factor greater than `7`, and the product's exponents of `2, 3, 5, 7` are at least the corresponding exponents in `s`.
- **Exponent caps:** For all possible digit sums under the constraints (`<= 81`), required exponents never exceed `2^6`, `3^4`, `5^2`, `7^2`. The code computes caps dynamically from all sums up to `9 * len(str(r))`, then caps tracked exponents at those maxima. Larger exponents are equivalent for divisibility by any possible sum.
- **DP state:** The zero-free digit DP state is `(pos, tight, started, sum, e2, e3, e5, e7)`. It counts zero-free numbers in the suffix. The function returns a packed integer `(total << SHIFT) | beautiful`, where `total` is the count of zero-free numbers and `beautiful` is the count of beautiful zero-free numbers.
- **Leading zeros:** The `started` flag prevents leading zeros from affecting sum or product. While not started, choosing `0` keeps the number unstarted. The first non-zero digit starts the number and initializes its sum and exponents.
- **Zero-free transitions:** Once started, the DP only chooses digits `1..limit`, because numbers containing `0` are counted separately by the `n - zero_free_total` term. Each transition updates the digit sum and capped prime exponents.
- **Final condition:** At the end of the digits, a started state contributes one zero-free number. It is beautiful if `large[sum]` is false and the capped exponents meet the precomputed requirements for that sum.
- **Precomputation:** For every possible digit sum, the code factors out `2, 3, 5, 7` and records required exponents plus whether a larger prime remains. It also precomputes digit exponent contributions and capped transition tables for speed.
- **Memoization:** A manual dictionary with an integer-encoded key is used per `count_up_to` call. The key packs position, tight flag, started flag, digit sum, and four capped exponents using fixed dimensions.
- **Complexity:** The state space is small because digit sum is at most `81` under the constraints and exponent caps are at most `6, 4, 2, 2`. Reachable states are far below the full Cartesian product, making two DP calls easily feasible.
- **Edge cases:** `n <= 0` returns `0`. Single-digit numbers are zero-free and beautiful. Numbers with internal or trailing zeros are included through the zero-containing term. The number `0` is never counted.
