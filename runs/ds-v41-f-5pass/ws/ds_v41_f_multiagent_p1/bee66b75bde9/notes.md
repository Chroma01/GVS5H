- **Reduction:** A valid coloring is exactly a Ferrers diagram anchored at the top-left. Let a_x be the number of black cells in row x (0..N). The column-prefix condition is equivalent to a_1 >= a_2 >= ... >= a_N. So we must choose a non-increasing integer sequence a_x.
- **Per-row intervals:** A known black at (x,y) forces a_x >= y. A known white at (x,y) forces a_x <= y-1. Thus each constrained row x has L_x = max black y (default 0) and R_x = min white y - 1 (default N). If L_x > R_x for any row, the answer is immediately No.
- **Global feasibility:** A non-increasing sequence with L_x <= a_x <= R_x exists iff for all x <= y, L_y <= R_x. This is equivalent to: for every row y, L_y <= min_{x <= y} R_x. Necessity: a_y <= a_x <= R_x. Sufficiency: define a_x = max_{y >= x} L_y; it is non-increasing, meets lower bounds, and the condition guarantees a_x <= R_x.
- **Algorithm:** Group constraints by row, keeping the maximum black y and the minimum white y-1. Sort the constrained rows by x. Maintain a prefix minimum `min_r` of R over processed rows (initialize to N). For each row in order: update `min_r = min(min_r, R_x)`, then if `L_x > min_r` output No. If all rows pass, output Yes.
- **Why unconstrained rows can be ignored:** They have L=0 and R=N, so they never violate L <= min R and never lower the prefix minimum. They can always be interpolated later.
- **Edge cases:** Multiple constraints in the same row must be combined before the global check. A white at column 1 gives R=0 (not negative). Same-row L > R is caught by the global loop as well, but checking early is fine.
- **Complexity:** O(M log M) time and O(M) memory. N can be up to 1e9 because only constrained rows are stored and sorted.
- **Samples:** The algorithm matches all four provided samples, including the No cases where a later row's lower bound exceeds the prefix minimum upper bound.
