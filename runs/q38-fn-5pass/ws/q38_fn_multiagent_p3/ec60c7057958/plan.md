The solution should count how many alternating permutations start with each candidate value, then greedily choose the k-th permutation lexicographically. Because n can be 100 and k can be 1e15, all counts must be capped at a value greater than k to avoid huge integers and overflow. The key observation is that once the parity of the first element is fixed, the parity pattern is forced, so the count depends only on how many unused odd and even numbers remain. We can precompute or dynamically compute counts using factorials of the remaining odd/even counts, capped at k. Then construct the answer by trying numbers from 1 to n, skipping used ones, and subtracting block sizes until the correct branch is selected.
