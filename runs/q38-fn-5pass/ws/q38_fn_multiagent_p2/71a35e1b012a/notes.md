- **Core model:** Choosing type-1 intervals adds their union. Choosing type-2 intervals adds the complement of their intersection. Final uncovered positions are `(intersection of type-2 intervals) \ (union of type-1 intervals)`.
- **Cost 1:** Possible iff some interval is exactly `[1, N]`, using type 1. Type 2 alone cannot cover all because every interval is nonempty.
- **Cost 2 completeness:** With two non-zero operations, only three combinations matter: type 1 + type 1 requires union cover; type 2 + type 2 requires disjoint intervals; type 1 + type 2 requires the type-2 interval to be contained in the type-1 interval.
- **Containment detection:** The old max-R scan is replaced by a Fenwick tree over compressed R values. Sort intervals by L ascending, R descending, and original index ascending for ties. For each current interval, all previously processed intervals have L <= current L. Query the Fenwick tree for previous intervals with R >= current R; the tree stores minimum original index, so the query returns the smallest original-index container for this current interval. Scan all intervals and keep the pair with the smallest container index, breaking early if container index 0 is found. This makes sample 1 choose interval 2 as container and interval 0 as contained.
- **Fenwick mapping:** Compress distinct R values ascending to ranks 1..K. Store at reversed rank `K - rank + 1`. Then the suffix condition `R >= current R` becomes a prefix query up to the current reversed rank. Update after querying to keep container and contained distinct.
- **Disjoint detection:** If any disjoint pair exists, the interval with minimum R and the interval with maximum L are disjoint, and `minR < maxL` is strict. They are necessarily distinct.
- **Two type-1 detection:** Keep the interval with `L=1` and maximum R, and the interval with `R=N` and minimum L. If both exist, are distinct, and `minL_of_RN <= maxR_of_L1 + 1`, their union covers all. If they are the same index, that interval is full and cost 1 was already handled.
- **Cost 3 construction:** If no cost <= 2 solution exists and `M >= 3`, take `A` with minimum L and `C` with maximum R. If they were disjoint, cost 2 would exist via two type-2 operations, so they intersect. Then `A union C` is the continuous interval `[L_A, R_C]`. Any third interval `B` lies inside `[L_A, R_C]`. Using type 1 on `A` and `C`, and type 2 on `B`, covers `[L_A, R_C]` by type 1 and everything outside it by type 2.
- **Distinctness:** All constructed solutions use distinct operation indices. The containment query is performed before inserting the current interval; disjoint indices are distinct when `minR < maxL`; the type-1 pair is distinct after the full-interval check; cost-3 explicitly chooses `B` different from `A` and `C`.
- **Fallback for `A == C`:** If the minimum-L and maximum-R interval is the same index, it contains every interval, so a cost-2 solution exists with that interval as type 1 and any other as type 2. This should already be caught by containment detection, but the fallback keeps the program robust.
- **Impossibility:** If `M < 3` and no cost <= 2 solution exists, no solution exists because at most `M` non-zero operations can be used and cost 0 is impossible for `N >= 1`.
- **Complexity:** Sorting plus Fenwick updates/queries is `O(M log M)` time and `O(M)` memory. `M <= 200000`, so this is safe in Python.
- **Samples:** Mentally checked: sample 1 outputs `2` and `2 0 1 0`; sample 2 outputs `1` and `0 1 0 0`; sample 3 outputs `2` and `1 1`; sample 4 outputs `-1`.
