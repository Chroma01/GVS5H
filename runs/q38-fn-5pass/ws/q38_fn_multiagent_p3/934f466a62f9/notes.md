- **Coloring equivalence:** A pairing can be converted to choosing exactly `2K` cakes and coloring each with one of three attributes, with every color used an even number of times. For a pair, choose an attribute attaining the maximum sum and assign it to both cakes. Conversely, any even-colored selection can be paired within each color, and each pair price is at least the sum of assigned values. Thus the original optimum equals the maximum even-coloring sum.
- **Upper bound:** For cake `i`, let `M_i = max(X_i, Y_i, Z_i)`. Ignoring parity, the best possible sum is the sum of the largest `2K` values of `M_i`. Choose those cakes as the base set and assign each an arbitrary maximum color. If the parity mask is zero, this upper bound is attainable and optimal.
- **Parity correction:** If the mask is nonzero, exactly two colors `a,b` are odd and the third is `c`. Every useful modification toggles two colors: recoloring a selected cake, or swapping a selected cake with an unselected cake assigned some color. Since all losses are nonnegative, any optimal correction can be reduced to either one direct edge `a-b` or a two-edge path `a-c` plus `b-c`.
- **Single directed edge cost:** For `u -> v`, the minimum loss is the minimum of:
  - recoloring a selected cake with default `u` to `v`: `M_i - value_i[v]`;
  - swapping out a selected cake with default `u` and adding an unselected cake colored `v`: `min M_i - max value_j[v]` over the two independent sets.
- **Two-edge cost:** For two directed edges, consider all four type combinations: RR, RS, SR, SS.
  - RR uses two selected cakes; if defaults differ they are automatically distinct, otherwise top-two recolor lists are enough.
  - RS/SR combine one recolor list with one selected-M list, subtracting the best unselected value for the swap color.
  - SS separates into a selected part (two distinct selected cakes) and an unselected part (two distinct unselected cakes). Selected and unselected choices are independent, so compute their best sums separately.
- **Top-two sufficiency:** For two sorted lists of candidates, the best pair with distinct IDs is either first-first if IDs differ, otherwise one of first-second or second-first. Therefore keeping two smallest/largest candidates per aggregate is sufficient. This also handles ties because the two kept IDs are distinct.
- **Unselected color conflicts:** Even when two swaps use different colors, the best unselected cake for each color may be the same cake. The unselected top-two lists store IDs, and `combine_max` enforces distinct IDs.
- **Tie handling:** Arbitrary tie-breaking in the top-`2K` set and in default maximum colors is safe. Zero-cost recolors and zero-cost swaps are included, so alternative tied choices that preserve the upper bound are captured by zero-loss corrections.
- **Boundary cases:** If `2K = N`, there are no unselected cakes, so swap-based costs become infinite and only recolor corrections remain. If the mask is zero, no aggregates are needed. Losses are clamped to `[0, base]` as a safety measure.
- **Complexity:** Sorting dominates: `O(N log N)` per test case, with `O(N)` aggregate construction. The sum of `N` is at most `1e5`, so this is easily fast enough in Python.
- **Verification:** Samples match by hand. The operation-subset proof shows that any multi-operation final solution contains a one- or two-operation subset with no larger loss and the same parity effect, so the implemented candidates cover all optimal corrections.
