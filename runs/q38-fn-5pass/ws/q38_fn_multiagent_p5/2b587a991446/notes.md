- **Exact oracle:** `exact_solve` remains enabled for `N <= 120`. For validation, the harness calls `structural_solve` directly with the exact fallback disabled, so the structural path is tested even on very small graphs.
- **Strong exhaustive validation:** An offline validator enumerated all unlabeled connected graphs up to `N=8` (12,113 graphs) and up to `N=9` (273,193 graphs). For every ordered pair `(S,T)`, it compared `structural_solve` with `exact_solve`. The `N=9` exact comparison used a bitset configuration BFS to keep the runtime practical. It also generated 50,000 random connected graphs with `10 <= N <= 12` and checked all ordered pairs. No mismatch was found, and there is no minimal failing graph in this validation range.
- **All-cycle check:** For the same small graphs, the validator enumerated every simple cycle and computed the full cycle expression `min_C |C| + 2*min_{p!=q in C}(distS[p]+distT[q])`. It compared this with the minimum produced by fundamental cycles of the BFS trees rooted at `S` and `T`. No case was found where a non-fundamental cycle gave a strictly better candidate that was required for the true optimum.
- **Early-exit bug:** The solver must not stop at `ans <= 2D+1`, because `2D` can still be possible. The minimal structural counterexample is a theta graph with three internally disjoint `S-T` paths of lengths `2, 2, 3`. The code now returns early only when `ans == 2D`.
- **Theta and cycle families:** For theta graphs, the answer is the minimum of cycle candidates (sums of two path lengths, possibly `2D` or `2D+1`) and endpoint local gadgets. After the early-exit fix, these families match the exact oracle. Chords and shorter cycles are found by BFS fundamental cycles.
- **Local rules:** An internal vertex on a shortest `S-T` path with one spare neighbor gives `2D+2`. Any vertex with two spare neighbors gives `2*(distS[v]+distT[v])+4`. These cover tree passing gadgets, endpoint tails, and cycles attached by bridges. A branch off an endpoint-side tail with two spare neighbors is valid and can be optimal; one spare neighbor on such a tail is not enough.
- **Endpoint spare path:** If a branching vertex or cycle entry is at distance `h` from an endpoint, the formula becomes `2D + 4h + 4`. Explicit sequences and exact oracle checks confirm this. One spare neighbor at the endpoint or along a dead-end tail is insufficient.
- **Cycle enumeration:** For each BFS tree rooted at `S` and `T`, non-tree edges define fundamental cycles. Binary lifting maintains the top two `d_other` vertices on tree paths, so the best distinct pair on each fundamental cycle is obtained in `O(log N)`. Processing both roots is necessary because a cycle may be fundamental in one BFS tree but not the other.
- **Remaining theoretical risk:** The main proof point is that fundamental cycles from the two BFS trees dominate all cycles for the weighted cycle expression. Exhaustive validation up to `N=9` and random validation up to `N=12` found no counterexample, but this remains the central structural assumption.
