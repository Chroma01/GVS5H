- **Problem shape:** minimize the longest run of identical chars after at most numOps flips. Feasibility is monotone in target length L (a string with runs <= L also satisfies L+1), so binary search the smallest feasible L over [1, n].
- **Correct oracle is a DP, never a per-run greedy.** State dp0[r]/dp1[r] = min flips over the processed prefix that ends in bit 0/1 with a trailing equal-run of length exactly r (1 <= r <= L). Two transitions per position: switch from the opposite bit to start a new run of length 1, or extend the same bit to grow the run by one (illegal past L). Answer feasible iff min over all final states <= numOps.
- **Critical bug that was fixed: the extend transition must also pay the current character's flip cost.** An earlier version copied `n0[2:L+1] = cur0[1:L]` with no cost added, undercounting flips whenever a run of length >= 2 swallowed a flipped character. Counterexample: s="111111", L=2. Truth is 2 flips ("110011"); the missing-cost version reported 1. Fixed with `ndp0[2:L+1] = [x + cost0 for x in dp0[1:L]]` (and similarly for bit 1). Always pay `cost0 = c`, `cost1 = 1 - c` in BOTH transitions.
- **Greedy floor(c/(L+1)) over maximal runs is DISPROVEN.** s="0110", L=1: greedy counts floor(2/2)=1, but reaching an alternating string costs 2 flips (both "0101"/"1010" differ in 2 positions). The failure is that splitting one run by a flip can merge with a neighbouring run into a fresh long run.
- **L=1 degrades naturally** to min Hamming distance to the two alternating patterns (the extend slice is empty since dp[1:1]==[]), so no special case is needed.
- **Complexity:** each feasible(L) is O(n*L) (slice/list-comp extend is C-level), binary search adds log n => ~O(n^2 log n); trivial for n <= 1000.
- **Edge cases:** n=1 returns 1 (lo==hi, no oracle call); hi=n is always feasible at 0 flips; numOps=n flips any all-identical string of length >= 2 down to 1; numOps can exceed needs, DP just caps.
- **Verification:** all target cases PASS — ("000001",1)->2, ("0000",2)->1, ("0101",0)->1, ("100001",2)->2, ("0",0)->1, ("0000",0)->4, ("000000",6)->1, ("111111",1)->3, ("111111",2)->2, ("111111",0)->6, ("0110",1)->2. Plus an exhaustive brute-force cross-check over all binary strings of length 1..6 with every numOps in 0..n (all match), which is what caught the extend-cost bug.
- **No fallback path:** the code uses only the binary search + dp[bit][run_len] oracle; there is no greedy shortcut or special-case branch anywhere.
