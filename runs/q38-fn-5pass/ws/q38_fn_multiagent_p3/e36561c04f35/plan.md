We can view the process as choosing a final order of all elements, paying the adjacent-swap distance to reach that order plus the number of equal-value runs in it. Starting from the run-length encoding of `A`, a swap is profitable only when it reduces the number of runs by 2; this happens exactly for four consecutive runs `x, y, x, y` where the two middle runs have length 1. Each such swap costs 1 and reduces the number of future deletion operations by 2, so it improves the total answer by 1. Therefore we need the maximum number of such profitable swaps that can be performed without interfering, which is a maximum set of “good” boundaries with pairwise distance at least 3. Compute this with a simple DP over runs, then answer = initial number of runs - maximum number of good swaps.
