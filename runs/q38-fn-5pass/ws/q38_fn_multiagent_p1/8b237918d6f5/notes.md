- **Reformulation:** Choosing K edges of weight 1 makes the shortest distance equal to the minimum, over all 1-to-N paths, of the number of chosen edges on that path. If some set of at most K edges makes every path contain at least d chosen edges, adding arbitrary extra edges up to K cannot decrease any path weight, so feasibility can be tested with “at most K”.
- **Bounds and monotonicity:** Feasibility is monotone in d, so binary search the maximum d. The answer is at most K and at most the unweighted shortest-path length from 1 to N, because that particular path has at most that many edges and each edge contributes at most 1.
- **Potential characterization:** For a candidate d, the minimum number of edges needed equals the minimum over integer potentials p_v in [0,d] with p_1=0, p_N=d, and p_v <= p_u+1 for every edge u->v, of the number of edges with p_v = p_u+1. Given such a potential, choosing exactly those +1 edges is feasible because along any 1-to-N path the potential rises by d while each edge increases it by at most 1, so at least d edges must increase it by exactly 1. Conversely, from any feasible edge set S, define p_v as min(d, minimum number of S-edges on a path from 1 to v), with unreachable vertices set to d; then every +1 edge belongs to S, so the potential cost is at most |S|.
- **Cut construction:** Boolean x_{v,i}=true means p_v >= i. Put true nodes on the source side. Source-to-(N,i) infinite edges force N to level d, and (1,i)-to-sink infinite edges force 1 to level 0. Infinite nesting edges (v,i)->(v,i-1) enforce downward closure. Infinite implication edges (v,i)->(u,i-1) for original u->v enforce p_v <= p_u+1. Unit edges (v,i)->(u,i) are cut exactly when p_v >= i > p_u; under the constraints this counts each original edge once iff p_v = p_u+1. The min s-t cut value is the minimum required number of edges.
- **Flow and search:** Use Dinic with a large infinite capacity and stop augmenting at K+1; check(d) is true iff the returned flow is at most K. d=0 is trivially true. Multi-edges are kept as separate unit-cost edges, so parallel paths are handled correctly.
- **Complexity:** d is at most N-1 <= 29. Each check has at most about N*d + 2 <= 872 nodes and O(Nd + Md) <= a few thousand edges. Binary search performs only a few checks, easily within limits.
