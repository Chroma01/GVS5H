- **Fix applied:** In the backward DP transition for capped run length 3, the precomputed switch candidate `best1` / `best2` is already `w_i[x] + dp[i+1][x][1]`, so it includes the cost of the new character at position `i`. The transition now compares `switch_cost` directly with `wc + dp[i+1][c][3]` and stores the minimum. It no longer adds `wc` to `switch_cost`.
- **Core model:** The final string is partitioned into maximal runs of identical characters, each of length at least 3. Changing original character `c` to target `x` costs `abs(c - x)`.
- **Feasibility:** If `n < 3`, no good caption exists. For every `n >= 3`, at least one good caption exists by changing the whole string to one character, but the DP still safely detects impossible states.
- **Suffix DP state:** `dp[i][c][l]` is the minimum cost to fill positions `i..n-1` given that the prefix before `i` ends with character `c` and its current run length is `l`, capped at 3. Stored lengths are 1, 2, and 3 meaning at least 3.
- **Base case:** At `i = n`, the suffix is empty and valid only if the last run length is at least 3, so `dp[n][c][3] = 0` for all `c`; lengths 1 and 2 are invalid.
- **Transitions:** If current run length is 1 or 2, the next character must be the same `c`, increasing the capped run length. If current run length is 3, either continue with `c`, or switch to any `x != c`, starting a new run of length 1.
- **Top-two optimization:** For run length 3, switching cost to `x` is `w_i[x] + dp[i+1][x][1]`. For each current character `c`, we need the minimum switch cost excluding `c`. Keeping the best and second-best switch values over all 26 characters gives this in O(26) per position.
- **Storage:** A flat `array('i')` of size `(n+1)*78` stores all suffix layers. This is about 16 MB and allows greedy reconstruction to query any future DP layer. Costs are at most `25*n = 1.25e6`, so `INF = 1e9` is safe.
- **Invalid values:** Invalid DP entries are at least `INF`. The top-two minima initialize to `INF`, so invalid values larger than `INF` are effectively ignored for comparison purposes. Valid costs are always far below `INF`.
- **Lexicographic reconstruction:** After computing suffix costs, greedily build the answer left to right. At each position, try characters from `'a'` to `'z'` and choose the first one whose transition cost plus the stored suffix optimum equals the remaining optimal cost. This is correct because the earliest differing character determines lexicographic order, and the suffix DP guarantees feasibility of the chosen transition.
- **Initial state:** There is no previous character before position 0. The answer is `min_x cost(0,x) + dp[1][x][1]`. Reconstruction starts by choosing the smallest first character satisfying this equality.
- **Implementation details:** The backward DP loop computes layers down to `i = 1`; `dp[0]` is unnecessary. Cost rows are stored as `bytes` for compactness. The result is built in a `bytearray` and decoded at the end.
- **Sample checks:** `"cdcd"` returns `"cccc"`, `"aca"` returns `"aaa"`, and `"bc"` returns `""`.
- **Complexity:** Time is `O(26*n)` with a small constant. Memory is `O(78*n)` using compact integer arrays.
