- **Core reformulation:** For each middle value B, count unordered endpoint pairs A,C in S with A+C=2B. If convolution coefficient g[2B] counts ordered pairs, contribution is (g[2B]-1)//2 because (B,B) is included once.
- **Numpy path:** Uses real FFT. Builds indicator f over [0,max(S)], pads to power of two n > 2*max(S), computes rfft, squares spectrum, irfft, rounds coefficients. Answer is (sum(coeff at 2B) - N)//2. It raises to fallback if parsing is incomplete or any exception occurs.
- **Fallback parsing:** Manual byte scanner avoids split() memory overhead. It preallocates a list of length N, fills values, and tracks max_val.
- **Sparse endpoint enumeration:** For small N, split S into even and odd lists. Valid endpoints must have the same parity. Enumerate pairs inside each parity list and test midpoint membership in a set. This halves pair checks versus checking all pairs and removes parity tests.
- **Complement inclusion-exclusion:** Let M=max(S), K=M-N missing values in [1,M]. Total APs in full interval is ((M-1)^2)//4. Subtract APs containing at least one missing value. For missing x, count APs containing x as A, B, or C: min(x-1,M-x)+(M-x)//2+(x-1)//2. For missing pair x<y, count APs containing both: endpoints if same parity, (x,y) as first two if 2y-x<=M, (x,y) as last two if 2x-y>=1. Sum over pairs can be computed in O(K): same-parity pairs directly, first-two term with a moving lower bound, last-two term with a moving upper bound. APs containing three missing values are counted by enumerating same-parity missing endpoints and checking midpoint missing. Answer = total - singles + pairs - triples. K=0 returns total directly.
- **Big-integer Kronecker fallback:** Parity-split to halve convolution length. Even values x=2a and odd values x=2a+1 are compressed to a. Convolve even indicator with itself and odd indicator with itself. For B, ordered pairs = conv_even[B] + conv_odd[B-1]. Base 2^20 is safe because each parity class has at most 500000 elements, so every convolution coefficient is below 2^20.
- **Packing details:** Store compressed value c as a single bit at bit position 20*c. Since 20*c bits = (5*c)/2 bytes, byte index is (5*c)//2; bit offset is 4 if c is odd else 0. Convert bytearray to int, square, convert back to bytes. Extract a 20-bit chunk at index idx by reading four bytes starting at (5*idx)//2 and shifting right by 4 if idx is odd, then masking 0xFFFFF.
- **Method selection:** If K is small and K<N, use complement first (handles full or nearly full intervals instantly). Else if N is small, use sparse enumeration. Else if K is small, use complement. Otherwise use big-integer convolution.
- **Thresholds:** SPARSE_LIMIT=5000 and COMP_LIMIT=5000. Sparse worst-case balanced parity is about 6.25M midpoint checks; complement triple counting is similarly bounded by same-parity endpoint pairs.
- **Verification:** Samples 1 and 3 use the complement path in fallback; sample 2 uses sparse path. Big-int path was checked conceptually on small AP sets such as {1,2,3}, {1,3,5}, and {2,4,6}.
- **Pitfalls:** FFT rounding must be robust; base-20 carries would corrupt Kronecker if coefficient bound is exceeded; byte alignment for 20-bit chunks requires reading four bytes; complement inclusion-exclusion must count pair multiplicities correctly because one pair can lie in up to three APs.
