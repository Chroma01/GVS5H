- **Core problem:** choose at most 4 pairwise non-overlapping intervals (strict `r < l`; sharing any boundary = overlap) maximizing total weight; tie-break by lexicographically smallest sorted list of original indices (shorter list wins a prefix tie).
- **Sort/reindex:** sort `(right, left, weight, original_index)` by right endpoint; keep original indices for output. If we force a chosen interval to be the last (max right) one, all its partners must satisfy `r < l`, which are exactly a prefix of the sorted order.
- **Predecessor:** `pred[i] = bisect_left(r_list, l_i)` = count of sorted intervals with `r < l_i`; these are exactly the ones compatible with interval `i`. `pred[i]` can be up to `n-1` (interval `i` itself has `r_i >= l_i` so it is never counted).
- **DP state:** `dp[k][i]` = best `(score, sorted tuple of original indices)` using exactly `k` intervals among the first `i` sorted intervals; `(-1, None)` = unreachable. Rolling row `prev_row = dp[k-1]`, `dp[0] = (0, ())` everywhere.
- **Transition:** `skip = dp[k][i-1]`; `take = dp[k-1][pred[i]] + index_i` (sort the new tuple). Keep larger score; on tie keep smaller tuple. Only one tuple per state is stored (justified below).
- **Tie-break monotonicity (key lemma, proved):** if sorted equal-length tuples `T1 < T2` and `j` is distinct, then `sorted(T1∪{j}) < sorted(T2∪{j})`. Proof sketch: reduce to `A < B` (the tails after the common prefix `P`). If `j <= A[0]` then both merged start with `j` followed by `A` resp. `B`, so `A<B` decides. If `j > A[0]` then `M1[0]=A[0]` while `M2[0]=min(B[0], j) > A[0]` (since `B[0]>A[0]` and `j>A[0]`), so `M1<M2` at position 0. Hence appending the same index preserves order, so keeping the single smallest tuple per state is sufficient and exact.
- **Why invariant holds:** a `k`-selection whose last interval is `i` has score `subscore + w_i`, maximized by the max `(k-1)`-score among first `pred[i]`; among equal scores the smallest tuple of that sub maximizes the combined tuple by the lemma. `dp[k][n]` is therefore the lexicographically smallest max-score selection of exactly `k` intervals.
- **Final choice:** scan `k=1..4`, `dp[k][n]`, pick larger score then smaller tuple. Python tuple comparison matches the problem rule exactly (elementwise, shorter-prefix smaller), so fewer intervals correctly win a prefix tie. Because all weights are positive, adding a compatible interval always raises the score, but ties across different `k` are still possible and handled.
- **Edge cases:** unreachable states guarded by `pidx is not None` (empty tuple is valid, `None` is not); single interval; identical/overlapping intervals excluded by strict `r < l`; large coordinates safe (comparisons only).
- **Complexity:** O(N log N) sort + predecessor, O(4·N) DP with ≤4-length tuple ops; N ≤ 5·10^4 → fast.
- **Verification (executed):** Example 1 → `[2,3]` (score 8) PASS; Example 2 → `[1,3,5,6]` (score 21) PASS.
- **Randomized brute force (executed):** thousands of random cases with `n≤8`, small coordinate/weight ranges; brute force enumerated every subset of size ≤4, filtered pairwise-disjoint (strict `r<l`), selected max score then lexicographically smallest sorted index list, and compared to this solution. Verdict: PASS, zero mismatches (no counterexample found). Result consistent with the monotonicity proof.
