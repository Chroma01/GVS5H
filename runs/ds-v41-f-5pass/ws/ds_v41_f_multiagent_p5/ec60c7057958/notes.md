- **Problem shape:** k-th lexicographically smallest alternating permutation of 1..n. n <= 100, k <= 1e15, so enumeration is impossible; need unranking with counting.
- **Key structural fact:** In any alternating permutation the parity pattern strictly alternates. Once the parity of position 0 is fixed, every position's required parity is forced. Therefore a prefix's number of valid completions depends only on (remaining odds, remaining evens, next required parity) — not on which specific numbers remain, since any odd in an odd slot and any even in an even slot preserves alternation.
- **Count function fcount(o, e, want_odd):** m = o + e remaining slots. If want_odd, odd slots = ceil(m/2), even slots = floor(m/2); else swapped. Feasible iff o and e equal those slot counts exactly (all remaining numbers must be placed). If feasible, ways = o! * e!, else 0. (For m = 0 → 1, correctly counts "one empty completion".)
- **Capping:** Factor products explode; cap at CAP = 10^15. Logic: we only ever subtract a block when block < k (<=1e15); a capped block equals CAP >= k so we always pick it and never subtract a capped value. Thus all subtractions are exact. Cap the total-count sum the same way.
- **Total existence check:** sum fcount over each choice for position 0; if total < k return []. With capping this is safe: capped total = CAP only when real total >= CAP >= k.
- **Greedy unranking:** For each position, iterate unused candidates in increasing order having the required parity (position 0: all numbers, no constraint). For candidate c compute block = fcount(remaining after c, opposite parity of c). If k > block, k -= block and move on; else fix c, mark used, update o/e. This enumerates blocks in lexicographic order, so the block containing k gives the correct element, then recurse.
- **Parity bookkeeping:** co = c & 1. After placing c the next required parity is opposite: want_odd = (co == 0). Remaining odds = o - co, evens = e - (1 - co).
- **Position 0 candidate sets:** all of 1..n. Afterward: previous even -> odd candidates (range(1, n+1, 2)); previous odd -> even candidates (range(2, n+1, 2)); skip used.
- **Feasibility nuance:** For odd n only the pattern starting with odd is viable (odds outnumber evens), which fcount naturally enforces via the exact-slot-count test. For even n both start parities are feasible.
- **Verification:** n=4,k=6 -> [3,4,1,2]; n=3,k=2 -> [3,2,1]; n=2,k=3 -> []; n=1,k=1 -> [1]; n=1,k=2 -> []. All match.
- **Complexity:** O(n^2) time (n positions x <= n candidates, O(1) count), O(n) space. Trivial for n <= 100.
- **Pitfall avoided:** Do not count completions using only parity-free factorials; the exact slot-count match is what rejects infeasible prefixes (e.g. n=3 first element 2 yields zero).
