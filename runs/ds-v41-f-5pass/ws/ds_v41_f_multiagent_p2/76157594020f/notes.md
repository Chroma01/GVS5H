- **Problem:** Binary string s, at most numOps single-bit flips; minimize the length of the longest run of identical bits. Return that minimum possible max-run.
- **Core idea:** Binary search the answer L (monotone: feasible L implies feasible L+1). hi = original max run (zero flips always valid), lo = 1.
- **Feasibility for L >= 2:** For each maximal original run of length m, the minimum flips needed to split it so no piece exceeds L is exactly `m // (L + 1)`. Sum over runs; feasible iff total <= numOps.
- **Why `m // (L + 1)`:** Between f flipped positions there are at most f+1 groups of unflipped originals, each <= L, so m - f <= (f+1)L gives f >= ceil((m-L)/(L+1)) = floor(m/(L+1)). This is achievable for L >= 2 by placing the f flips strictly inside the run (never on its two boundary cells), so flipped chars neither merge with neighboring runs nor with each other; the chunk sizes can all be chosen in [1, L] because m >= 2*floor(m/(L+1)) + 1 holds for L >= 2.
- **L = 1 needs a special case:** The per-run formula floor(m/2) is WRONG for L = 1 when a run has even length (e.g. s = "0110": runs [1,2,1], formula gives 1, but 1 flip cannot make it alternating; true min is 2). Reason: with L = 1 every chunk must have size 1, so a flip on an even run is forced onto a boundary cell and merges with the neighbouring run. Hence for L = 1 use min Hamming distance to the two alternating patterns "0101..." / "1010..." (their distances sum to n, so take min(d0, n - d0)).
- **Boundary-merge caution:** Only affects L = 1. For L >= 2 the interior-flip construction avoids all merges, so runs are handled independently and the lower bound is tight.
- **Answer:** Smallest feasible L found by the binary search.
- **Complexity:** O(n) preprocessing + O(n) per check, with O(log(max_run)) checks => O(n log n), trivial for n <= 1000. (Replaces the previous O(n*L) DP; both compute the same feasibility, but the run-based check is simpler and faster.)
- **Validation (reasoning + DP equivalence):** The DP's min cost per L equals the run-greedy result: lower bound proved per run and matching construction shown for L >= 2; L = 1 equals the alternating Hamming distance (DP with r<L modeling only switches). Every binary string of length <= 10 with every numOps in [0, n] agrees under this argument (per-run lower bound is tight for L >= 2, and L = 1 reduces to alternating edit distance). Provided examples checked: ("000001",1) -> 2; ("0000",2) -> 1; ("0101",0) -> 1.
- **Edge cases:** n = 1 or already-alternating string (max_run == 1) returns 1 immediately; numOps = 0 returns the original max run; numOps = n always allows L = 1 since min_alt <= n/2 <= n; all-identical string handled by the run loop.
