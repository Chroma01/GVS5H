- **Problem reduction:** Points lie on a square boundary. For D <= S, "pairwise Manhattan >= D" is exactly "pairwise shorter-perimeter-arc >= D". Hence for D in [0, S] the task is circular k-dispersion on a circle of circumference 4S.
- **Equivalence proof:** Manhattan distance <= arc distance always (arc is a path, L1 is a metric). If two points lie on the same or adjacent sides, Manhattan distance equals the shorter arc (adjacent: man = (S-a)+b <= 2S and 4S-man >= 2S >= man, so the short arc is that one). Only opposite sides can have man != arc, and there both quantities are >= S. Therefore for D <= S each direction of the iff holds: same/adjacent give man == arc; opposite automatically satisfy both.
- **No scoring above S:** Same side forces man <= S, so pairwise > S needs 4 distinct sides. With bottom a, right b, top c, left d the constraints become b > a, c+b < S, c > d, a+d > S, i.e. a+c < S and a+c > S, a contradiction. Also 4 points with a corner cannot occupy 4 sides. So any k >= 4 selection has min pairwise <= S; binary search hi = S is safe (k >= 4 is guaranteed by constraints).
- **Perimeter mapping:** y==0 -> t=x; elif x==S -> t=S+y; elif y==S -> t=3S-x; else -> t=4S-y. All formulas agree at every corner (0, S, 2S, 3S), values are distinct because points are distinct, and order matches the clockwise boundary walk.
- **Feasibility check:** Sort t, build doubled T with T[i+n]=T[i]+4S. Greedy from start s places points at the earliest feasible successors; for fixed s greedy positions are componentwise <= any valid configuration, so if a valid k-subset starts at s greedy stays inside window [s, s+n) and maximizes the wrap gap. Consecutive gaps plus the wrap gap all >= D is necessary and sufficient. Trying every s and unrolling the circle captures the optimum.
- **Implementation detail:** nxt built with a monotone two-pointer (O(n)); jumps accelerated with binary lifting on nxt (LOG <= 5 for k <= 25), so a check is O(n log k) instead of O(nk). Window bound pos < s+n guarantees the k chosen indices are distinct (one representative per physical point).
- **Complexity:** O(n log k + n log k log S) per the outer binary search of ~30 steps, ~7.7M elementary ops worst case for n=15000, k=25, S<=1e9. Fast and allocation-light.
- **Test results:** All three samples PASS -> sample 1 = 2 (corners, D=S feasible), sample 2 = 1 (D=2 correctly rejected, D=1 accepted), sample 3 = 1 (5 gaps of >=2 cannot fit in circumference 8). Stress checks PASS: side=2 four corners k=4 -> 2; side=1 (four lattice corners) k=4 -> 1; side=2 all 8 boundary lattice points k=4 -> 2 and k=5..8 -> 1; clustered points ((0,0),(1,0),(0,1),(2,0), k=4) -> 1; midpoints of a side=10 square k=4 -> 10. Small cases matched a brute-force subset enumeration.
- **Pitfalls avoided:** using >= D not > D; exclusive window [s, s+n); wrap comparison T[s]+4S-T[pos]; sentinel index m2 keeping lifting in range; corner formulas made consistent so no duplicate t.
