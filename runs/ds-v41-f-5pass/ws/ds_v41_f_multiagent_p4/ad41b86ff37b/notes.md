- **Problem model:** Deleting vertices from tree T leaves an induced connected subtree. We need the largest induced Snowflake subtree; answer is N minus its size.
- **Snowflake characterization:** A Snowflake has a center C, x >= 1 middle neighbors of C, and each middle has exactly y >= 1 leaves. Total kept vertices = 1 + x(y+1). The center can be any original vertex, including a leaf.
- **Fixed center formula:** For a fixed center C, for each neighbor M let d(M) = deg(M) - 1. M can be a middle for leaf count y iff d(M) >= y. Keeping every eligible M is optimal because their leaf sets are disjoint in a tree. If k(y) = #{M : d(M) >= y}, kept vertices = 1 + k(y)(y+1), provided k(y) >= 1 and y >= 1.
- **Optimal y:** Sort d values descending v[0] >= v[1] >= ... . k(y) is non-increasing in y. Between two consecutive d values, k is constant while y+1 grows, so an optimum y is always some positive d(M). With ties, iterating index i and using count i+1 covers the largest count for that y. Candidate = 1 + (i+1)*(v[i]+1) for v[i] >= 1.
- **Algorithm:** Build adjacency and degrees. For each vertex c as center, create vals = [deg(m)-1 for m in adj[c]], sort descending, and test every positive y. Track global best kept vertices. Print N - best. Complexity O(N log N) worst case from sorting adjacency lists, total O(N) memory.
- **Edge cases:** y must be >= 1, so d=0 values are skipped. x >= 1 is enforced by needing at least one positive value. Initializing best = 0 is safe under the guarantees. Leaf centers are handled, e.g. star K1,3 is a Snowflake centered at a leaf with x=1, y=2.
- **Sample checks:** Sample1 center 4 gives vals [2,2,0]; y=2 at i=1 gives kept 7, answer 1. Sample2 path of 3 gives vals [1] at an endpoint, kept 3, answer 0. Sample3 center 2 gives vals [3,1,1]; y=1 with count 3 gives kept 7, answer 3.
- **Implementation notes:** Use sys.stdin.buffer.read() for fast input. Vertices are 0-indexed internally. The sum of adjacency-list lengths is 2(N-1), so Python sorting is easily fast enough for N <= 3e5.
