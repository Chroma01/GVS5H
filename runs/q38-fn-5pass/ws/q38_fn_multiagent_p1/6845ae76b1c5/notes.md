- **Core idea:** Square-root decomposition on A. For each full A-block, precompute its contribution to every needed B-prefix. A query uses full blocks before its A-block, then handles only the shorter of the prefix part or suffix part inside its block as signed offline subqueries.
- **Block contribution:** For a block with sorted values, sweep B[1..max_y] sorted by value. Maintain `p = #block_values <= B_j`, `coef = 2p - block_len`, and `const = block_sum - 2*sum_le`. Then `d_j = B_j*coef + const = sum_{a in block}|a-B_j|`. Prefix-summing `d_j` over original B indices gives the whole-block contribution to each B prefix.
- **Partial subqueries:** Each chosen partial A element creates `(a, Y, qid, sign)`. Offline, sort subqueries by `a`, sweep B[1..max_y] by value, and maintain Fenwick trees over original B indices for count and sum of processed `B_j <= a`. For prefix `Y`, with `c,s` from Fenwick and `prefB[Y]`, `sum_{j<=Y}|a-B_j| = a*(2c-Y) + prefB[Y] - 2s`.
- **Distinct-Y optimization:** Only `max_y` and the distinct query Y values matter. `base` is compressed by distinct Y, and block prefix arrays are sampled only at those Y values. This reduces memory and base-update work.
- **Chunked offline solving:** Subqueries are solved in chunks (about 500k) to limit peak memory. Each chunk is sorted independently and uses fresh Fenwick trees. Extra B updates per chunk are acceptable.
- **Block size:** Dynamic `S = sqrt(max_y*N/K)`, capped so worst-case `K*S/2 <= 3e6`, clamped to `[1,N]`. For maximum constraints this gives about 600. This balances precomputation `O(max_y*N/S)` and partial offline work `O(K*S log max_y)`.
- **Packing:** Subqueries are packed into one integer: high bits store A value, then Y, then query id, then sign bit. Dynamic bit widths keep packs compact and sorting by integer sorts by A value.
- **Prefix implementation:** On CPython, `itertools.accumulate` is used for block prefix sums; on PyPy, an in-place Python loop is used to avoid many temporary list allocations.
- **Edge cases:** Duplicates are handled by `<=` in both sweeps. Last block may be shorter. If suffix length is zero, the whole block is used and no subqueries are generated. Small K or small max_y increases S automatically. Values and answers fit Python integers.
- **Performance details:** GC is disabled only on CPython. Packed A/Y/qid values are precomputed. Fenwick prefix queries use `i &= i - 1`. Work is roughly `2*max_y*num_blocks` for block contributions plus subquery Fenwick queries.
