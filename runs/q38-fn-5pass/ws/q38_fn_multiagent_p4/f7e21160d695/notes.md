- **Core observation:** f(x, y) is the smallest threshold t such that x and y are connected using only edges of weight at most t. Processing edges in nondecreasing order with DSU therefore reveals the exact cost at which two currently separate components first become mutually reachable.
- **Token surplus:** For each vertex, store count in A minus count in B. Positive surplus means unmatched A tokens, negative surplus means unmatched B tokens. The total surplus is zero because both sequences have length K.
- **DSU invariant:** After processing all edges up to the current weight, every DSU component has already matched as many opposite tokens as possible inside itself, so only its net surplus remains. The internal split of positive and negative tokens is not needed.
- **Merge rule:** When two components with surpluses su and sv merge at weight w, if they have opposite signs, min(abs(su), abs(sv)) pairs can now be matched for the first time, each at cost w. Add w times that number to the answer and replace the component surplus by su + sv. If signs are equal or one is zero, no new pair is forced at this merge.
- **Equal weights:** Processing equal-weight edges one by one is safe. All matches made while a set of components is being connected at the same weight have the same cost w. The total number of matches produced inside each connected component of the equal-weight graph is independent of union order and equals the maximum possible number of pairs that can have cost at most w.
- **Optimality:** For any threshold t, pairs with cost at most t must lie within components formed by edges of weight at most t. The maximum possible number of such pairs is the sum over those components of min(#A, #B). The greedy DSU maintains exactly this maximum after every threshold, so it maximizes the number of pairs matched at every cost level. Since total cost is minimized by matching as many pairs as possible as early as possible, the greedy result is optimal.
- **Complexity:** Sorting dominates: O(M log M) time. DSU operations are near O((N + M) alpha(N)). Memory is O(N + M) for edges and DSU arrays. Python integers handle the answer, which can be up to about 2e14.
- **Implementation details:** Read all integers from stdin. Build surplus by adding +1 for A and -1 for B. Store edges as (w, u, v) and sort. Use iterative find with path halving and union by size. Update the root surplus after union. The graph is connected, so all surplus is eventually matched.
- **Edge cases:** Duplicate vertices inside A or inside B are handled by counts. The guarantee that no A vertex equals a B vertex avoids zero-cost self pairs, but the net-surplus logic would also collapse such pairs to zero. All weights equal, K = N, and large multiplicities are handled naturally.
