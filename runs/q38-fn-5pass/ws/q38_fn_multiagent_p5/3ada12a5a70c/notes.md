- **Core reduction:** Because all points lie on the square boundary, map them to a 1D circular coordinate of circumference `4 * side`. For any candidate distance `d <= side`, two boundary points have Manhattan distance `< d` exactly when their circular perimeter distance is `< d`. Opposite sides can have Manhattan distance smaller than their perimeter distance, but only when that perimeter distance is greater than `side`; since the answer is at most `side`, this does not affect the decision problem.
- **Answer upper bound:** With `k >= 4`, any selected set has two points whose shorter circular arc is at most `side`, and Manhattan distance is no larger than that arc, so the answer is at most `side`. Also, `k` points on a circle of circumference `C` have minimum circular spacing at most `floor(C / k)`. Binary search upper bound is `min(side, (4 * side) // k)`.
- **Perimeter mapping:** Use a consistent clockwise order: bottom side `t = x`, right side `t = side + y`, top side `t = 2 * side + (side - x)`, left side `t = 3 * side + (side - y)`. Corner assignments are consistent and unique: `(0,0) -> 0`, `(side,0) -> side`, `(side,side) -> 2 * side`, `(0,side) -> 3 * side`.
- **Feasibility test:** For a fixed `d`, sort perimeter coordinates and duplicate them with `+ C`. For each index `i`, compute `nxt[i]`, the first later index whose coordinate is at least `d` ahead, using a two-pointer scan in `O(n)`.
- **Greedy circular selection:** For each original point as the first selected point, greedily jump `k - 1` times through `nxt`. This greedy choice is optimal for that fixed start because choosing the earliest possible next point never reduces the number of points that can be placed before the wraparound limit. The selection is valid if the last chosen coordinate is at most `start + C - d`, ensuring the final wraparound gap is also at least `d`.
- **Correctness outline:** If a valid circular selection exists, choose one selected point as the start. The remaining selected points appear in clockwise order with all gaps at least `d`, so the last point is within `C - d` of the start. Greedy from that start selects points no later than the valid selection, so it also finds a valid selection. Conversely, any greedy success gives `k` points with all circular gaps at least `d`, hence all Manhattan distances at least `d` for `d <= side`.
- **Complexity:** Sorting is `O(n log n)`. Each feasibility check computes next pointers in `O(n)` and tries `n` starts with `k - 1` jumps, so `O(nk)`. Binary search uses `O(log side)` checks. With `n <= 15000`, `k <= 25`, this is comfortably within limits. Memory is `O(n)`.
- **Edge cases handled:** `d = 0` returns true immediately. Wraparound is handled by duplicated coordinates. The final gap check uses `<= start + C - d`, allowing equality. Next pointers use strict `< d` in the while loop, allowing pairs exactly distance `d`. Shifted duplicate points cannot be accepted because the wraparound limit is strictly less than `start + C` for `d > 0`.
