- **Positive-product DP:** Maintain `dp0[p]` and `dp1[p]` as integer bitsets of achievable alternating sums for exact product `p`. `dp0` stores even-length non-empty subsequences, `dp1` stores odd-length non-empty subsequences. Bit index is `sum + offset`, where `offset = sum(nums)`.
- **Transitions:** For a positive `x <= limit`, iterate products descending from `limit // x` to `1`. Save both `old0` and `old1` before OR-ing. Appending to even length shifts left by `x` into odd length; appending to odd length shifts right by `x` into even length. Add singleton `[x]` to `dp1[x]` after the loop.
- **x=1 safety:** When `x == 1`, target product equals source product. Saved old snapshots prevent using the same `1` twice. Descending order handles `x > 1` because target product is larger and has already been processed as a source.
- **Skipping values:** Positive DP skips zeros and values greater than `limit`. A positive product cannot contain zero, and any factor greater than `limit` makes the product exceed `limit` because all positive factors are at least 1.
- **Zero handling:** Positive DP skips zeros because any zero makes product zero. A separate feasibility DP tracks whether a zero-containing subsequence can achieve a sum. States are `no0/no1` for no zero and `has0/has1` for at least one zero. `no0` starts with the empty subsequence only to allow starting a zero-containing subsequence; it is never returned.
- **Zero transitions:** For positive `x`, zero flag is unchanged, parity toggles, and sum shifts by `+x` from even states or `-x` from odd states. For `x == 0`, sum is unchanged, parity toggles, and all taken states become `has` states. Skipping keeps old states.
- **Bounds and masking:** Total sum is at most `150 * 12 = 1800`, so bitsets need `2 * total + 1` bits. If `abs(k) > total`, return `-1` immediately. Mask left shifts to discard sums outside `[-total, total]`; right shifts naturally drop invalid negative sums.
- **Edge cases:** Non-empty requirement is enforced because positive DP has no empty state and zero DP only returns from `has` states. Values equal to `1` keep product unchanged but still affect parity and sum. Product zero is returned only after all positive products have been checked.
- **Complexity:** Positive DP performs at most `n * limit = 750000` product iterations, each using big-int bit operations on at most 3601 bits. Zero DP is `O(n)` big-int operations. Memory is `O(limit * total / word_size)` for the two product arrays.
