- **Core idea:** Process values from N down to 1. Once all values larger than x have been fixed at the right end, the remaining values 1..x occupy the first x positions in their original relative order. Thus the current position of x is its rank among still-active original positions.
- **Cost for one value:** If x's current active rank is p, moving it right to its final position x crosses edges p, p+1, ..., x-1 exactly once. The cost is the arithmetic sum `T(x-1) - T(p-1)`, where `T(k) = k*(k+1)//2`.
- **Correctness sketch:** For the largest remaining value x, any sorting sequence must move x from its current position p to final position x. For every edge i with p <= i < x, x must cross that edge at least once, contributing at least i. Moving x monotonically right immediately achieves this lower bound. This preserves the relative order of smaller values and only shifts some of them left, which cannot increase future swap costs. Induction over descending x proves global optimality.
- **Fenwick tree usage:** Maintain active original positions of values not yet placed. Initially every position is active. `prefix_sum(pos[x])` gives x's current rank among active positions. After placing x, remove its original position with `add(pos[x], -1)`.
- **Initialization detail:** A Fenwick tree representing an all-ones array can be built in O(N) by setting `bit[i] = i & -i` for each i.
- **Implementation details:** Store `pos[value] = original_index`. Loop x from N down to 1, compute rank with an inline Fenwick prefix sum, add the triangular-number difference to the answer, then remove the position with an inline Fenwick update. Python integers safely handle the maximum answer.
- **Complexity:** O(N log N) time and O(N) memory, suitable for N up to 2e5.
- **Sample validation:** For `3 2 1`, costs are 3 for value 3, 1 for value 2, and 0 for value 1, total 4. For `2 4 1 3 5`, costs are 0, 5, 0, 1, 0, total 6. For `1 2`, total 0.
- **Pitfalls:** The rank is among active original positions, not the original position itself and not the value. Total inversion count alone is insufficient because swap costs depend on the edge index where the inversion is resolved.
