- **Problem:** delete every occurrence of at most one integer x (result must stay non-empty), maximize the resulting max subarray sum.
- **Zeroing equivalence:** erasing all x == replacing each occurrence by 0 for the purpose of subarray sums (subarrays of the erased array correspond to ranges of the zeroed array with equal sum). Empty/zero configs are harmless whenever M > 0.
- **Only negatives matter:** for x >= 0 every range sum is unchanged or lowered, so it never beats the no-op answer M. Candidates restricted to x < 0.
- **Non-empty / M <= 0 branch:** Kadane's M >= max element. If M <= 0 every element <= 0, so deleting only removes non-positive weight; answer = M. This also kills the illegal "delete makes array empty" case (e.g. [-1,-1] -> -1). Required early return.
- **Fixed-x decomposition:** for x with positions p_0<...<p_{m-1}, any candidate needing x has first x p_a and last x p_b (a<=b); its zeroed sum = max(0,E[p_a-1]) + (zeroed sum of [p_a,p_b]) + max(0,S[p_b+1]), where E ends-at / S starts-at Kadane arrays. Ranges avoiding x are <= M.
- **Prefix split:** u_a = max(0,E[p_a-1]) - P[p_a] + x*a, v_b = max(0,S[p_b+1]) + P[p_b+1] - x*(b+1); candidate = u_a + v_b. Sweep b keeping pref_u = max_{a<=b} u_a. O(count) per value, O(n) total.
- **Correctness (both bounds):** for any (a,b) the formula equals orig-sum[l*,p_a-1] + zeroed[p_a,p_b] + orig-sum[p_b+1,r*], which is <= the true zeroed sum of [l*,r*] because L/R (built on original nums) may carry other x occurrences at their real negative values while the true zeroed sum zeroes them (only increases), and the r* attaining S may extend past p_{b+1} (again only left as a lower bound). Conversely for the true optimum with first/last x (a,b), each of code's L, middle, R is >= the true L, middle, R, so code's candidate >= true optimum. Hence equality; no overestimate.
- **Verification (PASS):** brute-force oracle = {no-op} ∪ {delete each distinct value then Kadane}; matched the solution on all randomized small arrays (n<=8, values in [-5,5], thousands of trials) and exhaustive tiny cases. Examples: [-3,2,-2,-1,3,-2,3] -> 7; [1,2,3,4] -> 10. Edge checks (exact outputs): [-1,-1]->-1; [5]->5; [-5]->-5; [0]->0; [2,2]->4; [-1,-2,-3]->-1; [-5,-5,10,-5,-5]->10; [-1,5,-1,5,-1]->10; [-2,3,-1,3,-2]->6; [-5,100,-5,100,-5]->200; [-1,2,-3,2,-1]->4; [-1,2,-1,2,-1]->4; [5,-1,-1,5]->10.
- **Complexity:** O(n) time, O(n) space; ints are unbounded in Python so large sums are safe.
- **Pitfalls seen:** forgetting the no-op M; the M<=0 early return; the subtle "why crossing other x's is safe" argument; `pref_u` must be max over a<=b only (not all a).
