- **Operation model:** In the ordered rooted forest of a Dyck word, any valid substring is a consecutive block of sibling subtrees (or top-level trees). The operation maps a block T1...Tk to F(Tk)...F(T1), where F recursively reverses child order and flips every child. Thus the underlying unordered rooted forest is invariant.
- **Reachability:** Conversely, every ordered forest with the same unordered structure is reachable. Adjacent siblings A,B can be swapped: apply operation to AB to get F(B)F(A), then flip each of the two resulting subtrees individually to recover B A. Individual flips are operations on a single subtree. Hence we can realize any permutation of children and recursively fix each child. The orbit is exactly all ordered versions of the fixed unordered forest.
- **Counting formula:** For an unordered node (or the virtual root over the top-level forest) with k children, group children by unordered type t with multiplicity n_t. Let v_t be the number of distinct ordered versions of type t. Then the number of ordered versions of this node is k! / ∏ n_t! * ∏ v_t^{n_t} mod 998244353. This counts sequences of child strings, which are uniquely decomposable because each child is a primitive Dyck word.
- **DP implementation:** Parse S with a stack; each '(' creates a node whose parent is the stack top; each ')' pops. Node indices increase from root to leaves, so process v from high to low. For each node, collect child type IDs, sort them, and map the sorted tuple to a canonical integer type ID. Compute the node's value once per type using the formula; store val_type[id]. Group multiplicities by scanning the sorted child type IDs.
- **Virtual root:** Treat the top-level forest as children of a virtual root (index 0) and apply the same formula without an enclosing parenthesis pair. Print the resulting value.
- **Complexity:** O(N log N) time and O(N) memory. N ≤ 5000, so easily fast enough. Precompute factorials and inverse factorials up to N.
- **Pitfalls:** Use integer type IDs rather than nested tuples to avoid expensive comparisons. Ensure leaves get the empty tuple key and value 1. The modulo is prime and larger than N, so inverse factorials exist.
