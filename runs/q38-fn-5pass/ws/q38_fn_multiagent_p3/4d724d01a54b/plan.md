Use a greedy strategy that fixes elements from largest to smallest: for each value x from N down to 1, move x rightward until it reaches its final position x, swapping only with smaller elements. This is optimal because all larger elements that must cross x should do so before x moves, which shifts x left and makes its required swaps cheaper. When processing x, all larger values have already been placed, so x's current position is its initial position minus the number of larger values initially to its left. The cost for moving x from current position cur to x is the sum of swap indices cur, cur+1, ..., x-1. Maintain the set of already processed larger values in a Fenwick tree over initial positions to query the needed count in O(log N), giving an O(N log N) solution.
