- **Problem model:** a good caption = concatenation of constant blocks, each of length >= 3, adjacent block chars distinct; cost = sum of per-position alphabet distances |s_j - target_j|; first minimise cost, then take the lexicographically smallest string.
- **Feasibility:** return "" iff n < 3. For n >= 3 the single run of one char is always valid, so answers always exist.
- **DP definition:** rolling 3x26 arrays; g[i][c][L] = min cost to fill positions i..n-1 given position i-1 holds char c and the trailing run length is L (L in {1,2}; 3 means ">= 3"). Base g[n][c][1] = g[n][c][2] = INF, g[n][c][3] = 0.
- **Transitions:** L=1 and L=2 are forced: g[i][c][1] = |s_i-c| + g[i+1][c][2], g[i][c][2] = |s_i-c| + g[i+1][c][3]. L=3 is free: min( |s_i-c| + g[i+1][c][3], min_{x != c} |s_i-x| + g[i+1][x][1] ).
- **Switch in O(1):** per i precompute best/second-best over x of |s_i-x| + g[i+1][x][1]; if the argmin is the current run char c, use the second best. Strict `<` keeps the smallest x on equal values, which is what the lexicographic tie-break needs.
- **Monotonicity:** g[i][c][1] >= g[i][c][2] >= g[i][c][3] >= 0 (each level is the next plus a non-negative forced char cost). Consequence: when the switch argmin equals the run char c, continuing is never worse, so the char placed from that state is c whichever of best/second-best is used; the `b1x == c` handling is a consistency/safety detail, not an outcome changer. This supersedes the earlier note that claimed the second-best mishandling corrupted results.
- **Lex tie at that state:** if b1x == c then any x < c with an equal value would have been selected as b1x instead, so b2x > c and the tie-break min(c, sx) resolves to c.
- **Choice table:** `choice[i*26+c]` = char placed at position i from state (i, c, L>=3); every (i, c) with 1 <= i <= n-1 is written (the switch value can be INF, in which case the finite continue branch wins), so reconstruction never reads an unset slot.
- **Loop bound:** `range(n-1, 0, -1)` runs i = n-1 .. 1 inclusive, so after it the arrays hold g[1]; that is exactly the state the explicit first-position cost is added to. For n = 3 it iterates i=2 then i=1.
- **Reconstruction:** first char = smallest x minimising |s_0-x| + g[1][x][1] (strict `<`, x scanned ascending); then walk i=1..n-1: forced char while run length < 3, otherwise consult choice; update run length (cap at 3) or reset to 1 on a switch. Invariant "prefix cost so far + DP value of current state = OPT" holds at every step, so the greedy yields the lexicographically smallest optimal caption.
- **INF safety:** `cont = dist + g[i+1][c][3]` is always finite (keeping char c is always legal), so an INF switch value can never beat it.
- **Complexity:** O(26n) time, three rolling 26-element lists plus one n*26 bytearray (~1.3 MB at n = 5e4).
- **Harness:** brute force enumerates run compositions (parts >= 3) with all adjacent-distinct character assignments over a target alphabet, computes exact costs, and picks the (cost, string) minimum; it lives under `if __name__ == "__main__"`, so importing the class never runs it. Restricting the target alphabet to the input alphabet is safe because each block's cost function is convex with a minimiser inside its own data range.
- **Coverage:** exhaustive lengths 3..7 over {a,b,c} (3267 strings) and {a,b,c,d} (21824); 26-letter target alphabet for lengths 3..5 over 3 and 4 input letters (1695); 1500 random n in 3..8 over K in {2,3,4,5,26}; 150 random n in 9..11 over K in {2,3,4}; four explicit n=1,2 cases. Total 28440 inputs.
