- **Parity is essential:** The sign of a chosen element depends on the length parity of the subsequence before appending it, not on its original index. Every DP state therefore tracks parity 0 for even length and parity 1 for odd length.
- **Positive-product DP:** `dp0[prod]` and `dp1[prod]` store bitsets of alternating sums reachable by zero-free subsequences with exact product `prod`, where `1 <= prod <= limit`. For zero-free subsequences, multiplying by values >= 1 never decreases product, so discarding states with product > limit is safe for positive answers.
- **Zero product requires special handling:** A prefix product may exceed `limit`, but appending a zero later makes the final product zero, which is valid. Therefore positive-product DP alone is insufficient. Maintain `all0/all1` for all non-empty subsequences regardless of product, and `zero0/zero1` for subsequences that already contain at least one zero.
- **Zero transitions:** When `x == 0`, appending zero toggles parity and leaves sum unchanged. `zero_dp` receives old `all_dp` shifted by parity toggle, plus the singleton `[0]`. Positive-product DP is unchanged because appending zero cannot produce a positive product.
- **Positive transitions:** When `x > 0`, `zero_dp` appends `x` to old zero states. Positive DP appends `x` only from active states where `prod * x <= limit`. Even parity appends `+x`, odd parity appends `-x`.
- **All-subsequence DP:** `all_dp` is updated unconditionally for every `x`, including values greater than `limit`, because it is needed to create zero-product states when a zero appears later.
- **Bitset sum encoding:** Use `offset = sum(nums)`, at most 1800. A sum `s` is stored at bit position `s + offset`. Adding `+x` is a left shift by `x`; adding `-x` is a right shift by `x`. Since `offset` includes the current element, valid right shifts never drop reachable bits.
- **Snapshot discipline:** For each number, old `all_dp`, old `zero_dp`, and old positive active bitsets are snapshotted before updates. This prevents using the current number more than once while still allowing in-place OR updates.
- **Non-empty enforcement:** Empty subsequence is never stored. Singleton transitions start new non-empty subsequences. This avoids falsely accepting empty subsequence for `k = 0`.
- **Final answer:** Scan positive products from `limit` down to 1. If none has target sum, check `zero_dp` for product 0. If neither exists, return -1. Positive products always beat zero because `limit >= 1`.
- **Complexity:** Sum range is small, so each bitset has about 3601 bits. Positive active products are limited to products reachable from values <= 12, and `n <= 150`, `limit <= 5000`, making the pseudo-polynomial DP efficient in Python.
- **Important edge cases:** zeros-only input returns 0 for `k = 0`; product > limit before a zero can still yield answer 0; ones can create non-empty product 1; empty subsequence must not count.
