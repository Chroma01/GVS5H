- **Core reduction:** Each index must be flipped with parity matching A_i xor B_i. Since all C_i are positive, extra flips are only useful for indices with A_i=B_i=1: flip them off once and later back on once. Matched 0s never need flips, and mismatched indices need exactly one flip in an optimal solution.
- **Canonical order:** In an optimal sequence, all flips ending in 0 can be moved before all flips ending in 1. Within the off phase, larger C_i should be flipped earlier. Within the on phase, smaller C_i should be flipped earlier. Thus for chosen optional set X, the sequence is fully determined: off phase is sorted descending over O ∪ X, then on phase is sorted ascending over I ∪ X.
- **Sets:** O = forced 1→0 costs, I = forced 0→1 costs, M = matched 1 costs. S0 is the initial sum of active costs, i.e. sum of O and all M.
- **Cost formula:** For selected optional set X of size k, let D=O∪X and U=I∪X. Off cost is (|D|)S0 minus sum of prefix sums of D. On cost is (|U|)(S0-sum(D)) plus sum of prefix sums of U. Using sum of prefix sums = sum(values) + sum of pair maxima for descending order, and sum(values) + sum of pair minima for ascending order, the total is:
  F(k) = (|O|+|I|+2k)S0 - (|I|+k+1)(sumO+sumX) + (sumI+sumX) - pairmax(O∪X) + pairmin(I∪X).
- **Pair decomposition:** pairmax(O∪X)=pairmaxO+pairmaxX+crossOX, where crossOX=sum_{o∈O,x∈X}max(o,x). Similarly pairmin(I∪X)=pairminI+pairminX+crossIX, where crossIX=sum_{i∈I,x∈X}min(i,x).
- **Top-k choice:** For fixed k, the optimal optional set is the k largest values in M. Exchange proof: replacing a chosen x by a larger y changes F by at most -(y-x), because forced-on terms contribute at most y-x each, previously chosen terms contribute at most y-x each, forced-off terms contribute nonpositive, and the base coefficient is -(p+k). Hence larger values are strictly better.
- **Implementation:** Sort O and I ascending, M descending. Precompute pairmaxO as sum v*i over ascending O, and pairminI as sum v*(p-1-i) over ascending I. Scan M descending, maintaining sumX, pairmaxX, pairminX, crossOX, crossIX.
- **Cross sums:** For each new x, crossOX adds sum_{o∈O}max(x,o). With O ascending and pointer idx_off = count(o <= x), this is x*idx_off + (sumO - prefixO[idx_off]). crossIX adds sum_{i∈I}min(x,i). With I ascending and pointer idx_on = count(i < x), this is prefixI[idx_on] + x*(p-idx_on). Pointers only move left because x decreases.
- **Edge cases:** Empty O, I, or M are handled. k=0 is always evaluated. Matched 0 costs are ignored. Python integers avoid overflow. Ties are safe because max/min pair sums are independent of tie order.
- **Complexity:** Sorting dominates, O(N log N), with O(N) scan and O(N) memory.
