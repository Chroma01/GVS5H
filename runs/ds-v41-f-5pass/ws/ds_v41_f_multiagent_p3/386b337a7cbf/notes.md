- **Parity state:** `par` = index of the next chosen element within the subsequence. `par==0` -> contributes `+x` (left shift), `par==1` -> contributes `-x` (right shift).
- **Positive DP:** `dp[par][p]` is a bitset of alternating sums reachable using product `p`. Seeded per element with a singleton `ndp[1][x] |= 1<<(offset+x)`. Extensions always read the pre-update `dp` snapshot, so each element is used at most once.
- **Pruning positives:** only extend products with `p*x <= limit`. All positive values are >= 1, so a product exceeding `limit` never becomes valid again. Elements `x > limit` are dropped from `pos_nums` entirely.
- **Active sets:** `active[par]` lists products with a nonzero bitset; iterate those instead of scanning `1..limit`. The bitset itself is authoritative; active is only an accelerator.
- **Bitset bounds:** `offset = total = sum(nums)`, `size = 2*total+1`, `MASK = (1<<size)-1`. Any alternating sum lies in `[-total,total]`. Left shifts masked; right shifts safe (index can't go below 0).
- **Zero handling:** separate DP tracking `(used_zero, par, sum)`; product 0 requires `used_zero==1`. Seeded with the empty subsequence but the final check demands `used_zero==1`, so empty is never returned.
- **Answer order:** scan `p = limit..1` for a positive reachable product with sum `k`; else 0 if a zero-containing subsequence reaches `k`; else -1. Positive always beats 0, so this ordering is correct.
