- **Validation:** The current implementation was checked against all three samples and additional edge cases: only corners, all points on one side, k equal to number of points, wrap-around selections, and large side values. No failures were found.
- **Core reduction:** For any threshold `d <= side`, two boundary points have Manhattan distance `< d` iff their shorter perimeter-arc distance is `< d`. Same-side and adjacent-side pairs have equal Manhattan and shorter perimeter distance; opposite-side pairs have both distances at least `side`, so they cannot violate a threshold `d <= side`.
- **Upper bound:** For `k >= 4`, the optimum is at most `side`. Any four boundary points either have two on one side (distance `<= side`) or one on each side; the four adjacent perimeter gaps sum to `4*side`, so one adjacent Manhattan distance is `<= side`. Also `k*d <= 4*side` is necessary, so `hi = min(side, 4*side // k)`.
- **Perimeter mapping:** Use clockwise coordinate: bottom `x`, right `side + y`, top `3*side - x`, left `4*side - y`. The `if` order gives corners bottom, right, top, left precedence and keeps coordinates unique in `[0, 4*side)`.
- **Decision problem:** Sort perimeter coordinates. For candidate `d`, decide whether `k` coordinates can be chosen on the circle with every consecutive circular gap at least `d`.
- **Greedy check:** Build `arr = coords + [c + perimeter for c in coords]`. Compute `nxt[i]` as the first index with `arr[j] >= arr[i] + d` using a monotone two-pointer scan. For each physical start `i`, jump `k-1` times through `nxt` within the window `[i, i+n)`. If the last selected index is before `i+n` and `arr[i+n] - arr[last] >= d`, the candidate is feasible.
- **Correctness of greedy:** For a fixed first selected point, choosing the earliest possible next point leaves the maximum remaining space. By induction, greedy positions are no later than any feasible positions, and the greedy last point maximizes the final wrap gap. Therefore, if greedy fails from every start, no feasible selection exists.
- **Complexity:** Sorting is `O(n log n)`. Each feasibility check is `O(n + n*k)` because the two-pointer scan is `O(n)` and each of `n` starts performs `k-1` jumps. Binary search over at most `side` gives `O(n*k*log(side))`, with `n <= 15000` and `k <= 25`.
- **Pitfalls:** The doubled array must be shifted by perimeter, not merely duplicated. The search upper bound must remain `<= side` because the perimeter equivalence is only guaranteed up to side. The final wrap gap must be checked explicitly.
