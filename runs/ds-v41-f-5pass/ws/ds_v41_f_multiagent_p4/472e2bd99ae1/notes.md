- **Problem:** Find the K-th largest value among all N^3 triples (i,j,k) of A_i B_j + B_j C_k + C_k A_i, with N up to 2e5 and K up to 5e5.
- **Monotonicity:** After sorting A, B, C in non-increasing order, the function f(i,j,k) = A_i B_j + B_j C_k + C_k A_i is non-increasing in each index separately (partial derivatives B_j+C_k, A_i+C_k, A_i+B_j are all positive). Thus the global maximum is at (0,0,0), and the top-K set is a down-closed region of the 3D index grid.
- **Best-first search:** Start with (0,0,0) in a max-heap. Repeatedly pop the largest value. When popping (i,j,k), push (i+1,j,k), (i,j+1,k), (i,j,k+1) if within bounds and not visited. The K-th popped value is the answer. A visited set prevents duplicate insertions (each triple can be reached from up to 3 predecessors).
- **Fast value computation:** Use the identity f = (A_i+B_j)(A_i+C_k) - A_i^2. Precompute A2[i] = A_i^2. This reduces multiplications to one per neighbor evaluation.
- **Memory/time optimization:** Pack the heap key as a single integer: key = (-val) * BASE + code, where BASE = 1 << 54 (since max code = N^3 - 1 < 2^53 for N ≤ 2e5) and code = i*N^2 + j*N + k. This avoids tuple overhead and makes heap operations faster. Decode with divmod: i, rem = divmod(code, N^2); j, k = divmod(rem, N). The value is recovered as - (key // BASE).
- **Complexity:** O(K log K) time and O(K) memory. With K ≤ 5e5, this is well within limits. The heap size is at most O(K), and each pop pushes at most 3 new nodes.
- **Pitfalls:** Must sort descending. The visited set is essential to avoid counting duplicates. SHIFT must be large enough to hold the maximum code; 54 bits is safe for N ≤ 2e5. Ties are handled naturally because the heap orders by value first. Use fast I/O (sys.stdin.buffer.read). The initial heap must contain the origin with code 0.
