- **Model:** prefix sums A over towns. Person (S,T) -> interval [l,r]=[min,max], sign + if S<T else -. Constraints: A_l=A_r and every interior A_k strictly greater (+) or less (-). Over integers feasible iff strict-edge digraph after contracting equality components is acyclic.
- **Pairwise characterization (verified in earlier work):** a chosen set is feasible iff no two intervals (i) share a left endpoint, (ii) share a right endpoint, or (iii) cross with equal sign. Sharing an endpoint is always a conflict; a same-sign crossing forces A-chain x>y>x. Opposite-sign crossings, nesting, touching, disjointness are all realizable. Every minimal infeasible set has size 2.
- **3-cycle argument (re-confirmed):** a possible 3-component cycle forces some interval's interior to contain another's endpoint; that endpoint placement necessarily produces either a shared endpoint or a same-sign crossing, so pairwise suffices. Good.
- **Query reduction:** feasibility is hereditary. With g2[j]=max i<j forming a bad pair with j and G[R]=max_{j<=R} g2[j], query [L,R] is Yes iff G[R]<L. Correct because any j with g2[j]>=L must satisfy j>g2[j]>=L, i.e. the bad pair lies inside [L,R].
- **g2 sources:** same l / same r by last-seen dictionary (nearest previous maximizes i). Same-sign crossings need the hard part.
- **Crossing split (for pair i<j):** Type1 l_i<l_j<r_i<r_j; Type2 l_j<l_i<r_j<r_i. Type1 <=> i covers l_j and r_i<r_j. Type2 <=> i covers r_j and l_i>l_j. Running CDQ per sign (lists sorted by original index) makes i<j automatic.
- **CDQ implementation:** iterative bottom-up over segments that stay contiguous in index order; each level combines adjacent segments. Each segment keeps two sorted lists (by r, by l) built by merging, so sorting cost is O(M log M). Cross step: Type1 sweep right sorted by r, insert left with r_i<r_j as range-max-update on (l_i+1,r_i-1) value=i, point-query at l_j; Type2 sweep right in decreasing l_j, insert left with l_i>l_j on same range structure, point-query at r_j. Both give the true max-i crossing condition because the covering (point inside range) enforces the remaining strict inequalities.
- **Range-max-update / point-query segment tree:** lazy max on O(log) nodes, point query = max over ancestors. A global incrementing version counter with per-node (ver,val) clears state in O(1) per cross sweep — avoids any reset cost.
- **Complexity:** O(M log^2 M + Q) time, O(M + N) memory. This is the asymptotic bottleneck; pure Python may be slow for M=2e5 worst case (inner node visits ~ M log M log N), but correctness is complete and the code avoids recursion and uses local aliases to keep constants down.
- **Edge details:** |S-T|>1 guarantees nonempty interior so range updates are well-defined; empty ranges are skipped. Segment tree size is the power of two >= N+1. g2 uses 0 = "no partner" since indices are >=1.
- **Brute oracle (earlier):** union endpoints for equalities, add strict directed edges, require acyclicity; independent of the pairwise claim. Earlier exhaustive/random testing (N<=10) matched this solver.
