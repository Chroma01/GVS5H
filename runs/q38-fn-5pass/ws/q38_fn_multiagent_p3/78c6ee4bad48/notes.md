- **Gap model:** For four consecutive sorted pieces with gaps a, b, c, reflecting the two inner pieces about the midpoint of the outer two changes the gaps to c, b, a. Thus the operation is exactly a swap of the two gaps at distance 2, while the middle gap stays fixed.
- **Invariants and reachability:** A gap never changes the parity of its index. The 0-based even-indexed gaps and 0-based odd-indexed gaps evolve independently. The allowed swaps are adjacent swaps inside each parity subsequence, so they generate all permutations of each subsequence. Operations on different parity classes do not interfere.
- **Objective:** The leftmost coordinate is invariant. If the gaps are g_0, ..., g_{N-2}, the coordinate sum is N*X_0 + sum_j g_j*(N-1-j). The weights decrease from left to right.
- **Optimization:** Within each parity class, pair the smallest gap with the largest remaining weight, the next smallest with the next largest, and so on, by the rearrangement inequality. Therefore sort the 0-based even-indexed gaps and the 0-based odd-indexed gaps ascending, then multiply them by the weights at positions 0, 2, 4, ... and 1, 3, 5, ... respectively.
- **Implementation details:** Read all integers. Build gaps while scanning X. Put gap i into even if i is even, otherwise odd. Sort both lists. Compute ans = n*first. For the even list, the t-th sorted gap has weight n-1-2*t. For the odd list, the t-th sorted gap has weight n-2-2*t. Python integers avoid overflow, and no floating point is needed.
- **Pitfalls:** Do not sort all gaps together because parity classes cannot mix. Use 0-based parity consistently. Remember to add the invariant contribution N*X_0.

- **Complexity:** Time complexity is O(N log N) due to sorting two gap lists, and memory usage is O(N).
