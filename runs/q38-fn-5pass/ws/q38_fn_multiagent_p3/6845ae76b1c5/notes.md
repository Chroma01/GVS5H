- **Approach:** Index-block sqrt decomposition with dynamic block size `S = min(N, int(N / sqrt(K)) + 1)`. Number of blocks `M` is about `sqrt(K)` in the worst case.
- **Decomposition:** For query `(X,Y)`, split A into full blocks before `ba`, partial block `ba`, and similarly for B. Answer is full-full + partialA/fullB + fullA/partialB + partial-partial.
- **Full-full:** Precompute block-pair sums `P[ba][bb]` and a 2D prefix over them. This is only computed when some query has both `ba > 0` and `bb > 0`; otherwise it is skipped.
- **Sorted block data:** For every A/B block, store original block, total sum, sorted values, and sorted original indices. Sorted indices allow per-element contributions to be accumulated in original prefix order.
- **PartialA/fullB fringe:** For each A block with queries, sweep B blocks from left to right. Maintain `arr[i]`, the contribution of A position `i` against all processed full B blocks. Queries are sorted by number of full B blocks and prefix length, so prefix sums of `arr` can be scanned once per queried boundary.
- **FullA/partialB fringe:** Symmetric sweep per B block over A blocks. It only processes A blocks up to the maximum needed boundary.
- **Total/no-total variants:** When block-pair sums are needed, the fringe sweep also returns the block-pair sum. When only fringe values are needed, a no-total variant avoids extra additions.
- **Partial-partial grouping:** Queries are grouped by current block pair. Duplicate `(pa,pb)` pairs are compressed so each distinct prefix-pair is computed once and added to all query ids.
- **Full current block optimization:** If `pa == len(A_block)` and `pb == len(B_block)`, partial-partial equals the full block-pair sum. Use `P` if available; otherwise compute and cache the block-pair sum on demand.
- **Heavy block pairs:** If the number of distinct prefix pairs is large relative to block size, build a 2D prefix implicitly row by row using one column-prefix array. This costs `O(la*lb)` for that pair and answers all its distinct queries.
- **Light block pairs:** For small distinct query counts, use direct summation for tiny products, otherwise sort one prefix and use binary search with prefix sums. For moderately many distinct pairs, sort both needed prefixes and merge sorted lists.
- **Thresholds:** Direct if product <= 256 or one side length is 1. Merge branch for at least 64 distinct pairs. Heavy if `u * (la + lb) > la * lb`, roughly `u > S/2` for square blocks.
- **Complexity:** With `S ~ N / sqrt(K)`, block-pair and fringe work is about `O(N^2 / S)`, partial-partial work is about `O(K*S)` after duplicate compression, plus sorting of queried prefixes. Memory is `O(N + M^2)` plus temporary per-pair caches.
- **Edge cases:** Last blocks may be shorter than `S`. If `K` is small, `S` can be `N`, making `M=1` and reducing the method to a few block operations. If no full-full part exists, `P` is not built. Equal values are handled by `<=` and `bisect_right`.
