- **Core idea:** The constraint \(\binom{N}{K} \le 10^6\) makes direct enumeration feasible if we enumerate the smaller of the chosen set and its complement.
- **Complement trick:** Let \(T\) be the XOR of all elements. If we enumerate a complement set \(C\) of size \(N-K\), then the XOR of the chosen \(K\) elements is \(T \oplus \operatorname{xor}(C)\).
- **Enumeration side:** Set \(r = \min(K, N-K)\). If \(K \le N-K\), enumerate \(r\)-element subsets directly as the chosen elements. Otherwise enumerate \(r\)-element subsets as complements and transform their XOR with the total XOR.
- **Bound on work:** Since \(\binom{N}{r} \le 10^6\) and \(r\) is the smaller side, \(r\) is very small in practice, at most about 11. The total number of XOR operations over all enumerated combinations is comfortably small, around a few million in the worst case.
- **Special cases:** If \(r = 0\), then \(K = N\), so the answer is the XOR of all elements. If \(r = 1\), handle directly: for \(K = 1\), answer is \(\max(A)\); for \(K = N-1\), answer is \(\max(T \oplus a_i)\). This avoids unnecessary tuple creation on large \(N\).
- **Implementation details:** Read all input at once, compute total XOR, branch on the smaller side, and use `itertools.combinations` for enumeration. Track the maximum incrementally and do not store all subset XORs.
- **Duplicates:** `itertools.combinations` operates on positions, so duplicate values are still treated as distinct indices, matching the problem requirement.
- **Correctness:** Every valid choice of \(K\) elements corresponds either to an enumerated \(K\)-element subset when \(K \le N-K\), or to an enumerated complement of size \(N-K\) when \(K > N-K\). The complement XOR transformation is exact because XOR over all elements is the XOR of chosen and complement parts. Therefore the maximum over all enumerated candidates is the true answer.
- **Complexity:** Let \(r = \min(K, N-K)\). Time is \(O(N + \binom{N}{r} \cdot r)\), and memory is \(O(N)\) for the input array.
