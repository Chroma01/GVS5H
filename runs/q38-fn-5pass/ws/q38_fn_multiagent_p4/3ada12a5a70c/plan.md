The key observation is that because `k >= 4`, the optimal minimum Manhattan distance never exceeds `side`. For any threshold `d <= side`, two boundary points have Manhattan distance `< d` if and only if their shorter distance along the square perimeter is `< d`, so the decision problem becomes selecting `k` points on a circle with pairwise circular distance at least `d`. We can binary search the answer over integer distances in `[0, side]`. For a fixed `d`, sort points by perimeter coordinate, duplicate the sorted array, and greedily test each possible starting point by repeatedly choosing the earliest point at least `d` ahead, requiring the `k`-th chosen point to lie within one full circumference minus `d`. This gives an efficient binary-search + greedy circular-packing solution.
