- **Problem reduction:** A shortest palindrome having `S` as a prefix is obtained by appending the minimum number of characters to the end of `S`. If the longest palindromic suffix of `S` has length `L`, the answer is `S + reverse(S[:n-L])`.
- **Correct KMP orientation:** The longest palindromic suffix of `S` is the longest prefix of `reverse(S)` that matches a suffix of `S`. Therefore the correct prefix-function construction is `reverse(S) + separator + S`, or equivalently compute the prefix function for `reverse(S)` and run KMP over `S`.
- **Important correction:** Using `S + separator + reverse(S)` gives the longest palindromic prefix, not suffix. For example, `S = ABACX` would incorrectly report length `3` with that orientation, while the true longest palindromic suffix has length `1`.
- **Implementation details:** The code computes the prefix function for `r = reverse(s)`, then maintains the KMP matched length while scanning `s`. The final matched length is exactly the longest prefix of `r` that is a suffix of `s`, i.e. the longest palindromic suffix length.
- **Memory optimization:** Instead of building `reverse(S) + '#' + S` and storing a prefix array of length `2n+1`, the code stores only the prefix function of `reverse(S)`, length `n`. This is still O(n) memory and avoids the extra constant factor.
- **Complexity:** Time complexity is O(n), and memory complexity is O(n), suitable for `n <= 500000`.
- **Edge cases:** `n = 1` returns the original string. If the whole string is already a palindrome, `longest_pal_suffix = n` and nothing is appended. Every non-empty string has at least a length-1 palindromic suffix, so the final KMP state is at least `1` for valid input.
- **I/O:** The implementation uses bytes for faster indexing and output. Input consists only of uppercase English letters, so stripping whitespace/newline is safe.
