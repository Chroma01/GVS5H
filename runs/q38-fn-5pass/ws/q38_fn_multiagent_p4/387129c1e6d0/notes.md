- **Approach:** Use per-line difference arrays. Horizontal moves only matter for houses with the same `y`, vertical moves only for houses with the same `x`. Each move becomes an inclusive interval on one sorted coordinate list. Range additions and prefix sums determine which houses on that line are covered by at least one segment.
- **Data structures:** `h_lines` maps `y` to `(xs, ids)` where `xs` are sorted house x-coordinates on that horizontal line and `ids` are corresponding house indices. `v_lines` maps `x` to `(ys, ids)` analogously. `h_updates` and `v_updates` store pending `(l, r)` index intervals per line. `covered` is a `bytearray` for distinct house marking.
- **Build phase:** Read all houses, append `(coordinate, id)` to the appropriate horizontal and vertical line lists, sort each list, then split into coordinate list and id list. No per-house index in both orientations is needed for this difference-array method.
- **Move processing:** Maintain current `(curx, cury)`. For each move, normalize the segment endpoints to `[lo, hi]`. Query the relevant line dictionary. Use `bisect_left(xs, lo)` and `bisect_right(xs, hi) - 1` to get the inclusive index range of houses on that line. Add the update only if the range is nonempty and the line exists. Update the current coordinate after querying the old line.
- **Counting phase:** For each line with updates, allocate a difference array of length `len(coords) + 1`, apply all range additions, then prefix-sum. If the prefix count is positive, mark the corresponding house id in `covered`. Process horizontal and vertical updates separately; `covered` prevents double counting a house hit by both orientations. The answer count is `sum(covered)`.
- **Complexity:** Sorting all line lists costs `O(N log N)`. Each move does two binary searches, costing `O(M log N)`. Difference-array processing touches each house at most once per orientation, so `O(N)` plus the number of updated lines. Memory is `O(N + M)` for line data and pending updates.
- **Pitfalls handled:** Segment endpoints are inclusive, so `bisect_left`/`bisect_right` are used carefully. Negative coordinates and large coordinates are fine with Python integers. Final coordinates can exceed 32-bit range. Houses may be hit by multiple horizontal segments, multiple vertical segments, or both; difference arrays and the global `covered` bytearray handle all cases. Lines with no houses are skipped. Consecutive moves share endpoints, and inclusive intervals count them correctly.
- **Implementation choices:** Use `sys.stdin.buffer.readline` to avoid storing the whole input token list. Store updates until after all moves because a line's difference array needs all its intervals before prefixing. Direction tokens are compared as bytes.
