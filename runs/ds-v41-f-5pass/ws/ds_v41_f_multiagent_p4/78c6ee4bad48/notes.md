- **Model:** Let sorted positions be x_1<...<x_N and gaps d_j = x_{j+1}-x_j (j=1..N-1). Work in gaps, not coordinates.
- **Operation action:** Using pieces i,i+1,i+2,i+3 (i=1..N-3), with M=(x_i+x_{i+3})/2, the two middle pieces reflect and swap order. Resulting sorted order is x_i, x_{i+2}', x_{i+1}', x_{i+3}, whose three internal gaps are exactly (d_{i+2}, d_{i+1}, d_i). So the operation swaps gaps d_i and d_{i+2}; the middle gap is untouched.
- **Reachability:** The allowed move is "swap two gaps whose indices differ by 2", i.e. an adjacent transposition inside the odd-index class {1,3,5,...} or the even-index class {2,4,...}. Adjacent transpositions generate the full symmetric group, so every permutation of the odd gaps and every permutation of the even gaps is achievable. Reason: after reflection the moved pieces stay strictly between x_i and x_{i+3}, so ordering vs. outside pieces is preserved; gaps stay positive hence positions stay distinct.
- **Objective:** x_1 is fixed forever (position 1 is never i+1 or i+2 since i>=1). Sum = N*x_1 + sum_{j=1}^{N-1} (N-j)*d_j. Coefficient of gap j is w_j = N-j, decreasing in j.
- **Reduction:** Classes are independent. For each parity class minimize sum of (gap * fixed multiset of weights) over permutations, i.e. pair largest gap with smallest weight (rearrangement inequality). Sort each class's gaps descending, its weights ascending, dot-product them.
- **Indexing:** Use 1-based j=k+1 for the k-th gap (k=0..N-2). Odd j -> odd class with weights N-1, N-3, ...; even j -> even class with weights N-2, N-4, .... Watch the 0- vs 1-based off-by-one: j odd <=> k even.
- **Answer:** N*x[0] + (min dot of odd class) + (min dot of even class). Complexity O(N log N). No simulation of swaps needed.
- **Samples verified:** N=4, X=[1,5,7,10]: odd gaps {4,3} weights {3,1} -> 4*1+3*3=13; even gap 2 weight 2 -> 4; total 4*1+17=21. N=6, X=[0,1,6,10,14,16]: odd gaps {4,2,1} vs weights {5,3,1} -> 4+6+5=15; even gaps {5,4} vs weights {4,2} -> 10+16=26; total 6*0+41=41.
- **Edge cases:** N=4 (single odd class of size 2, even class of size 1) works; already-sorted so no operation needed still yields correct sum; large coordinates up to 1e12 and N up to 2e5 give sums fitting in Python int (no overflow concerns); strict increase guarantees positive gaps so no division/distinctness issues.
- **Pitfalls:** pairing bigger weight with bigger gap (wrong direction), mixing parities, assuming x_N formula is needed (it is implied by the gap weights).
