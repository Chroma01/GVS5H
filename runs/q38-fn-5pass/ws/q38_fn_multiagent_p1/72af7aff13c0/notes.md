- Approach: maintain prefix and suffix path-product DP on anti-diagonals. A point update at cell v changes the total answer by (new-old)*pref_excl(v)*suff_excl(v). Excluded values are sums of included values of predecessors/successors, so zero weights are safe and no division is used.
- Frontier invariant: after each query, prefix DP is correct for diagonals up to the cursor diagonal, and suffix DP is correct from the cursor diagonal onward. Moving to a larger diagonal only requires recomputing prefix for the new diagonal; moving to a smaller diagonal only requires recomputing suffix for the new diagonal.
- Transpose: if original H<W, transpose the grid and map directions L->U, R->D, U->L, D->R. This makes W<=H, so the padded stride is small and diagonal indices are cache-friendly. Diagonal length is at most min(H,W)<=447 under HW<=200000.
- Arrays: padded 1-based flat arrays are used. Border pref(1,0)=1 and suff(H+1,W)=1 provide start/end excluded values without special cases. Diagonal indices are arithmetic progressions and are precomputed as lists.
- Query order: move cursor, optionally apply the immediate-backtrack shortcut, compute excluded values, update answer, set A, then either full-recompute the entered diagonal or use the shortcut, update the other side of the current cell, and store the current cell's own pref/suff deltas.
- Immediate-backtrack shortcut: if the current move is exactly opposite the previous move, the entered diagonal was correct before the previous update. For an increasing move, add the previous cell's pref delta times A to its valid successors on the entered diagonal; for a decreasing move, add the previous cell's suff delta times A to its valid predecessors. Then skip the full diagonal recompute. Store only deltas caused by the current A change, not changes caused by applying an older delta.
- Correctness details: cells on the same anti-diagonal do not depend on each other, so setting A before recomputing the entered diagonal is safe. Excluded values do not depend on the updated cell's own value. If old value equals new value, the answer is unchanged, but the frontier may still need recompute unless the shortcut proves it is already correct.
- Performance: initial DP is O(HW). Each full diagonal recompute is O(diagonal length). Worst-case is O(HW + Q*min(H,W)), about 9e7 cell updates. The shortcut removes repeated long recomputes for back-and-forth moves. The implementation uses local variables, precomputed diagonal lists, conditional subtraction for sums, and recomputes after setting the new value to avoid one extra modulo per query.
- Edge cases: start and end use border bases; first/last row/column borders are zero; negative modulo differences are normalized by adding MOD; the printed answer is kept modulo 998244353.
