- **Problem:** N contests, each adds 1 to rating iff rating in [L_i,R_i]. Answer Q queries for initial rating X. N<=2e5, Q<=3e5, values<=5e5, final rating<=5e5+N.
- **Chosen approach (backward, order-statistics on a multiset):** Define G_i(r)=final rating of contests i..N starting from r. G_{N+1}(r)=r. G_i(r)=G_{i+1}(r+1) if L_i<=r<=R_i else G_{i+1}(r). Since each f is nondecreasing, every G_i is nondecreasing, so the sorted list of its values is the function itself.
- **Sequence transform:** Let S be values of G_{i+1} indexed by position r. Building T=G_i: uses S[1..L-1], S[L+1..R+1], S[R+1..]. So S[L] is dropped and S[R+1] is duplicated. Equivalently: delete the L-th smallest, then duplicate the element that was at original position R+1 (now at position R after deletion). Multiset view: remove one copy of kth(L), add one copy of kth(R+1) computed BEFORE the removal (R+1 > L always). This avoids the "after deletion" off-by-one.
- **Fenwick details:** Start multiset = {1,2,...,M} with count 1 each; tree[i]=i&-i directly. add(i,delta) and kth(k) via binary lifting with top=highest power of two <= M.
- **Bound M:** Need M >= (maxR+1) so kth(R+1) is valid, and M >= (maxX+N) so final answers fit. Using M = max(maxR,maxX)+N+5 is safely above both. Verified on sample 3 (e.g. query 8580<min L stays unchanged).
- **Answers:** After all contests the multiset sorted IS G_1(1),G_1(2),...; answer for X is the X-th smallest. Reconstructed the array in O(M) via the count array (cheaper than Q kth calls) then O(1) lookup.
- **Off-by-one (critical):** use kth(R+1) on the pre-deletion multiset; deleting at L (< R+1) shifts original position R+1 down to R, so its value is exactly what gets duplicated.
- **Verification:** Sample 1 yields 6,6,8. Sample 2 endpoints reasoned (8,2002,2003,2402,500001,2800,1007). Forward simulation of sample 3 queries 287940->287946 and 390310->390315 both confirmed by hand, matching backward transform expectation.
- **Complexity:** O((N+Q) log M) time, O(M+Q) memory. N kth-queries + N adds; M~7e5.
