- **Core observation:** The mochi sizes are already sorted. For any fixed number of pairs K, the most favorable choice is to reserve the K smallest mochi as possible tops and the K largest mochi as possible bottoms. Since K <= N//2, these two groups are disjoint.
- **Fixed-K feasibility:** If K pairs are possible, then after sorting the chosen tops and bottoms, pairing the i-th smallest top with the i-th smallest bottom is valid whenever any matching is valid. Replacing chosen tops by the K smallest mochi only makes tops smaller, and replacing chosen bottoms by the K largest mochi only makes bottoms larger, so feasibility is preserved.
- **Check condition:** For K pairs, the i-th top is A[i] and the i-th bottom is A[N-K+i]. The condition is `2 * A[i] <= A[N-K+i]`, implemented as `A[i] + A[i] <= A[N-K+i]` to avoid multiplication overhead and floating point issues.
- **Monotonicity:** If K pairs are feasible, then any smaller number of pairs is also feasible by simply discarding some pairs. This makes binary search over K valid.
- **Binary search range:** The answer is between 0 and N//2 inclusive. Use an exclusive upper bound `N//2 + 1` and maintain `lo` as the largest known feasible value.
- **Implementation details:** Read all integers from stdin, ignore any trailing values beyond N sizes, and use a local reference to the array inside the feasibility function for speed. The feasibility check returns early on the first invalid pair.
- **Complexity:** Binary search performs O(log N) feasibility checks. Each check scans at most K elements, giving O(N log N) worst-case time and O(N) memory, easily sufficient for N up to 5e5.
- **Edge cases:** K=0 is always feasible. Duplicate sizes are handled naturally by the sorted pairing and the integer inequality. If no pair can be made, the binary search leaves `lo` at 0.
