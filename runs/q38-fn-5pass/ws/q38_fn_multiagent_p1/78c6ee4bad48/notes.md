- **Gap operation:** For four consecutive sorted coordinates a < b < c < d, reflecting b and c about M = (a + d) / 2 gives new sorted coordinates a, a + d - c, a + d - b, d. Therefore the three gaps (b - a, c - b, d - c) become (d - c, c - b, b - a). The operation swaps gap i and gap i + 2 while leaving gap i + 1 unchanged.
- **Reachability:** Swapping gap i with gap i + 2 is exactly an adjacent swap inside the subsequence of gaps whose 1-indexed positions have the same parity. Every adjacent pair in the odd-position gap subsequence and every adjacent pair in the even-position gap subsequence can be swapped, so any permutation of odd-indexed gaps and any permutation of even-indexed gaps is reachable. A gap can never move to a position of the opposite parity.
- **Objective function:** The leftmost coordinate is invariant. If g_j is the gap between the j-th and (j+1)-th pieces, then the sum of all coordinates is N * x_1 + sum_{j=1}^{N-1} (N - j) * g_j. The weight N - j strictly decreases as j increases.
- **Optimization:** Within each parity class, the weights are decreasing with position. By the rearrangement inequality, the minimum weighted sum is obtained by assigning smaller gaps to earlier positions and larger gaps to later positions, i.e. sorting each parity class in ascending order and placing them back into their original parity positions.
- **Implementation:** Read all integers, compute consecutive gaps, split them by 1-indexed parity using slicing gaps[0::2] and gaps[1::2], sort each list ascending, then iterate over gap positions 1 through N-1, taking the next sorted gap from the corresponding parity list and adding (N - j) * gap to N * x_1.
- **Complexity:** Sorting dominates, giving O(N log N) time and O(N) memory, which is sufficient for N up to 2e5.
- **Edge cases:** N = 4 works directly. Python integers handle the large coordinate and sum bounds. Input may be split across lines, so reading all tokens is safe. Equal gaps are harmless.
