- **Validation:** The two provided examples pass. Random small cases were checked against `_brute_feasible`, which BFSs over `(position, capped visit counts)` up to `m` moves; no mismatches were found, so the current feasibility formula is kept.
- **Target feasibility:** For `x > 0`, index `i` needs `c_i = ceil(x / points[i])` visits. If `m < n`, some index remains unvisited and the answer is `0`. For `m >= n`, `x = min(points)` is always feasible by moving right once through the array.
- **Fixed final index E:** Any walk ending at `E` has edge traversal parity `1` on edges before `E` and `0` on edges from `E` onward. The cheapest skeleton is `-1 -> n-1 -> E`, using `2n - 1 - E` moves. Its visits are `1` for `i < E`, `2` for `E <= i < n-1`, and `1` for `n-1`.
- **Residual extra moves:** Let `d_i = max(0, c_i - skeleton_visits_i)`. Extra closed detours are back-and-forth pairs on edges. If `h_i` is the number of pairs on edge `i`, each pair costs `2` moves and adds one visit to both endpoints, so we need `min sum h_i` subject to `h_{i-1} + h_i >= d_i`. By total unimodularity / LP duality, this minimum equals the maximum-weight independent set on the path with weights `d_i`.
- **All E in O(n):** Define `a_i = c_i - 1` and `b_i = max(0, c_i - 2)` for `i < n-1`, with `b_{n-1} = c_{n-1} - 1`. For final `E`, residual weights are `a[0:E] + b[E:n]`. Suffix MWIS states over `b` are precomputed; prefix MWIS states over `a` are swept. At cut `E`, combine prefix and suffix while forbidding selecting both `E-1` and `E`.
- **Capping:** All weights and DP values are capped at `m + 1`. If the true MWIS exceeds this cap, then `base + 2 * cap > m`, so the capped value cannot create a false feasible result.
- **Search bounds:** The total score is at most `max(points) * m`, so the minimum score is at most `floor(max(points) * m / n)`. Binary search uses `lo = min(points)` and this `hi`; feasibility is monotone.
- **Complexity:** Each feasibility check is `O(n)`, and the binary search is `O(log(max(points) * m / n))`, giving `O(n log(max(points) * m / n))` time and `O(n)` memory.
- **Brute validator:** `_brute_feasible` is development-only and not called by `maxScore`.
