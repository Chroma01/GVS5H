- **Core sweep:** Sweep the right cut end `J` (0-indexed middle end) from `1` to `N-2`. Maintain for every active left cut `I < J` the value `distinct(A[0..I]) + distinct(A[I+1..J])`. The answer for this `J` is the maximum active value plus `R[J+1]`, where `R[x]` is suffix distinct count from `x`.
- **Update rule:** When moving to `J`, the new left cut `I=J-1` has middle length one, so its value is `prefix_distinct[J-1] + 1`. For old active `I`, adding `A[J]` increases middle distinct count by one iff the previous occurrence `p` of `A[J]` satisfies `p <= I`. Thus add `1` to old active range `[p, J-1)` (exclusive), with `p=0` if there is no previous occurrence.
- **Segment tree design:** Use an iterative lazy segment tree over possible left cuts `0..N-3` (`M=N-2`). It supports range add `+1` and global maximum. Inactive leaves start as a large negative sentinel. Each iteration activates exactly one new leaf by direct assignment, then range-adds the old active suffix. The query is simply `d[1]`.
- **Activation invariant:** All previous range additions ended at or before the new leaf index, so no lazy tag can be stored on a segment-tree node whose segment contains the new leaf. Therefore direct leaf assignment without pushing is safe. After assignment, ancestors are updated; the climb can stop early if a node's maximum did not change.
- **Off-by-one details:** Valid 0-index cuts are `0 <= I < J <= N-2`. Store `Lval[i] = distinct(A[0..i]) + 1` only for `i <= N-3`. Store `prev[j] = max(previous occurrence, 0)` only for `j <= N-2`. Add suffix `R[J+1]`, which is valid because `J <= N-2`.
- **Lazy tree style:** The tree maintains `d[node] = max(children) + lazy[node]`. Pushing propagates lazy to children and leaves `d[node]` unchanged. Range add pushes boundary paths, applies to covered nodes, then recomputes boundary ancestors. Alignment checks use precomputed bit masks.
- **Complexity:** Time `O(N log N)`, memory `O(N)`. For `N=3e5`, tree size is the next power of two above `N-2`, about `524288`.
- **Edge cases:** `N=3` gives `M=1`, `size=1`, `log=0`; the loop runs once and no range add is needed. Consecutive duplicates have `p=J-1`, so the old active update range is empty and only the newly activated leaf gets the `+1`.
- **Alternatives considered:** A prefix-initialized tree with prefix maximum queries avoids the activation invariant but costs an extra prefix query per step. Symmetric left-to-right sweeps, Monge/D&C with interval distinct queries, rectangle-addition reformulations, and sqrt decomposition were considered, but the activation-based lazy segment tree is the most direct and efficient Python implementation.
- **Pitfalls:** Do not apply updates to future inactive leaves; doing so would corrupt later activations unless carefully compensated. Ensure the middle subarray is non-empty by activating `I=J-1` before querying and excluding it from the old range update. Ensure the third subarray is non-empty by stopping at `J=N-2`.
