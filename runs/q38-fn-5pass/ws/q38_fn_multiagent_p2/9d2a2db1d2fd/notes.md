- **Core reduction:** For any block path, let `B` be the maximum possible minimum building height along the path. The minimum stair count is `max(abs(Y-Z), Y+Z-2*B)`. If `B >= min(Y,Z)`, stay at floor `min(Y,Z)` across the path; otherwise descend to `B` and ascend again.
- **Bottleneck graph:** Treat blocks as vertices with height `F[i][j]`. For adjacent blocks use edge weight `min(F[u], F[v])`. For distinct blocks, the desired `B` is the maximum bottleneck path value, equal to the minimum edge weight on a maximum spanning tree path.
- **Kruskal reconstruction tree:** Sort edges descending. DSU merges components; each merge creates a new node with weight equal to the current edge weight and children equal to the two component roots. The LCA weight of two original leaves is the bottleneck `B`. Leaf weights are original `F`, handling same-block queries.
- **Edge packing:** Pack each edge as `(w << 40) | (u << 20) | v`. This keeps sorting memory and time low because `N < 2^20` and `F <= 10^6 < 2^20`.
- **KRT construction details:** DSU is over original cells only. `root_node[dsu_root]` stores the current reconstruction-tree root for that component. Union by size is used. Stop once `N-1` merges are done (`next_id == max_nodes`).
- **LCA method:** Binary lifting was replaced by Heavy-Light Decomposition to avoid a large parent table. KRT parent ids are always larger than child ids, so subtree sizes and heavy children are computed by one increasing scan over nodes.
- **HLD preprocessing:** Iteratively traverse from the root following heavy children, assigning `depth` and `head`. Light children are pushed as new chain heads. This is O(N) and uses only `parent`, `depth`, `head`, plus temporary `size` and `heavy`.
- **HLD query:** Climb chain heads. If head depths are equal, move both nodes up; otherwise move the deeper head. Once heads match, the shallower node is the LCA. Query time is O(log N) because every light edge at least halves subtree size.
- **Memory choices:** `weight`, `lc`, `rc` use compact arrays. `parent`, `depth`, `head` use lists for faster query access. Large temporary structures (`edges`, DSU arrays, `lc`, `rc`, `size`, `heavy`) are deleted before answering queries.
- **Input/output:** Grid is read line by line. `Q` is read before preprocessing, then queries are read after preprocessing. This avoids storing all queries. Answers are accumulated and joined once.
- **Edge cases:** `H=W=1`, same-block queries, `H=1` or `W=1`, equal edge weights, and stopping Kruskal early when the grid becomes connected are all handled.
