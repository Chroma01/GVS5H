- **Depth model:** For positive integer `x`, the required number of selections is the smallest `k` such that `floor(x / 4^k) = 0`. This depth is constant on blocks `[4^(k-1), 4^k - 1]`: depth 1 for `[1,3]`, depth 2 for `[4,15]`, depth 3 for `[16,63]`, etc.
- **Prefix sum:** `F(n) = sum_{x=1}^n depth(x)` is computed by summing full base-4 blocks and one partial final block. For `n <= 10^9`, there are fewer than 16 blocks, so each query is very fast.
- **Pairing argument:** Each operation can reduce total remaining depth by at most 2, giving a lower bound of `ceil(total_depth / 2)`. For arbitrary depth multisets, the true optimum is `max(ceil(total_depth / 2), max_depth)`. The solution uses only `ceil(total_depth / 2)`, which is valid for this problem because every query range has at least two elements and is contiguous.
- **Why max_depth never dominates:** If a range contains at least two elements of maximum depth `D`, then total depth is at least `2D`, so `ceil(total/2) >= D`. If it contains exactly one maximum-depth element, the only possible length-at-least-two contiguous range is `[4^(D-1)-1, 4^(D-1)]`, whose total depth is `(D-1) + D = 2D - 1`, again giving `ceil(total/2) = D`.
