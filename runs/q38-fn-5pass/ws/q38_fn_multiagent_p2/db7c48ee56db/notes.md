- **Core idea:** The constraint \(\binom{N}{K}\le 10^6\) makes exhaustive enumeration feasible. Enumerate the smaller side: if \(K\le N-K\), enumerate the \(K\) chosen elements and XOR them directly; otherwise enumerate the \(N-K\) excluded elements and use the identity chosen_xor = total_xor XOR excluded_xor.
- **Enumeration bound:** Let \(r=\min(K,N-K)\). Then \(\binom{N}{r}=\binom{N}{K}\le 10^6\) and \(r\le N/2\). The largest possible \(r\) is 11 because \(\binom{22}{11}=705432\) while \(\binom{24}{12}>10^6\). Thus the total number of combinations and partial prefixes is small enough for Python.
- **Implementation:** Compute the total XOR first. Handle \(r=0\) directly. For \(r=1\) and \(r=2\), use direct loops to avoid tuple or recursion overhead. For \(r\ge 3\), use a recursive DFS that carries the current XOR of the already selected side. The DFS inlines the final 3 or 4 choices as nested loops, reducing function-call overhead while still computing XOR incrementally.
- **Correctness details:** The complement identity is valid because the XOR of all elements equals the XOR of the chosen part XOR the excluded part. Duplicate values in \(A\) are harmless because enumeration is by positions/indices, not by unique values.
- **Edge cases:** \(K=N\) returns the XOR of all elements. \(K=1\) returns \(\max(A)\). \(K=N-1\) returns \(\max(total\_xor \oplus a)\). If all values are zero, the answer is zero. \(N=1\) is handled by the \(K=N\) case.
- **Complexity:** \(O(N + \binom{N}{r}\cdot r)\) time in the worst case, which is only a few million operations under the given constraint, and \(O(N)\) memory.
