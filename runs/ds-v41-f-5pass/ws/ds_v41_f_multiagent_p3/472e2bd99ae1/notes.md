- **Problem:** k-th largest of f(i,j,k)=A_i B_j + B_j C_k + C_k A_i over all N^3 triples; N<=2e5, K<=min(N^3,5e5).
- **Monotone structure:** sort A,B,C descending. Then f is nonincreasing in each index (coefficients B_j+C_k, A_i+C_k, A_i+B_j are all positive). So the implicit 3D array is a monotone nonincreasing grid.
- **Correct algorithm (comb max-heap):** start heap with root (i,j,k)=(0,0,0). Pop the maximum K times. From a popped node push children by the rule: always (i+1,j,k); push (i,j+1,k) only if i==0; push (i,j,k+1) only if i==0 and j==0. Each cell is generated exactly once (unique predecessor: i>0 from (i-1,j,k); i==0,j>0 from (0,j-1,k); i==j==0,k>0 from (0,0,k-1)) and every cell is reachable (reduce i to 0 via the always-edge, then j to 0 via i==0 edge, then k to 0). Best-first on this monotone forest yields the globally sorted order; tie values are irrelevant because the K-th popped value equals the K-th largest value. Answer = value of K-th pop.
- **Incremental values:** f(i+1,j,k)-f(i,j,k)=da[i]*(B_j+C_k) with da[i]=A[i+1]-A[i] (<=0); similarly db,dc for j,k. Compute each child as parent + diff*(sum of the other two), avoiding full re-evaluation.
- **Bug fixed (k-increment):** in the i==0,j==0 branch the child (0,0,k+1) fires for every k, so the difference must use dc[k] (not dc[0]): v + dc[k]*(a0+b0). Other pushes were already correct: i==0 implies A_i=a0, and j==0 in that branch implies B_j=b0; the i>0 branch correctly uses da[i]*(B[j]+C[k]). Samples 1 and 2 masked this: n=2 has only one k-step (dc[0]) and sample 2 has all dc=0.
- **Index packing:** n<2^18, so pack p=(i<<36)|(j<<18)|k; child deltas D3=1<<36, D2=1<<18, D1=1; decode via shifts/mask. Keeps heap entries as 2-tuples (-v, p), making tie-breaking comparisons cheap (single int compare).
- **Complexity:** O(K log K). Pushes per pop: 3 when i==j==0, 2 when i==0<j, 1 when i>0; heap size stays ~O(K). Sum of values fits in a Python int (<=3e18).
- **Disproven approach:** truncating each array to its top a=ceil(K/N^2), b, c elements and brute-forcing a*b*c is WRONG. With ties (e.g. all elements equal, sample 2) any index can appear in the top K; also a small element of one array can still outrank many triples of top elements of the others. Only the full monotone enumeration is safe.
- **Edge cases:** n=1 works (only root, bounds checks fail so no pushes). K>=1 and K<=n^3 guaranteed so heap never empties early. Sample1 -> 31 (verified step-by-step by hand), sample2 -> 30000 (all-equal), sample3 -> 689589940713840351.
