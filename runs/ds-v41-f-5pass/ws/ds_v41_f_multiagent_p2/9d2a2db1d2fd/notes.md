- **Model:** Each cell is a vertex of capacity F; adjacent cells share an edge of weight min(F_u,F_v). For a fixed height h, cells with F>=h are connected exactly as in the induced subgraph, so u and v can be traversed horizontally at height h iff h <= M(u,v), where M is the maximum bottleneck over cell paths.
- **Cost formula:** answer = |Y-Z| + 2*max(0, min(Y,Z) - M). Derivation: cross at height h costing |Y-h|+|Z-h|; if M >= min(Y,Z) pick h=min(Y,Z) giving |Y-Z|, otherwise h=M (must be >=1) giving Y+Z-2M. Same-cell is the special case M=F_u, which makes min(Y,Z)-M <= 0.
- **Computing M:** Process cells in descending F (this equals Kruskal on edges sorted by min(F_u,F_v), so the merge threshold is the maximum bottleneck). Union each cell with already-active neighbours; every successful merge happens at threshold F[c] and connects all pairs across the two components with that M.
- **Offline DSU with query sets:** Attach each distinct-endpoint query to both endpoint cells. Give each component a set of query ids pending in it. On merge of small into big (union by component size), the common ids s & l are exactly the queries whose endpoints now connect -> set their M to fc, then union the sets. Union by size makes each query copy be iterated O(log N) times.
- **Key implementation detail:** use `common = s & l` (C-level) so the Python-level loop only runs once per eventually-answered query (total Q), and use `l |= s` (in-place) so the big root keeps the merged set. Using `l = l | s` would be an aliasing bug.
- **Tie handling:** equal F values are fine; whether a cell merges as the earlier or later endpoint, the threshold min(F_u,F_v) is identical. Stable sort order does not matter.
- **Edge cases:** H=W=1 (only same-cell queries); 1-row/1-column grids (boundary checks); all queries get answered because the grid is 4-connected; M >= 1 always so the descent height is valid.
- **Complexity:** O(N log N + (N+Q) alpha + Q * C) where the set intersections/unions are C-level; memory ~ (N + Q) with up to ~N small sets.
