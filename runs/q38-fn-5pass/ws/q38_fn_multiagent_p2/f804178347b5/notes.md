- **State:** Each node keeps its original output bit and the minimum flips needed to force the opposite bit. Leaves start with the input bit and opposite cost 1.
- **Combination:** For a triple, the parent current bit is the majority of the three child current bits. Let target be the opposite of that parent bit. For each child, the cost to make it output target is 0 if its current bit is already target, otherwise its stored opposite cost. The parent opposite cost is the sum of the two smallest of these three costs, because at least two children must output target and the third can be left unchanged. This is equivalent to enumerating the eight child-flip subsets.
- **Bottom-up in place:** Use a bytearray for current bits and a list for opposite costs. Repeatedly combine adjacent triples, writing parent states to the front of the arrays, until one root remains. The answer is the root opposite cost, not the minimum of two independent root costs.
- **Input parsing:** Read all bytes, parse N manually, then delete all bytes <= 32 from the remainder. This supports both a contiguous binary string and digits separated by spaces or newlines.
- **Complexity:** Time O(3^N), with about (3^N - 1) / 2 triples processed. Memory O(3^N). For N = 13 the length is about 1.6 million, which is safe in Python.
- **Cost bounds:** The opposite cost at height h is at most 2^h, so for N = 13 it is at most 8192. Most values are small cached Python ints, so a list of costs is memory-efficient enough; an array of unsigned short would also work.
- **Pitfalls:** Do not store or use a positive cost to preserve a child's current output, since leaving it unchanged is always optimal. The third child in the majority condition does not need to be forced away from target. Ensure the root current bit is computed from original bits while costs are updated simultaneously.
