- **Approach:** Greedy lexicographic unranking. Build the permutation position by position. At each position, scan unused numbers from 1 to n in increasing order, count how many valid completions each compatible candidate allows, and subtract those block sizes from k until the target block is found.
- **Counting completions:** After choosing a candidate with parity p, let odd_rem and even_rem be the remaining counts. The suffix must start with parity 1-p. If suffix length is L, the starting parity appears ceil(L/2) times and the other parity appears floor(L/2) times. If the remaining counts match this requirement, the number of completions is odd_rem! * even_rem!, because remaining odd numbers can be permuted independently among odd slots and even numbers among even slots. Otherwise the count is 0.
- **Capping:** Use limit = initial k + 1. During unranking, current k never exceeds the initial k, so any count capped at limit is certainly large enough to contain the target. Factorials, products, and totals are capped at limit. This avoids huge arithmetic while preserving all comparisons needed for k up to 10^15.
- **Total check:** Compute the total by summing completions for every possible first value, not by assuming all odd-start permutations come before even-start permutations. This naturally handles both n odd and n even and respects lexicographic interleaving of first values. If capped total is less than k, return an empty list.
- **State maintenance:** Maintain used array, remaining odd count, remaining even count, and previous parity. Parity convention is 1 for odd and 0 for even. The initial previous parity is -1, allowing either parity at the first position.
- **Complexity:** O(n^2) time because each of n positions scans up to n candidates, and each count is O(1). O(n) extra memory. This is easily fast enough for n <= 100.
- **Pitfalls handled:** k is 1-indexed; feasibility of remaining parity counts must be checked before multiplying factorials; first-position candidates interleave by numeric value; capped counts must remain strictly greater than any possible current k; final position count is 1; added a guard for non-positive k for robustness.
- **Sample validation:** Manual execution passed the provided examples: n=4,k=6 returns [3,4,1,2]; n=3,k=2 returns [3,2,1]; n=2,k=3 returns [].
- **Edge validation:** n=1,k=1 returns [1]; n=1,k=2 returns []; n=2,k=1 returns [1,2]; n=2,k=2 returns [2,1]; n=2,k=3 returns [].
- **Boundary validation:** n=4,k=1 returns [1,2,3,4]; n=4,k=8 returns [4,3,2,1]; n=5,k=12 returns [5,4,3,2,1]. These match the expected first and last lexicographic alternating permutations.
- **Large validation:** n=100,k=1 returns the increasing sequence [1,2,...,100], which is valid and lexicographically first. n=100,k=10^15 is well within the enormous total count, and capped arithmetic prevents overflow or slow big-integer growth.
- **Verdict:** Sample tests pass.
