- **Problem restated:** answer[i] = max L such that at least k of the words remaining after deleting index i share a length-L prefix. Equivalent to the max depth of a trie node whose post-deletion count is >= k.
- **Key invariant:** deleting word i only reduces counts by 1 along i's root-to-terminal path; every other node count is unchanged. So a depth-L node is valid after deletion iff it is on i's path and original count >= k+1, or it is off-path and original count >= k.
- **Monotonicity:** if a length-L prefix is shared by >= k remaining words, its length-(L-1) parent is too, so validity is monotone in L; binary search per word is correct. L=0 (empty prefix) is the fallback and is always valid once n-1 >= k.
- **Depth-layer data:** for each depth L store cnt_ge[L] = number of trie nodes at depth L with original count >= k. For word i at depth L, let c be the on-path node count (node exists only if L <= len(word i)). Then valid iff c >= k+1, or cnt_ge[L] - (1 if c >= k else 0) >= 1. If L > len(word i) (no on-path node), valid iff cnt_ge[L] >= 1.
- **Implementation:** build trie with per-node count, depth, children dict; store each word's path node ids (total size = sum of lengths); compute cnt_ge in one pass over nodes; binary search the max valid L in [0, maxlen] for each word.
- **Edge cases:** n-1 < k => return all zeros immediately. k=1 collapses to "max remaining word length" and the condition handles it (on-path needs count>=2 since the word itself is removed; off-path needs count>=1). Duplicate words and word-is-prefix-of-another are handled because counts are occurrence counts per node and the on/off split depends only on the deleted word's path. Word shorter than current mid is treated as no on-path node.
- **Complexity:** O(total length) trie build + O(total length) cnt_ge + O(n log maxLen) binary search; memory O(total length). Well within limits (sum lengths <= 1e5).
- **Sample tests:** Example 1 words=["jump","run","run","jump","run"], k=2 gives [3,4,4,3,4] (matches; removing a "run" lets the two "jump"s give length 4, removing a "jump" leaves three "run"s giving length 3). Example 2 words=["dog","racer","car"], k=2 gives [0,0,0] (matches; every prefix has count 1 < k). Verdict: PASS on both samples.
- **Rejected alternatives:** Euler-tour intervals with prefix/suffix maxima and segment-tree range-max updates both work but are heavier and need careful interval/complement handling; rolling-hash grouping risks collisions; sorted LCP-array + deletion-window needs complex merge logic. Depth-layer + binary search is the simplest correct and fast enough.
- **No external modules beyond typing:** plain lists/dicts, no recursion.
