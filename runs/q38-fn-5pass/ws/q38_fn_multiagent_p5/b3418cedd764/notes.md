- **Graph model:** Each index `i` has one outgoing edge to `A_i`, and the condition `x_i <= x_{A_i}` means values are nondecreasing along edges. Every weak component of this functional graph consists of one directed cycle with rooted in-trees feeding into cycle nodes.
- **Cycle equality:** Around any directed cycle, the inequalities force all cycle values to be equal. Therefore each component contribution is a sum over the common cycle value.
- **Tree DP:** For a node `u`, `dp[u][v]` is the number of valid assignments in the tree feeding into `u`, excluding the cycle predecessor, under the condition `x_u = v`. For each child `w`, the child value may be any `t <= v`, so the transition is `dp[u][v] = product_w prefix_sum_w[v]`.
- **Kahn removal:** Indegree counts unprocessed incoming children. Nodes with indegree zero are leaves and are processed bottom-up. When a node is popped, all children have already been folded into its DP. Its DP is converted to prefix sums and multiplied into its parent. Cycle nodes never reach indegree zero because their cycle edge remains.
- **Cycle combination:** After Kahn removal, nodes with positive indegree are exactly cycle nodes. For each cycle, compute `sum_v product_{u in cycle} dp[u][v]`, then multiply all component contributions modulo `998244353`.
- **Implementation details:** The code is 0-indexed. DP arrays are allocated lazily. If a popped node has `dp[u] is None`, it is a leaf, and its prefix contribution is exactly `1,2,...,M`, so a precomputed base array is copied. Otherwise the stored array contains original DP values and is converted to prefix sums in-place. If a parent has no DP array yet, the child's array is reused as the parent's array to avoid extra allocation. Cycle product starts from a copy of the first non-empty cycle-node DP, then multiplies pointwise; if all cycle nodes have no attached trees, the contribution is simply `M`.
- **Pitfalls:** Self-loops are cycles of length one and must not be processed as ordinary tree nodes. The cycle predecessor edge must not be folded into a cycle node's tree DP. Cycle nodes need their original DP values, so only popped non-cycle nodes are converted to prefix sums. Prefix addition uses one subtraction because both operands are kept below the modulus. Iterative processing avoids recursion-depth issues.
- **Complexity:** Time is `O(N*M)` because each edge causes at most one prefix pass and one pointwise multiplication pass, and each cycle node contributes one pointwise pass. Worst-case memory is `O(N*M)` for DP arrays, with lazy allocation and freeing reducing practical usage. Constraints `N, M <= 2025` make this feasible in Python.
