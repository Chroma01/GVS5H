- **Domain reduction:** Only initial ratings that appear in queries can affect the output. We collect unique query values, sort them by scanning `1..max_x` with a `bytearray`, and maintain the current rating only for these values. Let `U` be the number of unique queries. `pos[x]` maps a query value to its index in the sorted unique array.
- **Monotonicity:** For any prefix of contests, the final/current rating as a function of initial rating is nondecreasing. Therefore, on the sorted unique query values, the current values are also nondecreasing. For a contest `[L, R]`, the affected indices form one contiguous interval `[first_ge(L), first_ge(R + 1))`.
- **Preserving monotonicity:** Adding 1 to that interval cannot break nondecreasing order. At the left boundary, the previous value is `< L` and the updated value becomes `>= L + 1`. At the right boundary, the last updated value was `<= R`, so after update it is `<= R + 1`, while the first non-updated value is `> R`, hence at least `R + 1`.
- **No-push lazy segment tree:** The tree stores maxima. For each node, `d[k]` is the maximum in its segment excluding lazy additions from ancestors, while `lazy[k]` is an addition applied to the whole node segment and included in `d[k]` but not propagated to children. The invariant is `d[k] = lazy[k] + max(d[2k], d[2k+1])` for internal nodes.
- **Range add:** A range add applies `+1` directly to the canonical covering nodes by increasing both `d[node]` and `lazy[node]`. Then only ancestors of the two boundaries that are not fully covered are rebuilt. Alignment is checked with precomputed masks: a node at level `i` needs rebuilding iff the corresponding boundary leaf index has nonzero lower `i` bits.
- **First greater-or-equal search:** `first_ge(t)` descends from the root while carrying `acc`, the sum of lazy values of ancestors. For a child, its actual maximum is `d[child] + acc + lazy[current]`. This avoids pushing lazy values during searches.
- **Padding:** Leaves beyond `U` are initialized to `0`. All searched targets are at least `1`, and real values are always at least their initial query value, so padding is never chosen when a real answer exists. `first_ge` still clamps an index to `U` for safety.
- **Initialization:** Leaves are the sorted unique query values themselves, not `1..U`. Internal nodes are built by taking child maxima.
- **Final answers:** After all contests, lazy values are propagated top-down once. Then each leaf contains the actual final rating for its unique query value. Duplicate queries reuse the same leaf through `pos`.
- **Complexity:** Let `U` be the number of unique queries and `size` the next power of two. Time is `O(max_x + U + N log U + size + Q)`, memory is `O(size + max_x + Q)`. In the worst case `U <= 300000`, so `size <= 524288`.
- **Micro-optimizations:** The contest loop skips a search if `maxv < L`, uses `a = 0` when `L == 1`, and sets `b = U` when `maxv <= R`. Functions use default arguments to keep frequently accessed lists and constants local. GC is disabled because no cyclic garbage is created.
- **Edge cases:** `U = 1` gives `size = 1`, where the root is also a leaf; the code handles this because rebuild loops are empty and `first_ge` returns index `0` directly. Full aligned ranges may update the root directly and correctly skip unnecessary rebuilds.
