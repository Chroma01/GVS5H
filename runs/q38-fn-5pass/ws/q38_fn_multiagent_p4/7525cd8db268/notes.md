- **Validation added:** The program now includes a direct brute-force validator and a deterministic PRNG. It checks the two provided examples, targeted edge cases, two large sanity checks, and 300 random small tests with `n <= 6` and `m <= 2n`. Random tests include forced duplicate pairs and reversed input order. All assertions pass when the file is run directly.
- **Targeted cases covered:** duplicate pairs, reversed duplicate pairs, equal smaller endpoints, equal larger endpoints, single pair, many pairs sharing an endpoint, nested constraints, disjoint constraints, and cases where deleting the unique maximum reveals a lower second maximum.
- **Core reduction:** Normalize each conflicting pair to `(a, b)` with `a < b`. For a fixed right endpoint `r`, only pairs with `b <= r` are active. A subarray `[l, r]` is invalid exactly when `l <= M(r)`, where `M(r)` is the maximum `a` among active pairs. Therefore the valid count ending at `r` is `r - M(r)`, and the base total is `sum_{r=1}^n (r - M(r))`.
- **Effect of deleting one pair:** Removing a pair improves the count at right endpoint `r` only if that pair is active, attains the current maximum `M(r)`, and is the unique active pair with that maximum. In that case the new maximum becomes the second-largest distinct active smaller endpoint, so the gain at `r` is `max1 - max2`. If the pair is inactive, not the maximum, or tied for the maximum, its gain at that `r` is zero.
- **Sweep invariant:** Bucket normalized pairs by `b`. Scan `r = 1..n`, insert all pairs with `b == r` before evaluating `r`, then add `r - max1` to the base. Maintain `max1`, `max2`, `cnt1`, and `unique_id`. `max1` is the largest active smaller endpoint, `cnt1` is the number of active pairs attaining it, `unique_id` is valid only when `cnt1 == 1`, and `max2` is the largest active smaller endpoint strictly below `max1`, or zero.
- **Insertion rules:** If `a > max1`, the old maximum becomes `max2`, `a` becomes `max1`, `cnt1 = 1`, and `unique_id = idx`. If `a == max1`, increment `cnt1` and invalidate uniqueness. If `a < max1` and `a > max2`, update `max2 = a`. These rules are order-independent within the same bucket because the whole bucket is inserted before computing gains.
- **Important edge cases:** Duplicate pairs and multiple distinct pairs with the same maximum smaller endpoint must not earn gain; `cnt1` handles this. All pairs with the same `b` must be inserted before evaluating that `r`, otherwise a pair could temporarily appear unique before another same-`b` pair dominates it. If no pair is active, `max1 = max2 = 0`. A single pair yields gain equal to all subarrays containing it, so the answer becomes all subarrays. Python integers safely handle the maximum answer around `n(n+1)/2` for `n = 1e5`.
- **Complexity:** The solution uses `O(n + m)` time and `O(n + m)` memory, where `m = len(conflictingPairs) <= 2n`.
