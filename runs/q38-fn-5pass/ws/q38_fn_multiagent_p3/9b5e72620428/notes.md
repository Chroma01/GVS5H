- **Core reduction:** Choose a common target sum `S`. Every known value must be at most `S`. Known `A` values not paired with known `B` values must be placed against originally unknown `B` positions, and vice versa.
- **Required known-known pairs:** Let `nA`, `nB` be counts of known values. If `k` known-known pairs are made, we need `nA-k <= N-nB` and `nB-k <= N-nA`, so `k >= L = max(0, nA+nB-N)`.
- **Shortcuts:** If `L <= 1`, answer is Yes. For `L == 1`, both sides have known values; pair the global maximum known value with any known value from the other side. Its sum is at least `maxKnown`, and the remaining known counts fit the unknown positions exactly.
- **Fixed S condition:** For a fixed `S >= maxKnown`, the maximum number of disjoint known-known pairs is `sum_x min(cntA[x], cntB[S-x])`. This is exact because each `A` value `x` can only pair with the single `B` value `S-x`.
- **Candidate sums:** If `L > 0`, any feasible `S` must be the sum of some known `A` value and known `B` value. It is enough to enumerate distinct value pairs with sum at least `maxKnown`.
- **Filtering:** Remove `A` values `a` with `a + maxB < maxKnown`, and `B` values `b` with `b + maxA < maxKnown`. Such values cannot appear in any valid known-known pair for `S >= maxKnown`.
- **Quick single-class check:** If there is a value pair with `min(cntA[a], cntB[b]) >= L` and `a+b >= maxKnown`, answer is Yes immediately.
- **Unit-weight optimization:** If after filtering one side has all remaining frequencies equal to 1, every valid distinct value pair contributes weight 1. Also, for `L == 2`, if the quick check failed, no valid pair can have weight 2 or more, so all valid weights are 1. In this case store only sums and count consecutive equal sums after sorting.
- **General accumulation:** For non-unit cases, encode each valid distinct value pair as `(sum << SHIFT) | weight`, where `SHIFT` is large enough for `weight <= N`. Sort the encoded integers, group by high bits (the sum), and add low-bit weights. If any group reaches `L`, answer is Yes.
- **Complexity:** Distinct values are at most `N <= 2000`, so distinct value pairs are at most about `4e6`. The solution is `O(P log P)` time and `O(P)` memory for `P` valid distinct value pairs, which is intended for this constraint.
- **Implementation details:** Sort value lists before generating pairs so each inner loop produces a sorted run; Timsort can exploit these runs. Choose the smaller side as the outer loop. Use encoded integer sorting instead of a large dictionary to keep memory more predictable.
- **Edge cases:** All entries unknown gives `L <= 0` and Yes. Duplicates are handled by frequency minima. Self-complement values (`x = S-x`) are handled by `min(cntA[x], cntB[x])`. Unknown-unknown leftover positions can always be filled with `0` and `S`.
