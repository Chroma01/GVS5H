- **Core formula:** For each of the `n - 1` adjacent transitions, mark whether it is equal or different. Choose exactly `k` equal transitions in `C(n - 1, k)` ways. Choose the first array value in `m` ways. Every non-equal transition has `m - 1` choices, independent of the previous value. Therefore the answer is `C(n - 1, k) * m * (m - 1)^(n - 1 - k) mod 1e9+7`.
- **Why the formula is exact:** A fixed equal/different pattern uniquely determines the number of valid arrays. Equal transitions force the next value to match the previous one; different transitions allow any of the other `m - 1` values. Every valid array corresponds to exactly one pattern with `k` equal transitions, so there is no overcounting.
- **Edge cases:** If `n = 1`, then `k = 0` and the answer is `m`. If `m = 1`, only the all-equal array exists, so the answer is `1` when `k = n - 1`, otherwise `0`. The formula handles this naturally because `pow(0, 0, MOD) = 1` and `pow(0, positive, MOD) = 0`.
- **Modular binomial:** Since `n <= 1e5 < MOD`, factorials up to `n - 1` are invertible modulo `1e9+7`. Compute factorials and inverse factorials once, then evaluate `C(n - 1, k)` in `O(1)` after preprocessing.
- **Caching:** The implementation stores factorial and inverse-factorial tables as class-level caches. Repeated calls reuse previously computed values and extend the tables only when a larger `n` is requested.
- **Complexity:** Amortized `O(max n)` preprocessing across calls, `O(1)` per call after preprocessing, plus `O(log n)` for modular exponentiation. Space is `O(max n)`.
- **Superseded approaches:** Dynamic programming, generating functions, inclusion-exclusion, and transfer matrices are unnecessary here because the closed-form combinatorial count is simpler and optimal for the constraints.
