- **Problem:** Split A at 1 <= i < j <= N-1 into three non-empty contiguous parts; maximize D(1..i)+D(i+1..j)+D(j+1..N).
- **Reduction:** Precompute pref[i]=distinct in A[1..i], suff[i]=distinct in A[i..N], prev[i]=previous occurrence. Answer = max over t=2..N-1 of suff[t+1] + max_{i=1..t-1}(pref[i] + D(i+1..t)).
- **Update rule:** extending the middle right end to t adds +1 to D(i+1..t) exactly for left cuts i in [max(1,prev[t]), t-1] (i must be >= prev[t] so A[t] is new to the middle). So it is a range-add +1 over leaves indexed by i.
- **Data structure:** iterative segment tree over leaf i at position i-1, supporting range add and global max. Because only the root max is ever queried, NO lazy pushdown is needed: node k stores add[k] (subtree tag) and mx[k] = max(mx[2k],mx[2k+1]) + add[k]. Applying +1 to a fully covered node k is add[k]+=1; mx[k]+=1. After the standard range decomposition, recompute ancestors level by level for k = L0>>i and k = (R0-1)>>i, i=1..log. Dropping all push-down code simplified and sped up the hot loop.
- **Activation trick:** at step t, activate left cut i=t-1 (leaf p=t-2) with base pref[t-1] before the range add, by setting mx[p] and recomputing its ancestor path. Ancestors of p have add=0 (no earlier range reached p), so a plain set is valid. The following +1 over [.., t-1] then makes its leaf value pref[t-1]+1 = pref[t-1]+D(A[t..t]). This separate path recompute cannot be skipped: a current covering node can be an ancestor of p, and its direct +=1 would otherwise use a stale value.
- **Query:** at each t the candidate is mx[1] + suff[t+1]; keep the running maximum.
- **Edge cases:** t in 2..N-1 keeps the third part non-empty; i=t-1 keeps the middle non-empty; prev[t]=0 clamps the left bound to 1; consecutive equal values give a single-element range; N=3 has only t=2; answer is always >= 3.
- **Complexity:** O(N log N) time, O(N) memory; everything inlined (no recursion, no function calls in the loop).
- **Verification (stress test):** compared against an O(N^2) brute force that tries every i<j and counts distinct integers with sets, on many small random arrays (N up to ~40, values up to N) plus many hand-built cases; no off-by-one or logic discrepancies were found. Manual traces agree on A=[1,1,1,1], [1,2,1,3], [1,2,2,3], [1,2,3,1], [1,1,1,2,3], [2,1,2,1,3], and both samples (5 and 9). At each t the root equaled the expected max_i(pref[i]+D(i+1..t)).
- **Superseded:** the earlier ACL-style lazy-pushdown version and the difference-array/max-suffix alternative are both unnecessary; the pushdown-free global-max tree is equivalent, simpler, and faster.
- **Micro-optimisation note:** if CPython times out at N=3e5 (about 4*log inner operations per position), run under PyPy or further inline; complexity is already optimal.
