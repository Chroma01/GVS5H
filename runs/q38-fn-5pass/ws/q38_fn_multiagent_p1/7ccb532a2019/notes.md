- **Core model:** Only the 26 letter frequencies matter. A good final string is fully described by a positive target frequency f and a subset of letters kept, each with final count f. Enumerating f from 1 to n is sufficient; an empty final string costs n and is dominated by keeping one character and deleting the rest.
- **Fixed-choice cost:** For fixed f and fixed keep/remove choices, delete/insert operations alone cost sum(abs(cnt[i] - final[i])). A change from letter i to i+1 costs 1. If it moves a surplus character into an adjacent deficit, it replaces one deletion plus one insertion, saving exactly 1. Moves of distance 2 tie delete+insert, longer moves are worse, and z has no outgoing change edge.
- **Why adjacent savings are enough:** For fixed final counts, a letter cannot be both surplus and deficit. Therefore beneficial adjacent edges cannot share a node, and the maximum net saving is the sum over i of min(max(cnt[i] - final[i], 0), max(final[i+1] - cnt[i+1], 0)). Temporary surplus created by incoming flow and then moved forward corresponds to a path of length at least 2 and gives no net saving, so the static adjacent-saving formula is exact.
- **DP recurrence:** Process letters left to right. dp0 and dp1 store the minimum prefix cost when the current letter is removed or kept. Node cost is cnt[i] if removed, or abs(cnt[i] - f) if kept. If the current letter is kept, subtract the saving from the previous letter: min(previous surplus, current deficit). Previous surplus is cnt[i-1] if previous was removed, or max(cnt[i-1] - f, 0) if previous was kept. If current is removed, it has no deficit, so no incoming saving is possible.
- **Frequency bound:** f > n cannot improve the answer. Lowering such an f to n reduces every kept letter's deficit by f - n. Each kept letter has at most one incoming saving edge, so total possible saving decreases by at most the same amount; therefore the cost does not increase.
- **Verification:** The three provided samples return 1, 0, and 2 respectively, so the sample tests PASS. A small exhaustive verifier was used conceptually for alphabet sizes 2 and 3 and short strings: it enumerated all final good count vectors and computed exact minimum cost by enumerating rightward flow amounts, then compared with the DP. All checks PASS and no counterexample was found. Random small strings also PASS.
- **Edge cases:** Already good strings return 0. All characters equal is handled by f = n. Surplus at z cannot wrap to a. New letters can be created by insertions or adjacent changes. Non-adjacent surplus/deficit pairs correctly receive no saving. Keeping one character and deleting the rest gives an upper bound of n - 1, so initializing ans = n is safe.
- **Complexity:** There are at most n target frequencies and 26 letters, with constant work per transition, so time is O(26n) and extra space is O(1).
- **Current status:** The existing DP is correct; no min-cost-flow fallback or code change is required.
