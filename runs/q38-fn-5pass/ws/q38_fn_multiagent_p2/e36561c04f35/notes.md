- **Reformulation:** Any complete strategy determines a deletion order `B`, a permutation of the multiset. The number of deletion operations is the number of monochromatic runs of `B`, and the minimum adjacent swaps needed is the inversion count between the original sequence and `B` (equal values are matched stably). Thus the problem is to minimize `runs(B) + inv(A,B)`.
- **Run compression:** Compress the original sequence into runs. Let `R` be the number of runs. If no swaps are used, the answer is `R`. A profitable swap reduces the number of runs by 2 and costs 1, so it improves the answer by 1. A neutral swap reduces runs by 1 and costs 1, so it does not change the answer but can enable future profitable swaps. Therefore `answer = R - max_profit`, where `max_profit` is the maximum number of profitable swaps achievable using neutral swaps as helpers.
- **Atomic runs and length cap:** In an optimal solution, elements of one initial run are never separated in the final deletion order; separating adjacent equal elements only adds inversions and runs. Hence each initial run is atomic. Only singleton runs can be moved as middle runs of a nonnegative-profit swap. Runs of length at least 2 are never split in an optimal solution; splitting costs at least one non-profitable swap and cannot increase the maximum profit. Therefore run lengths only need to be capped at 2: `1` means singleton, `2` means long.
- **Useful local swaps:** For singleton middle runs, the only useful patterns are:
  - Profitable: `x y x y -> x y`, where the middle `y` and `x` are singleton. Profit `+1`.
  - Neutral: `x y x -> x y`, where the middle `y` and right `x` are singleton. Profit `0`. The other orientation `x y x -> y x` is equivalent to simply fixing the runs without a swap, because it trades one extra final run for one fewer swap.
  Swaps with zero matching neighbors do not reduce run count and cannot create a future nonnegative swap involving the swapped pair, so they are never useful.
- **Single-anchor DP:** Process runs left to right. After processing a prefix, only the rightmost surviving/anchor run can interact with the unprocessed suffix. Earlier anchors are blocked by it. If an optimal continuation would remove the current anchor, we can instead keep the previous anchor and treat the current one as an unprocessed middle run; this gives an equivalent or better decomposition. Thus a state only needs the processed position and the value of the current anchor.
- **DP definition:** `dp[i][v]` is the maximum profit after processing runs `0..i`, where the current anchor has value `v`. Initially `dp[0][A_0] = 0`.
- **Transitions from state `(i, x)` with profit `p`:**
  - Advance: make run `i+1` the new anchor with the same profit. This also covers neutral orientations that only trade a swap for an extra final run.
  - Neutral: if runs `i+1` and `i+2` are singleton, `val[i+2] == x`, and `val[i+1] == y`, then `x y x -> x y` makes `y` the anchor at `i+2` with profit `p`.
  - Profit: under the same singleton condition, if additionally `val[i+3] == y`, then `x y x y -> x y` makes `y` the anchor at `i+3` with profit `p+1`.
  The right outer run of a profitable swap may be long; only the two middle runs must be singleton.
- **State size:** Each position receives updates only from `i-1` (advance), `i-2` (neutral), and `i-3` (profit), so each `dp[i]` has at most three values. The algorithm is linear in the number of runs.
- **Counterexample for greedy neutral:** For `1 2 1 3 1 3`, greedily applying the first neutral `1 2 1` gives anchor `2` and misses the optimal profit. The DP also keeps the state with anchor `1` at position 3, then uses the profitable pattern `1 3 1 3`, obtaining profit 1.
- **Correctness sketch:** By induction on the processed prefix, the DP considers the first future operation that changes the anchor. If it does not involve the current anchor, we can advance until its left outer becomes the anchor. If it is useful, it must be one of the neutral or profitable patterns above. Each profitable transition corresponds to one valid swap improving the answer by 1; neutral transitions preserve the answer and only serve as enablers. Hence maximizing DP profit gives the minimum total operations.
- **Implementation:** Compress runs, cap lengths at 2, run the DP with small dictionaries, and output `R - max(dp[R-1].values())`. Total complexity is `O(sum N)` time and memory.
