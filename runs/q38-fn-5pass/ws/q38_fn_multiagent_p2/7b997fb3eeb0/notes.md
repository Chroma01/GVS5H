- **Core reduction:** For an interval of length `D` and a target `K`, feasibility is equivalent to pairing the `K` smallest mochi as tops with the `K` largest mochi as bottoms in sorted order. If any `K` pairs exist, replacing tops by smaller unused mochi and bottoms by larger unused mochi preserves feasibility.
- **Indexing:** Use 0-based `l = L - 1`, interval length `D = R - L + 1`. For top index `p = l + i`, the paired bottom is `p + D - K`. Thus `K` is feasible iff every top in `[l, l+K)` has its first valid bottom within offset `D-K`.
- **Precomputation:** Two pointers compute `nxt[p]`, the first index with `A[nxt[p]] >= 2*A[p]`, and `C[p] = nxt[p] - p`. The array is sorted, so `nxt` is nondecreasing and the two-pointer scan is linear. Sentinel `N` makes impossible tops fail automatically.
- **Query predicate:** For a candidate `K`, `max(C[l : l+K]) + K <= D` is necessary and sufficient. This predicate is monotone in `K` because the prefix maximum and `K` are both nondecreasing.
- **Range maximum:** A sparse table over `C` gives O(1) range maximum queries. To reduce per-query overhead, precompute `row_by_len[length]` and `off[length] = length - highest_power_of_two(length)`, so a query uses two direct row accesses.
- **Binary search:** For each query, binary search `K` in `[0, D//2]`. The upper bound enforces disjoint top and bottom halves. `K=0` is implicitly feasible.
- **Implementation details:** Input is parsed in bulk, then `A` and `queries` are sliced and the raw list is deleted. The sparse table is built with lists; rows store references to existing integer objects, keeping memory reasonable. Large structures are deleted before output to reduce peak memory during string joining.
- **Complexity:** Precomputation is O(N log N), each query is O(log N), total O((N + Q) log N). Memory is O(N log N) for the sparse table plus O(N) auxiliary arrays.
- **Pitfalls handled:** Duplicates are handled by using `2*a <= b`; sentinel values cannot pass because `D-K` is always smaller than the sentinel offset for any top in the top half; self-pairing is prevented by `j >= p+1` and by `K <= D//2`.
- **Alternatives considered:** Per-query greedy scans are too slow. Segment-tree predicates would add another logarithmic factor. Mo-style or segment-tree monoid approaches are more complex and do not improve the core feasibility test.
