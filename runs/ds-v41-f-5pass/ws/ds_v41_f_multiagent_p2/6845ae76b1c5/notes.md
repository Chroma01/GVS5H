- **Problem:** For each query (X,Y) answer sum_{i<X, j<Y} |A_i - B_j|; N<=1e5, K<=1e4.
- **Core decomposition:** Fix row-block size BL. Write X = qx*BL + r. Full rows i < qx*BL are handled by a cumulative array P[j] = sum_{i<qx*BL} |A_i - B_j| plus its prefix sums over j; partial rows i in [qx*BL, X) are handled individually. Total cost ~ (N/BL)*N + K*BL; balance gives BL ~ N/sqrt(K)/3.2 (~270 for N=1e5,K=1e4).
- **Partial rows (key trick):** For an event (row value a, column prefix Y) the column sum is s(a)=2*a*cnt_le - 2*sum_le + SB_Y - a*Y where cnt_le/sum_le count B_j (j<Y) with b_j<=a. All events across queries number <= K*BL (~2.7e6 worst) and are answered in O(log D) each with a wavelet matrix over B (supports count/sum of values < threshold in a prefix).
- **Wavelet matrix:** Build levels from high bit to low on compressed ranks; per level store prefix count of zeros (zc) and prefix sum of actual values among zeros (zv) plus total zeros Z. Query count_less(t) over prefix [0,y): if bit of t is 1 add zero-group count/sum and move to ones (l,r -> Z+(l-zc[l]), Z+(r-zc[r])); else move to zeros (l,r -> zc[l],zc[r]). Threshold t = searchsorted(unique,a,'right'). Vectorize across events; chunk events (~1e6) to bound memory.
- **Precompute full rows efficiently:** Adding a block of nb rows to P can be done in O(N+nb log N) WITHOUT log-N per column: p = searchsorted(sortedBvals, block, 'left'); sort block by p; freq=bincount(p); cumfreq[k]=#{p<=k}; cnt_le_sorted=cumfreq[:N]; sum_le_sorted=prefA[cnt_le_sorted]; contr_sorted = 2*b*cnt - 2*sum_le + tot - b*nb; scatter via argsort(B). (Using 'right' insertion and prefixA[cnt-1] is a trap and wrong with duplicates.)
- **Summation over partial events:** events are stored grouped by query (np.repeat), so per chunk use np.add.reduceat with local query boundaries (from cumsum of counts) instead of slow np.add.at; avoids float bincount precision loss.
- **Overflow:** All answers <= N*N*2e8 = 2e18, fits int64; keep everything int64 (never float, bincount weights would lose precision).
- **Edge cases:** handle BL clamped to [1,N]; queries with X multiple of BL have zero partial rows; BL=1 makes all queries full-only. sorted/unique handle D=1.
