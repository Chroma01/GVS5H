- **Approach:** Maintain the current rating `A[x]` for every possible initial rating `x = 1..500000`. Initially `A[x] = x`. Represent `A` as prefix sums of a difference array `D`, where `D[i] = A[i] - A[i-1]` and `A[i] = sum(D[1..i])`. Initially all `D[i] = 1`.
- **Contest update:** For interval `[L, R]`, because `A` is always nondecreasing, the affected indices form one contiguous range. Let `l` be the first index with `A[l] >= L`, and let `r` be the last index with `A[r] <= R`. Using Fenwick lower-bound, `l = first_ge(L)` and `r = first_ge(R + 1) - 1`. If `l <= r`, add `1` to `A[l..r]`, which is equivalent to `D[l] += 1` and `D[r + 1] -= 1` when `r < M`.
- **Fenwick lower-bound:** The Fenwick tree stores `D`. Since all `D[i]` remain nonnegative, the standard binary-lifting `first_ge(target)` works in `O(log M)`. It returns `M + 1` when no prefix sum reaches `target`.
- **Invariant:** `A` remains nondecreasing after each contest. At the right boundary, if `r < M`, then `A[r] <= R` and `A[r + 1] >= R + 1`, so after incrementing `A[r]` we still have `A[r] + 1 <= A[r + 1]`. Therefore `D[r + 1]` never becomes negative, preserving the Fenwick lower-bound requirement.
- **Query handling:** Instead of answering each query with a Fenwick prefix sum, maintain `diff` explicitly alongside the Fenwick tree. After all contests, convert `diff` to final `A` in one linear pass, then answer each query in `O(1)`.
- **Complexity:** `O(N log M + M + Q)` time and `O(M)` memory, with `M = 500000`. This avoids `Q log M` query cost and is efficient in Python.
- **Implementation details:** Use fast input via `sys.stdin.buffer.read().split()`. Initialize Fenwick tree for all-ones difference array by `bit[i] = i & -i`. Use the highest power of two not exceeding `M` for binary lifting. Inline Fenwick point updates in the contest loop for speed.
