- **Core model:** Sort initial piece positions `a` and final occupied positions `b`. Operations preserve left-to-right order and never increase gaps. The first piece must finish at `b[0]`, the last at `b[-1]`. The remaining task is to choose `M-1` transition gaps from the `K-1` initial gaps, in order, each at least the corresponding final gap.
- **Basic impossibilities:** If `K < M`, impossible. If final span `b[-1]-b[0]` exceeds initial span `a[-1]-a[0]`, impossible. Gap matching below also catches finer span/gap failures.
- **Base lower bound:** Let `X = b[0]-a[0]` and `Y = a[-1]-b[-1]`. Span feasibility gives `X+Y >= 0`. Any valid sequence needs at least `max(X, Y)` operations, because the endpoint that moves inward must make that many moves. This is `base`.
- **Unchanged gaps and parity:** If a chosen transition gap has `d == g`, that gap never shrinks. Its two bounding pieces must move identically in every operation, so their common displacement `b[j] - a[t]` has the same parity as the total number of operations. Therefore all chosen equal gaps must share one parity `p`.
- **Feasibility for a fixed parity:** Greedily match final gaps to initial gaps. For current final gap `g` and left final position `bj`, skip initial gaps with `d < g`, and skip `d == g` when `(bj - a[t]) & 1 != p`. Take the first gap with `d > g`, or with `d == g` and correct parity. Exchange argument: any valid matching must use a gap no earlier than this first usable gap, and taking it cannot hurt later matches.
- **Answer formula:** If parity `base % 2` is feasible, answer is `base`. Otherwise if the opposite parity is feasible, answer is `base + 1`. If neither parity is feasible, no operation count can satisfy the rigid-gap parity condition, so answer is `-1`.
- **Sufficiency sketch:** For a matching satisfying parity `p`, target displacements are nonincreasing, with equalities exactly on unchanged gaps. Choosing right-move counts as roughly `(L + displacement)//2` gives monotone right/left move counts compatible with prefix/suffix operation cuts. Gap deficits can then be reduced by edge operations (reduce one gap by 2) and vertex operations (reduce adjacent gaps by 1), with extra paired moves handling the parity slack.
- **Implementation details:** Use 0-based positions; parity differences are unchanged. Parse input as bytes and collect positions where byte equals `49`. The feasibility scan is linear, called at most twice per test case, so total time is `O(sum N)`. Negative parity is handled safely with `& 1`.
- **Samples:** Manual traces give sample outputs `3`, `-1`, and `5`. The first uses a `d > g` gap then a skipped wrong-parity equal gap; the second fails by piece count; the third matches all final gaps with parity `1` at `base = 5`.
