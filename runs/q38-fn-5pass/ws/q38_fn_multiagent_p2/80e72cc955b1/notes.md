- **Reduction:** For a value `x`, define `steps(x)` as the number of times it must be selected in operations until it becomes zero. One operation selects two array elements and consumes one needed selection from each. Therefore, for a multiset of positive step counts, the minimum number of operations is `max(max_step, ceil(total_steps / 2))`. The lower bounds are obvious: the largest element needs at least `max_step` operations, and two selections are made per operation. They are achievable by repeatedly pairing two currently largest positive counts; if one count dominates, pair it with zeros.
- **steps(x):** `steps(0) = 0`. For `x > 0`, `steps(x)` is the smallest `k` such that `x < 4^k`, equivalently the number of powers `4^0, 4^1, ...` that are `<= x`. This function is nondecreasing, so for a range `[l, r]`, the maximum step count is `steps(r)`.
- **Prefix sum:** To answer many ranges, precompute powers of 4 up to the maximum `r`. For `prefix_steps(n) = sum_{v=1..n} steps(v)`, use the tail-sum view: each threshold `p = 4^i` contributes 1 to `steps(v)` for every `v >= p`. Hence `prefix_steps(n) = sum_{p <= n} (n - p + 1)`. This is equivalent to summing bucket counts over intervals `[4^(i-1), 4^i - 1]`.
- **Query formula:** For each query `[l, r]`, `total_steps = prefix_steps(r) - prefix_steps(l - 1)`. The answer for that query is `max(steps(r), (total_steps + 1) // 2)`. Accumulate these answers in a Python integer.
- **Implementation details:** Generate powers from the actual maximum `r` in queries. Use `bisect_right` to compute `steps(x)` as the count of thresholds `<= x`. Handle `x <= 0` in `prefix_steps`. Use integer ceiling via `(total_steps + 1) // 2`.
- **Edge cases:** `l = 1` gives `prefix_steps(0) = 0`. Exact powers of 4 are included in the correct bucket because thresholds are inclusive. The constraints guarantee `l < r`, so there are at least two array elements; zeros can be selected after they appear, allowing a dominant element to be paired until it reaches zero. Empty queries are handled defensively.
- **Complexity:** There are at most 15 powers of 4 up to `1e9`. Each query does `O(log_4 max_r)` work for prefix sums and `O(log log max_r)` for bisect, effectively `O(15)` per query. Overall time is `O(queries * log_4 max_r)`, and extra space is `O(log_4 max_r)`.
- **Alternative:** A closed form is also possible. If `k = steps(n)`, then `prefix_steps(n) = k * (n + 1) - (4^k - 1) // 3`. `steps(n)` can also be computed as `(n.bit_length() + 1) // 2` for `n > 0`. The implemented tail-sum version is simple and less prone to off-by-one mistakes.
