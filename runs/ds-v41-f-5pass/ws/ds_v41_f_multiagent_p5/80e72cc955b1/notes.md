- **Core reduction:** For a value x, let d(x) be the number of times we must apply floor(x/4) to reach zero. Then d(x)=k exactly for x in [4^(k-1), 4^k - 1], k>=1. For query [l,r], let S = sum_{x=l}^r d(x). Every operation supplies at most two useful divisions, so the answer is at least ceil(S/2). This is achievable because the interval has at least two elements and the largest d-value never exceeds ceil(S/2); specifically c_max = d(r) and the next element r-1 satisfies d(r-1) >= d(r)-1, so S >= 2*d(r)-1. Hence answer = (S+1)//2.
- **Prefix computation:** F(n) = sum_{x=1}^n d(x). Iterate k=1..~15 blocks [4^(k-1), 4^k - 1], adding k times the number of integers from that block that are <= n. Each prefix call costs O(log_4(maxVal)) ~ 15 iterations. For each query, compute S = F(r) - F(l-1) and add (S+1)//2. Total complexity O(Q * log_4(maxVal)) ~ 1.5e6 operations for Q=1e5.
- **Boundary handling:** Use hi = min(lo*4 - 1, n) to respect inclusive interval endpoints. n <= 0 returns 0. Verified examples: [[1,2],[2,4]] -> 1+2=3; [[2,6]] -> 4. Manual checks: [3,4] gives S=3, answer 2; [15,16] gives S=5, answer 3; [1,4] gives S=5, answer 3.
- **Overflow/precision:** Python integers safely hold sums up to ~1.5e10 per query and ~1.5e15 total. No floating-point logarithms are used, avoiding precision errors at exact powers of 4.
