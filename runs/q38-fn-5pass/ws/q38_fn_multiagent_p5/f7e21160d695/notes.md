- **Implemented approach:** DSU merge counting over edges sorted by increasing weight. Each DSU component stores the total multiplicity of A vertices and B vertices currently inside it. When two components merge at weight w, the number of newly matchable A-B pairs whose minimax cost becomes w is added to the answer.
- **Core invariant:** after processing all edges of weight at most w, the DSU components are exactly the connected components of the subgraph containing edges of weight at most w. For a component C, min(cnt_a[C], cnt_b[C]) is the maximum number of A-B pairs that can be assigned with cost at most w entirely inside C. Thus sum_C min(cnt_a[C], cnt_b[C]) is the maximum number of pairs assignable with cost at most w.
- **Union contribution:** merging components X and Y at weight w changes the assignable-pair count by min(a_X+a_Y, b_X+b_Y) - min(a_X,b_X) - min(a_Y,b_Y). Those newly enabled pairs can be charged exactly w, because before this merge the two components were disconnected using edges of smaller weight, and after this merge they are connected using edges of weight w.
- **Correctness intuition:** f(x,y) is the first threshold at which x and y become connected in Kruskal order. The resulting component hierarchy is laminar. Matching as many pairs as possible inside a component is always optimal, since any pair postponed to a higher merge has cost no smaller. Therefore greedily counting newly matchable pairs at each merge gives an optimal assignment.
- **Equal weights:** sequential unions at the same weight are safe. All pairs created during a weight group have the same cost, and the total increase over the group telescopes to the increase for the final connected components, independent of union order.
- **Implementation details:** input is parsed from all whitespace tokens, vertices are converted to 0-indexed, edges are sorted by weight, DSU uses union by size and path-halving find, and counts are maintained only at roots. Python integers handle the large answer naturally.
- **Complexity:** sorting dominates with O(M log M), DSU operations are near-linear, so total time is O(M log M + (N+M) alpha(N)). Memory is O(N+M).
- **Edge cases:** duplicate vertices inside A or B are handled by multiplicities. The guarantee that no A vertex equals a B vertex means there are no zero-cost leaf matches, but the formula would still omit them correctly if they existed. The graph is connected, so all K pairs are eventually counted.
- **Pitfalls avoided:** no recursion or explicit Kruskal reconstruction tree is needed, stale counts on non-root nodes are harmless because find returns the root, and full whitespace parsing avoids issues with long input lines.
