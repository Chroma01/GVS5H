- **Reduction:** For value x the answer is max{ d : d | x, cnt[d] >= K }, where cnt[d] = number of array elements divisible by d. A K-set including A_i can reach gcd >= d iff at least K elements are divisible by d (A_i counts among them, leaving K-1 others). Conversely any set's gcd divides A_i and all chosen, so it is an eligible divisor of A_i. So answer_i = max eligible divisor of A_i.
- **Chosen approach (prime transform):** freq array up to M=max(A). Compute cnt with the multiple/superset sum using primes; then compute the max-over-divisors transform on the indicator value[d]=d if cnt[d]>=K else 0. Answer = transformed[A_i].
- **Multiple/superset sum correctness:** after processing prime p with `for i from M//p down to 1: cnt[i]+=cnt[i*p]`, cnt[i] becomes sum over multiples whose (multiple/i) uses only processed primes. Descending is required so the chain p, p^2, ... accumulates within one pass. Prime order is irrelevant.
- **Max-over-divisors transform:** after `for i from 1 to M//p: cnt[i*p]=max(cnt[i*p],cnt[i])`, cnt[x] = max over all divisors. Ascending is required (chain handling). Prime order irrelevant.
- **Complexity:** O(M log log M) for both transforms (sum over primes of M/p ~ M*2.88 for M=1e6 => ~2.9e6 inner steps each), plus O(M) sieve and O(N) I/O. Memory O(M + N).
- **Edge cases:** K==1 -> answer is A_i (shortcut, no transforms). M==1 (all ones) -> primes empty, cnt[1]=N>=K, answer 1. cnt[1] is always N>=K so every answer is >=1. Duplicates handled by freq counting. K==N handled naturally (only divisors of the global gcd survive).
- **Verified:** sample1 (3,4,6,1,6), sample2 (1,1,1) both match; sample3 consistent with rules. Reuse of freq as cnt (and in-place conversion to candidate array) saves one array.
- **Pitfalls avoided:** do not build cnt by iterating divisors directly (slower / more Python overhead); ensure descending vs ascending directions are not swapped; the `a > cnt[j]` comparison already skips zero entries, so no extra `if a:` is needed.
- **Alternatives considered:** Approach of ascending overwrite over eligible d (sum M/d ~ 14e6 writes) and per-value divisor enumeration (sum tau) are correct but heavier in Python; transform done instead.
