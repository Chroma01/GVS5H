Use anti-diagonals \(d=h+w\): every monotone path visits exactly one cell on each diagonal. Maintain forward DP values \(F\) from \((1,1)\) and backward DP values \(G\) to \((H,W)\) lazily along the walk. If the current position moves to a larger diagonal, recompute \(F\) for that diagonal from the already-correct previous diagonal; if it moves to a smaller diagonal, recompute \(G\) for that diagonal from the already-correct next diagonal. This keeps \(F\) correct for all diagonals up to the current one and \(G\) correct for all diagonals from the current one onward. For the updated cell, its coefficient in the total path sum is \(F_{\text{ex}}\cdot G_{\text{ex}}\), where \(F_{\text{ex}}\) is the sum of predecessor \(F\)-values and \(G_{\text{ex}}\) is the sum of successor \(G\)-values; update the answer by \((new-old)F_{\text{ex}}G_{\text{ex}}\) and update only that cell’s \(F/G\) entry. Each query recomputes one diagonal of length at most \(\min(H,W)\le \sqrt{HW}\le 447\), giving an efficient solution.
