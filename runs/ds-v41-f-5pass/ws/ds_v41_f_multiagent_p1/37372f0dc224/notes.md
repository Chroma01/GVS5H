- **Problem reduction:** The shortest palindrome with prefix S is S + reverse(S[:k]) where k = n - L and L is the length of the longest palindromic suffix of S. Writing S = A B with |A| = k and B palindrome, S + reverse(A) is a palindrome; minimality follows because a smaller k would imply a longer palindromic suffix of S.
- **KMP prefix function:** Build T = reverse(S) + separator + S with a separator outside the alphabet, e.g. b'#'. The prefix-function value at the last position of T equals L. The unique separator prevents any border from crossing the boundary, so pi[-1] <= n. This gives O(n) time instead of quadratic checks.
- **Implementation details:** Read all input as bytes with sys.stdin.buffer.read().split(). S is uppercase-only, so b'#' is safe. Compute the prefix function with the standard linear loop using a Python list for pi. The answer is bytes concatenation S + S[:k][::-1], written to sys.stdout.buffer.
- **Complexities:** Time O(n); memory O(n) for pi and T. Constraints n <= 500,000 imply T length <= 1,000,001, well within limits.
- **Edge cases:** If S is already a palindrome, L = n and k = 0, outputting S unchanged. A single character outputs itself. The final character of S always matches the first character of reverse(S), so pi[-1] >= 1, hence k <= n - 1. For strings whose only palindromic suffix is the last character, the algorithm appends reverse(S[:n-1]).
- **Alternatives:** Manacher or the Z-algorithm can also find the longest palindromic suffix, but the KMP prefix-function approach is simpler and fast enough in Python for this input size.
- **Sample verification:** ABC -> L=1, k=2 -> ABCBA. Z -> L=1, k=0 -> Z. TREE -> L=2, k=2 -> TREERT. ABAB -> L=3, k=1 -> ABABA.
