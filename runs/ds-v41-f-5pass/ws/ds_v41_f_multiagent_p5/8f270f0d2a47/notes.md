- **Goal:** self-contained program; `Solution.beautifulNumbers(l,r)` returns the count. Harness runs examples, exhaustive prefix 1..3000, 5 random ranges ≤3000, and 3 large windows near 1e9 (brute-forced per number), then prints `OVERALL: PASS/FAIL`.
- **Core idea:** a number is beautiful iff it contains a zero digit (product 0), or all digits are nonzero and `sum | product`. For nonzero digits the product's primes ⊆ {2,3,5,7}, so `sum | product` requires `sum` to be 7-smooth and its exponent tuple componentwise ≤ the product's.
- **Caps:** `(C2,C3,C5,C7)=(6,4,2,2)` because `2^6,3^4,5^2,7^2 ≤ 81 <` next powers. Capping exponents is safe since comparisons are only against `need[s]`, whose components never exceed the caps.
- **`freeD[k][s]`:** 4-D dominance suffix-sum over the 7·5·3·3=315 cell space, giving, in O(1), the count of length-`k` nonzero-digit strings with digit-sum `s` whose capped exponent tuple dominates any queried tuple. `B[m]` = length-`m` all-nonzero beautiful count = `freeD[m][need[s]]` summed over `s`.
- **`count_up_to(x)`:** `x - Z(x)` (all zero-containing numbers) + `B[m]` for shorter lengths + length-`n` enumeration (fix first strictly-smaller nonzero digit `e`, free suffix via `freeD[k]`), stopping at the first zero digit, then testing `x` itself. Answer = `count_up_to(r) - count_up_to(l-1)`.
- **Caching:** tables built once lazily in `Solution._cache`; a bound call is ~ms, so the 3000-call exhaustive loop is fast. Workspace has no runner, so timing/`OVERALL` numbers are not captured.
