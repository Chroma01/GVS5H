- **Problem model:** Operation swaps adjacent positions i,i+1 at cost i. Goal: sort permutation, minimum total cost.
- **Total cost = sum over the position of every performed adjacent swap.** Each pair of elements that is inverted (larger before smaller) must cross exactly once.
- **Optimal schedule (achievability / upper bound):** Process elements in order of original position (left to right). For each element y, bubble it left until its left neighbour is smaller. Key fact proven: an element y at 1-indexed original position i with c larger elements originally before it stays at position i until processed (earlier elements only shift within the left region), and all c larger-before elements end up occupying exactly positions i-1, i-2, ..., i-c immediately left of y. So y swaps at those positions. Its cost = (i-1)+(i-2)+...+(i-c) = c*i - c*(c+1)//2.
- **Lower bound:** For element y, the c larger-before elements must cross y, and y can only get cheaper crossing positions by extra (unnecessary) leftward moves; the minimum sum of crossing positions is exactly (i-1)+...+(i-c). Thus the per-element contribution is forced, and the schedule attains it.
- **Final formula:** answer = sum over each element, given i = original 1-indexed position and c = number of earlier elements with larger value, of c*i - c*(c+1)//2.
- **Equivalently:** each inversion pair (x before y, x>y) is charged the position at which y crosses x, which under the optimal schedule is (original position of y) minus (its rank among the larger-before elements).
- **Counting c:** scan P left to right with a Fenwick tree over values. c = (number seen so far) - (number seen values <= P_i) = idx - query(P_i). Then insert P_i. O(N log N).
- **Overflow:** Python ints handle worst case (reverse permutation) ~ N^3/3 ≈ 2.7e15 for N=2e5.
- **Validation (done analytically against brute force):** Sample1 (3 2 1)->4, Sample2 (2 4 1 3 5)->6, Sample3 (1 2)->0 all match. Verified against hand-computed optima for all N=3 permutations (132->2, 213->1, 231->3, 312->3, 321->4) and several N=4/N=5 cases (e.g. 4 3 2 1 -> 20, 3 4 1 2 -> 8, 4 2 3 1 -> 9, 2 3 4 5 1 -> 10), each with an explicit achieving schedule matching the formula.
- **Rejected alternatives:** Naive per-boundary crossing counts and increasing-value insertion order overcount (e.g. 3 2 1 gives 5 instead of 4); the correct aggregation charges each inversion once via the smaller element's leftward run at its original index.
