- **Count model:** The string is summarized by 26 letter counts. A good final string is defined by a positive frequency `f` and a subset of letters kept; kept letters have final count `f`, all others have final count `0`. Operations on counts are delete, insert, and move one unit from letter `i` to `i+1` at cost 1.
- **Cost for fixed `f` and subset:** Let `d_i` be either `0` or `f`. Without changes, cost is `sum |c_i - d_i|`. A change `i -> i+1` saves exactly one operation only when it consumes an excess at `i` and fills a deficit at `i+1`, giving edge saving `min(max(c_i - d_i, 0), max(d_{i+1} - c_{i+1}, 0))`.
- **Why only adjacent savings matter:** Moving a character two or more steps costs at least 2, the same as deleting it and inserting at the destination, so it cannot produce a net saving beyond adjacent moves. Chains through absent, balanced, or already-excess letters are never strictly better than the baseline plus independent adjacent savings.
- **DP over alphabet:** For each `f`, run a two-state DP over the 26 letters. State 0 means final count `0`, state 1 means final count `f`. Node cost is `|c_i - d_i|`. Transition from previous state to current state subtracts the edge saving computed from the two final counts. This is exact because savings only couple adjacent letters, and a letter cannot simultaneously provide excess to the right and receive a saving from the left.
- **Frequency range:** Enumerating `f` from `1` to `len(s)` is sufficient. If `f > len(s)`, every kept letter has original count less than `f`, so each kept letter needs at least `f - max_count` incoming operations; total cost is at least `f - max_count`. Keeping only a most frequent original letter at frequency `max_count` costs `len(s) - max_count`, which is smaller. Empty final string costs `len(s)` and is dominated by keeping one character for nonempty inputs.
- **Implementation details:** Build `cnt`. For each `f`, initialize absent/present costs for `'a'`. For each next letter, absent current has no deficit, so `new_abs = c + min(prev_abs, prev_pres)`. Present current has `base = abs(c - f)` and `deficit = max(f - c, 0)`. Previous absent excess is `prev_c`; previous present excess is `max(prev_c - f, 0)`. Subtract `min(excess, deficit)` from the corresponding previous DP value and add `base`.
- **Edge cases:** There is no wrap from `'z'` to `'a'`, so no edge after index 25. Letters with zero original count may be chosen present if insertions or changes make it worthwhile; the DP handles this. All absent is included but never wins for nonempty inputs. If `n == 0`, the method returns `0`.
- **Validation:** The provided samples pass: `"acab"` gives 1 with `f=1`; `"wddw"` gives 0 with `f=2`; `"aaabc"` gives 2 with `f=2` via one `a -> b` change and one `c` insertion. A small exhaustive brute-force verifier over short count vectors, using BFS over count states with enough intermediate letters, found no mismatches with the DP. No failing input was found.
- **Complexity:** Time complexity is `O(26 * len(s))`, and extra space is `O(1)` beyond the 26 counts.
