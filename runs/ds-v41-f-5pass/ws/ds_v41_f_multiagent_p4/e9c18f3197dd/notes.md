- **Problem shape:** Each target must have at least one multiple present in nums (after increments). One element can simultaneously satisfy several targets if it becomes a multiple of their LCM, so this is a small-universe covering problem over targets, not independent rounding.
- **State:** Bitmask over target indices (target.length <= 4, so <= 16 masks). `dp[mask]` = min total ops to cover exactly the target set `mask`.
- **Per-element cost:** For subset S, the cheapest value for nums[i] is the next multiple of LCM(S) at or above nums[i]. Cost = `(-nums[i]) % LCM(S)`. Precompute LCM for all subsets via `lcm[prev] // gcd(lcm[prev], target[i]) * target[i]` (divide before multiply; LCM of 4 values <= 10^4 fits easily in Python ints).
- **DP transition:** Process elements one at a time; snapshot old `dp` so an element is used at most once: `ndp = dp[:]`, then `ndp[old | S] = min(ndp[old|S], dp[old] + cost[i][S])` for all old, S. Using the exact subset S as coverage is sufficient, because if an element's chosen value happens to also divide some target outside S, then the subset equal to its full real coverage has LCM dividing that value and thus cost <= cost(S) — so iterating all subsets discovers it. Duplicate target values are handled automatically.
- **Bounding used elements:** Any optimal solution uses at most m elements (drop any element covering no new target). This makes a candidate-set reduction valid.
- **Candidate reduction (key optimization):** Full DP over all n elements would be ~n*2^m*2^m = 50k*256 ≈ 13M inner steps (risky in Python). Instead, for each of the <=15 nonempty subsets keep the K = m+1 cheapest elements for covering that subset. Argument: in an optimal assignment each element covers some set C_j; if it is not among the m+1 cheapest for C_j, then since at most m-1 other elements are used, one of those cheapest is free and no more expensive for C_j — swap it in. Repeating yields an optimal solution of candidates only. Candidate pool <= 15*5 = 75 elements, so total DP work is tiny.
- **Correctness cross-checks:** nums gains are non-negative so skipping is safe; LCM values up to ~10^16 fine; constraint target.length <= nums.length guarantees a distinct-element assignment exists.
- **Pitfalls avoided:** no element reuse (fresh dp copy / candidate list is a set); LCM via gcd not naive product; next-multiple via modulo handles nums[i] already a multiple (cost 0) and nums[i] < L uniformly.
