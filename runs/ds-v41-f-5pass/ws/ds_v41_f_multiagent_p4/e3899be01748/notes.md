- **Problem restatement:** Count substrings whose last character is a non-zero digit c and whose integer value is divisible by c. Substrings ending in '0' are never counted. Leading zeros are allowed and must be included in the numeric value.
- **Simultaneous residue DP:** For each possible divisor d in 1..9 maintain cnt_d[r] = number of substrings ending at the previous index whose value ≡ r (mod d). Processing a new digit c maps each old residue r to (10r+c) mod d; a fresh one-character substring contributes residue c mod d.
- **Counting step:** When c != 0, all substrings ending at the current index with last digit c are exactly those counted in the d=c table with residue 0. Add new_c[0] to the answer.
- **Why all divisors:** A substring ending earlier may be extended to end with any future non-zero digit, so we cannot keep only the current divisor. Maintaining all nine divisors simultaneously is O(45n).
- **Complexity:** Time O(n * (1+2+...+9)) = O(45n) ≈ 4.5M inner operations for n=1e5. Space O(45) integers plus a 45-element update buffer.
- **Implementation:** Use a flat list of length 45 with offsets off[d]. For each char build a new flat list, iterate d=1..9 and r=0..d-1, then insert the single-digit substring. If c != 0, add new[off[c]] (residue 0 for divisor c). Swap cnt and new.
- **Correctness argument:** Induction on the processed prefix. The transition covers all substrings ending at the new position: those extending a previous substring plus the one-character substring. Residue arithmetic holds because (a*10+c) mod d = ((a mod d)*10+c) mod d. The counting step selects exactly substrings whose last digit equals their divisor and whose value is ≡ 0 mod that divisor.
- **Edge cases:** s all zeros → 0. s all ones → n(n+1)/2 because every substring ending in 1 is divisible by 1. Leading zeros work naturally (e.g., "01" is built as 0 → 1, value 1). Divisor 1 is handled uniformly; no special branch is needed. n=1 is handled.
- **Validation:** Matches examples: "12936" → 11, "5701283" → 18, "1010101010" → 25. A brute-force checker on random small digit strings agrees with direct substring enumeration.
- **Pitfalls avoided:** Not counting zero-ending substrings; not resetting the DP at zeros (zero still extends prefixes and creates a new all-zero substring); adding the one-character substring after the extension step; using the full numeric value including leading zeros instead of relying on divisibility rules for 2,4,5,8 (10 is not invertible modulo those, but the DP never divides).
- **Potential micro-optimization:** Avoiding modulo inside the innermost loop by precomputing transitions is unnecessary for the given constraints; the flat-array version already runs comfortably within limits.
