- **Cost formula:** For subarray `nums[l..r]`, the minimum increments needed to make it non-decreasing is `sum(running maxima) - sum(elements)`. The greedy final value at each position is the maximum seen so far in the subarray.
- **Record chain:** Prefix maxima change only at the first strictly greater element. Compute `nxt[i]` as the next index to the right with `nums[nxt[i]] > nums[i]`, or `n` if none exists, using a monotone stack from right to left. Equal values are not new records.
- **Binary lifting:** `up[0][i] = nxt[i]`, `jump[0][i] = nums[i] * (nxt[i] - i)`. For `j > 0`, `up[j][i] = up[j-1][up[j-1][i]]` and `jump[j][i] = jump[j-1][i] + jump[j-1][up[j-1][i]]`. These store whole record intervals ending at `up[j][i]`. Sentinel `n` has `up[j][n] = n` and `jump[j][n] = 0`.
- **Cost query:** To compute `max_sum(l, r)`, set `target = r + 1`, start at `cur = l`, and for levels from high to low jump while `up[j][cur] <= target`, adding `jump[j][cur]`. After all whole intervals, if `cur < target`, add the partial interval `nums[cur] * (target - cur)`. Cost is `max_sum(l, r) - (pref[r+1] - pref[l])`.
- **Two-pointer monotonicity:** For fixed `l`, extending `r` cannot decrease cost. For fixed `r`, removing the left endpoint cannot increase cost, so the maximum valid right endpoint is nondecreasing as `l` advances. Keep `r` monotone, extend while `cost(l, r+1) <= k`, and add `r-l+1`.
- **Complexity:** Next-greater and prefix sums are `O(n)`. Binary lifting is `O(n log n)` time. There are at most `2n` cost queries, each `O(log n)`. For `n = 10^5`, `LOG = 17`.
- **Memory:** Up levels are Python lists of shared index references. Jump sums are stored in `array('q')` to avoid storing millions of Python integers, keeping memory around tens of MB. Prefix sums and input are `O(n)`.
